Saving Input ...................................................... 21 The Save Record Routine.............................................................................. 23 Example 7: An Unexpected Child Pops Up ........................................................ 27 Example 8: Saving One Child At a Time ........................................................... 29 Conclusion ..................................................................................................... 34 A Note about 4D Web 2.0 Pack ........................................................................ 34 Related Resources .......................................................................................... 34 Bridging Your Grids: Custom Web 2.0 Forms By Tim Kaufman, Technical Services Team Member, 4D Inc Page 2 Abstract ------------------------------------------------------------------------------------------------------------------------------------------------------------------ The best known marquee player in the 4D Ajax Framework’s lineup of front end objects is the Data Grid. It provides the familiar list style of an output form, rowlevel inline editing, and a built-in pop-up edit window in the style of an input form. Yet you may still crave your own custom forms, without too much effort of course. With the help of 4DAF’s Bridge object and a little JavaScript, this Technical Note demonstrates building a Web subform which will dynamically display the related records of a secondary table. Record saving is also implemented, both for the main form and the subform. A sample database is included. Published August 13, 2008 as Technical Note 08-29 for 4D Web 2.0 Pack v11.2 (Mac &amp; Win), this note was written by Tim Kaufman, Technical Services Team Member, 4D Inc during the 4D v11 SQL era, when 4D's newly integrated SQL engine (introduced 2007) and the 4D Ajax Framework (4DAF) for AJAX-based web UIs were the platform's flagship modern capabilities. It reflects the pre-ORDA, pre-Project-Mode 4D development model, in which the binary Design Mode structure file was the only structure format and 4D's own SQL layer was still new relative to the classic procedural/set-based language that had defined 4D since the 1980s.
