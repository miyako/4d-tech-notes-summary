Written by Steve Hussey (CEO, Alto Stratus LLC), this Tech Note explains 4D v6.7's newly introduced inherited forms feature, which lets a developer define one master form (with standard navigation, accept/save, or list-management buttons) that is then inherited by forms belonging to other tables, ensuring visual and behavioral consistency across a database. It walks through the Form Editor steps for setting a form's Inherited Form Table and Inherited Form Name properties, explains how inherited-form content is combined with the open form's own objects in a fixed page order (inherited master page, inherited page 1, open form's master page, then open form's current page), and notes that the inheritance link stays live so edits to the parent form propagate automatically, unlike the static New Form Wizard templates. The central problem the note solves is that a shared form's code cannot inherently tell which table it is currently attached to; the accompanying sample database (Util_Preference_Application, Client, and Contact tables sharing one input form and one list form) solves this using the Current form table command as a pointer to the calling table, feeding it into generic Query, Subset, All, Delete, Sort, Labels, and Reports button methods, and into a WND_TableName project method that sets an appropriate window title via Table name and Records in selection/Records in table. The result is a single reusable set of standard forms and buttons that behave correctly no matter which table's form triggered them, with any behavioral change needing to be made only once.
