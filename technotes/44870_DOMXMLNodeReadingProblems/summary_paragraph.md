This Technical Note by David Adams explains why 4th Dimension's DOM XML tree-navigation commands (such as DOM Get first child XML element and DOM Get Parent XML element) can leave a developer holding a reference to an invalid, non-existent node — a normal and expected outcome when navigating past the edges of the tree — and why subsequently trying to read that invalid node's name, value, or attributes causes problems. It reviews the two suites of XML commands in 4D 2004 (DOM and SAX), focusing exclusively on DOM, and documents four escalating strategies for avoiding trouble: (1) testing the built-in OK system variable, which the navigation commands set to 0 whenever they move to an invalid node, allowing generic tree-walking code to detect when to stop; (2) using the optional name/value parameters supported directly on the navigation commands themselves, which sidesteps the risk entirely for the common case of reading a node's name and value but doesn't help with attributes or generic tree-walking; (3) installing a custom ON ERR CALL error handler as a safety net, necessary whenever code needs to count or read attributes without first testing OK; and (4) writing a reusable, general-purpose node-validation routine (the note's DOM_ReferenceIsValid) that installs a temporary error handler, attempts to read the element's name, and reports validity based on whether an error occurred or the name came back empty. The note then documents a special, more dangerous case: calling DOM Count XML attributes on the synthetic "#document" node (an artificial node above the true root that stores document-level info like XML version and encoding) causes some versions of 4th Dimension to quit unexpectedly, and shows a DOM_CountAttributes routine that safely detects and special-cases both invalid references and the #document node before calling the native count function. This #document special-casing and the DOM_ReferenceIsValid/DOM_StartCustomErrorHandling/DOM_StopCustomErrorHandling routines introduced here form the reusable error-handling foundation reused across several sibling XML tech notes from this period. The featured technology throughout is 4D's classic DOM XML command suite and the general defensive-programming techniques needed to use it safely.
