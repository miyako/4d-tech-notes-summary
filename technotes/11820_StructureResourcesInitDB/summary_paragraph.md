This Tech Note explores how to use resources stored in the 4D structure file to create missing default records when a new data file is created. It demonstrates storing initialization data as resources within the structure file itself, which are then read and used to populate default records in the database. Additionally, the note illustrates how to embed a user's serial number or other identifying information into the structure file in a way that carries this information into every new data file the user creates. This technique could be used as a simple copy protection mechanism. The resource-based approach was typical of the classic Mac OS era, where resource forks were a fundamental part of the file system and commonly used for storing structured data alongside applications. This was a creative use of 4D's resource access commands for practical deployment needs.
