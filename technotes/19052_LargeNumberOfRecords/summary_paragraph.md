This Tech Note (TN 01-51, 4D v6.7, Mac & Win, published November 30, 2001) presents guidance on speeding up databases with very large record counts and working around the classic 16-million-record table limit. Only a short on-page teaser paragraph survives in this archive rather than the full downloadable PDF and example database, because the original download was an old Windows self-extracting .exe installer (https://kb.4d.com/ftp://ftp.4D.com/ACI_TECHNICAL_NOTES/2001/Windows/TN_2001_50-53_(NOV)/01-51_Large_Num_of_Records.exe) that could not be extracted in this environment; the original 4D Tech Notes site offered separate Windows and Mac downloads of the complete note and its companion example database, but neither is retrievable here. Based on the surviving teaser text, the note's proposition is: 4D has a limit of 16 million records per table. This tech note describes how you can speed up databases with a large number of records and how you can exceed this limit in some cases. Its featured technology centers on 4D data file architecture, Record count limits, Performance optimization, Indexing, reflecting typical concerns of the 4D 6.7 (4D 2000/2001 era) developer community working in binary Design Mode on classic Mac OS/early Mac OS X and Windows 98/2000/NT. This note discusses the then-current 16-million-record-per-table ceiling in 4D and techniques for improving performance and working around the limit. 4D's data engine has been substantially rearchitected since 2001 (including the move to a 64-bit engine around 4D v13), which raised or removed many of these classic record-count and file-size ceilings, so the specific limit cited is outdated even though the general performance techniques (proper indexing, selection management) remain conceptually useful.
