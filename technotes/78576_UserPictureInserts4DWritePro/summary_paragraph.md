This Tech Note addresses a gap in 4D Write Pro's default behavior: when a user drags or pastes an image into a document, 4D Write Pro automatically inserts it as an in-line picture, with no built-in way to ask whether the user actually wanted a background or anchored image instead. It begins by cataloguing 4D Write Pro's three picture types and their attribute APIs: background pictures are document-level attributes set/read with `WP SET ATTRIBUTES`/`WP GET ATTRIBUTES` (e.g. `wk background image`, `wk background repeat`); in-line pictures behave like a text character and are inserted with `WP INSERT PICTURE` targeting a Write Pro range; and anchored pictures, the most flexible type, are added with `WP Add picture` and positioned using attributes like `wk anchor origin`, `wk anchor horizontal/vertical align`, and `wk anchor layout` to control stacking order relative to text. To intercept user-driven inserts, the note shows disabling the 4D Write Pro area's automatic drop behavior (setting "Droppable" to Custom) and enabling the `On Drop` event, where the developer can inspect the drag-and-drop pasteboard contents (via the Pasteboard command theme) and decide how to handle a dropped picture — either automatically inserting it as an anchored picture or opening a dialog to let the user choose the insertion style. Because 4D Write Pro has no native "on paste" event, paste is instead detected by enabling `On Before Keystroke` and checking for the platform paste shortcut (Cmd+V / Ctrl+V) using modifier-key detection commands plus `Keystroke`. The hardest case — pasting via the (non-modifiable) built-in contextual menu — requires a more convoluted `On After Edit` workaround: check if the freshly inserted content matches the pasteboard, and if so, remove the automatic in-line insertion and re-insert the picture programmatically as desired. The note cautions that pasteboard data structure varies significantly by source application (Word, a web browser, a file), requiring source-specific handling, and ships a six-demo sample database (v18Rx) illustrating each scenario.
