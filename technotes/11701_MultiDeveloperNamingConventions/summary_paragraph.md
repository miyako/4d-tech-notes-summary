Although the batch metadata for this note carries the title "Developing with 4D Server Part 3: Naming Conventions for Multi-Developer 4D Projects," the actual technical content of TN 96-41 as published is titled "File Names and Pathnames" and focuses on a narrower, concrete problem: writing platform-independent 4D code to extract just the file name from a full pathname string, given that Mac OS and Windows use different path separator characters and conventions (colon-delimited Mac HFS paths vs. backslash-delimited Windows paths). The note presents custom "Path to name" and "Path only path" utility methods that parse a full document pathname and split it into its filename and containing-folder-path components, written to work correctly regardless of which platform generated the path, and discusses practical constraints of the era such as DOS's 8.3 filename length limit that developers had to account for when a database might exchange documents across both Mac and Windows systems. A companion topic covered is the MAP FILE TYPES command, used to associate a Mac file's type/creator codes with a Windows file extension (and vice versa), so external documents opened or created by 4D are recognized correctly regardless of which platform later accesses them. An example database accompanying the note demonstrates these routines via "Save Multiple" and "Test One Document" menu commands, letting a developer test the pathname-parsing logic against real files on the current platform. Featured technology is the custom pathname-parsing utility routines (Path to name / Path only path) and the MAP FILE TYPES command, addressing cross-platform document/file naming as it existed for 4D applications spanning both classic Mac OS and Windows in 1996.
