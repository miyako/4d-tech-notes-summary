This Tech Note extends the earlier "Keyword Support in 4D v11 SQL" note by tackling multi-keyword search, and includes a sample database of 5,000 Wikipedia articles to demonstrate it. It explains 4D v11 SQL's Keyword Index option for Alpha/Text fields, which indexes data word-by-word (including single-character words) and can coexist with a regular index on the same field, and introduces the `%` (Contains Keyword) operator, contrasting it against the older `@text@` (contains) and `text@` (begins with) operators using a comparison table showing how "system," "systematic," and "ecosystem" match differently under each. It defines how 4D determines "word boundaries" per ICU standards (keeping numbers, apostrophes, and hyphens attached to words while splitting off punctuation) and notes the important limitation that `%` only matches a single keyword per call, meaning multi-word phrase searches require chaining several `QUERY` calls together with the `&` (AND) compound-query operator — one call per word. The sample database implements this pattern with a custom `Util_GetStringToken` method that tokenizes free-form user input on a delimiter (defaulting to a space) into a text array, then a `4D_AKS_Find` method that loops through the tokens building either a single keyword query or a chained compound query depending on token count, and lets the user choose whether each word should match as a whole word, "begins with," or "contains." Supporting methods handle result display, article preview, list/edit views, and query-plan diagnostics via `DESCRIBE QUERY EXECUTION`. The note targets developers who need to implement fast, precise, user-facing full-text search over large Alpha/Text datasets.
