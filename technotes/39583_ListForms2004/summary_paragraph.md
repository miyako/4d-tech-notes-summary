This Technical Note by Daniel Do covers the fundamentals of list (output) forms in 4D 2004, which display multiple records as a browsable, sortable, printable list, in contrast to detail (input) forms that show a single record. It documents the two commands used to display list forms programmatically — DISPLAY SELECTION, which shows a selection read-only and automatically switches the table to read-only mode, and MODIFY SELECTION, which allows in-list editing and switches the table to read-write mode — both sharing the same parameter signature (table, selectMode, enterList, and two optional "*" display flags) and both restoring the table's prior state after execution. It explains the selectMode parameter's three constants (No Selection, Single Selection, Multiple Selection, the last being the default), the enterList parameter that enables "Enter in List" editing directly within the output form rather than requiring the input form, and the special-case behavior where a single-record selection displays in the input form unless overridden by the optional "*" parameters. The note documents the UserSet, a set of user-highlighted records that remains available to the calling method after DISPLAY SELECTION or MODIFY SELECTION completes, useful for follow-up actions like printing only the selected records, and covers exiting behavior via custom Accept/Cancel buttons or the platform Escape key. It closes by describing 2004-era UI behavior updates — list forms no longer allow scrolling past the last record when more records exist than fit on screen, the "Double-click on Empty Line" compatibility property for upgraded pre-2004 databases (recommended against for new work), and the removal of the blinking subform-focus triangle in favor of standard OS focus indication — reflecting 4D's effort to align list-form behavior with contemporary OS GUI conventions.
