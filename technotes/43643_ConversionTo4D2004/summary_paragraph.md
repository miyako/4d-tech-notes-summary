This lengthy Tech Note, compiled by 4D SA/4D Inc. from various technical notes, tech-tips, and product documentation, serves as a comprehensive migration guide for converting existing 4D databases—ranging from very early versions (2.x, 3.x) through 6.x and 2003—into 4D 2004. It lays out upgrade principles: recent versions (like 6.5.x) can convert directly to 2004 without passing through intermediary versions, while very old databases (version 3 or earlier) should first pass through an intermediary version like 6.5 or 6.7, and cross-platform migrations should be done on the original platform first before switching OS. The note warns against launching very old 4D versions on modern operating systems due to data-level risks, and details required tools, handling of externals and plug-ins across version ranges, and how to resolve data problems the conversion process might reveal. A major focus is the architectural shift in 4D 2004 itself: the separation of structure and data files into "resource fork" and "data fork" components, a new folder architecture, a relocated Preferences folder, a new plug-in architecture and loading priority system, and license activation changes. It documents compatibility considerations for converted databases across structure, Web features, menu bars, platform-specific preferences/forms, window sizing, system highlight colors, and ASCII filters. Significantly, the note describes 4D 2004's integration of previously separate companion products directly into the core application: 4D Insider functionality, 4D Customizer features (both in the core app and in plug-ins), 4D Backup enhancements, and 4D ODBC, plus three new bundled plug-ins. It also catalogs new behaviors and features introduced in 2004, including a new Formula editor, harmonized list operations across User Mode/Custom Menus mode/subforms, new List Box commands and events (List Box being an entirely new form object in 2004), new form events, new 4D Write and 4D View features, and modified/renamed language commands and keyboard shortcuts. As an all-in-one migration reference tied specifically to the jump from pre-2004 4D versions to 2004, it is a valuable historical snapshot of 4D's early-2000s architectural consolidation, though entirely superseded by many later version-specific migration guides.
