This Tech Note introduces dynamic (form) variables, a new 4D v12 concept, and explains why a developer would want to use them: to reduce a form's memory footprint and to manage the "window of vulnerability" that arises when the same form is multi-instantiated by different components sharing variable names. It walks through evaluated expressions as a forerunner concept (illustrated with a clock example) before showing how to actually declare and use dynamic variables, including handling them through programming with OBJECT Get pointer and using pointers to support multiple form instances cleanly. The bulk of the note then describes the custom XVH component, built specifically to let a form using dynamic variables communicate with the process that opened it — covering getters/setters, calling a binding method before and after form display (via On Load and On Validate form events), managing bindings, handling communication both between processes and between separate 4D applications, and the utility methods that tie it all together. The note targets 4D developers building forms reused across many contexts (e.g., components) who need a robust, memory-conscious way to bind form data to caller-provided variables.
