This tech note introduces form macros, a v18 R5+ feature exclusive to Project mode that lets developers execute arbitrary code from a contextual "Macros" menu directly inside the form editor, with full read/write access to the form and its objects. Setting one up requires two artifacts: a formMacros.json file in the project's Sources folder declaring each macro's name, its backing 4D class, and any optional custom parameters, and a corresponding 4D Class implementing an onInvoke function (mandatory), an optional Class constructor for retrieving custom parameters, and an optional onErr handler. The onInvoke function receives an $editor object exposing the current page's objects, the current selection, the form's pages/views/properties, and the table number if applicable; any modifications (adding, editing, or removing object attributes) are returned via a $result object that the form editor applies immediately. The note documents several important rules: macros with duplicate names collapse to one entry (preferring the one with uppercase-containing names, or the later-declared one); host and component macros can coexist and are labeled by their source; and a macro won't appear in the menu at all unless its class exists and defines onInvoke. A large set of demo macros illustrates practical uses: adding a button object programmatically, changing/removing object properties like font color or icon image via generic classes (ChangeObjectProperty, RemoveObjectProperty), opening the formMacros.json or CSS file directly from the editor, checking the 4D version, validating image paths, and scanning for obsolete/unsupported commands or plugin areas as part of a Project mode conversion workflow. Because form macros are a productivity/tooling feature for the design-time editor rather than end-user runtime functionality, they are positioned as a way to codify and share repetitive design tasks across a team.
