This revised January 1996 Tech Note (originally by Julie Pearson, revised by Jeff Browning) addresses a practical problem introduced by 4D's transition to a platform-independent extension architecture using the Mac4DX and Win4DX folders: prior testing techniques for external availability, written for the pre-1.5 external architecture, no longer worked reliably. The solution presented uses only standard 4D code, requiring no help from the external itself: it deliberately calls one of the external's commands (e.g. a minimal 4D Write call such as `WR Error text`) inside a procedure trapped by `ON ERR CALL`, and if the external is missing, 4D raises a syntax error that the error handler catches and records via a global `LError` variable; the calling code then checks whether `LError` is zero to determine whether the external is available. The note walks through example procedures — `OnErrCall`, `WriteAvail`, and a `Startup` procedure that calls `WriteAvail` and alerts/quits if 4D Write isn't installed — and stresses that an explicit `IDLE` call must follow the error-triggering command so the error is properly registered, particularly in compiled databases where a callback to the 4D kernel is required. The general rule of thumb given is to call a command that does very little, so as not to alter data while merely probing availability. The featured technology is 4D's error-trapping mechanism (`ON ERR CALL`) applied specifically to detect 4D Write and, by extension, any 4D external or third-party package.
