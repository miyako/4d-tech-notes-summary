This Tech Note by Tai Bui introduces REST (Representational State Transfer) as an architectural style for stateless, cacheable client-server communication over HTTP, and explains how a 4D Web Server can be leveraged to implement REST endpoints even though 4D at the time did not yet ship a fully native REST server product. It walks through how REST is typically served, how a client consumes REST services via plain URLs and HTTP GET/POST parameters, and the general benefits of REST (simplicity, statelessness, broad client compatibility). The implementation section covers handling incoming requests inside 4D's web server hooks, formatting JSON responses, parsing GET and POST parameters manually, handling errors gracefully, and implementing custom authentication for protected endpoints. A sample database demonstrates a basic REST method, a method for handling GET parameters, one for POST parameters, and an access-control example restricting certain REST calls to authenticated users. The note targets 4D developers wanting to expose their database functionality to web, mobile, or IoT clients (the abstract explicitly mentions smart-home devices and wearables) without needing deep web development expertise, noting that basic HTML/JavaScript familiarity helps but isn't required. Because this predates 4D's native ORDA-based REST server, all routing, parameter extraction, and JSON serialization is done by hand using 4D web server commands rather than automatic dataclass exposure. It stands as a useful primer on REST concepts, but its concrete implementation technique has since been made largely unnecessary by 4D's built-in REST server.
