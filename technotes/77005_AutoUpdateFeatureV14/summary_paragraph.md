This Tech Note by Julian Weidenbacher documents 4D v14's new automated application update mechanism, which for the first time allowed merged server and standalone 4D applications to be fully updated without the end user manually downloading, unzipping, and copying files. It walks through both halves of the process: on the developer side, building the application, compressing it, and hosting it (the example uses an FTP server) for distribution; on the customer side, downloading, extracting, preparing, running, and restarting into the update, all of which can now be fully automated. Practical guidance covers pitfalls such as never naming the application with "update" in its name, always keeping the data file outside the database folder, and using the user's temporary folder for downloads/backups to avoid permission issues. The bundled sample application demonstrates each step in code: downloading via 4D Internet Commands' `FTP_` routines or `HTTP Get`, extracting archives using platform-native tools (7-zip on Windows launched via `LAUNCH EXTERNAL PROCESS`, or OS X's built-in unzip), backing up logs/preferences/web folders before they're overwritten, pointing 4D at the new build with `SET UPDATE FOLDER`, and triggering the actual swap-and-restart with `RESTART 4D`. It closes with startup-time success/failure detection using a marker file and the new `Get last update log path` command for reviewing what happened during the update.
