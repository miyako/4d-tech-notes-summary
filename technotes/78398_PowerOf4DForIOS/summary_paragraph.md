This tech note showcases 4D for iOS, an integrated 4D component that let developers design, build, and deploy native Swift/Xcode iOS applications directly from a 4D database backend without writing Swift code themselves. Using a running example app called "WorkPin" — a workplace bulletin-board CRUD app where users post/edit/delete announcements tied to their own account — the note walks through the full workflow: defining a backend structure in 4D (Postings and Users tables linked by a foreign key), creating a new Mobile Project via File > New > Mobile Project, and navigating the mobile project editor's eight sections (General for app identity/icon/theme, Structure for publishing table fields, Data, Actions for defining CRUD operations, Labels & Icons, Main Menu, Forms for frontend screen design, and Publishing). It documents detailed compatibility requirements tying together specific Xcode, Swift, 4D, and macOS versions (e.g., 4D v18 with Xcode 11.2/Swift 5.1/macOS 10.14, going back to 4D 17R2 with Xcode 9.3.1), reflecting how tightly 4D for iOS was coupled to Apple's own fast-moving toolchain. The note covers publishing table fields for mobile exposure, defining CRUD actions bound to backend data, building frontend forms, implementing user authentication, and finally testing in 4D's built-in simulator before deployment. Positioned as making native mobile development accessible to 4D developers without deep iOS expertise, the note frames 4D for iOS as extending existing 4D applications to mobile or building standalone iOS apps from scratch, with offline mode, data synchronization, and the ability to generate multiple apps from a single 4D database.
