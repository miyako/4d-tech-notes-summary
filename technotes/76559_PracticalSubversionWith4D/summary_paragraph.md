This Technical Note by Josh Fletcher addresses a long-standing pain point in 4D development: because 4D databases store methods in binary form, tracking changes over time with a revision control system like Subversion has historically been an unsolved problem for most developers. The note presents the CodeExport component, which uses 4D v13's Source Toolkit feature to automatically export every method in a host database as UTF-8 text files suitable for committing to a repository. Designed for zero impact on the host database, CodeExport requires no startup code or configuration — it is driven entirely by Method Editor macro events, so opening, closing, saving, or creating a method silently triggers a stored procedure ("CodeExport Component Process") that exports changed code in the background, checking for changes every second and displaying a progress bar if an export is expected to take more than a second. Exported methods land in a "ce_source" folder next to the database (organized by method type, e.g., project methods at the root and table/form methods in nested subfolders), while a separate "ce_data" folder holds the component's own metadata database so it can be upgraded independently. The note also documents available macros (Start/Stop Monitor, Resolve Error, Full Reset, optional Startup Install), notes that the export runs server-side in client/server deployments, and cautions that CodeExport is interpreted-only and has no purpose in compiled databases.
