This note introduces 4D.HTTPRequest, a new class-store class shipped in 4D v19 R6 that modernizes how 4D applications make outbound HTTP calls. A request is created and sent with 4D.HTTPRequest.new($url; $requestOptions), where $requestOptions is typically an instance of a developer-defined class exposing callback functions such as onResponse($request; $event), onError($request; $event), onHeaders, and onTerminate; unless request.wait() is explicitly called, all requests execute asynchronously by default, so multiple requests can be in flight simultaneously without dedicating a separate process to each one as the older HTTP Get command required. The resulting HTTPRequest object centralizes everything about the exchange — .response, .errors, .wait() — replacing the pattern of juggling separate output variables for headers, body, and status that the classic HTTP Request/HTTP Get commands required. Error handling also improves: an onError callback replaces the need for ON ERR CALL around network calls. The note demonstrates all of this with a working demo against the Art Institute of Chicago's public API, chaining three request types (search query, per-artwork data fetch, then an IIIF-compliant image fetch) inside nested onResponse callbacks to progressively populate a list-box gallery, and using a final synchronous request (via .wait()) to fetch a larger image when the user selects an artwork to view in a modal.
