Written by Jon Baltazar of 4D, Inc. Technical Support, this Tech Note explains how 4D v6.7 added the ability to interoperate with CGIs (Common Gateway Interface programs) from its web server, letting developers offload tasks 4D itself could not perform to external executables, DLLs, or Perl scripts placed in a required cgi-bin folder alongside the structure file. The note first contrasts 4D's Contextual web-serving mode (where 4D auto-generates HTML and the developer has no control over markup) with Non-Contextual mode (where the developer supplies hand-authored HTML pages and can freely add CGI calls), which is required for CGI support and needs Publish Database at Startup, Start without Context, and a Default HTML Root/Home Page configured in Database Properties. It surveys the CGI types supported on each platform (Windows: .exe/nph-*.exe, ISAPI .dll; Mac OS: WebSTAR/MacHTTP .cgi/.acgi extensions; both: Perl scripts requiring ActivePerl or MacPerl) and notes that a CGI call never modifies the 4D environment and is capped at 30 seconds of processing time. The accompanying sample database demonstrates five Perl CGI scripts — img_counter.pl (an image-tag hit counter reading/writing count.txt), counter.pl (a script-execution counter), hello_world.pl (a minimal CGI), qa.pl (a question/answer board backed by three text data files), and redirect.pl (a dropdown-driven site redirector) — each invoked from HTML tags such as an <img src=/cgi-bin/img_counter.pl?file=...> tag, illustrating the mechanics of wiring a 4D-served HTML page to an external Perl interpreter.
