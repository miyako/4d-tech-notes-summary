This Tech Note surveys the landscape of 'standard' picture formats developers encountered in the mid-2000s — PICT for Mac OS, BMP for Windows, GIF and JPEG for the web, and software-specific formats like PSD (Photoshop) and PSP (Paint Shop Pro) — and explains that 4D's READ PICTURE FILE and SAVE PICTURE TO FILE commands rely on Apple's QuickTime framework to read and display all of these supported formats. It then makes a key conceptual point: like any computer file, a picture file is fundamentally just an organized sequence of bytes, and understanding a format's native byte-level structure lets a developer both create/read pictures at that level and apply transformations directly by manipulating those bytes. Building on this, the note draws a distinction between a picture's original format and the format actively used for editing/transformation purposes, and shows how the PICTURE TO BLOB command lets a 4D developer convert a picture to and from the various formats QuickTime supports, enabling byte-level picture manipulation workflows within otherwise standard 4D applications. This combination of QuickTime-backed format conversion and BLOB-level byte access represents the primary way 4D developers of this era worked with image data programmatically, well before 4D gained any QuickTime-independent native picture handling.
