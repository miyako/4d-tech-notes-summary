This Tech Note by Hugo Fournier (Technical Support Engineer) explains how to send an e-mail containing both a plain-text and an HTML version of its body using 4D Internet Commands, contrasting the simple one-call `SMTP_QuickSend` (plain text only) with the low-level `SMTP_` command sequence (`SMTP_New`, `SMTP_Host`, `SMTP_From`, `SMTP_Cc`, `SMTP_Bcc`, `SMTP_Subject`, `SMTP_AddHeader`, `SMTP_Send`) needed for richer control over headers and content. It walks through the relevant Content-Type headers -- `text/plain`, `text/html`, and the key `multipart/alternative` header with a `boundary=` parameter that lets a mail client pick whichever body part it supports best -- and stresses two easy-to-miss RFC 2046 requirements: each body part needs its own Content-Type line, and a blank line must always follow it. The accompanying example database's `Form1` lets a user pick To/Cc/Bcc recipients from a `[Contacts]`/`[Email_Table]` pair of tables via pop-up menus (all sharing a single `Gen_Fil_List` handler driven by pointers), enter plain-text and HTML bodies in tabbed text areas, and see the computed header type and full multipart message live before sending; the sending code chains the SMTP_ calls with error trapping at each step, aborting the sequence and reporting whichever command failed via `Err_Alert`.
