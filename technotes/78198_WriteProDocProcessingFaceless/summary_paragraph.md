This Tech Note by Vance Villanueva addresses a gap that arose when legacy 4D Write's offscreen-area API (`WR New offscreen area`) had no direct 4D Write Pro equivalent for batch/backend processing: how to evaluate embedded expressions in a 4D Write Pro document (e.g., queries or formulas inserted via `WR INSERT EXPRESSION` or the Insert → 4D Expressions menu) without a form object present in the UI. The note explains that in 4D Write Pro, every character occupies a single document position, so multi-character expressions can fail to evaluate reliably in this faceless context; as a workaround, it encapsulates each found expression inside a call to a custom `EVALUATION_METHOD` project method, re-inserts that wrapped call back into the document at the same location, and relies on the built-in `PROCESS 4D TAGS` command inside `EVALUATION_METHOD` to actually resolve the expression text at runtime. A second helper method, `PROCESS_EXPRESSIONS`, walks the entire 4D Write Pro object (passed by pointer), locates every expression, and rewrites it using this technique, after first registering `EVALUATION_METHOD` and `PROCESS_EXPRESSION` as callable via `SET ALLOWED METHODS`. The accompanying sample database demonstrates the full pipeline: opening a document (with or without a form object), running expression substitution, and producing output either by printing the 4D Write Pro document/object to paper or PDF, or exporting to HTML for emailing. The note also flags an important compatibility caveat: since 4D Write internally references tables and fields by unique numeric IDs within expressions, documents converted from 4D Write to 4D Write Pro must be tested against the same database (not a copy with matching table/field names) to keep expressions functioning. This positions the note as a practical bridge for developers automating document generation (e.g., mail merges, reports) who need 4D Write Pro to behave like the old offscreen-area workflow but in a modern, 64-bit, object-based document model.
