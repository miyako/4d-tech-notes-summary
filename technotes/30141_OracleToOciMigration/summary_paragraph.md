Written by Jamras Komoncharoensiri, a Technical Support Engineer at 4D, Inc., this Tech Note documents a 'painless' migration path from the legacy 4D for Oracle connectivity plug-in to the newer 4D for OCI plug-in, centered on a compatibility framework called OCI Mapper 2003. It first contrasts the two plug-ins: 4D for Oracle offers both high-level and low-level commands and supports Oracle 7.x/8.x, while 4D for OCI is low-level only, requires OCI driver/Oracle client 8.1.6+, gives finer control over execution timing, and adds support for LOB (CLOB/BLOB) data types that 4D for Oracle's Long/Long Raw handling couldn't accommodate. Rather than manually rewriting every 4D-for-Oracle call, OCI Mapper — implemented as a 4D component using native 4D language plus 4D for OCI commands — sits between the two and automatically redirects low-level command calls; the note lists all 25 mapped commands (OD BIND TOWARDS 4D, OD Create cursor, OD Login, etc.), highlighting the 11 added in the 2003 release (OD Execute SQL, OD COMMIT, OD ROLLBACK, OD GET SERVER LIST, and others). The migration procedure itself is a short checklist: open the database in 4D Insider, install the OCI_Mapper component, add OCI_TOOL_INITVAROCI to the On Startup method, retokenize every method that calls a 4D for Oracle command, then swap the 4D for Oracle plug-in for 4D for OCI in the Win4DX/Mac4DX plug-in folders. A before/after code sample shows an INSERT statement built with OD BIND TOWARDS SQL / OD Set SQL in cursor working identically on both sides of the migration once OCI Mapper is installed.
