This Tech Note by Jean-Yves Fock-Hoon, QA Manager at 4D, Inc., walks through how the 4D Search sample database works: it lets a 4D client connect to one or more 4D WebSTAR V web servers, retrieve the list of search 'index pages' those servers maintain (built by WebSTAR's Search plug-in over HTML, text, and PDF files, and — since WebSTAR 5.3.1 — over dynamic URL lists generated via the SOAP-driven 4D Dynamic Data Indexer, referenced to an earlier August 2003 Tech Note), and then issue keyword searches against those indexes with results parsed and cached locally. Connecting to a server is done via WSAPI_LoginDialog and WSAPI_WebSrv_GetSearchIndices from the 4D WebSTAR API component (which itself depends on the 4D Internet Command plug-in for low-level communication); the trickiest part, covered in detail, is resolving a raw index-page name into a usable, absolute URL by calling WSAPI_WebSrv_GetRouting to confirm the realm and get its site/port, and WSAPI_WebSrv_GetWebListeners to fall back to the server's actual listening IP/port when a realm is configured generically (host '*', port 'Any'). Once index paths are chosen and saved, a search builds a URL such as 'http://host/test.search?numdocs=9999&minscore=10&xml=1&geturl=1&getrelevance=1&gettitle=1&getsummary=1&query=keyword' against each selected index page, and — unlike older 4D versions that would need a hand-written TCP_Send/TCP_Receive component — the note highlights that because the result comes back as XML and the database targets 4th Dimension 2003, the whole request/response cycle and result parsing can be done with the single native Parse XML source command inside M_ParseXMLSource, extracting URL/relevance/title/summary tags straight into [Results] records. Results are then browsable by category (HTML/PDF/text/all), computed by testing each URL's file extension and adding the record to the matching 4D set, with a double-click launching the page via OPEN WEB URL in the user's default browser. The author notes a live benchmark of searching the word 'ODBC' across the entire (100MB+) 4D documentation set and parsing the results in under two seconds.
