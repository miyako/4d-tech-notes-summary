This Tech Note addresses a common first-impressions problem: 4D's built-in login dialog cannot be customized, but developers frequently want branded messaging, custom business logic (like logging failed login attempts with IP addresses), or a more polished look for their application's entry point. The solution relies on 4D's built-in Password System, which must be enabled (by assigning the Designer a password via CHANGE PASSWORD or the Toolbox GUI) since it gates several critical features — Structure Design Access, the 4D Server Admin Window, the Runtime Explorer, the Backup System's abort controls, and Plug-In license group assignment — all of which default to fully open when the password system is disabled. The implementation pattern configures a "default user" with no password in the Toolbox and sets it as the database's default user in the Security page of Database Settings; this user auto-connects on startup, letting developer code run (and display the custom login form) before any real end user authenticates. The custom login dialog itself is a simple form with username/password inputs (the password field uses the %password font for masking) and Login/Cancel buttons; the Login button validates by checking GET USER LIST + Find in array for the username, then Validate password for the credentials, and finally calls CHANGE CURRENT USER followed by ACCEPT. Cancel triggers QUIT 4D. The note frames this as a simple but essential technique that puts full UI and logic control in the developer's hands while still leveraging 4D's native security/user-group infrastructure.
