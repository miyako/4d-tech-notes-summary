This Tech Note by 4D's Senior Technical Services Engineer addresses the challenge of correlating 4D's two primary diagnostic logs — the Request Log (4DRequestLog.txt and its companion 4DRequestLog_ProcessInfo.txt) and the Debug Log (4DDebugLog.txt, in both standard and tabular forms) — which record different but related information about server activity and process execution. It documents the exact column layout and semantics of each log file in detail, since understanding the raw format is prerequisite to any meaningful analysis. The centerpiece is a new Log Parser tool that takes advantage of a process-identifying field added to the Request Log in 4D v16 R5, letting a developer merge Debug Log and Request Log data together, organized per process, in a single readable view. The tool provides a job list for selecting which logs to parse, a Log Viewer for browsing correlated results, and a mechanism for updating request IDs via the web. The note is aimed squarely at developers doing performance profiling and troubleshooting on 4D Server deployments, where isolating slow or problematic requests across multiple log sources by hand is tedious and error-prone. It closes with a conclusion and pointers to additional 4D resources on logging. As a diagnostics-focused note, its value lies primarily in explaining log file semantics that remain relevant, packaged with a bespoke correlation utility tied to the specific v16 R5 log schema.
