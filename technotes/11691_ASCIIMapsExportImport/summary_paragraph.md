This February 1996 Tech Note by Jeff Browning addresses the character-translation problem that arises whenever data is exported from 4D to other Windows applications or imported into 4D from a Windows text file: while ASCII characters 0-127 are common across platforms, characters 128-255 (high-order/diacritical characters, including many non-English symbols and some common US symbols) are represented completely differently on the Macintosh versus the many different Windows ASCII character sets used around the world, and 4D always uses the Macintosh character set internally, even when running under Windows. The note explains that 4D's ASCII Map feature — a 256-character string acting as a position/value translation table — solves this, with separate input maps (used when reading from disk/serial port, e.g. via IMPORT TEXT/DIF/SYLK or RECEIVE PACKET) and output maps (used when writing to disk/serial port, e.g. via EXPORT TEXT/DIF/SYLK or SEND PACKET) that are mirror images of one another. It walks through building custom Windows ASCII maps by leveraging the Altura Mac2Win porting layer's automatic character translation during copy-and-paste: opening the default 4D ASCII map data in both 4D's Create ASCII Map dialog and in Notepad, then copying the character data across via clipboard paste to build output.4fi and input.4fi map documents matching whatever Windows ASCII code page is in use. It demonstrates testing the maps with an example [Test] file and export/import round-trip, and shows how to apply maps in code via the USE ASCII MAP command (0 for output, 1 for input) combined with GET PLATFORM INFO to detect whether the client is running on Windows ("Wintel"), so the maps are only invoked where needed. As a fully readable full-PDF Tech Note, this summary reflects the complete document, which includes several screenshots of the relevant 4D dialogs that could not be reproduced here.
