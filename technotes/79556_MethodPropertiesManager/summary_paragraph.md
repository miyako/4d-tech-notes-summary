This Tech Note presents the Method Properties Manager, a component that solves a practical pain point in large 4D codebases: 4D's built-in tools for viewing and editing the ten method properties (such as preemptive-capable or web-published) require selecting each method individually via the Explorer or Code Editor, and the existing "batch setting of attributes" tool only works well if methods follow a naming convention that maps cleanly to their properties (e.g., a "Web@" prefix matching string). The component instead lets developers browse a filterable list of methods by which property they currently have, multi-select methods (via shift-click) regardless of naming convention, and toggle boolean-style properties on/off with "Apply"/"Remove" buttons, or set the special three-state preemptive property (capable/incapable/indifferent) directly. Under the hood, method properties are stored as a hidden `//%attributes = {}` header line at the top of each .4dm method file (visible in an external text editor like VS Code but hidden in 4D's method editor), and the component reads/writes these programmatically via the METHOD GET ATTRIBUTE and METHOD SET ATTRIBUTE commands. Installation requires running the project locally in interpreted mode, dropping the provided .4dbase into a Components folder, and executing the "open_property_manager" method. The note positions this as a practical developer-productivity tool for codebases with many methods and inconsistent naming, streamlining bulk property auditing and modification during refactoring or migration work.
