This March 1996 Tech Note by David Adams collects several distinct problems 4D developers commonly encountered running 4th Dimension on Power Macintosh hardware during the mid-1990s 68K-to-PowerPC transition. It explains Type 11 errors as most often caused by an application's memory partition being set too small, and walks through using the Finder's Get Info memory settings to increase the allocation. It describes how native PowerPC (RISC) code has different, generally larger memory requirements than 68K (CISC) code, meaning memory partition sizes tuned for 68K Macs are often insufficient once running natively on a Power Mac, and recommends specific increased partition sizes. It documents a WorldScript-related bug affecting international text handling in certain configurations, along with a workaround. It flags a known conflict between the CommonGround Shortcut extension and 4th Dimension that could cause instability, recommending its removal or reordering relative to other extensions. It offers general guidance on diagnosing system extension conflicts through the classic Mac OS technique of selectively disabling extensions (rebuilding the Extensions folder / holding down keys at startup) to isolate the offending INIT. Finally, it provides a formula 4D developers could use to correctly estimate the memory required by the compiler when compiling larger 4D applications on Power Macintosh hardware.
