4D ships an embedded PHP interpreter (PHP 7.3 x64 as of the next R-release referenced here) that developers invoke from 4D code via commands such as `PHP Execute`, but the bundled build only includes a fixed, 4D-tested subset of extensions/modules. This Tech Note by Timothy Aaron Penner explains how to build a custom PHP engine from source when an application needs additional PHP extensions that 4D does not ship by default, since 4D officially does not support adding modules to its bundled PHP. On macOS, it walks through compiling extension dependencies, then configuring PHP itself with `--enable-cgi --disable-cli` to produce the FastCGI variant 4D requires, choosing static vs. shared extensions via `--enable-static`/`--enable-shared`, and finally renaming the resulting `php-cgi` binary to `php-fcgi-4d` to replace the one inside 4D's application package (`Contents/Resources/php/Mac/`). On Windows, it details installing Visual C++ 2015/2017 (matched to the PHP version being built), using Microsoft's php-sdk-binary-tools, running `phpsdk_buildtree.bat` and `phpsdk_deps.bat -u` to fetch dependencies, then `buildconf.bat`/`configure.bat`/`nmake` to produce `php-cgi.exe`, renamed to `php-fcgi-4d.exe` and placed in `4D/Resources/php/Windows/` alongside required DLLs. Shared extensions are activated afterward by editing `php.ini` in the database's `Resources` folder with `extension_dir` and `extension=` directives. The note closes with a verification snippet using `PHP Execute("";"phpversion";$result)` and `PHP Execute("";"get_loaded_extensions";$result)` to confirm the custom engine and its modules loaded correctly after restarting 4D. This is squarely a low-level systems/build tutorial for advanced 4D shops that depend on PHP extensions (e.g., specific image, crypto, or LDAP libraries) beyond 4D's default set.
