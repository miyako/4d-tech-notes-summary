This Tech Note addresses a practical pain point for developers of large 4D databases: finding a specific method when you can't quite remember its exact name or which folder it lives in. It builds a custom Method Explorer using the Design Object Access suite of commands, introduced in 4D v13, which gives programmatic read/write access to method contents and metadata. The note first reviews the Design Object Access commands' features and limitations, then presents a Custom Method Explorer offering on-the-fly filtering of the method list as the user types any part of a method name, sorting by modification date/time or by name, a preview pane for method source, and the ability to execute a method directly from the explorer window. A related Code Object Explorer section extends the idea to other design objects beyond methods. The note closes with a few smaller illustrative examples: counting the number of methods in a database, counting total line numbers across all code, and computing the total size of all code — all built on the same Design Object Access primitives. This is a solid example of developer-tooling content built for the binary/Design-Mode era of 4D, where finding, exploring, and analyzing methods required custom tooling built on introspection commands, because there was no file-system-based project structure to browse externally. Since Project Mode's introduction, methods are stored as individual, named text files in ordinary folders, so much of this pain point (locating a method by fuzzy name search) can now be addressed with a normal code editor, IDE fuzzy-file-finder, or OS-level search — reducing, though not entirely eliminating, the need for an in-4D custom explorer of this kind.
