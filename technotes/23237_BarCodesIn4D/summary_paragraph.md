This 2002 Tech Note by Eric Juhel, a 4D Developer, explains how to generate scannable bar codes directly inside 4D without any external plug-in or font, covering four common symbologies: Code 39 (EAN 39), Code 128 (EAN 128), UPC, and EAN-13. The core trick is deceptively simple: store exactly two 1x1 pixel pictures in the picture library, one black and one white, then build each bar-code character by concatenating black and white pixel pictures side by side according to each standard's bit pattern and finally vertically resizing the assembled strip to the correct bar-code height. For Code 39, the note details the 9-element-per-character structure (5 bars, 4 spaces, with wide/narrow variants) and the printing-width formula based on margins and narrow-element width, along with a modulo-43 checksum for the optional control character; for Code 128 it explains the three encoding modes (Code A/B/C) and a modulo-103 weighted checksum. Character-to-pattern mappings are stored in 4D choice lists (`Characters_Set_39`, `Characters_Set_128`) keyed by ASCII code, and the sample `EAN_EditBarcode_39` and `EAN_Edit_Barcode_128` project methods walk through each string character, look up its 9- or 11-element pattern via `Find in array`, and append the resulting black/white pixel picture into a growing final image. The technique demonstrates how far 4D's basic picture and array commands could be pushed to solve a specialized printing problem without additional tooling.
