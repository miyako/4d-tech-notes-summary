This Tech Note explains how to call existing 4D project methods from inside SQL statements in 4D v11 SQL, letting developers reuse proven 4D code (such as multi-table relational lookups) without rewriting it in pure SQL or constructing explicit joins. Any project method can be exposed to SQL by enabling its "Available through SQL" property, after which it can be invoked in a SELECT or WHERE clause using the syntax `{fn method_name(params) AS TYPE}`, where the `fn` keyword marks it as a callable function and the `AS` clause declares the SQL return type. The note carefully walks through parameter-passing differences from standard 4D syntax — SQL uses commas instead of semicolons, and 4D variables are referenced with a leading colon or wrapped in `<<>>` — and shows how mismatched return types or forgotten WHERE-clause filtering can produce arrays with unexpected null/zero-filled entries (since the method runs once per record scanned). A sample database demonstrates the same underlying query — counting a customer's invoices — implemented four different ways: inline Begin/End SQL, dynamically built EXECUTE IMMEDIATE, the SQL EXECUTE command with SQL LOGIN/LOGOUT, and QUERY BY SQL combined with a manual For loop. The note positions this feature as a bridge letting SQL-savvy developers leverage existing 4D logic without needing deep 4D language expertise.
