## Overview
This entry documents Part 1 of a two-part Tech Note on backup and recovery strategies for mission-critical 4D Server databases. Only the short on-page teaser paragraph is available in this archive (the old page has no working download link), so this page summarizes that teaser text only.

## Key Points
- Notes that ACI Technical Support was fielding daily calls from customers running 4D Server with as many as 100 connected users and data files up to five gigabytes.
- Frames these deployments as "mission-critical," where downtime prevents the organization from functioning, often running 24/7.
- States the goal of the two-part series: give administrators the information needed to set up and maintain an effective backup and recovery strategy.
- This is Part 1; Part 2 was announced to follow the next month.

## Historical Context
**Status:** Still relevant

The full archive for this note could not be recovered — the old page has no working download link at all — so only the teaser paragraph above is confirmed content. The overarching discipline of planning and testing backup/recovery procedures for mission-critical databases remains timeless and directly applicable today. However, the specific scale figures cited (100 users, 5GB data files) were considered large in 1997 but are quite modest by modern standards, and 4D Server's backup, logging, and journaling tooling has been substantially enhanced in the decades since.
