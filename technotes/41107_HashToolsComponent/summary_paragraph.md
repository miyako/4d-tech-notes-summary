This Technical Note by David Adams documents the public and protected method API of the HashTools component, a packaged 4D component implementing nine hashing algorithms and utility routines for hashing and hash-optimized searching of text, BLOBs, pictures, and documents. It explains the rationale for delivering this code as a component rather than raw source: reduced complexity (exposing roughly 10 public methods out of over 50 internal ones), simplified updating across the several related tech notes and databases that use HashTools, and efficient, centralized error/parameter validation via "gateway" protected methods that screen inputs before calling unprotected private routines. The component is designed to run compiled (supporting "all variables typed" compilation) and includes built-in Explorer documentation for each visible method. Core hashing routines covered include HashTools_HashText, HashTools_HashBlob, HashTools_HashPicture, and HashTools_HashDocument (the latter reading documents in 32,000-character chunks to avoid high memory use on large files), each taking a pointer to the value and a hash algorithm name and returning a longint hash. The note details HashTools_FindByHash, which uses a stored hash field to run an indexed pre-filter search before confirming exact matches on the underlying alpha, text, BLOB, or picture field — recommending triggers as a natural place to maintain stored hashes. It closes with the component's error-management API (HashTools_GetLastErrorLocation, HashTools_GetLastErrorCode, HashTools_GetErrorText) and a full table of the 14 defined internal error codes, positioning HashTools as the reusable engine underpinning the hashing techniques discussed in the related notes on optimizing searches, case-sensitive operations, and efficient text/BLOB scanning.
