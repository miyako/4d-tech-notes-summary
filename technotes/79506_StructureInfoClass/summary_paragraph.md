This Tech Note introduces the StructureInfo class, a utility that addresses a gap in 4D's introspection commands by exposing the richest source of structural metadata — the project mode catalog.xml (specifically catalog.4DCatalog) — as a queryable 4D object. Built as a shared singleton class (leveraging the singleton pattern introduced in 4D 20 R5), StructureInfo requires no manual instantiation or initialization: on first use, 4D automatically triggers the class constructor, which reads the catalog file via 4D's Filesystem pathnames (`File("/PROJECT/Sources/catalog.4DCatalog").getText()` — notably working transparently even inside a compiled/zipped .4DZ package) and parses it into a cached object shared across all processes. The class exposes a raw `.get()` function for full structure browsing via object notation and collection.query(), plus targeted helper functions: getTableInfo() and getFieldInfo() (identified by name, uuid, or pointer) for table/field metadata; getRelationInfo()/getRelationInfos() for finding relations between tables (supporting wildcards and directional or bidirectional lookups via fromTable_name/toTable_name or Table_name1/Table_name2); and getIndexInfo()/getIndexInfos() for looking up index definitions and all indexes for a given table or field, since a single field can participate in multiple indexes of different types. The class is published as open source on GitHub (ThomasMaul/Classes) for developers to copy directly into their applications and receive future updates or fixes. The note positions this as a lightweight, elegant tool for programmatically inspecting relations, indexes, and table/field settings without manually parsing raw structure XML.
