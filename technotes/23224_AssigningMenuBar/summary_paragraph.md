This 2002 Tech Note by Jamras Komoncharoensiri of 4D, Inc. Technical Support explains how 4D manages menu bars within a single process, covering both the design-time and programmatic mechanisms available. It first shows how to assign a menu bar directly to a form via Form Properties' "Associated Menu Bar" drop-down (combined with the "Active Menu Bar" checkbox), illustrating with an Output form using menu bar #2 and an Input form using menu bar #3, and explaining that 4D automatically swaps the loaded menu bar when the user navigates between such forms. It then covers the procedural alternative, the MENU BAR command, which loads a menu bar for the current process and persists until changed, but only takes effect if the form already has an associated (even blank) menu bar enabling the "Active Menu Bar" option; 4D combines the process-loaded and form-associated menu bars into one. A worked example shows conditionally loading menu bar #5 for an Administrator versus #3 for other users via Current user. The note explains system menu behavior -- new processes need an explicit menu bar load for the Edit menu to become accessible, while Help remains available regardless -- and demonstrates a New process example that calls MENU BAR(3) before displaying records. Finally, it covers programmatic menu editing with APPEND MENU ITEM, INSERT MENU ITEM, and DELETE MENU ITEM, including a reusable Delete_Menu_Item method that searches all menus and items by name using Count menus, Count menu items, and Get menu item, and warns that inserting items can shift subsequent items' numbers and break their associated methods.
