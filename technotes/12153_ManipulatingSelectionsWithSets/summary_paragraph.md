Written by Jamras Komoncharoensiri of 4D, Inc. Technical Support, this Tech Note explains why 4D Sets are valuable for avoiding repeated, costly queries: once a selection is saved into a set with CREATE SET, it can be restored instantly with USE SET rather than re-running the original search, and the note works out the switching-time math (N*(T+F) versus S*T) showing when the set approach wins over repeatedly querying. It then demonstrates a more advanced 'partitioning' technique for splitting a single selection into several sub-selections — for example dividing 90 records into top, middle, and bottom groups of 30 — without performing multiple queries, using the Initial_Set and Make_Initial_Set project methods to shrink the current selection with REDUCE SELECTION and stash each shrinking selection into progressively named sets (Set3, Set2, Set1), followed by a Start_Partitioning method that computes the actual partitions by taking the DIFFERENCE between consecutive sets. The note closes by pointing to related resources including the earlier TN 97-37 'Sets in 4D V6' and several Tech Tips on set operations, framing this as an illustrative rather than universally applicable technique.
