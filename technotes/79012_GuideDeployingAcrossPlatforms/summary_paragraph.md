Deploying a 4D merged client-server application gets complicated once server and clients run on different operating systems or CPU architectures, and this note works through four concrete scenarios: Windows server/Windows clients, Mac server/Mac clients (both M1-to-Intel and Intel-to-M1 directions), Mac server/Windows clients, and Windows server/Mac clients. Two rules anchor everything: a client-server app must be built at least once on each targeted platform, and Apple Silicon Macs must run Intel-compiled apps under Rosetta unless the database has been converted to project mode with its compilation target set to "All processors (Intel/AMD and Apple Silicon)", in which case the Mac can natively produce a universal build — though a Windows build host is still Intel-only. For automatic updates, the note walks through incrementing the Current version value (or the /Preferences4D/BuildApp/CS/CurrentVers key in buildApp.4DSettings when scripting with BUILD APPLICATION), enabling the platform-specific "Allow automatic update" checkbox, and — for cross-platform scenarios — physically transferring the opposite platform's 4D Volume Desktop folder or the .4darchive file so the server can package updates for clients on a different OS. The trickiest case, Windows server updating Mac clients, additionally requires 4D 19 R3+'s "Allow connection of Silicon macOS clients" option and a transferred Compiled Database folder generated from an M1 Mac build, since Windows cannot natively compile Apple Silicon code.
