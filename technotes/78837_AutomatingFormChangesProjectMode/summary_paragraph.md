This Tech Note leverages a defining characteristic of project mode: every form (project or table form) is stored as a plain-text .4DForm JSON file rather than a binary structure record. It walks through the .4DForm folder layout (Project/Sources/Forms/{name}/form.4DForm for project forms; Project/Sources/TableForms/{tableNum}/{name}/form.4DForm for table forms) and the JSON schema of a form (top-level attributes like events/pageFormat, and a `pages` collection of objects keyed by object name, each holding its Property List attributes like type, top/left/width/height, text, events). Building on this, it implements an `applyFormChangesByAttribute($toFind; $toSet)` method that takes a match criterion (by object name pattern or object type) and a collection of property changes to apply, then uses FORM GET NAMES and GET TABLE TITLES to enumerate every project and table form path, parses each with JSON Parse, walks every page's objects collection looking for matches, applies the requested property changes in place, and writes the modified JSON back with TEXT TO DOCUMENT + JSON Stringify. A first demo restyles every button whose name starts with '3D' into a custom raised button with a background image across the whole codebase in one call. A second variant (implied by the table of contents) drives changes from the conversion log's errors rather than a manual name/type filter, directly complementing the binary-to-project migration workflow. This turns what would be an enormous, error-prone manual GUI task — editing hundreds of forms one property at a time — into a single scripted pass.
