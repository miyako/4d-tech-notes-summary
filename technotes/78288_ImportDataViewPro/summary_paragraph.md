This Tech Note demonstrates how to import a query's worth of data into 4D View Pro, 4D's native spreadsheet feature built on the SpreadJS JavaScript engine, positioning it as a natural target for generating exportable, formattable reports (billing, order lists, itemizations) that can later be saved as XLS or PDF. The implementation begins by locating the "active cell" — the top-left insertion point — via the newly introduced VP Get active cell command, which returns a View Pro range object describing sheet/row/column coordinates. Because as of v17R5 there's no simple native command to add rows/columns to accommodate an import, the note offers two workarounds: modifying the exported document object (VP Export to object, adjusting spreadJS.sheets.Sheet1.rowCount/columnCount and reloading, which resets the view) or calling into the underlying SpreadJS JavaScript API via WA Evaluate JavaScript (e.g., spread.getActiveSheet().setRowCount(100)), which avoids the view reset but depends on JS knowledge. Actual cell population uses VP SET VALUE with a range from VP Cell, passing a value object that can carry "value", "time", or "format" properties (with "time" flagging time-typed data specifically). The core import loop iterates entity-selection records/fields, calling VP SET VALUE per cell — a simple but inherently sequential process, so the note flags that large datasets can take a while to import. Five sample demos cover basic import, sheet-size increase, data shifting to avoid overwrite, formatted import, and custom field/order selection. The overall message is that 4D View Pro, as a fully native (non-plugin) feature, is a capable, general-purpose reporting surface directly reachable from ORDA entity selections using object notation.
