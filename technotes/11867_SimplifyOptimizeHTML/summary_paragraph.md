This Tech Note by David Adams addresses a common pain point of using 4D to generate HTML in 1996 — whether for static pages, as a CGI processor to an external Web server, or via 4D acting as a Web server itself — namely that naively concatenating HTML strings in 4D code is tedious, error-prone, slow, hard to test, and requires recompiling the database for any output change. The proposed solution stores reusable HTML blocks as text in [HTMLBlocks] records, each containing placeholder tokens (e.g. "^Title", "^Body") that are swapped out at runtime using 4D's Replace string command, which the note demonstrates is faster than reconstructing entire blocks from scratch and can substitute all instances of a token in one call. It then generalizes this pattern with numbered insertion targets (^1, ^2, ...) and a documented HTMLBlock procedure that uses 4D's parameter indirection (${n} syntax, driven by Count parameters) to accept an arbitrary number of substitution values, drawing them from sources such as user input, other database records, calculation results, disk files, or CGI/HTTP request data. A companion InitHTMLBlocks startup procedure preloads frequently used HTML blocks into a pair of arrays (keyed by block name) for fast access, falling back to a database SEARCH only for blocks not marked AutoLoad. The note shows nested HTMLBlock calls to compose more complex pages (e.g. embedding a "Page Stamp" block with date/time/user info inside a "Standard Page" block) and emphasizes that centralizing HTML in data records means global changes (such as adding a footer credit line) require editing a single record rather than many procedures. The technique is explicitly positioned as reusable and general enough to support other structured tagging languages beyond HTML, such as QuarkXPress tags or FrameMaker Interchange Format, by simply changing what is stored in the block records. As one of 4D's earliest tech notes on web-facing development, it reflects the moment 4D began being used to construct HTML content for the nascent World Wide Web, well before 4D had its own dedicated built-in web server or Internet Commands plugin.
