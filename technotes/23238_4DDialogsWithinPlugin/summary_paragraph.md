This 2002 Tech Note by Christian Cypert, 4D & WebSTAR Plug-in Evangelist, shows how to embed a 4D Dialog resource inside a compiled C/C++ plug-in to build a simple database security screen. The workflow starts in 4D itself: a dialog is created with two 40-character string variables (username and password) and saved to disk as a resource by pressing Command-9/Ctrl-9, producing a per-table resource file that is then imported into the Plug-in Wizard. The plug-in command, named sc_openSecurity, takes pointers to the database's username and password fields as parameters, and its C code defines variables using the PA_Pointer, PA_Dial4D, and PA_QueryRef API types. The core logic opens the imported dialog with PA_OpenDialog, then runs a do-while loop calling PA_ModalDialog to detect the Log-In button click, retrieves the entered strings with PA_Dial4DGetString, and validates them with PA_OpenQuery/PA_QueryString/PA_CloseQuery against the corresponding table, checking PA_RecordsInSelection to determine whether to grant access, alert on an unknown user, or alert on a non-unique match. The note closes with PA_CloseDialog and a note that the compiled plug-in should be placed in the 4DX folder. It is a compact, practical illustration of how the classic 4D Plug-in API let developers reuse 4D-designed UI resources from native compiled code.
