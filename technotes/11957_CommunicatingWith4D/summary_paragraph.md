Written by Jamras Komoncharoensiri of 4D, Inc., this Tech Note builds "4D Communicator," a multi-user chat and internal-mail application, to demonstrate several techniques for real-time client-to-client communication in 4D v6.7. It starts with a custom password system storing each member's username, password, first/last name, online status, current chat room, and an InBoxStatus flag as a plain [Member] record (rather than relying on 4D's built-in structure-based password system), used both for authentication and for tracking where each signed-in user currently is. The note then explains several interface tricks needed to make a variable-based Msg_Displayer text object behave like a proper scrolling chat log — trimming the text once it exceeds 30,000 characters, using HIGHLIGHT TEXT to move the cursor (and thus the visible scroll position) to the newest line, and using POST KEY with the Tab code to shift focus back to the message composer field while re-positioning the cursor to avoid overwriting existing text — plus a Boolean InBoxStatus field driving a two-frame mailbox picture button that flips via On Timer polling. The centerpiece is a reliability and multicasting mechanism: a Multicast_Message method loops over all [Member] records in the same chat room and calls EXECUTE ON CLIENT([Member]Username; "Set_G_Message"; $Message) to push text onto a shared inter-process variable <>G_Message on each recipient's machine, guarded by a shared <>G_Flag Boolean and a DELAY PROCESS-based busy-wait loop so a second message can't overwrite one still waiting to be displayed. A "Test Driving 4D Communicator" walkthrough covers the resulting end-user features — eMessage internal mail with a multi-recipient "To:" selector, a ten-room Chat lobby with a "Find Member" locator that reports which room (if any) a named user is in, and a Mailbox inbox with Prev/Next/Delete controls — closing with a summary that frames the note as showing workarounds for interface limitations and how to implement multicasting in 4D.
