This Technical Note by David Adams tackles the problem that a generic XML parser like 4th Dimension's DOM parser can successfully read any well-formed XML document, but successfully parsing a document is different from correctly interpreting its contents, since formats like WSDL, SVG, and XHTML are all XML yet require very different handling and even XHTML itself has four distinct sub-types (Strict, Transitional, Frameset, and 1.1). The note works through a Demo_ReadXHTMLDocument example that layers a cascade of tests to identify a document: first confirming the document is well-formed XML, then checking that the root element name is literally "html" (case-sensitively, using the CS_AlphasAreEqual routine from an earlier Tech Note 05-41), then verifying the root element carries the xmlns="http://www.w3.org/1999/xhtml" namespace attribute, and finally comparing the document's DTD Public ID and System ID (read via DOM Get XML information) against hard-coded constants for each of the four defined XHTML DTDs to determine the specific version. A helper routine, DOM_GetRootElementReference, is documented for locating the true root element while correctly skipping the synthetic "#document" node that sits above it, again using the shared custom ON ERR CALL error-trapping pattern used throughout this family of XML tech notes to safely handle invalid references. The note is explicit that its exact rules are XHTML-specific and meant only to illustrate the general approach — checking root element name, namespace, and DTD identifiers — which can be adapted to detect other XML document types such as WSDL or SVG. A Test_GetRootElementReference routine in the sample database exercises the helper against valid, invalid, and #document node references. Overall, the featured technology is 4D's classic DOM XML API applied to the format-sniffing problem, using XHTML's DTD-based versioning scheme as its concrete worked example.
