Historically, displaying a PDF inside 4D required a Web Area backed by a system web-rendering engine that itself depended on a PDF viewing plugin being installed and configured on the end-user's workstation, an unreliable and non-portable setup. This Tech Note presents an "engine-independent" workaround: it uses the free command-line tool `pdftopng` from the open-source Xpdf project, invoked through `LAUNCH EXTERNAL PROCESS` (with `SET ENVIRONMENT VARIABLE` used to fix the working directory), to convert each page of a target PDF into a PNG image. The images are moved into a per-document, UUID-named folder inside the Resources directory, then wrapped into a generated HTML file using a template processed with `PROCESS 4D TAGS` (leveraging 4D's `#4deval`/`#4dloop`/`#4dtext` templating tags) and written out with `TEXT TO DOCUMENT`. The final HTML is loaded into a Web Area via `WA OPEN URL`, and a list box bound to an array of scaled-down PNGs (produced with `READ PICTURE FILE`, `PICTURE PROPERTIES`, and `TRANSFORM PICTURE`) provides clickable page thumbnails that jump the Web Area to a target page using an HTML anchor appended to the URL. Because everything is rendered as static images, the result is read-only — no links, form fields, or text selection — but the payoff is an out-of-the-box, zero-configuration PDF viewer that works identically across platforms. The sample application is built as an installable 4D component exposing three public methods, `openPDFReader`, `loadPDFInWA`, and `deleteViewedPDF`, the last of which is needed to clean up generated PNG folders and avoid unbounded disk growth. The note positions this as a lightweight alternative for hosts that want to display or preview 4D Write Pro-exported PDFs without shipping or configuring any third-party PDF viewer.
