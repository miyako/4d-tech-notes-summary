This Technical Note by Jesse Pina covers the VERIFY CURRENT DATA FILE command (alongside its counterpart VERIFY DATA FILE), introduced in 4D v11 SQL as part of the incorporation of 4D Tools functionality into 4D and 4D Server's Maintenance and Security Center. Both commands perform a structural check of the data file and/or index file, with VERIFY CURRENT DATA FILE targeting the currently opened database (more convenient for programmatic and partial verification) and VERIFY DATA FILE targeting a data file that is not currently open (better suited to offline maintenance scenarios similar to legacy 4D Tools usage). The note focuses on VERIFY CURRENT DATA FILE, documenting its full syntax with optional parameters for restricting verification to specific object types, individual objects (tables/fields), and options, and explains why this automation opens up new maintenance routines beyond the graphical MSC tools. A central feature discussed is partial verification — checking only specific objects rather than the entire database — supported through a callback method that receives verification progress and results, with the note detailing the callback's parameters, return value, and several worked callback examples along with reasons to use the callback approach. A demonstration database rounds out the note, showing both a "Verify" and a "Rebuild" walkthrough so developers can see partial verification and partial repair in action.
