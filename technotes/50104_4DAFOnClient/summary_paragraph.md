This Technical Note explains how to install and configure the 4D Ajax Framework (4DAF) on a 4D Client machine to serve as a web application publisher for a 4D Server database, a deployment pattern that offered two key advantages over hosting 4DAF directly on the main server: resource dedication (web requests could be handled by the client machine rather than the database server) and enhanced security (the main 4D database and server could remain behind the firewall with only the client machine exposed to the internet). The note covers installation steps for both 4D v11 SQL Release 2 (11.2) and 4D 2004, including component installation via folder copying or 4D Insider, support folder migration for upgrades, plugin folder setup, 4D database preferences configuration (enabling web server publishing in non-contextual mode), and WebFolder placement (using new 4D v11 commands like Get 4D folder to locate the correct path on Windows and Mac or setting the Default HTML Path in 4D 2004 preferences). The note assumes familiarity with basic 4D administration and emphasizes that this setup creates a remote access layer allowing users to edit and add data via the rich 4DAF web interface while the primary database remains protected on an internal server, a pattern useful for load balancing and security-conscious deployments of the early 2000s web era.
