Written by Tai Bui, this Tech Note introduces developers to using 4D's two newer dataset types — collections and ORDA entity selections — as the data source for list boxes, alongside the traditional array- and current-selection-based approaches. It first explains collections as ordered, mixed-type lists accessed with bracket/object notation (`myCollection[0]`, zero-based unlike 4D arrays), and entity selections as ORDA's analog to a 4D current selection, generated by querying a `DataClass` within the `Datastore` object model (`ds` → DataClass → entitySelection → entity), but crucially storable in a variable/object rather than existing only as an implicit global current selection. It then walks through binding either type to a list box: both share the same "Data Source" property setting, "Collection or entity selection," which then repurposes the "Value or expression" property to hold the collection/entity-selection expression, evaluated when the form loads. For collections, the note stresses that list boxes only render simple scalar types (String, Text, Numeric, Date, Picture, Boolean), so a collection of consistently-shaped objects (e.g., `{"name":"Joe","age":26}`) works well as a source with columns bound to object properties, while collections with inconsistent object shapes produce gaps in the grid. Further sections (per the table of contents) cover formatting columns for both collection-of-values and collection-of-objects cases, formatting entity-selection-backed columns, identifying selected rows/columns, modifying list box data in place, managing/maintaining entity selections, and opening a selected entity in a detail form — with a bundled sample database demonstrating each scenario (collection-based list boxes, entity-selection-based list boxes, row/column identification, and entity-selection maintenance). This note captures a formative moment in 4D's transition toward ORDA-centric UI design, showing how classic form controls like the list box were being extended to natively consume the new object-oriented dataset primitives.
