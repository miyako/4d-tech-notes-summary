This tech note is a from-the-ground-up introduction to Docker aimed at 4D developers and DevOps-minded administrators, explaining containerization concepts before applying them to 4D Server deployment. It covers Docker's architecture (the `dockerd` daemon/server, the REST API used to instruct it, the CLI client, and public/private Docker registries/Docker Hub), the container lifecycle (read-only, layered Docker images either pulled from a registry or built from a `Dockerfile`; running containers instantiated from images; and volumes for data that should persist independently of a container's lifecycle), and walks through installing Docker Desktop on Windows, macOS, and Linux. Applying this to 4D, the note lists prerequisites for running 4D Server inside a container: removing any startup windows/dialogs since no GUI is displayed by default, ensuring licenses are already registered (recommending an embedded-license standalone server build), and — if a GUI truly is needed inside the container — adding a VNC server/X Server setup to expose it to a host-side VNC client. The core demo builds a Docker image from a Dockerfile (Step 1), creates the image (Step 2), and instantiates and runs a container from it (Step 3), then introduces volumes for persisting 4D Server data outside the container's writable layer, and covers sharing built images (e.g., via Docker Hub or exporting/importing image files) as well as managing containers through Docker's own GUI application. The note frames Docker as bringing 4D Server the same portability, consistency, and resource-efficiency benefits (versus full virtual machines) that had already made Docker a DevOps staple elsewhere, positioning containerized 4D Server as a viable production deployment option.
