Written by Steve Hartman (MCP, Information Systems, 4D, Inc.) as Technical Note 04-01, this note walks through the complete, practical steps of taking input submitted from a 4D "Non-Contextual" web page and saving it into a database record, using a fictional "Acme Pain Clinic" online appointment-request form as the running example. It starts by defining a sixteen-field `WebData` table (names, date of birth, phone, symptom checkboxes, comments, and two proposed appointment date/time pairs), then builds a `WEB_WebInfoSave` project method — exposed via "Available through 4DACTION" — that reads the incoming `WEBF_t_*`/`WEB_t_*` web variables, creates a record, assigns and type-converts each field, saves it, and responds with `SEND HTML TEXT`. Because web form variables always arrive as text, the note details two conversion helpers: `CB2Boolean_Input`, which maps a checkbox's "Yes"/other text value to a Boolean field, and a considerably more elaborate `Date_Validate` method (credited in-code to Tom Dillon of DataCraft, later modified by Hartman) that tries to interpret free-typed date strings in varying lengths and delimiter styles (MM/DD/YY, DD/MM/YY, no separators, partial year, etc.) and falls back to "Invalid date" messaging when the round-tripped date doesn't match. The note also shows the full HTML form markup, including `<!--4DVAR fieldName-->` substitution tags for redisplaying prior values and dropdown-based date-of-birth entry to sidestep free-text date ambiguity for that field specifically. It closes by acknowledging that even with careful coercion logic, developers must anticipate multiple possible user input formats since no amount of instruction fully prevents inconsistent entry.
