This Tech Note addresses a foundational question for anyone building dynamic, data-collecting websites with 4D: after serving a web page from a 4D database is straightforward, how does a developer actually persist the data a visitor submits through that page? The note frames this directly, observing that "serving web pages from a 4D database is nice, but how do we save the data?" before answering that question specifically in the context of a 4D "Non-Contextual" web page, one of the publishing modes available in 4D's native Web server at the time (as distinct from contextual, record-bound web pages that maintain a live connection to a specific database context). The core technique demonstrated is taking the input submitted by a user through such a Non-Contextual web page — likely an HTML form — and moving that submitted data into a table residing in the same 4D database, effectively closing the loop between a stateless, non-contextual web front-end and 4D's underlying persistent data store. As Tech Note 04-01, the very first note published in the 2004 series, it functions as an early and fairly fundamental building block for 4D web development at the time, addressing a task (capturing and saving web form input) that virtually every dynamic 4D website needed to solve in some form. The featured technology is 4D's native Web server together with its Non-Contextual web publishing mode and the underlying record-creation/update language commands needed to write submitted values into a database table.
