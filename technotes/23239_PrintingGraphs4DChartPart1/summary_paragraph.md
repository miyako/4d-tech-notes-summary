Written by Tim Tonooka, a 4D Solution Partner, this is Part I of a two-part Tech Note that catalogs every available technique for printing graphs created in 4D Chart and helps developers choose the right one for a given scenario, with Part II to follow covering coding details for trickier sizing issues. It opens with background on 4D Chart's evolution -- from the original limited GRAPH/GRAPH TABLE/GRAPH SETTINGS commands, through 4D Chart as a $295 add-on product requiring per-client expansion packs, to its integration as a free built-in part of 4D v6 and later -- and reiterates 4D Chart's document-oriented model where a document (savable to a picture field, disk file, or template) can contain multiple graphs and other objects. The note organizes nine possible printing paths (the 4D Chart menu bar's Print and Print Merge commands, CT DO COMMAND with codes 1009/1010, the User Environment Print command, and PRINT FORM/PRINT RECORD/PRINT SELECTION/PRINT LABEL) along two key axes: whether you're printing directly from a 4D Chart document (only objects in the chart print) versus from a 4D form (which can combine a chart area with other form objects, though limited to the chart area's on-form dimensions); and whether the technique requires an actual current record (PRINT RECORD, PRINT SELECTION, PRINT LABEL, Print Merge) versus not (the 4D Chart Print command, PRINT FORM), the latter avoiding the need for a "dummy" table and temporary unsaved record. It walks through each command's specific behavior and constraints -- e.g., PRINT FORM cannot print 4D Chart plug-in areas or subforms at all (a blank space results unless the chart is first converted to a picture variable), Print Merge requires a 4D Chart field reference object to merge per-record field data into an otherwise identical printed document, and the exact form-event firing order differs between PRINT RECORD/PRINT SELECTION (On Printing Header, On Load, On Printing Detail, On Printing Break, On Printing Footer) and PRINT LABEL (only On Load) -- then closes with scenario-by-scenario recommendations for graphs only in memory, graphs in plug-in windows, graphs on a form's chart-area menu bar, graphs stored as disk documents, and graphs stored in record picture fields.
