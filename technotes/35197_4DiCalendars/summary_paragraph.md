This Technical Note by 4D Evangelist Frank Chang explores how 4D 2004 can act as a data-driven iCalendar publishing server, extending an earlier note on iCal-driven scheduling by focusing on 4D acting as a WebDAV server that iCal, Microsoft Outlook, and Mozilla Firefox's Calendar extension can subscribe to and publish into. It walks through the iCalendar (.ics) file format defined by RFC 2445 (VCALENDAR/VEVENT/VALARM components), then shows how the 4D Web Server's new HTTP-level commands — GET HTTP HEADER, GET HTTP BODY, and SEND HTTP RAW DATA — are used inside the On Web Authentication database method to detect WebDAV-style requests, extract and Base64-decode HTTP Basic credentials, and route to a Connection project method. Server-side, iCalendar files are built entirely in memory as BLOBs (via iCal_Header and iCal_Build_Calendar methods) rather than written to disk, then streamed back to the requesting client as raw HTTP responses. On the ingestion side, a Parse_Request method interprets WebDAV Get/Put/Delete semantics, converting posted iCalendar text (chunked through a text array to handle files over 32K) into 4D records via a Receive_Calendar_Blob method chain. The note references a companion demo database with a WebDAV-capable structure and readme, and cross-references an earlier tech note (03-45) for the reverse process of parsing iCalendar data into 4D. The overall proposition is that 4D can serve as a genuinely data-driven, cross-application calendaring backend rather than a static export/import bridge, showcasing 4D 2004's new raw HTTP command set as the enabling technology.
