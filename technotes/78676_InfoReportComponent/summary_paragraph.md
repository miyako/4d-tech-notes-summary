This tech note covers the Info Report component, a long-lived 4D troubleshooting tool originating as a library of diagnostic methods in v6 (2004) and converted into a proper installable component in v11, maintained since by community developer Thomas Schlumberger and distributed via TAOW (the 4D component/plugin marketplace). The component automates periodic logging (default every 5 minutes) of key database health metrics — number of users, tasks, and processes, cache usage vs. max cache size, memory/virtual memory usage, and stack size — and is described as lightweight enough to run continuously without the performance hit of the heavier debug log. Setup differs slightly by deployment: for 4D Standalone or 4D Server, a single method invokes the component's built-in scheduled report generator (aa4D_NP_Schedule_Reports_Server); for 4D Remote clients, because the component only ships a single-report method, the note provides a custom wrapper (infoReports_Create_Local_Report) that loops with DELAY PROCESS to replicate scheduled logging, plus a companion method (infoReports_Max_Set_Limit) to cap the number of retained log files given they aren't auto-pruned on Remote clients the way they are on Server. Log files land under Folder_Reports next to the .4dbase for Standalone/Server, or in OS-specific cache/AppData directories for Remote clients. The analysis section covers graphing collected reports via aa4D_NP_Report_Compare_Display, visually identifying memory leaks as a monotonically increasing memory line independent of user/process count, and using the "Attention" marker to flag database setting changes, low disk space, syntax errors, and other events overlaid on the same timeline — the classic first diagnostic step 4D's own technical support team uses when investigating long-running performance issues.
