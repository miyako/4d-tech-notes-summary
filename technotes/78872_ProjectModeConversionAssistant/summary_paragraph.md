This Tech Note tackles the practical difficulty of converting a legacy binary 4D database (.4DB/.4DC) to project mode, a step required to unlock v18+ features like classes and CSS stylesheets. When a binary structure is exported to project mode, 4D generates a Conversion_YYY-MM-DDTHH-MM-SS.json log file classifying every change as Info (automatic, no impact), Warning (automatic but may affect UI/behavior), or Error (requires manual developer fix, e.g., unsupported form-object styles) — and this list can range from a handful to several thousand entries for large, old databases. The provided component (installed as a standard .4dbase in the host's Components folder and launched via the PMCA_ConversionAssistant method) parses this JSON log into a browsable form where developers can double-click any message to jump straight to the offending form in Design mode, mark items as completed, filter by Show Uncompleted or by severity (Info/Warning/Error), and save progress to a Conversion_Component_Log.json file in Resources so work can resume across sessions without altering the original conversion log. This turns what would otherwise be a manual, error-prone trawl through a huge JSON file into a structured, trackable checklist — directly reducing the friction of adopting project mode for organizations with large legacy 4D applications.
