This Tech Note shows how to build a fully custom, in-application file explorer using 4D's object-notation File and Folder commands introduced around v17R5, avoiding any dependency on the operating system's native file browser. The core technique populates a collection-based list box by concatenating folder.folders() and folder.files() results (with fk ignore invisible) and ordering them via .orderBy(); listbox columns reference object properties directly (This.getIcon(), This.fullName, This.modificationDate, This.size). Two custom display methods, displayDateModified and displaySize, format the raw date/time and byte-count values into more readable combined-date and unit-scaled (KB/MB/GB) strings, and manual sort handlers are wired to the listbox's On Header Click event using LISTBOX GET ARRAYS and Find in array to detect which column header was clicked. Navigation is implemented with a "previous/forward" pattern using two collections treated as stacks (prev_stack, next_stack) that push/pop the current directory on button clicks, achieving full browsing history with just push/pop operations. Folder creation and deletion use the straightforward folder.create() and folder.delete() commands, the latter wrapped in an ON ERR CALL to catch attempts to delete a non-empty folder and surface the error via GET LAST ERROR STACK. Overall the note serves as a practical, self-contained reference for building a native, fully-controlled file management UI using modern object-notation commands rather than older array-based or OS-dependent techniques.
