This Tech Note is a technical reference for 4D plugin ("external package") developers, documenting three new C-level entry points introduced in 4th Dimension 3.5.3 that are not yet present in the standard Ext4D.h header file on the Partner CD. The first, kEX_SUBSELECTION_TO_ARRAY (166), lets a plugin bulk-copy field values or record numbers from a range of a file's current selection directly into one or more 4D arrays (local, process, or interprocess), using a caller-supplied ArFldCouple data structure array to specify which fields map to which arrays; it supports following automatic Many-to-One relations across files, is explicitly optimized for 4D Server (building arrays server-side before sending them to the client), and warns developers to test resulting array sizes since large ranges can consume significant memory. The second, kEX_SET_HOOK (168), solves a prior distribution headache with Sequential Operation Progress and Printing Progress hooks — previously these had to be manually placed as Mac HOOK resources or Windows DLLs at fixed file locations, bypassing 4D Server's automatic Mac4DX/Win4DX network distribution — by letting a plugin register its progress hook functions directly as compiled, platform-specific resources bundled with the external package itself, with example code showing installation at plugin init time and removal at de-init time. The third, kEX_4DPX_ATTRIBUTES (169), lets one external package introspect another installed external package's entry point address, code type (68K/PowerPC/Intel), private data handle, resource file reference, and name, enabling inter-plugin calls, with an explicit warning about crash risk if called before the target package has been initialized by 4D. Featured technology is 4D's original external package (plugin) API as expressed in the Ext4D.h header and ParameterBlock-based calling convention used across 68K, PowerPC, and Windows/Intel builds of 4D, 4D Client, and 4D Server.
