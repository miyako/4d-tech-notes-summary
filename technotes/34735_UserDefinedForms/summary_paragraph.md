Written by Sati Hillyer, a 4D Evangelist, this Tech Note introduces User Defined Forms, a new 4D 2004 feature that lets developers mark a form "Editable by User" so that end users -- even running a compiled, merged, double-clickable application -- can customize its layout at runtime through a simplified Form Editor invoked with the new EDIT FORM command, with the customized copy stored separately in a User Structure File (.4DA) alongside the database's structure file. The note walks through two usage patterns: directly editing the "source" form via EDIT FORM for simple one-off tweaks (e.g. adding a missing company logo to an invoice), and using CREATE USER FORM to stamp out multiple independently-editable duplicates of a template form for different departments or clients (illustrated with a university vertical-market scenario spanning Accounting, Scholar, and Admission department forms), supported by the companion LIST USER FORMS and DELETE USER FORM commands and the extended INPUT FORM/OUTPUT FORM commands that can target a named user form. It also shows Scenario 3, where 4D's existing inherited (parent/child) form system is combined with User Defined Forms so a developer can keep pushing "source" form updates (via the parent) without invalidating the end-user's already-customized child-derived forms -- solving the conflict where any edit to a source form normally obsoletes existing user copies. The note closes by listing other commands compatible with user-defined forms (PRINT LABEL, QUERY BY EXAMPLE, MODIFY SELECTION, DIALOG, etc.) and the new error codes (-9750 through -9758) introduced for this feature.
