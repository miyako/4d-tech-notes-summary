Written by Thierry Ozil of 4D S.A. Technical Support, this Tech Note is a reference document describing precisely how 4D encodes variable values inside a Blob. It opens with a table mapping 4D's internal one-byte type codes (Alpha, String, Text, Number, Integer, Long integer, Date, Time, Boolean, Picture, Subtable, Blob, arrays, etc.), then covers foundational encoding rules: hexadecimal literals (`0x64` equalling 100), Time values stored internally as a longint number of seconds, and the crucial difference in byte ordering between Mac OS (most significant byte first/big-endian) and Windows (least significant byte first/little-endian), illustrated with a 4-byte long integer example that reads as "BLVR" on Mac and "RVLB" reversed on Windows. It explains that Alpha variables are stored as classic Pascal strings (one length byte followed by the characters, no terminator), that Real numbers use a 10-byte word on 68K Macs versus 8 bytes on PowerPC/Windows (with Apple-supplied conversion routines bridging the two for backward compatibility), and that odd-length structures receive an extra padding byte for CPU alignment efficiency. The bulk of the note is a field-by-field specification of the Blob layout for each variable type: the four-byte "RVLB"/"BLVR" native-variable marker, then per-type byte counts for Long Integer, Real, Time, Date, Alpha, Text, Picture, and each of the array variants (element count, current selected element, then packed per-element data with padding). It closes by noting there is no built-in way to visually inspect a Blob's contents in the 4D interface, and that multiple variables can be packed sequentially into one Blob by repeated VARIABLE TO BLOB calls as long as the returned offsets are tracked and reused to locate each variable later.
