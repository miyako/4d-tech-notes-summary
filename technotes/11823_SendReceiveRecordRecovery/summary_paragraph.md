This Tech Note describes using the SEND RECORD and RECEIVE RECORD commands to effectively move data between two 4D databases. The note identifies several scenarios where data migration is necessary: abandoning an outdated structure, delivering only specific tables to a client, recovering data from a corrupted database beyond repair, upgrading to a different version of 4D when the data file doesn't convert cleanly, and cases where exporting and importing data is faster than letting v6 convert a very large v3 data file. The SEND RECORD and RECEIVE RECORD commands provided a record-level transfer mechanism that preserved field data while allowing it to be moved between different database structures. This was a critical technique for 4D developers in the v6 era, especially during the v3-to-v6 transition when data file conversion could be problematic. The approach offered a reliable fallback when standard conversion methods failed.
