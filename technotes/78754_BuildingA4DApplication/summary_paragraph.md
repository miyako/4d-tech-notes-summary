This tech note is a deep, practical reference on turning a 4D database into a distributable application via the Application Builder (Design > Build Application) or programmatically via the Build Application command. It requires a developer license and a successfully compiled database, and covers three build categories: a compiled structure (a binary .4DC file or, for Project mode databases, a .4DZ file, with a related "Build component" option for packaging as a host-database-loadable .4dbase), a stand-alone single-user Application (.exe/.app, requiring a 4D Volume Desktop license and a choice of Application-name-based or Application-path-based data linking mode), and a Client/Server deployment producing separate Server and Client executables, including automatic-update packaging and multi-platform (Mac+Windows) considerations. It details the Plugins & Components tab for trimming unused native components from a build, the Licenses & Certificates tab (Developer license with Volume Desktop expansion, OS X code signing), and explains that clicking Build generates a buildApp settings file — named buildApp.xml prior to v19 and buildApp.4DSettings from v19 onward — an XML file that can also be authored/edited directly and passed to the Build Application command for scripted, repeatable builds. The note documents several advanced XML keys beyond the builder UI, including Client/Server IP address and port overrides, the Server Selection Dialog toggle, Windows elevated-privilege auto-update keys, allowing multiple Windows client instances, and the new v19 PackProject setting, which controls whether a Project mode build's packed structure is read-only (relevant for post-build index creation or SQL DDL operations).
