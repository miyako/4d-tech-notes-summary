This Tech Note illustrates how to use Oracle's PL/SQL procedural extension to SQL from within a 4D application connected via the 4D for OCI plug-in. It introduces PL/SQL briefly as a language that adds control structures and procedural capability atop SQL, then presents two simple example routines: a recursive PL/SQL "Factorial" function and a "READINFO" procedure that returns the connected Oracle user, server date, and server time as output parameters via SELECT...INTO...FROM DUAL statements. For each example, the note provides a complete 4D project method that walks through the full OCI lifecycle: creating an environment handle (OCIEnvCreate), allocating an error handle, logging on (OCILogon) with hardcoded Scott/Tiger-style credentials, allocating a statement handle and using OCIStmtPrepare/OCIStmtExecute to CREATE OR REPLACE the PL/SQL routine on the Oracle server, then allocating a second statement handle to execute an "anonymous" PL/SQL BEGIN...END block that actually calls the routine, binding 4D variables to its parameters by name via OCIBindByName (distinguishing BIND_IN from BIND_OUT), executing it, and finally dropping the routine and freeing all handles. The note highlights that OCIBindByName's final parameter is the key mechanism for indicating whether a 4D variable supplies input to or receives output from the PL/SQL routine. A companion test database contains both example methods, requiring the developer to substitute their own Oracle connection credentials before use. The note closes by reiterating that PL/SQL's dynamic SQL and object-oriented features add meaningful flexibility to 4D-for-OCI-based Oracle integrations, though the routines shown are intentionally simple teaching examples rather than production-ready code.
