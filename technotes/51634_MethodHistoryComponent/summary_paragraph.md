This technical note describes a reusable 4D component that automatically captures and stores modifications to 4D methods (project, object, form, and database methods) using 4D v11 SQL Release 3's macro system. Every method change is recorded to a Method_History table in either the local host database or an external 4D Server (via SQL pass-through with TCP/IP, available in Release 3, or ODBC in Release 2). The component hooks into method saves via the "method_save" macro, automatically triggered when a developer modifies and saves any method. On demand, developers invoke the "Method_Compare" macro to open a history dialog displaying all stored versions of the currently edited method, with timestamps and usernames. Selecting two versions side-by-side displays them with colorized differences: orange for modified lines, green for additions, red for deletions. The diff rendering leverages a JavaScript library (jsdifflib and jsdiffview from Snowtide Informatics, open-source licensed) executed within a Web Area form object to dynamically build a DOM tree and apply CSS formatting. The component supports optional Unicode mode (required for methods >32K in size), customizable SQL syntax for different SQL dialects (includes MS SQL Server 2008 example), and flexible storage options (local database, external 4D Server via TCP/IP pass-through, or ODBC source). Installation is drag-and-drop into the Components folder; initialization is via EXECUTE METHOD("MethodHistory_init",...) on startup, allowing the component to be optionally removed for deployment without affecting compilation.
