This third installment in Larry Sharpe's ongoing example-database series shows how to design a 4D process that is configured and monitored from a 4D Client but actually executes on the 4D Server, using a small conditional layer so the exact same code also runs correctly under a single-user or Client-only installation. The example implements a recurring "People Import" process, driven by the People_ImportProcess method, that periodically scans an Import Needed folder, imports any files found, sends a confirmation email or 4D Alert, moves the file to an Import Finished folder, and loops again after a user-configurable delay. Preferences for the process (whether to run at startup, run on server vs. client, polling interval, and email/alert options) are stored separately from per-user preferences in the xPreferences table, keyed under the name "Processes" rather than a specific user. The note pays close attention to the subtle differences between New process, Execute on server, and EXECUTE ON CLIENT, and to synchronizing client UI state via EXECUTE ON CLIENT plus On Outside Call, since the server itself cannot display alerts or dialogs. It also documents GET PROCESS VARIABLE, SET PROCESS VARIABLE, VARIABLE TO VARIABLE, and REGISTER/UNREGISTER CLIENT, clarifying which of these accept local variables and which do not.
