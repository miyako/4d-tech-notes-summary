This Tech Note tackles the now-ubiquitous UX pattern of a search field with a live autocomplete dropdown, framed as a significant efficiency improvement over navigating records manually or via a separate search-then-select workflow. The implementation starts with a simple enterable variable whose On After Edit event captures Get edited text and issues a QUERY (with an optional Split string-based two-field first-name/last-name matching pattern using QUERY SELECTION for the refinement) against a classic 4D table. A dropdown, implemented as a selection-based list box layered beneath the search field, is shown/hidden via OBJECT SET VISIBLE depending on whether there's typed input, and its height is dynamically computed from Records in selection and LISTBOX Get rows height, capped at a maximum row count (5 in the sample) via OBJECT SET COORDINATES. Keyboard interaction is implemented with three invisible bound buttons (up-arrow, down-arrow, enter) that manipulate LISTBOX SELECT ROW and Selected record number, load the highlighted record, and write its display text into the search field through a pointer ($pt->). Additional polish includes using HIGHLIGHT TEXT to keep the text cursor positioned at the end of the inserted text, and OBJECT SET SCROLL POSITION to keep the currently selected suggestion visible when scrolling past the visible row count. The note positions this purely as a reusable UI template developers can extend, built on classic (non-ORDA) table selections and array-style list box wiring characteristic of 4D's traditional forms programming model.
