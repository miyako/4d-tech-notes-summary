Because 4D lacks native high-level commands for inspecting or editing audio file metadata, this Tech Note works from first principles: it documents the binary structure of the two most common audio formats, WAV (Waveform Audio File Format) and MPEG-1/2 Audio Layer (MP3), and then implements 4D methods to read and modify them directly at the byte level. For WAV, it covers the chunk-based file structure, the distinction between big-endian and little-endian byte ordering (critical for correctly parsing multi-byte header fields), and the layout of the actual audio sample data. For MP3, it covers the file structure plus the ID3v1 tag (a fixed-size trailer with basic metadata) and the more flexible, frame-based ID3v2 tag format (header plus multiple metadata frames), before addressing the MP3 audio data itself. The 4D implementation section then supplies information getters/setters for both formats and shows how to modify the underlying audio/metadata bytes, backed by utility project methods like Util_BitConvert, Util_Base10Convert/Util_Base10Revert (numeric base conversions needed for parsing binary fields), and Util_GetMean. A sample database ties it together. This note is a strong example of "timeless" 4D content: WAV and MP3/ID3 are stable, decades-old binary formats that have not changed, and BLOB-level byte manipulation techniques in 4D (reading/writing specific byte ranges, endian conversion) are exactly as valid today as in 2016. The one caveat is that 4D has since added or improved some native BLOB/text-conversion commands, so a few of the custom utility methods shown might now have more direct built-in equivalents, but the core techniques and format knowledge remain fully applicable.
