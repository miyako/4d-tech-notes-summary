This March 1996 Tech Note by David Adams and Forrest Swilling presents a reusable 4D procedure, ArraysToTable, that converts an arbitrary number of parallel string/text arrays into a fully formatted HTML table using the table tags proposed in the HTML 3.0 draft and extended by Netscape Navigator (and supported by Spry Mosaic). The note walks through a worked example — a small table of 4D user group meeting details built from a [UserGroups] file — showing how SELECTION TO ARRAY populates parallel arrays for name, city, state, and meeting fields, with array element {0} reserved for column titles, before calling ArraysToTable to assemble the markup and writing it to disk with a document reference and SEND PACKET. The ArraysToTable procedure itself accepts caption text, border/cell-spacing/cell-padding sizes, and per-column horizontal alignment, vertical alignment, and word-wrap codes as compact one-character-per-column strings (with sensible Netscape defaults, e.g. border 2, cell spacing 2, cell padding 1), plus a variable number of pointers to the content arrays themselves — leveraging 4D's variable-parameter and pointer-to-array features to support any number of table columns with one general-purpose routine. Helper procedures (PadChars, HAlign, VAlign, Wrappage) pad the alignment code strings to match the number of columns and translate the abbreviated codes (L/R/C, T/M/B/A, N) into their full HTML attribute values. The featured technology is squarely 4D's procedural language combined with early Netscape-flavored HTML table markup, illustrating how a database developer of the era could programmatically publish structured 4D data as web tables without a web server.
