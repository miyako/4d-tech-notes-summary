This Tech Note introduces 4D View Pro (VP) offscreen areas, which allow spreadsheet documents to be created, imported, manipulated, and exported entirely in the background with no visible UI element — useful for server-side report generation or batch document processing. It shows two ways to set one up: a class-based approach where a dedicated class implements an `onEvent` function handling VP lifecycle events (On VP Ready, On Load, On Unload, On End URL Loading, On VP Range Changed, On Timer, etc.), initialized via `cs.MyVpOffscreenArea.new()` passed to `VP Run offscreen area`; and a formula-based approach for developers not using classes, where a project method is wrapped in `Formula(...)` and assigned to the area object's `onEvent` property. It documents the configurable attributes of the offscreen area object — area (name), onEvent, autoQuit (auto-closes after On VP Ready unless callbacks are needed for async import/export, in which case it must be False and closing handled manually via CANCEL/ACCEPT), timeout (default 60s, 0 = no timeout), result (return value from VP Run offscreen area, settable via This.result), and arbitrary custom properties. Demos cover creating a new spreadsheet with VP NEW DOCUMENT and returning its object definition via VP Export to object in the On Unload handler, and importing spreadsheet formats (4D View Pro's native .4vp, Excel .xlsx, and UTF-8 text/.csv) via VP IMPORT DOCUMENT, noting that Excel imports run asynchronously and require careful callback handling. This positions offscreen areas as the standard technique for any spreadsheet automation task that doesn't need to be shown on screen.
