This Tech Note introduces the FileHandle object, a new 4D v19R7 class built on top of the File object (from v17R5) that modernizes reading and writing file content in 4D. It contrasts the "classic way" — opening a file with `OPEN DOCUMENT` to get a document reference, positioning the offset with `SET/GET DOCUMENT POSITION`, reading with `RECEIVE PACKET` (by character count or stop-character), writing with `SEND PACKET`, and manually closing with `CLOSE DOCUMENT` (forgetting which locks the file until a restart) — against the new object-oriented pipeline: instantiate a `File` object (from a POSIX/platform path or a built-in file constant), call its `.open()` function in read, write, or append mode to get a `FileHandle`, then use `.readLine()`/`.readText()`/`.readBlob()` or `.writeLine()`/`.writeText()`/`.writeBlob()`, with the handle's `.offset` property tracking position automatically and no manual close needed — the handle self-closes when its reference is set to null or its process terminates. Notably, `.readLine()`/`.writeLine()` natively handle Mac/Windows end-of-line differences that previously required manual `stopChar` handling. For whole-file operations regardless of approach, the note notes there's no performance difference between the classic `Document to text`/`TEXT TO DOCUMENT`/`DOCUMENT TO BLOB`/`BLOB TO DOCUMENT` commands and the File class's `.getText()`/`.setText()`/`.getContent()`/`.setContent()` functions — it's purely a matter of whether a File object is already in play. The note also introduces the complementary `Folder` object (largely mirroring File's properties/functions, plus `.files()`/`.folders()`/`.file()`/`.folder()` for traversal) and a POSIX-vs-platform-path aside, before demonstrating both text and blob file handle usage in a bundled logger demo application. Overall it positions FileHandle as the more maintainable, OOP-aligned, multi-mode-capable (simultaneous independent read/write/append handles with separate offsets) replacement for legacy packet-based file I/O.
