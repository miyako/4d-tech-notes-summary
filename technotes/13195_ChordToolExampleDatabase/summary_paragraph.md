This Tech Note by Eric Saltzen (4D, Inc. Technical Support) walks through the Chord Tool example database, originally written by Tad Michael Wheeler of DataCraft for 4D version 6, which lets a user pick a musical key and chord construct and see the resulting notes light up on an on-screen piano keyboard. The core technique encodes which of the (up to 32) notes in a chord are active as bits of a single Long Integer, using an offset (the Key) combined with a bit-field definition (the Notes/Construct) so that `SET VISIBLE` and bit tests can show or hide the "little red dot" objects representing each key. The heart of the database is the `ChordTool_EncodeChord` project method, which uses the bit-set operator (`?+`) to build up the chord's bit pattern from a root note and a `[Constructs]` record's `Note_2` through `Note_7` fields, and the note walks through a worked example (a C Major triad) converting the resulting binary pattern to its decimal value of 145. Along the way it explains 4D's pop-up-menu array idiom, where an array's out-of-index storage slot tracks the currently selected item, used in the `[Chords]` form's Key and Construct pop-ups. The note closes with an aside on the historical origins of Arabic numerals, algebra, and the word algorithm, and suggests extensions such as precomputing bit-fields per record or using the PLAY command to sound the encoded chords.
