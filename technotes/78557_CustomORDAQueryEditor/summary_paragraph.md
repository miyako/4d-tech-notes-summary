With ORDA delivering dramatic performance gains (cited as 2–3x LAN and up to 30x WAN improvements over classic queries), this Tech Note addresses the fact that 4D's built-in Query Editor still relies on the classic, non-ORDA querying mechanism, and shows developers how to build their own ORDA-native query editor from scratch. The resulting form replicates the classic editor's familiar workflow but generates its query string for `dataClass.query()`: each query row consists of a table dropdown, a table-field hierarchical list (refreshed dynamically whenever a different table is selected), a comparison-operator dropdown (equal, not equal, less/greater than, etc.), a query-value text field, and plus/minus buttons to duplicate or hide rows. Active rows are tracked in a `Form.queryRows` collection of integers, with each row's form objects named by convention (e.g., `queryField1`, `queryText1`) so the UI can dynamically add or remove rows; the minus button and conjunction dropdown are hidden/disabled when only one row remains. On load, the form populates the table list and its field sublist using `GET TABLE TITLES`/`GET FIELD TITLES`, appending fields as nested list items under each table. The plus button clones the previous row's objects and repositions them, while the minus button hides a row and shifts the query rows collection. When the user clicks Query, all active rows are combined (respecting AND/OR conjunctions) into a single query string, which is passed into `dataClass.query()`; for display purposes the resulting entity selection is then converted back into a current selection for the output form's list box. The accompanying demo database showcases the complete editor built on this pattern, providing a template developers can adapt to give their own applications a dynamic, ORDA-driven search/query builder UI.
