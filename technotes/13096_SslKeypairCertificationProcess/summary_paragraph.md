This Tech Note by Steve Hartman and Elaine Smith (4D, Inc. Technical Support) explains how SSL secures communication between a 4D web server and browsers, starting with a first-principles tour of public-key cryptography: how a public/private keypair enables encryption and authentication, how digital signatures work (illustrated with the classic Alice-authenticating-Bob scenario, message digests, and a "web of trust" via a mutual friend Ted), and why certificates -- signed statements binding a public key to an identity -- solve the problem of trustworthy key distribution (with an impersonator "Carol" shown failing to fake Bob's private key). It then turns practical: 4D and WebSTAR both use RSA, qualified under the US Federal Advanced Encryption Standard, and 4D's `GENERATE ENCRYPTION KEYPAIR` command produces a private/public key pair (default 512 bits, optionally 1024, since many browsers reject longer keys), which can be saved to disk as PEM-style `-----BEGIN RSA PRIVATE KEY-----` documents via `BLOB TO DOCUMENT`. The `GENERATE CERTIFICATE REQUEST` command (secured protocol version 6.7) then produces a certificate signing request suitable for submission to a certificate authority like Verisign or Thawte, and the note walks step by step through filling out the example database's Certificate Request form (Common Name, Country, City, State, Company, Unit), generating the keypair and request files, and finally installing the received certificate into the WebSTAR Server Suite's virtual host folder to enable HTTPS.
