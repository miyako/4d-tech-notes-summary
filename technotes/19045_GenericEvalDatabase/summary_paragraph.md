This Tech Note (TN 01-49, 4D v6.7, Mac & Win, published October 30, 2001) by Raymond Manley of 4D, Inc. explains the internals of the GenericEval example database, which configures its own field schema at runtime by parsing machine-readable tags out of incoming email. The scenario: a web registration form emails its submission to a holding mailbox with each field wrapped in [***FieldName***] tags (building on the companion mailer database from TN 01-36), and GenericEval's MAIL_ProcessEMails method, run periodically via POP3_Login/POP3_GetMessage/POP3_Delete, parses each message, extracts every tag/value pair, and stores the values into a generic 100-field table (Table2, with fields simply named Field1 through Field100). The first time a given tag is seen, a new record is created in a zStructure alias table linking that tag to the next unused generic field number; GET FIELD PROPERTIES is then used to check whether that field has been manually retyped (e.g., to Date or Boolean) so the incoming text can be converted appropriately before being stored. A companion ALIAS_DeployAliases method reads zStructure to relabel the database's table and field names in the UI via SET TABLE TITLES and SET FIELD TITLES, so forms and the Query Editor display friendly labels like "Company" and "Date Purchased" instead of Table2/Field7. The result is a genuinely self-configuring intake database that adapts its schema to whatever tagged data arrives, without requiring the developer to predefine every possible field in advance.
