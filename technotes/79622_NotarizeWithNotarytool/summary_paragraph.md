This Tech Note walks 4D developers through Apple's notarization requirement — mandatory for any 4D application built on macOS, downloaded on another Mac, or deployed over the internet — using Apple's streamlined "notarytool" command-line utility in place of the older altool workflow. It requires macOS 11.3+, 4D 18+, Xcode 13+, and an Apple Developer account with a Developer ID Application Certificate and app-specific password. The core workflow covers preparing the app (compiling and building via Design → Compiler/Build Application, signing with a Developer ID certificate under Licenses and Certificate), then a one-time keychain profile setup via `xcrun notarytool store-credentials --apple-id ... --team-id ...` that stores credentials so subsequent notarization calls need only reference `--keychain-profile "notaryTN"` rather than re-entering credentials. For applications needing extra files not automatically signed by 4D's build process, the note provides a shell script (using codesign with --options=runtime --timestamp and an entitlements file) plus a 4D method using LAUNCH EXTERNAL PROCESS to invoke it, along with a special manual codesign step required for the "lib4d-arm64.dylib" library inside compiled databases. Actual notarization is a single command, `xcrun notarytool submit "[ZIP]" --keychain-profile "notaryTN" --wait`, with log inspection available via `xcrun notarytool log`. The final step, stapling (`xcrun stapler staple [PATH]`), attaches the notarization ticket directly to .app/.dmg/.pkg files (but not .4dbase components) so Gatekeeper can validate the app offline. The note positions this as essential, low-friction tooling for meeting Apple's cybersecurity requirements when distributing 4D-built macOS applications outside the App Store.
