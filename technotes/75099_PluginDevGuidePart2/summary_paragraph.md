This Tech Note is the hands-on, code-focused second half of a two-part series on 4D plug-in development, following a Part 1 that covered the theory of writing cross-platform, Unicode-aware, Universal Binary plug-ins for 4D 2004 and v11 SQL. It walks through a "Code Page" sample plug-in demonstrating wrapper functions (`PA_strings.c`) that bridge text parameter handling between 2004's legacy multi-byte/code-page encodings and v11 SQL's native UTF-16 Unicode, including a Windows-specific reliance on `mlang.DLL` (bundled with Internet Explorer) for broader encoding support beyond the standard Windows conversion APIs. It then covers practical Plug-in Wizard workflow: importing command/theme definitions from an existing rsrc file, defining custom constants, binding constant themes to command parameters (new in v11 SQL, producing a `kmapper.xml` resource), and creating stub projects for a platform you haven't built binaries for yet. A large section addresses the shift in picture handling away from the legacy QuickDraw 'PICT' format toward Core Graphics types (`CGImageRef`/`CGPDFDocumentRef` on Mac, GDI+ on Windows), with a "Picture Tools" sample plug-in exposing commands like `picture to data`, `picture save as pdf`, and `picture from file` (using the QuickLook framework), and detailed Xcode project configuration steps (architectures, deployment target, custom executables) for building and testing such plug-ins. The note closes with an extensive walkthrough of registering a custom Apple Help Book for a plug-in on Mac OS X — explaining Carbon vs. Cocoa help registration differences, `Info.plist` configuration, `AppleTitle`/`AppleIcon` meta tags, and the C code needed to call `AHRegisterHelpBook` — alongside a "UTI Tools" sample plug-in for working with macOS Uniform Type Identifiers. The intended audience is experienced 4D developers with working C skills who need to build native plug-in commands spanning both legacy and then-current 4D plug-in APIs and both Mac and Windows platforms.
