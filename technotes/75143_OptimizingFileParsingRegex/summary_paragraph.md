This Tech Note revisits classic 4D file-parsing techniques in light of three new v11 SQL capabilities: the Match regex command, 2GB Text variables, and native UTF-16 Unicode support, and demonstrates that combining them yields both simpler and faster parsing code. It reviews two older approaches — looping with `RECEIVE PACKET` and `Position` (simple but limited to "contains" matching and subject to frequent filesystem hits), and converting a file to a BLOB and scanning it byte-by-byte with a Boyer-Moore search (abstracted from the file, but complex and made worse by Unicode's variable-width characters) — before introducing the new technique: loading a file into a Text variable and repeatedly calling `Match regex` with a start position to walk through lines and extract data using position/length outputs. It carefully documents `Match regex`'s behavior, including the requirement to pass a `start` parameter (initialized to at least 1) to search beyond the first line, and shows tips like using the pattern `.*` to grab a full line. A real-world benchmark parsing ~85,000 lines of Perforce `p4 fstat` output found the BLOB technique dramatically slower than the other two, and Match regex 1.3x faster than Position on that dataset; a second, simpler 10,000-line synthetic test in the included example database showed Match regex 1.4x faster than Position and 40x faster than BLOB search. The sample database provides working implementations of all three techniques (`TN_Parse_Position`, `TN_Parse_BLOB`, `TN_Parse_Regex`) with a test dialog to run and compare them. The note is aimed at developers who need to parse large text files efficiently and want to modernize legacy parsing code using v11 SQL's new string-handling capabilities.
