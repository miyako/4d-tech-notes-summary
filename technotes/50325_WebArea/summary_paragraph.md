Web Area, introduced in 4D v11 SQL Release 2 (11.2), is a native form object that embeds a web browser control directly into 4D desktop forms, enabling display of HTML content, images, PDF files, Flash animations, JavaScript, and more—functionality previously requiring the 4D Live Window plug-in but now delivered without plug-in installation overhead. Web Areas use the host platform's native rendering engine (WebKit on Mac OS X, matching Safari; ActiveX Web Controls on Windows, matching Internet Explorer), ensuring consistent rendering and eliminating cross-platform plugin complications. Developers can place multiple Web Areas in a single form, including on multi-page forms. Each Web Area is associated with two automatic variables: a URL variable (e.g., WebAreaName_url, a String type) that holds the current URL and can be assigned to load new URLs, and a Progression variable (e.g., WebAreaName_progress, a Longint 0–100) that tracks loading percentage. Four standard navigation actions simplify UI construction: Open Back URL, Open Next URL, Refresh Current URL, and Stop Loading URL—actions automatically manage browser history and disable buttons when unavailable. Seven form events fire at URL lifecycle milestones: On Begin URL Loading, On URL Resource Loading (for each resource), On End URL Loading, On URL Loading Error (with error code access), On URL Filtering, On Open External Link, and On Window Opening Denied. On Mac OS X, URLs must include the protocol (http://..., not just www.example.com), and the form window must run in compositing mode (Open Form with compositing type 4096). Over twenty new commands (WA OPEN URL, WA GET CURRENT URL, WA GET LAST URL ERROR, etc.) provide programmatic control. The Edit menu and context menu automatically work within Web Areas. Drag-and-drop is supported for URLs and files. A sample database is included."
