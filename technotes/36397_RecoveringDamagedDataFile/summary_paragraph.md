Data integrity is one of the most important elements within a database. No matter how secure and prepared we are; unfortunate events such as power outages, system crashes, application crashes, etc. can corrupt the data. In this technical note, we will discus ways to recover data when corruption occurs. There are many ways to detect and recover the data, however this technical note will focus on four ways; using 4D tools, re-indexing a data file, or re-saving records, and exporting data to a new data-file. This 2005-era Tech Note (TN 05-09) was published for 4D version 2004 on Mac & Win, during the pre-SQL, Design Mode-only period of 4D's history (4D 2004/2004.1, before v11 SQL, ORDA, or Project Mode existed). Featured technology associated with this note includes: 4D data file recovery tools, Data/index re-indexing, Record re-saving, Data export/re-import. This note surveys four classic-era techniques for recovering a corrupted 4D data file: using built-in 4D recovery tools, re-indexing, re-saving records, and exporting/re-importing into a fresh data file. Data corruption recovery remains a conceptually relevant practice today, but the specific binary .4DD data file structure and tools referenced are from the pre-SQL 4D 2004 era, and 4D has since introduced more robust logging, backup, and mirroring/recovery mechanisms.
