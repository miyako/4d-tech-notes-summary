This Technical Note by Josh Fletcher of 4D Inc. explains the automatic client upgrade feature introduced in 4th Dimension (4D) 2004, distinguishing it from the "update" functionality 4D had long supported automatically (new/changed methods, forms, picture library entries, plug-ins, resource files, and the Extras folder). It defines key terminology — compiled (.4DC) applications, merged (double-clickable) client/server applications, the per-user "Client Cache" folder location on Windows and Mac OS, and the distinction between an "Install Image" (the manually installed client), an "Install Client," and an "Upgrade Client" (the special image downloaded only for automatic upgrades) — before explaining that prior to 4D 2004, changes like a new 4D version or an external resource change had to be handled manually or via custom code. The feature is enabled/disabled via the Build Application XML key `<BuildCSUpgradeable>` and further tuned with `<CurrentVers>`, `<RangeVersMin>`, and `<RangeVersMax>` keys, which can be set through the Build Application dialog for the simple case or via a custom build project XML file for version-range logic; the note includes flowcharts showing that a client whose current version doesn't match the server's expected version (or falls outside a configured range) is prompted to upgrade, while a 4D-version mismatch always blocks the connection regardless of the current-version check. When an upgrade is triggered, the merged client quits, a platform-specific script deletes the old install and extracts a new one from an "archive.win" or "archive.mac" file staged in an "Upgrade4DClient" folder next to the merged server (noting a Windows machine can still build a Mac upgrade client, but not a Mac install client, and vice versa), and the upgraded client relaunches, with the local client cache preserved throughout. The note also covers two customization avenues: modifying the install image (any files added to the underlying 4D Client/Server/single-user software folder are automatically carried into the merged build) and modifying the platform-specific upgrade scripts themselves (upgclnt.bat on Windows, Upgclnt.sh on Mac OS), explicitly flagged as undocumented and subject to change across 4D versions, with suggested customizations such as launching a full installer, adjusting permissions, or displaying release notes during the upgrade.
