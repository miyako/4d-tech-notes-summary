This Tech Note surfaces an undocumented behavior of 4D v6's early built-in web serving capability: when a 4D method is bound to an HTML link using the /4DMETHOD/Name_of_your_method URL convention (as covered in the Language Reference manual's "Web Services, Your First Time" section), 4th Dimension automatically sends a text parameter to that method — even though this parameter is not mentioned in the official documentation for the feature. The note flags two practical consequences for developers: first, that the parameter must be explicitly declared with C_TEXT($1) in the called method, even if the developer has no intention of using its value, because omitting this declaration would trigger runtime errors specifically when the database is running in compiled mode and being accessed via the web. Second, it explains what the parameter actually contains: any extra text appended to the end of the invoking URL, which developers can deliberately exploit as a simple mechanism for passing values from the HTML/browser side into the 4D method's execution context. This is a narrow but practically important tip for anyone building web-callable 4D methods in this era, since failing to declare the parameter correctly could cause web-triggered failures that would not manifest when testing the same method outside a compiled, web-served context.
