This Tech Note by Cha Yang (4D, Inc. Technical Engineer) introduces recursion — a method calling itself repeatedly until a condition is met — and explains how each recursive call consumes stack space to remember its return line and local variable state, producing the "Not enough Stack Space to complete the current Method" error if the stack fills up. The first example, a five-line `RecursiveFactorial` method, computes 3! by having the method call itself with an incrementing parameter until a base case is reached, then unwinds the stack multiplying results back up through each call level. The second, more practical example walks through `NumToText`, a real project method (originally written by Dave Batton of DataCraft, from a 4D NUG code snippet by Kirk Brooks) that recursively converts a numeric dollar amount into its English word equivalent — e.g., 5432 becomes "Five Thousand Four Hundred Thirty Two" — by repeatedly dividing off billions/millions/thousands/hundreds and recursing on the remainder, wired to an object method's `On Data Change` event. The note closes with practical guidance: recursion suits problems and data structures (like trees) that are naturally self-similar, but an iterative loop is preferable when possible since it avoids the memory/performance overhead of the call stack.
