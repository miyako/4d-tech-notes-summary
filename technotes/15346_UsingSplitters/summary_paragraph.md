This Tech Note by Gilles Mellot (4D S.A.) aims to popularize the Splitter object, introduced in 4D v6.5 but under-used by developers unaware of its full capabilities. It explains that a splitter divides a form area into regions (area 1 and area 2 for a simple case), and that dragging it affects only the objects on either side according to each object's "grow"/"move" resize properties — illustrated through a progressive series of examples (Test_1 through Test_8) showing objects that stay fixed, grow with the splitter, move with the splitter, or combine both behaviors on either side, including cases requiring a second splitter to independently manage move-only objects. It shows that a splitter's position is bound to a longint variable that updates as the user drags it and can also be set programmatically to move the splitter (demonstrated with an On Timer-driven "animation" that steadily shrinks pictures and slides them using `Splitter_V:=Splitter_V-4` / `Splitter_H:=Splitter_H+1`, interruptible by holding Shift). A more advanced example demonstrates dragging a group of splitter-managed array columns out of the window entirely to spawn a separate floating palette process that mirrors and continues to control the same column widths, synchronized via `CALL PROCESS` and the `On Outside Call` event reading shared interprocess variables. The note closes noting that invisible objects are not moved/resized by splitters and must be repositioned manually with `MOVE OBJECT` when made visible again.
