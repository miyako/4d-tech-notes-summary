This Technical Note (25-12, published December 22, 2025, requires 4D 20 R10+ for `UDPSocket`/`UDPEvent`) presents a complete, serverless peer-to-peer discovery implementation for local networks, built around a `PeerDiscovery` class. Each instance opens a listener and sender pair of `4D.UDPSocket` objects (bound via a worker process, `CALL WORKER("p2pworker"; ...)`, synchronized with a `4D.Signal` during initialization) and periodically broadcasts JSON-encoded `ANNOUNCE` messages to `255.255.255.255` on a configurable discovery port (default 54321), while listening for incoming `onData` events carrying `ANNOUNCE`, `PROBE`, or `BYE` message types from other peers. Discovered peers are tracked in a shared collection (`id`, `name`, `ip`, `port`, `lastSeen`, `info`), refreshed on each new announcement and expired via TTL-based pruning (default 90 seconds) so stale entries disappear automatically; a background `RunPeerDiscovery` worker method drives the loop (send probe, prune, publish peers/log to `Storage`) on a `closingSignal`-gated cycle, and a `stop()` method sends a graceful `BYE` message before shutting down sockets. A companion `Util_formatLastSeen` project method renders "N seconds/minutes/hours ago" strings for listbox display. The note frames this as a template for any distributed-tool, collaborative-desktop, or local-synchronization scenario needing rapid, rendezvous-server-free instance coordination, entirely within native 4D language features (shared objects/collections, signals, workers) and with real-world UDP use cases (BitTorrent-style discovery, multiplayer matchmaking, IoT service detection) as motivating context.
