Written by Eric Saltzen of 4D, Inc. Technical Support, this Tech Note tackles a specific web-serving gap in 4D v6.5: HTML forms with a MULTIPLE-attribute SELECT input submit several values under the same field name, and 4D's built-in form decoding was not equipped to recognize and separate them. The accompanying 657MultipleItemSelect sample database (published Non-Contextually with 4DVAR-comment syntax) demonstrates both submission styles with hand-built HTML pages (getform.html, postform.html, index.html, results.shtml) and five 4D methods: On Web Connection handles POST submissions routed through /4DCGI/Form01, while AcceptForm01 handles GET submissions routed through /4DACTION; both call the reusable ProcessMultipleItemSelect method, which walks the raw query-string/header text looking for repeated "Name=value" occurrences separated by ampersands and collects each match into a results array via INSERT ELEMENT. Because POST data arrives URL-encoded, the POST path also calls DecodeURLText, which replaces "+" with spaces and converts "%XX" escape sequences back to characters using the companion HexToDec utility (a manual hex-to-decimal converter capped at 8 digits). The note closes with a candid postscript: the author had planned a 6.7 version of this note, but 4D v6.7's new GET WEB FORM VARIABLES command made this entire hand-rolled parsing exercise unnecessary, and readers are told outright to just upgrade instead.
