This 2001 Tech Note by Steve Hussey, Editor and Publisher of Dimensions Journal, addresses a real gap in classic 4D: arrays are heavily used for building on-screen summaries but cannot be printed directly, and this note demonstrates a reliable technique for printing them anyway using the PRINT FORM command. The sample database tracks invoice records (Amount, Invoice_Type of Cash/Credit/Check, Invoice_Year) and, from an Invoice Summary menu item, displays a dialog with grouped scrollable arrays -- aint_Year, areal_YearTotal, and separate cash/credit/check amount arrays -- built by taking DISTINCT VALUES of Invoice_Year, sorting with SORT ARRAY, sizing companion arrays to match, then looping through each year with a QUERY on Invoice_Year and a nested loop over the resulting selection that accumulates cash/credit/check totals into the arrays using a Case-of on Invoice_Type. To print this data, the INV_SmryPrt project method first calls PRINT SETTINGS to let the user choose paper size/orientation, then prints a header form (with the Detail marker dragged to the top, since PRINT FORM only ever uses a form's Detail part), loops through the year array copying each array element into matching process variables placed on a detail form (int_Year_frm, real_Amount_Cash_frm, etc.) and calling PRINT FORM once per year to emit each line, accumulates running totals along the way, prints a footer form with the grand totals, and finally issues PAGE BREAK(*) to eject the accumulated print job from memory to the printer. The note frames this "process variable stand-in for an array element" pattern as broadly reusable for printing any array-backed report.
