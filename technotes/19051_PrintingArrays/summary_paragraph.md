This Tech Note (TN 01-52, 4D v6.7, Mac & Win, published November 30, 2001) presents a technique for printing array data using form variables and the PRINT FORM command. Only a short on-page teaser paragraph survives in this archive rather than the full downloadable PDF and example database, because the original download was an old Windows self-extracting .exe installer (https://kb.4d.com/ftp://ftp.4D.com/ACI_TECHNICAL_NOTES/2001/Windows/TN_2001_50-53_(NOV)/01-52_Printing_Arrays.exe) that could not be extracted in this environment; the original 4D Tech Notes site offered separate Windows and Mac downloads of the complete note and its companion example database, but neither is retrievable here. Based on the surviving teaser text, the note's proposition is: Arrays are a powerful feature of 4D. They are often used to create summaries of data, such as reports, built from 4D records. However they cannot be printed directly from within 4D. This technical note describes a simple technique for printing data in arrays using variables and the PRINT FORM command. It can be used to print any type of array data. Its featured technology centers on 4D Arrays, PRINT FORM, Report generation from array data, reflecting typical concerns of the 4D 6.7 (4D 2000/2001 era) developer community working in binary Design Mode on classic Mac OS/early Mac OS X and Windows 98/2000/NT. This note explains a workaround for a real classic-language limitation — arrays cannot be printed directly — by mapping array data into form variables and using PRINT FORM to render it. This general variable/PRINT FORM technique still functions in current 4D versions, though today a List Box bound to a collection or array, or 4D Write Pro, would often be a more convenient way to lay out and print the same tabular data.
