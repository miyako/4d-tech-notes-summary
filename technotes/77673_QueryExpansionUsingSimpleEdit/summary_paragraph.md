Authored by Timothy Tse of 4D Inc. in October 2016 for 4D v15.x, this tech note implements Peter Norvig's well-known "simple edit distance" spelling-correction algorithm inside 4D to expand search queries with similarly spelled candidate words — useful for fuzzy matching against surnames or catching user misspellings. It defines the four types of single-letter edits that constitute an "edit distance of one" — deletion, insertion, transposition, and replacement — with clear before/after examples for each (e.g., "Smith"→"Smit" for deletion, "Smith"→"Smithy" for insertion). The core of the note walks through the algorithm step by step: splitting the target word into all possible left/right substring pairs, then systematically generating every possible single-edit variant by deleting, inserting, transposing, or replacing characters at each split point, building up a results array of all one-edit-away candidate words. The technique is packaged as a 4D component and demonstrated in a sample database that shows the expanded query candidates in action. Because this is fundamentally a language-agnostic algorithm — Norvig's original write-up (as Google's Director of Research) remains a widely cited reference in spell-checking and search literature to this day — the conceptual content of this note has aged extremely well and would translate directly into any programming environment. The specific 4D implementation, built on classic ARRAY TEXT commands, still runs unmodified in current 4D, though a developer writing this today would likely reach for 4D's newer collection objects instead of arrays, and in production settings might offload large-scale fuzzy search to a dedicated search engine like Elasticsearch rather than computing edit-distance candidates within 4D itself.
