# Tech Note 16-19: Query Expansion using Simple Edit

**Author:** Timothy Tse, Technical Services Engineer, 4D Inc.
**Published:** October 31, 2016 | **Product/Version:** 4D v15.x | **Platform:** Mac & Win
**Page:** https://kb.4d.com/assetid=77673
**Download:** https://kb.4d.com/DLTN/TN/2016/16-19_QueryWithSimpleEdit.zip

## Proposition
Peter Norvig's simple edit-distance method finds all words within one letter-edit of a target word, useful for spell-checking, surname matching, or expanding a search query with similar terms. This tech note implements the algorithm in 4D and provides a demo database and component showing its use for query expansion.

## Key Points
- **Four edit types:** deletion ("Smith"→"Smit"), insertion ("Smith"→"Smithy"), transposition ("Smith"→"Simth"), and replacement ("Smith"→"Smyth").
- **Split-based algorithm:** the word is decomposed into all possible left/right substring pairs, then each edit type is systematically applied at every split point.
- **Deletion candidates:** generated by removing the first character of each right-substring and recombining with the corresponding left-substring.
- **Insertion/transposition/replacement:** follow analogous systematic recombination patterns (detailed further in the full algorithm walkthrough).
- **Component packaging:** the algorithm is delivered as a reusable 4D component.
- **Demo database:** shows the expanded candidate list generated from a sample query term.

## Featured Technology
- Peter Norvig's simple edit-distance spelling algorithm
- 4D arrays (`ARRAY TEXT`) for candidate generation
- Reusable 4D component for query expansion

## Best Practices Highlighted
1. Generate all edit-distance-one candidates systematically (by split point and edit type) rather than through ad hoc string manipulation, to guarantee completeness.
2. Package the algorithm as a standalone component so it can be reused across multiple query/search features.

## Context / Positioning
Published October 2016 for 4D v15.x, this note applies a general computer-science algorithm within the classic, pre-Project-Mode, pre-ORDA 4D environment, using traditional array-based data structures rather than the collection objects that arrived in later 4D versions.

## Historical Commentary
**Status:** Current

Norvig's edit-distance algorithm (he was, and remains, well known for this and other computational work, at Google) is a foundational, language-agnostic technique that still underlies modern spell-checkers and fuzzy-search features; the algorithmic content of this note has not dated at all.

The 4D implementation itself, built on classic `ARRAY TEXT` commands, still runs unmodified on current 4D. A developer writing this today would likely use 4D's newer collection objects instead of arrays for cleaner code, and for large-scale production fuzzy search, many teams would now offload the workload to a dedicated search engine (e.g., Elasticsearch, Meilisearch) rather than computing edit-distance candidates inside 4D — but the core technique this note teaches remains directly useful and portable.
