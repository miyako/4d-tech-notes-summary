This short 2019 Tech Note documents a demo database showing how to enumerate and manage active 4D Mobile session connections from within a 4D application. The problem addressed is administrative visibility: when 4D Mobile clients (via REST requests such as `http://127.0.0.1/rest/$catalog`) connect to a 4D standalone or 4D Server, each session consumes one of the license's connection slots (limited to 3 by default on a Developer Pro license), and developers previously had no simple UI to see who is connected or to forcibly disconnect them. The sample database opens a form that lists all active 4D Mobile sessions, flagging the admin session versus standard client sessions, and provides a button to end a selected non-admin session, immediately freeing its license slot. The implementation relies on two project methods, `getRestSessions` and `closeRestSession`, whose code and the corresponding "MobileSession" project form are bundled in the sample. Only a brief readme accompanies the demo (no narrative PDF body was available beyond setup/test steps), so the underlying command/API details are inferred from the method names and behavior described rather than from an extended technical discussion. The note targets 4D v17 and above and requires the demo to be run in 4D standalone. This kind of session-introspection tooling was relevant chiefly to shops actively building native/hybrid 4D Mobile client apps against a 4D REST backend, a use case tied to the now-retired 4D Mobile product line.
