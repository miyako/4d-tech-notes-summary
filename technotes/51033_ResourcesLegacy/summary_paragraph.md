This Technical Note explains the fundamental resource architecture change introduced in 4D v11 SQL, moving away from the legacy Macintosh resource fork model (used in 4D 2004 and earlier) toward a file-based resource system compliant with modern Mac OS X standards. In 4D 2004, resources were defined as "data of any kind stored in a defined format in a separate file or in the resource fork of a Macintosh file" and were accessed via 4-character resource types (STR, STR#, TEXT, PICT, cicn, CURS, 4DK#) using Resource theme commands like Get string resource, Get indexed string, Get picture resource, Get icon resource, and Get resource. The resource fork approach, while powerful, represents an obsolete Mac OS paradigm that Apple has deprecated and will progressively phase out. In 4D v11 SQL, resources are now defined as "files that are necessary for the translation of application interfaces," stored as individual files in the Resources folder rather than in .RSR files or resource forks. Strings are stored in XLIFF (XML Localization Interchange Format) files (for STR, STR#, TEXT resource types), pictures and icons are stored as individual image files (.jpg, .png, .gif, etc.), and custom constants are now stored in plug-ins rather than as 4DK# resources. The note provides detailed comparison tables, includes sample databases for both 4D 2004 (demonstrating resource fork storage) and 4D v11 SQL (showing both converted and upgraded resource approaches), and documents compatibility mechanisms that allow legacy .RSR resources to continue functioning in v11 SQL during the transition period, acknowledging that while old-style resources remain supported, developers are encouraged to upgrade to the new file-based architecture for future-proofing.
