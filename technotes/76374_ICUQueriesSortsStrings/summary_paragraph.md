This Tech Note explains what ICU (International Components for Unicode) is — an open-source library providing consistent Unicode handling, character/word/line boundary management, collation, and script transliteration across platforms and languages — and how 4D has used the ICU collation algorithm since v11.2 Unicode for all sorts, queries, and string comparisons. It covers Unicode fundamentals and the ASCII/Unicode table, then digs into the practical limits of ICU-based comparison, notably how "ignorable" Unicode characters (codes below 9, between 14-31, and unbreakable spaces) can silently be treated as equivalent to nothing or to a regular space during comparisons, with the "*" parameter as a workaround to force character-code-based comparison where supported. It enumerates specific 4D commands affected by ICU in v11 Unicode — including the C_STRING/C_TEXT equivalence, Position, Replace string, Uppercase/Lowercase, and Char — plus a special note on databases using Japanese as the data language starting in v11.5, XLIFF file saving, forbidden characters, keyboard-layout-based database conversion, and a summary table of pre/post-ICU behavioral differences. The note is essential reading for any developer debugging unexpected query, sort, or comparison results after upgrading to 4D's Unicode-based versions.
