# Tech Note: My First Web Grid

## Overview
This article is a first introduction to the 4D Ajax Framework Data Grid 2.0. If you are developing a Web application that displays a selection of records and want to incorporate a Web 2.0 technology into your application, this is the article for you. In this technical note, you will learn what 4D Ajax Framework has to offer as far as the data view functionality in both the 4D Ajax Framework Client and in a customized HTML page. The discussion will evolve around the integration of Data in an HTML page. It will cover some basic techniques on how to use the 4D Ajax Framework JavaScript API to manipulate Data Grid layout and control certain features that are standard to the Data Grid object. Introduction ------------------------------------------------------------------------------------------------------------------------------------------------------------------ The Data Grid is the most commonly used object to display data and it is the number one choice for most Ajax websites. In comparison to 4D objects, the Data Grid is a close relative to a List Box or 4D View area. In 4D, the List Box column can be bound to a field or array. The same behavior can be found in the Data Grid. The field in each physical table or view will automatically bind to each column in the Grid. When the Data Grid is used with a DCS (Developer Created Selections), each column will automatically bind to each array specified for the DCS. In the 4D Ajax Framework, the Data Grid provides much functionality that gives the developer many controls over the behavior and appearance. Before you begin working a Data Grid into your HTML page, it is important to become familiar with the basic functionality of a Data Grid in the 4D Ajax Framework first. The best place to see these functionalities is from the 4D Ajax Framework Client. 4D AJAX FRAMEWORK CLIENT ------------------------------------------------------------------------------------------------------------------------------------------------------------------ For the initial installation of the 4D Ajax Framework, all tables will appear in the 4D Ajax Framework Client in the Data Grid window. This viewing style can be modified through the Admin Control Panel. In the 4D Ajax Framework Client, most of the features and behaviors have been pre-defined. Some features can be enabled and disabled by the Administrator through the Admin Control Panel. Some can be changed directly by the user. The default features in the Data Grid are: Toolbar 1 The Toolbar option consists of Add/Delete button and Basic/Advanced Search option. Preset Query Tabs or Side Bar The Query Tab appears automatically when the Data Grid appears in the 4D Ajax Framework Client. The number of tabs depends on the number of preset queries defined by the developer in the Query Manager or Developer Hook (backend database). If no additional preset query is defined for the table, the Data Grid will display only the “All” records table. The Sidebar is another representation of a preset query. In the 4D Ajax Framework, the user can choose to display the preset query either in the form of tabs or a sidebar at any given time while in the session. This option to change the appearance can be found at the top of the Data Grid window (as shown in the previous screenshot). Once clicked, the sidebar on the left side of the Data Grid window appears, and the title of the Sidebar button becomes “Tabs”, as shown below. 2 Grid Area The grid area consists of the column header, footer, the control column (first column in the grid), and detail area. The column header is clickable giving the user the ability to sort the selection based on the value in a column. When a row is clicked, the inline-editing icon appears in the control column. Once the user clicks on the icon, the record will be editable in the grid. To modify the record in the full screen editor, the user can double click on a row and the record editor will be displayed on top of the Data Grid. There are a few settings in the Admin Control Panel that affects the way Data Grid appears and behaves. Field Visibility Under the Properties section of the Access Control, the Administrator can toggle the visibility mode for particular fields in the Data Grid through the checkbox under the “O” (Output) column. Any field that has this option turned 3 off will be excluded from the query response returned from the 4DAF Server (backend database) to the Data Grid. Field Search Ability The checkbox under the “S” column represents the searchable property. This option ties directly to the search option in the Toolbar of the Data Grid. The search option appears at the top of the Data Grid only if one or more fields in the field Properties have the searchable checkbox checked. Visible in the output column Allow this field to be searchable Adding a Data Grid into Your Own HTML Page ------------------------------------------------------------------------------------------------------------------------------------------------------------------ Bringing the same Data Grid functionality from the 4D Ajax Framework Client into your own HTML page can be done with a few lines of code. Depending on your requirements, the Data Grid can be programmatically manipulated through the 4D Ajax Framework Javascript API and CSS. In this section we will go over some of the basic appearances that you can apply to the Data Grid JavaScript API. Changing Row Height The height of the grid row can be changed to a specific pixel through a function named setRowHeightInPx(). This function must be executed for a specific Data Grid. However, the result of the execution affects all rows in the Data Grid, including the header and footer row. <script type="text/javascript"> <!-window.onload = dax_login('User1', 'UserPass'); function dax_loginSuccess(){ 10 mygrid = new dax_dataGrid('Artist', $('myGridDiv'), 0, 0, false); mygrid.go(); mygrid.setRowHeightInPx(50); } // --> </script> Changing Column Width The column width can be modified in a fashion similar to the row height. However, column resizing can be done one column at a time. The function that performs this task is called setColumnWidth(column, pixel). <script type="text/javascript"> <!-window.onload = dax_login('User1', 'UserPass'); function dax_loginSuccess(){ mygrid = new dax_dataGrid('Artist', $('myGridDiv'), 0, 0, false); mygrid.go(); mygrid.setColumnWidth(0, 40); } // --> </script> Please note that the column index starts at 0 to N-1. Setting Number and Height of Header Row The number of header rows must be predefined in the function dax_dataGrid. Here is an example of the results for different header row values. // Do not display grid header mygrid = new dax_dataGrid('Artist', $('myGridDiv'), 0, 0, false); // Display one row of the grid header mygrid = new dax_dataGrid('Artist', $('myGridDiv'), 1, 0, false); 11 // Display two rows of the grid header mygrid = new dax_dataGrid('Artist', $('myGridDiv'), 2, 0, false); Once all header rows have been constructed, you can apply a new height unit to each one of them through the function named setHeaderHeight(header-rowindex, header-unit). Here is the call syntax: mygrid.setHeaderHeight(header-row-index, header-unit); The following example shows how to double the height of the 2nd header row. <script type="text/javascript"> <!-window.onload = dax_login('User1', 'UserPass'); function dax_loginSuccess(){ mygrid = new dax_dataGrid('Artist', $('myGridDiv'), 2, 0, false); mygrid.go(); mygrid.setHeaderHeight(1, 2); } // --> </script> 12 Setting Number and Height of Footer Row By default, the footer row is not visible in the Data Grid. You need to enable the footer area through a function named setFooterRows(). This function allows you to specify the number of footers that will appear in the Data Grid. Please note that the execution of setFooterRows() must be done before the execution of the command go(). <script type="text/javascript"> <!-window.onload = dax_login('User1', 'UserPass'); function dax_loginSuccess(){ mygrid = new dax_dataGrid('Artist', $('myGridDiv'), 1, 0, false); mygrid.setFooterRows(2); mygrid.go(); } // --> </script> In the example, the 2 footer rows are added to the Data Grid. The height of each row is set to the same height as the detail row. To change the height of the footer row, the function named setFooterHeight() must be executed for a particular footer row. In the Data Grid, the footer row index starts at 0 and goes to n-1. 13 Example: Set the height unit of the 1st footer row to 3. <script type="text/javascript"> <!-window.onload = dax_login('User1', 'UserPass'); function dax_loginSuccess(){ mygrid = new dax_dataGrid('Artist', $('myGridDiv'), 1, 0, false); mygrid.setFooterRows(2); mygrid.go(); mygrid.setFooterHeight(0, 3); } // --> </script> Example: Set the height unit of the 2nd footer row to 3. <script type="text/javascript"> <!-window.onload = dax_login('User1', 'UserPass'); function dax_loginSuccess(){ mygrid = new dax_dataGrid('Artist', $('myGridDiv'), 1, 0, false); mygrid.setFooterRows(2); mygrid.go(); mygrid.setFooterHeight(1, 3); } // --> </script> 14 Feature control ------------------------------------------------------------------------------------------------------------------------------------------------------------------ When integrating a Data Grid into a custom HTML page, some of the features are not automatically enabled. The developer will have to decide whether those features are suitable or when they will be enabled. Features such as Toolbar, Preset Query or Edition options will be enabled or disabled programmatically through the JavaScript API. Toolbar The toolbar feature in Data Grid consists of 4 options: 1. Create record button 2. Delete record button 3. Search option 4. DDW button (only if one is assigned to the selection) The first 3 options can be enabled through a function named showToolbar(). The function can be executed to enable all options with a single call. It can also be executed independently to enable each option. When showToolbar() is executed, the toolbar area will appear at the top of the Data Grid area. Depending on the preference, the developer can choose to display the preset query in one (or both) of the following ways. 1. Query Tabs The tabs will appear above the Data Grid area. The number of tabs depends on the number of preset queries that is specified by the Administrator. To display the query tabs, the showQueryTabs() function must be executed. The sidebar will automatically appear on the left side of the Data Grid when calling showQuerySidebar() with no parameters. Otherwise, the developer can pass in either ‘left’ or ‘right’ into the function to determine the display position of the sidebar. When the user double clicks on a record, the editor appears as a floating window allowing the user to make modification to the record. This editor is the same as the editor in the 4D Ajax Framework Client. It cannot be customized. The Data Grid also has an inline-editing feature. This feature is disabled by default. The developer can enable this option by first setting the 5th parameter of the dax_dataGrid function to true. The true value tells the Data Grid constructor to display the control column in the Data Grid. Once the control column is enabled, the function allowInlineEditing() needs to be executed in order to display the inline-editing option in the control column. 19 To edit a record, the user needs to click on the edit icon and the modifiable field will be enterable. Notice that the Edit icon has changed to a check mark. This indicates that a save action has been clicked.

## Historical Context
This 2008 Tech Note documents a feature of the then-new 4D v11 SQL engine or the 4D Ajax Framework (4DAF), both of which were central to 4D's product strategy at the time. The 4D v11 SQL engine itself was foundational and its core concepts (schemas, SQL access, list boxes, components) persist conceptually in modern 4D, though the specific syntax and interfaces have evolved substantially through later versions and ORDA (introduced 2018). 4DAF-based web UI techniques (Data Grids, YUI integration, custom AJAX components), by contrast, reflect a web-development approach that has been superseded by 4D's modern web server, web components, and Qodly Studio (2021+).

**Status:** obsolete

**Related updates:**
- 4D Ajax Framework (4DAF) has been discontinued; modern 4D web development uses 4D's built-in web server, REST/ORDA APIs, and Qodly Studio (2021+) for low-code web UI
- AJAX-era manual grid/component techniques have been superseded by modern JS frameworks and 4D web components
