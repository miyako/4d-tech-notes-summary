This Tech Note addresses a specific migration pain point: 4D's built-in primary key manager can detect (but, for databases originating from v14+, not create) missing primary keys, making it tedious to fix an old database with hundreds of tables lacking primary keys — a common blocker when preparing to convert to project mode or a newer 4D version, since primary keys are required for ORDA. The solution queries 4D's SQL system tables — _USER_TABLES (table names/IDs), _USER_CONSTRAINTS (constraint type 'P' for primary key), and _USER_CONS_COLUMNS (constraint column mapping) — via 4D's Begin SQL/End SQL blocks to build a hasPrimaryKey(table) check and a getTablesWithoutPK() collection builder. It then uses ALTER TABLE SQL statements (ADD field, MODIFY ... ENABLE AUTO_GENERATE or AUTO_INCREMENT, ADD PRIMARY KEY) to programmatically create UUID- or Longint-based auto-generated primary keys for every flagged table, with a listbox UI letting the developer review/adjust field names and types before execution. A companion deletePKFields routine (for demo/testing convenience) reverses the process. The result is effectively a small reusable component that can turn an hours-long manual structure-editor task into a one-click bulk operation, directly supporting a smoother path to project mode/ORDA compliance.
