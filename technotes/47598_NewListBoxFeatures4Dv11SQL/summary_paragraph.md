This Technical Note covers new List Box capabilities added in 4D v11 SQL, moving the control beyond its previous array-only limitation to support three distinct Data Sources: Arrays (the pre-existing 4D 2004 approach), Current Selection (showing fields and expressions from the records currently selected), and Named Selection (similar to Current Selection but based on a persisted, ordered set of records). It introduces this alongside another new v11 SQL concept, Project Forms — forms not bound to a specific table, ideal for dialogs and other UI not tied to one data source — which the note's bundled example database uses for all three List Box demonstrations. The sample database models two related tables, [People] and [Companies] (linked via a company reference on each person record), each with trigger-assigned auto-incrementing ID fields and basic Input/Output forms usable in "List of Tables" mode (the v11 SQL renaming of "User Mode"). All three List Box examples support Add/Modify (double-click a row) and Delete operations on [People] records via buttons, configurable for single or multiple row selection through List Box Properties and matching button script changes, and reuse a shared Project Method (ListBox_xxx_Functions) to avoid duplicating logic across the List Box's Object Method and the Add/Delete buttons' Object Methods. The Arrays example works exactly as in 4D 2004 — populating and clearing arrays via Selection To Array and loading a hidden ID array to identify records for query-based modify/delete — but cannot use in-column Expressions the way the two new data sources can. The Current Selection example instead configures which fields populate which columns directly through the List Box's Property List (List Box Properties / List Box Column Properties) without manual array management, using a simple All Records call (though a Query or a related table's records could substitute). The note emphasizes that developers can still fall back to List Box and Object Properties commands to configure everything in code if the ~95% form-editor-based workflow doesn't suffice, pointing to other Technical Notes covering that programmatic approach. As a practical, example-driven note tied to 4D v11 SQL's List Box overhaul, it documents a lasting improvement that made data-bound, low-boilerplate List Boxes standard practice in 4D development.
