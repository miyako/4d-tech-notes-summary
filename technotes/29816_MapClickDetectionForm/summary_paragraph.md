This Tech Note by Gérald Czwiklinski of 4D S.A. addresses a specific UI limitation: standard techniques for detecting mouse clicks on a picture — invisible buttons over rectangular zones, or manually testing coordinate ranges with GET MOUSE — both break down for non-rectangular regions such as the individual states on a map. The demo database instead builds a hidden grayscale 'mask' version of the map, where each US state is filled with a distinct, near-identical gray level (e.g., Texas at RGB 40/40/40, Washington at 44/44/44 — deliberately subtle so the mask still looks like a normal map), and converts that mask into a 2D array, Pixel_State, sized to the image's height and width. Populating the array is done once, up front: the mask picture is retrieved with GET PICTURE FROM LIBRARY and its dimensions read via PICTURE PROPERTIES, then converted to an uncompressed 24-bit BMP BLOB with PICTURE TO BLOB('...';$BlobBMP;'BMPf'), and every pixel is read sequentially starting 54 bytes in (past the BMP header) at 3-byte (RGB) intervals, storing each pixel's gray value into Pixel_State{row}{col}. At click time, the technique collapses to two lines: GET MOUSE($x;$y;$bt) to get the click coordinates, then $State:=Pixel_State{$y}{$x} to look up which state (by numeric ID) was clicked, followed by a QUERY on the [State] table to find the matching record. The note notes the approach is limited to 256 distinct regions with a single-channel grayscale mask, but can be extended past that limit by decoding a full RGB value as R*65536+G*256+B, and closes by generalizing the technique beyond maps to any non-rectangular clickable shape, such as pie-chart wedges or arrow buttons.
