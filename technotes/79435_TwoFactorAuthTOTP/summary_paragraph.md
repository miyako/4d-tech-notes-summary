This Tech Note shows how to add Two-Factor Authentication (2FA) to a 4D application using TOTP (Time-based One-Time Password), a widely used standard where a 6-digit code generated by an authenticator app (Microsoft/Google Authenticator) changes every 30 seconds based on a shared secret, making password logging or replay attacks ineffective since codes expire before they can be reused. The technical flow starts by generating a random 16-character base32-encoded secret per user via a singleton Auth_tools class's Random_token_base32() helper, storing it alongside existing user credentials; the secret is then shared with the authenticator app not as plain text but as a scannable QR code, built by combining the secret and account name into an otpauth:// provisioning URI (via cs.TOTP.new(secret).provisioningUri("app_name")) and rendering it through the open-source qrencode plugin (by Keisuke Miyako of 4D Japan). At verification time, both the authenticator app and the 4D server independently combine the shared secret with the current 30-second time window to produce a hash, truncated to a 6-digit code; because clocks and user input speed vary, the server compares against the current, previous, and next time windows (a 90-second tolerance) using cs.TOTP.new(secret).verify(code). The example login flow layers TOTP verification on top of existing password verification (Verify password hash) for a full multi-factor check. The underlying TOTP/HOTP/OTP classes are credited to Eric Marchand (4D France, github.com/mesopelagique/OTP), with the note providing both a modern 4D 20 R5+ implementation using singleton classes and an adapted non-singleton version compatible back to 4D 20 LTS. The note frames 2FA as an easy, low-cost way to meaningfully raise application security and demonstrate security-conscious development practices to customers.
