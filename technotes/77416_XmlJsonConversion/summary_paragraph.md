This Tech Note by Timothy Tse compares XML and JSON as data interchange formats and provides a purely code-based approach to convert between them in 4D. It explains that XML uses nested markup elements while JSON uses property/value pairs organized as native 4D objects, and shows that JSON STRINGIFY can turn a 4D object directly into a JSON string once the data has been captured as an object. The bulk of the note walks through a recursive algorithm: parse XML via DOM PARSE XML SOURCE/VARIABLE, then use DOM GET XML ELEMENT NAME, DOM COUNT XML ATTRIBUTES, DOM GET ATTRIBUTE BY INDEX, and DOM GET XML ELEMENT VALUE together with OB SET to rebuild the structure as a 4D object, recursing into child elements found via DOM GET FIRST CHILD XML ELEMENT and DOM GET NEXT SIBLING XML ELEMENT. The reverse direction uses JSON PARSE plus the DOM XML creation commands (DOM CREATE XML REF, DOM SET XML ATTRIBUTE, DOM SET XML ELEMENT VALUE) to rebuild an XML tree from a parsed JSON object, again with recursion for nested objects. The note is candid about lossy edge cases: JSON property names can't contain ":", repeated XML elements must be manually accumulated into JSON arrays via OB GET ARRAY/OB SET ARRAY because of the algorithm's sequential nature, 2D arrays inside objects are unsupported, and mixed value/sub-element XML nodes get folded into a synthetic "#text" property. A bundled sample database offers a simple two-pane UI with buttons to convert in either direction and a "pretty formatting" toggle. The conclusion frames the note as a practical bridge for developers who need to interoperate with XML-based systems while working natively in JSON/object terms in 4D.
