Written by Frank Chang, this note documents version 2.x of the IP Component for 4D Business Kit (4DBK), a stand-alone e-commerce application built on 4D 2003.x. Where the previous component version only allowed uploading data to a 4DBK server, this release adds the ability to pull Item, Customer, and Order records back down into a separate 4D application, demonstrated with a small companion application and a 4DBK demo store. After configuring the demo store's 'ST01' properties to allow 4D Component data exchange and setting a shared password, the note walks through placing a sample order on the demo store, then downloading it into the 4D application using the driver method Store_Demo_getOrders. That method builds a timestamp-based incremental query with 4DBKC_ToolsString (converting a stored last-update date/time into a 4DBK-compatible GMT timestamp string like '*Ts>=20030707115635') and passes it to the core new component method 4DBKC_ImportFileFrom4DBK, which takes the server address, port, timeouts, shared password, store code, module ('ORD' for orders, 'ITM' for items, 'CUS' for customers), the query string, and a local file path, returning the queried records into an MD5-encrypted local file that the 4D application then decrypts and parses. The note emphasizes this incremental Ts-based querying avoids re-downloading previously retrieved orders, and notes the same download pattern applies equally to customer and item retrieval, not just orders.
