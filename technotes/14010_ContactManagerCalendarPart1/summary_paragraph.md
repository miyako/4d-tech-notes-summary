This Tech Note by Hugo Fournier (4D, Inc. Technical Support) is Part I of a two-part series reviewing the forms and code behind the Calendar interface in the Contact Manager example database, focusing here on how the calendar's objects are placed and displayed (Part II covers user interaction). At the user level, the calendar dialog offers a button bar (Add Event, Delete Event, Go to Today, Go to Date, Previous/Next Month/Year, Print Calendar) above a grid of up to 42 date boxes, and double-clicking a box or event opens one of four Event Detail dialog variants — Special Day, Appointment, Banner (a multi-day event like the 4D Summit), or Picture — all stored in a single `[Calendar]` table distinguished by an Event Type field. At the designer level, the note traces the startup sequence from the `On Startup` database method's call to `Calendar_Startup`, through `Calendar_Setup` (detecting the machine's date format and initializing interprocess variables) and `Calendar_Dialog` (opening the modal window via `Open form window`/`DIALOG`), into the event-driven `On Load` phase: `Calendar_GetCoordinates` reads reference object positions so the form adapts automatically to layout changes, `Calendar_SetupMonth` computes the first/last displayed date boxes (handling both 5-row and 6-row month layouts), and `Calendar_SetNumbers` loops through three date ranges (previous month tail, current month, next month head) assigning day numbers to `<>Cal_Num1`–`<>Cal_Num42` via pointers. Finally, box positioning and event redrawing are deferred to the form's `On Resize` event (via `Calendar_PlaceBoxes`, using nested loops based on the window's current size) specifically so the layout also recalculates whenever the user resizes the window, not only at initial load.
