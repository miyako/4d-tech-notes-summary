This tech note addresses the mandatory migration from classic 4D Write to 4D Write Pro triggered by 4D's shift to 64-bit-only builds starting around v17R5/v18, since the 4D Write plugin only ever existed in 32-bit form. It walks through three conversion goals: converting stored 4D Write documents (on disk as .4w6/.4w7/.4wt files, or embedded in the datafile as picture/BLOB fields) into 4D Write Pro's .wp/object format; replacing 4D Write plugin areas on forms with 4D Write Pro areas (plain, control-dialog, or toolbar variants); and removing or translating 4D Write (WR ...) commands to their 4D Write Pro (WP.../ST...) equivalents, noting the mapping is not one-to-one — some commands like WR LOCK COMMAND and WR ON COMMAND have no replacement. Key APIs include WR New offscreen area, WR OPEN DOCUMENT, WR SAVE DOCUMENT, WP Import document, WP EXPORT DOCUMENT, WR PICTURE TO AREA, WR Area to blob, and WP New. Critically, converting the oldest .4w6 format or picture-field documents requires a 32-bit version of 4D (17.5 or 17 R4 at the latest) because the offscreen-area conversion command itself is 32-bit only, while newer .4w7/BLOB-stored documents can be converted directly in 64-bit 4D v17R5+. The author recommends testing old and new areas side by side before removing the legacy 4D Write area to avoid syntax errors from stray WR commands. This is fundamentally a one-time migration/cleanup tech note rather than an ongoing best practice, aimed at developers still running pre-v18 databases with legacy rich-text content.
