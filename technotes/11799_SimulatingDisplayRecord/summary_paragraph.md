This Tech Note provides a method to display records one by one using standard navigation buttons (Next, Previous, First, Last record) without locking records as they are displayed and without requiring users to double-click in a list. The technique simulates the DISPLAY RECORD command while avoiding its record-locking behavior, making it especially suitable for client/server deployments where unnecessary record locks can cause contention, and for read-only data scenarios such as serving data from a CD-ROM. The approach would have used 4D's selection and navigation commands to iterate through a set of records while keeping them in a read-only state. This pattern addressed a common complaint about the standard DISPLAY RECORD behavior in multi-user environments. The note was relevant to 4D v6 developers building client/server applications with 4D Server.
