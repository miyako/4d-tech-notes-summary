This Tech Note by David Adams presents a sample database of wrapper routines that refine 4th Dimension 2004's built-in DOM (Document Object Model) XML-reading commands, addressing three categories of rough edges: invalid node references, whitespace handling, and attribute access. It explains that DOM tree-navigation commands like `DOM Get Parent XML element` and `DOM Get first child XML element` use the OK system variable to signal when navigation has walked off the tree, which is useful for traversal but means code can easily end up holding an invalid node reference; calling native value/name-reading commands on such a reference triggers an intrusive error dialog, so the accompanying routines automatically wrap the native commands in a suppressing error handler, and expose a `DOM_ReferenceIsValid` function for explicit validity checks. It also documents a whitespace-cleaning integration: because DOM/SAX commands always return leading/trailing XML whitespace as part of an element's value (previously addressed in a separate Tech Note on `XML_CleanWhitespace`), the enhanced `DOM_GetElementValue` function offers an optional whitespace-cleaning parameter built on that same trimming routine. On the attributes front, it notes that the native `DOM Count XML attributes` command crashes certain versions of 4D when called on the special `#document` root node, and provides `DOM_CountAttributes` as a crash-safe replacement, alongside `DOM_AttributesToArrays` for conveniently copying all of a node's attributes into paired name/value text arrays. The note documents roughly a dozen routines in total — including `DOM_CountElementByName`, `DOM_ElementExists`, `DOM_FindElementByName`, `DOM_GetElementName`, and a case-sensitive string comparison helper `String_EqualCaseSensitively` (needed because XML element names are case-sensitive) — each with its exact 4D command signature and behavior description. The accompanying sample database demonstrates each enhancement with an interactive demo screen and includes internal documentation plus a "DOM Read Me" method. The note closes by summarizing that while 4D's native DOM commands are feature-complete, this collection makes them safer and more convenient by centralizing error handling, whitespace trimming, and attribute access into a small, reusable, well-documented function library.
