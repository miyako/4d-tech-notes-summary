This is Part II of a two-part tech note by Timothy Aaron Penner of 4D Inc., published January 2017, continuing the 4D-ACME-Client open-source component introduced in Part I (TN 16-17) that lets a 4D Web Server obtain and renew free Domain Validated SSL/TLS certificates from Let's Encrypt using the ACME protocol. Part II adds two new public methods aimed at certificate lifecycle management: KEYS_get_expiration, which returns the ISO-format expiration date of the certificate currently in use (checking either the server's structure-file location or the client cache depending on execution context), and KEYS_cert_expires_in_x_days, which returns a boolean indicating whether the certificate will expire within a caller-specified number of days — useful for building an automated renewal loop that avoids Let's Encrypt's rate limits given its 90-day certificate lifetime. The note also documents important robustness fixes: the domain-authorization and well-known-challenge logic was rewritten to use files on disk instead of thread-unsafe Inter-Process Variables, specifically so the ACME client would work correctly under 4D v16's new Preemptive Web Server; the Base64 URL-safe encoder methods gained decode functionality in addition to encode; and the GUI was enhanced to show the certificate's expiration date color-coded (green if more than 30 days out, red if imminent or missing) plus a "Generate New Account Key" checkbox for recovering from failed account-key registrations. The component and its GitHub repository are referenced as ongoing resources. While the ACME protocol fundamentals and general TLS/certificate concepts remain valid, 4D subsequently added native Let's Encrypt integration directly into 4D Server's administration settings, meaning this hand-built component — while still functional and educational — is no longer the primary way most 4D developers would obtain certificates today.
