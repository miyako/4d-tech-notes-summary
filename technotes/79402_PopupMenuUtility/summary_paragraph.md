This technical note addresses the complexity of building sophisticated popup menus in 4D, where the native `Pop up menu` and `Dynamic pop up menu` commands require substantial boilerplate — `Create menu`, `APPEND MENU ITEM`, and `SET MENU ITEM PARAMETER` calls — to construct multi-level menus, and offer no built-in support for tracking selection state (checkmarks) across invocations. The proposed solution is a small utility layer, built around three project methods (`inCollection`, `buildPopupMenu`, and the public `popup` method), that lets developers describe an entire popup menu — including nested submenus — as a single 4D collection of strings and objects, where a submenu is represented as an object whose property holds a nested collection. Special text-based markers embedded in item strings control behavior declaratively: a leading "(" disables an item, appended style codes like "<B", "<I", "<U" apply bold/italic/underline, `Char(1)` appended to a submenu's property name enables single-choice "radio" checkmark switching among its children, and `Char(2)` appended to an item enables independent on/off checkmark toggling. The `popup()` method signature is `popup(menuDefinition : Collection{; coordinateDefinition : Object}) -> selected : Text`, returning the selected item's text (or a "/"-joined path for nested selections), and an optional coordinate-definition object lets the menu be anchored to a specific object's corner (top-left, top-right, bottom-left, bottom-right) rather than defaulting to the mouse position via `OBJECT GET COORDINATES`. By centralizing menu construction and state handling behind this data-driven API, the note reduces popup-menu code to defining structure rather than imperative menu-building logic, making menus easier to maintain and extend.
