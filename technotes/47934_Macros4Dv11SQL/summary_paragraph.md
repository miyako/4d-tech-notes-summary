This Technical Note explains what changed with 4D's macro feature — a method-editor automation mechanism that has existed since 4D 2003, letting developers trigger insertion of text or calls to 4D methods with a shortcut — as of 4D v11 SQL, describing the macro conversion process, new XML-standard conformity, and new element attributes. It walks through how 4D v11 SQL detects and migrates macro storage on first opening a database: if a "Macros v2" folder already exists in the active 4D/system folder, macros are simply loaded from it as-is; if only an older "Macros" folder or Macros.xml file exists, 4D v11 SQL creates the new "Macros v2" folder and copies the existing macros into it; and if none of these exist, 4D v11 SQL creates a "Macros v2" folder with a generated, default Macros.xml file. During this migration, 4D v11 SQL prepends standard XML declaration and DOCTYPE lines to the macro files (specifying encoding — "windows-1252" on Windows or "x-mac-roman" on Mac when converting existing files, versus UTF-8 recommended for new files), so that macro definitions now fully conform to the W3C XML standard (whereas earlier 4D versions used an XML-resembling but non-conformant syntax), enabling the files to be parsed by any standards-compliant XML tool. The note frames this XML conformity change, along with the elimination of the earlier need to store macro text larger than 32,000 characters as blobs, and the addition of event-triggered macros, as the three headline improvements for macros in 4D v11 SQL, and goes on to detail the specific new attributes available on the <macro> XML element. Aimed at developers who maintain custom macro libraries across 4D version upgrades, this note is a practical guide to a largely internal, tooling-level change accompanying the broader 4D v11 SQL release.
