4D v11 SQL introduced a new Component Architecture that changed how 4D Components are developed and installed, breaking compatibility with the previous component format. This note examines the new component mechanism in depth, compares it against the legacy pre-v11 implementation, and walks through a bundled example component database to illustrate the advantages of the new architecture for distributing reusable functionality across 4D databases. Published March 5, 2008 as Technical Note 08-08 for 4D Developer v11 (Mac & Win), written by Luis Pineiros, Technical Services Team Member, 4D Inc.. This documents a genuine architectural turning point for 4D's component system, and the core concept of 4D Components as a distribution mechanism for reusable code is still very much alive today; however, the specific v11 SQL-era component format and creation process described has since been superseded by further evolutions of the component/plugin architecture in subsequent 4D versions.
