# Components in 4D v11 SQL

## Overview
4D v11 SQL introduced a new Component Architecture that changed how 4D Components are developed and installed, breaking compatibility with the previous component format. This note examines the new component mechanism in depth, compares it against the legacy pre-v11 implementation, and walks through a bundled example component database to illustrate the advantages of the new architecture for distributing reusable functionality across 4D databases.

## Key Points
- Published March 5, 2008 as Technical Note 08-08.
- Targets 4D Developer v11 on Mac & Win.
- Author: Luis Pineiros, Technical Services Team Member, 4D Inc..

## Featured Technology
- 4D v11 SQL Component Architecture
- 4D Components (plugins/reusable modules)
- Legacy vs. modern component comparison

## Historical Context
This documents a genuine architectural turning point for 4D's component system, and the core concept of 4D Components as a distribution mechanism for reusable code is still very much alive today; however, the specific v11 SQL-era component format and creation process described has since been superseded by further evolutions of the component/plugin architecture in subsequent 4D versions.

**Status:** superseded

**Related updates:**
- 4D's component architecture has continued to evolve significantly since v11 SQL, including compiled component changes and, later, the ability to build components in Project Mode (2018+)
- Modern 4D component distribution also increasingly involves ORDA-aware components and the 4D package/dependency model
