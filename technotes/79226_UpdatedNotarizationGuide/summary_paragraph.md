This Tech Note updates 4D's Mac notarization guidance because Apple stopped accepting apps notarized with `altool` or Xcode 13 and earlier as of November 1, 2023, requiring developers to switch to the `notarytool` command-line utility. Notarization is required whenever a 4D app is built/engined on macOS, distributed over the internet, and intended to run on another Mac (interpreted/compiled databases distributed via USB or LAN are exempt). The note walks through the prerequisites — enrolling in the Apple Developer Program, generating an app-specific password via the Apple ID account page, and creating/importing a "Developer ID Application" signing certificate through Keychain Access' Certificate Assistant and the Apple Developer certificates portal — then shows how to store Apple ID, Team ID, and the app-specific password securely in the keychain with `xcrun notarytool store-credentials`. The actual workflow becomes a short sequence of terminal commands: build and archive (ZIP/DMG) the app, submit it with `xcrun notarytool submit ... --keychain-profile ... --wait` and monitor its Accepted/Invalid status, pull the JSON log with `xcrun notarytool log` to check for warnings even on success, then staple the notarization ticket onto the extracted app with `xcrun stapler staple` so Gatekeeper can validate it offline before final re-archiving and distribution. The author frames this as functionally similar to the older `altool`-based process but consolidated into fewer, keychain-integrated commands, making it straightforward to script and automate as part of a release pipeline.
