This 2003 Tech Note by Kent Wilbur (Manager, Information Systems, 4D, Inc.) tackles the problem of synchronizing data between two 4D databases whose table/field structures differ and may change over time, while keeping the connection secure. Rather than publishing a WSDL that exposes individual fields as SOAP parameters (which the author considers a security risk and inflexible when structures change), the sample Server/Client databases pass everything through a single undocumented SOAP entry point, SERVER4D_ConnectFromRemote, which accepts one BLOB in and returns one BLOB out. Each connection begins with a four-element Connection Validation Array (store ID, user name, password, requested function) packed into the BLOB via VARIABLE TO BLOB, and the server rejects anything that doesn't match, returning descriptive errors through SEND SOAP FAULT. To avoid hard-coding field order, the client can request a 'common vocabulary' — the server returns the exact array layout it expects (e.g., ReadCustomersArrayFormat) via a stored choice list, so field additions/reordering on the server don't break the client. BLOBs are optionally compressed with COMPRESS BLOB/EXPAND BLOB, and the note describes (without fully implementing) end-to-end encryption using GENERATE ENCRYPTION KEYPAIR with per-side public/private key pairs. The note closes with practical throughput notes (10,000+ records per BLOB on a LAN, ~25 over dial-up) and positions the whole approach as more secure and maintainable than exposing per-field SOAP calls.
