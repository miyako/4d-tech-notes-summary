This Tech Note (TN 01-37, 4D v6.7, Mac & Win, published August 31, 2001) by Steve Hussey, CEO of Alto Stratus LLC, presents a technique for attaching multiple addresses to records in several unrelated tables (Contact, Doctor, Staff, etc.) using a single shared Address table and no 4D relations at all. Each parent table has a unique, indexed ID field (Contact_ID/etc.), and the Address table carries two key fields -- Table_ID (the numeric table number of the owning parent table, obtained via Table($1) on the form's own table pointer) and Contact_ID (matching the parent record's ID) -- so a query for a given parent record's addresses is simply QUERY([Address];[Address]Table_ID=...;*) combined with the matching Contact_ID. The ADRS_Ld, ADRS_Add, and ADRS_Cnt project methods handle loading, adding, and counting address records for whichever parent form calls them, and the address subform, plus its Add/Delete buttons, is reused unmodified across the Contact and Doctor detail forms; notably, the Delete Subrecord automatic action still works on the subform's currently-selected record even though no formal relation exists, because 4D tracks the current record of any active selection. Hussey notes this same relationless polymorphic-linking pattern generalizes cleanly to other repeating child data like email addresses, phone numbers, or to-do items attached to multiple different parent tables.
