This technical note builds a fully native encoded-image generator (barcodes and QR codes) on top of 4D View Pro's SpreadJS-based barcode formula functions (e.g., BC_QRCODE, BC_EAN13, BC_EAN8, BC_CODE39, BC_CODE93, BC_CODE128, BC_GS1_128, BC_CODE49, BC_PDF417, BC_DataMatrix), which normally require inserting a formula into a spreadsheet cell with many positional parameters for color, quiet zones, and label styling. To make this practical for general application use, the author designs a thirteen-class hierarchy: a generic `_VP_Barcode_Base` class holding shared properties (Value, Color, BackgroundColor, QuietZone_*) and image-generation logic, a `_VP_Barcode_Subbase` class extending it for the label-related properties common to all 1-dimensional barcode formats, and eleven concrete per-format classes (VP_QRCode, VP_DataMatrix, VP_PDF417 extending the base directly for 2D formats; VP_Barcode128, VP_Barcode39, VP_Barcode93, VP_Barcode49, VP_Barcode_EAN13, VP_Barcode_EAN8, VP_Barcode_GS1_128 extending the sub-base for 1D formats) that expose the format-specific attributes via simple object properties (using an underscore prefix to hide internal helper properties from the method editor's autocomplete). Under the hood, the implementation drives a 4D View Pro document that is run in an offscreen web area (via `VP Run offscreen area` and the `On VP Ready` event) so no visible form is needed, inserts the appropriate barcode formula programmatically, and then uses 4D Web Area JavaScript commands (`WA Evaluate JavaScript`, `WA EXECUTE JAVASCRIPT FUNCTION`) to extract the rendered result and return it as a native 4D Picture via each class's `generateImage()` function. The result is that generating a QR code can be as short as `cs.VP_QRCode.new("Hello World").generateImage()`, with any additional formatting done via simple property assignment (e.g., `.ShowLabel := True`, `.Color := "#FFFFFF"`). The note ships an example database with a full UI for exploring every barcode format's parameters, and positions the whole feature as modular (pick only the classes/formats needed), portable (drop into any database as classes), and simple (one-line generation), suitable for inventory/product management, badges, invoices, or tickets, while noting practical caveats such as format-specific value-length requirements and 4D text-size limits on very large generated images.
