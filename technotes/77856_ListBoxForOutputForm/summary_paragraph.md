This Tech Note by Sara Nakkach makes the case for replacing 4D's traditional Output form (built on the List form type) with the List Box form object, tracing List Box's evolution from its 4D 2004 debut as an array-only object through v11's addition of field/expression-based columns and current-selection/named-selection data sources. It argues that List Box is a superior choice for displaying and navigating large data sets because it provides many automatic UI features out of the box — automatic column sorting when a header is clicked, movable and resizable columns, and other built-in interactive behaviors — that would otherwise require custom coding in a traditional Output form. The note also covers dynamic control of List Box via the 4D Language, showing how developers can programmatically manipulate columns, selections, and behavior at runtime. The bulk of the document is a step-by-step conversion guide walking a developer through transforming an existing List-form Output form into an equivalent List Box-based form, covering the practical mechanics of the migration rather than just the conceptual benefits. It closes with a conclusion summarizing the advantages gained. Aimed at developers still using legacy Output forms, the note functions as a modernization guide encouraging adoption of a more powerful, already-mature 4D UI component, and its guidance holds up well since List Box remains a first-class, actively used object in current 4D form design.
