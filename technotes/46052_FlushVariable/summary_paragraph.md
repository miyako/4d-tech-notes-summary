This Technical Note is a special nostalgia reprint, republished on April 1, 2007 with a foreword from then-4D Inc. president/CEO Brendan Coveney marking the company entering its 21st year of publishing Tech Notes (and joking that over a thousand notes had been published since this very first one). The original note, "The Flush Variable" (Technical Note 001), was written by Samir Arora in March 1987, revised by Scott Knaster in August 1987, and describes a special system variable called Flush that could be used to speed up 4th DIMENSION's disk operations on classic Macintosh systems. Normally, 4th DIMENSION forced the Macintosh File Manager's disk buffer to be flushed to disk after every record save to maximize data reliability in the event of a crash, but this came at a performance cost; setting Flush to zero (from its default of 1) let the buffer accumulate and only flush when full or explicitly reset, trading crash-safety for a claimed two-to-three-times speed improvement, particularly useful when importing large numbers of records. The note lists the specific classic-4D routines affected by the Flush setting (ADD RECORD, SAVE RECORD, IMPORT SYLK/TEXT/DIF, MODIFY SELECTION, APPLY TO SELECTION, DELETE RECORD/SELECTION/DOCUMENT, SAVE LINKED/OLD LINKED RECORD, SAVE VARIABLE) and provides a sample procedure that sets Flush:=0 before a batch of RECEIVE RECORD/SAVE RECORD calls and restores Flush:=1 immediately afterward, with an explicit warning to use the technique only for special bulk operations given its data-loss risk. Even at the time of its 2007 republication, the note is explicitly flagged as not applicable to current 4D versions and presented purely "for the nostalgia." Featured technology is entirely the classic 4D/Macintosh File Manager buffering model and the Flush system variable that controlled it, illustrating just how far 4D's underlying storage engine has evolved since the platform's earliest days in the late 1980s.
