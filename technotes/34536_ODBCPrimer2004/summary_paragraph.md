Written by Jamras Komoncharoensiri of 4D, Inc., this Tech Note is an introductory primer covering what ODBC is, how its driver/data-source architecture works, and how 4D 2004's newly native ODBC support builds on the pre-existing 4D ODBC plug-in (available since 4D v6.0). It explains the two common ODBC access models -- direct file-based access (Model 1, e.g. an Excel or Access file) versus DBMS-mediated access (Model 2) -- and covers setting up a data source through the ODBC Data Source Administrator on both Windows and Mac OS X, noting that Mac OS X ships with no default ODBC driver and typically requires a third-party one. It documents the revamped User-environment Import/Export dialogs that can target an ODBC source directly, then details the full 4D 2004 native ODBC command set under the "External Data Source" theme (ODBC LOGIN, ODBC LOGOUT, ODBC SET/GET OPTION, ODBC EXECUTE, ODBC End selection, ODBC LOAD RECORD, ODBC CANCEL LOAD, ODBC SET PARAMETER, ODBC GET LAST ERROR, ODBC IMPORT, ODBC EXPORT), with worked code examples showing SELECT statements bound to 4D arrays or directly to fields, and INSERT statements built either with array binding (`<<arComID>>` style tags) or field binding (`<<[Company Info]Company_ID>>`). It closes with a handful of practical SQL tips (using `*` for all columns, `SELECT COUNT(1)`, `DISTINCT`) for developers new to writing SQL against an ODBC source from 4D.
