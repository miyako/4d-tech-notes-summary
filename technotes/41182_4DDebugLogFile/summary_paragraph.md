This Tech Note by Hugo Fournier documents the 4DDebugLog.txt file, a debugging feature introduced in 4D version 2004.3 that lets 4D Server, 4D Client, and 4th Dimension record a sequential, timestamped log of programming-level events for post-mortem troubleshooting of crashes or intermittent bugs that resist normal breakpoint debugging. Logging is enabled per-application via `SET DATABASE PARAMETER(34;Option)`, with Option 0 disabling logging (the default), 1 enabling basic recording, and 2 enabling a detailed mode that additionally captures plug-in area events and externCall invocations, useful for example when diagnosing drag-and-drop interactions between 4D View areas. Recorded entries include elapsed milliseconds since file creation, process number, executed 4D commands and plug-in calls (with stack depth), and calls into project, object, and form methods; each event is written before it executes so the log survives even an unexpected application quit. The log file itself is placed next to the database structure file for 4D Server/4th Dimension, or in the 4D Preferences folder for 4D Client, and it is truncated and rewritten each time the application launches, remaining locked until the application quits or logging is explicitly disabled. Because continuous logging degrades performance and can quickly fill disk space, the note explicitly states it should never be enabled in production, and instead presents a companion technique: a monitoring process (`M_Monitor_Process`), started from `On Startup`/`On Server Startup`, that polls the log's size every 60 seconds via `DELAY PROCESS`, and once it exceeds roughly 500KB, briefly disables logging, renames/archives the current log with a date-and-time-stamped filename via `MOVE DOCUMENT`, re-enables logging to start a fresh file, and prunes older archives so that no more than five are retained at once. The note walks through the exact `On Startup`, `On Exit`, and `M_Monitor_Process` method code needed to install this rotation scheme in a 4D Client, 4D Server, or standalone database. Featured technology centers on the low-level `SET DATABASE PARAMETER` selector 34 debug-logging mechanism and a hand-built process-based file rotation/archiving pattern using interprocess variables, `DELAY PROCESS`, and `MOVE DOCUMENT`/`DELETE DOCUMENT`. As a 2006 note tied to 4D 2004.3's diagnostic internals, it reflects an era well before 4D's SQL engine, Project Mode, or more modern structured logging tooling existed.
