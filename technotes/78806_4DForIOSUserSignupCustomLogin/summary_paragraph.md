This Tech Note builds a sample iOS recipe-book app ('DishDoc') using 4D's now-discontinued native mobile app generator, 4D for iOS, focusing specifically on user account management: signup and custom login. The backend schema links a Recipes table to a Users table via a userID many-to-one relation, storing not the user's raw password but a password hash in a `pwhash` field, and explicitly disabling 'Expose as REST resource' on the entire Users table/fields to keep credentials out of the mobile app's REST surface. In the Mobile Project editor, the Recipes table's fields (excluding ID/userID) are published, a Data-section filter query (`user.email = :userEmail`) restricts each user to their own recipes, and the `On Mobile App Authentication` database method captures the authenticated request's email, looks up the corresponding Users entity, and returns a `userInfo` object (userEmail, userID) used by later per-request logic; the `On Mobile App Action` method then reads `$request.userInfo.userID` to correctly attribute newly created recipes (via an `addRecipe` project method calling `ds.Recipes.new()`, mapping request parameters onto the entity, then `.save()`). Separately, a plain HTML signup form (served via `WEB SEND FILE` from an `On Web Connection` case for a `/signup` route) posts to a `/4DACTION/processForm` project method that parses, validates, and — per the note's description — securely hashes and stores new users' credentials, completing the account-creation loop that feeds into the custom login. While the specific delivery vehicle (4D for iOS) is gone, the underlying security and REST-filtering patterns remain broadly applicable to any authenticated ORDA/REST-backed app.
