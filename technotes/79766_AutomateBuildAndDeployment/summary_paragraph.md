This Technical Note (25-07, published July 24, 2025, applying to 4D v20 R project-based applications on Windows) introduces Build4D, a 4D component (available since 4D v19 R3, versioned to track 4D releases and hosted on the official `4D-depot/Build4D` GitHub repository) that replaces manual, menu-driven builds with fully scripted, repeatable build automation. Build4D is installed into a project's `Components` folder (interpreted `.4dbase` or compiled) and exposes its functionality through a set of classes in the `cs.Build4D` ClassStore — `cs.Build4D.CompiledProject` (for `.4dz` compiled structures), `cs.Build4D.Component` (reusable `.4dbase` components), `cs.Build4D.Standalone`, `cs.Build4D.Server`, and `cs.Build4D.Client` — all extending a shared `_core` class and exposing a common `build()` method. Each class is configured via a settings object with parameters like `projectFile`, `sourceAppFolder`, `destinationFolder`, `buildName`, `IPAddress` (for wiring client builds to a server), `versioning`, `appShortVersion`, and `iconPath`, and the note walks through worked code examples for each build scenario (e.g. instantiating `cs.Build4D.CompiledProject.new($settings)` and calling `.build()` to produce a `.4dz`, or `cs.Build4D.Component` to produce a distributable component while excluding development-only files). The second half of the note connects Build4D to CI/CD: it explains GitHub Actions fundamentals (triggers, jobs, steps defined in `.github/workflows/*.yaml`) and introduces `tool4d.exe`, 4D's headless command-line utility (`--startup-method`, `--build`, `--compile`, `--check`) for running builds or 4D project methods without the GUI. A full worked demo shows pushing a 4D project to GitHub, configuring a self-hosted Windows runner, and creating two GitHub Actions workflows — a "Compile" workflow (triggered on push, running a `compileMethod`) and a "Build" workflow (triggered manually, running a `buildMethod`) — capturing logs to detect success/failure (including a real example of a `tool4d.4DRT [-10716]` error and its resolution). The note positions Build4D as the key enabler for bringing modern DevOps practices — consistent, unattended, auditable builds — into 4D application delivery.
