Written by Tai Bui of 4D Inc. in September 2016 for 4D v15.2, this tech note addresses a common query-UI need — letting users select a minimum and maximum value together, such as a price range on a shopping site — that 4D's built-in single-value slider doesn't directly support, and shows how to build a custom two-handle range slider entirely from native 4D form objects with no third-party resources required. It first explains the general concept of sliders (a track representing a value range plus a draggable handle indicating position) and range sliders specifically (two sliders on one track, narrowing a selection to a min/max pair), contrasting simple sliders used for things like volume/brightness control against range sliders more suited to search/filtering scenarios. The design section breaks the component into three parts — the static track (optionally labeled at intervals) and the two draggable slider handles — and the implementation section covers building the visual components (track and handle graphics), laying out the form, and writing the code and methods that handle drag interaction, constrain each handle so the minimum handle cannot cross the maximum handle (and vice versa), and expose the resulting min/max values to the rest of the application. The note packages the result as a reusable sample database and component, with a section explaining how to reuse the component in a different database. Because this technique relies purely on fundamental 4D form objects, drag-handling logic, and method code — none of which is tied to any deprecated 4D subsystem — it remains fully functional in current 4D versions and is a reasonable reference for classic-form UI work. That said, for teams building web-facing 4D applications today, an equivalent range-slider control is readily available as a standard HTML/CSS/JS component (or a Qodly-hosted widget), making a hand-built classic-form implementation less commonly the first choice for new web-oriented projects.
