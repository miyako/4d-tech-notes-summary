Written by Stephanie Robineau of 4D's Technical Note Department, this short Tech Note explains the processing of form events in 4D and demonstrates a generic event-trapping method that, when applied to forms and objects, lets a developer observe and control the order in which events execute during deployment. The included sample database provides a "Test" window where the user selects which object types and which specific events to monitor (with a Shift-click shortcut to select/deselect all), plus a Test Mode pop-up offering three scenarios: Add/Modify Records, Dialog, and Print record. Running the test opens a floating palette that logs each event as it is executed (new events appended to the top of the list) alongside the window containing the selected test objects, letting the user interact with those objects and watch how the event list grows and differs between modes -- notably, events differ between Add/Modify Records and Dialog modes, and the Print record mode additionally triggers a print dialog and updates the palette with printing-related events, with an option to print the palette's contents. The "Display record" mode was intentionally left out of the demo because only the On Load event fires there, and only for the main form. The author closes by noting the same event-trapping technique can be applied to database triggers as well as form/object events.
