This Tech Note surveys the practical options available in 4D v6 for importing data delivered as text documents/files from other programs and platforms, framing the choice of method around the difficulty involved and the nature of the source data. It lists three approaches in increasing order of difficulty: using the Import Manager in User mode (the simplest, most user-facing option), importing through a form using the IMPORT TEXT command (giving developers programmatic control over the import), and importing data at a lower level using the RECEIVE PACKET command (the most flexible but most involved option). The note distinguishes between the two fundamental categories of input files a developer is likely to encounter: fixed-length (fixed-format) files, where each field occupies a predetermined number of characters, and delimited files, where fields are separated by a designated character such as a comma or tab. It frames method selection as depending both on the nature of the incoming data and on how that data needs to integrate with records and relations already present in the target database. As a practical how-to for a perennial developer task — getting external data into a 4D database — the note's guidance on file format types (fixed-length vs. delimited) remains conceptually sound today even though the specific 4D commands and Import Manager UI referenced are era-specific to 4D v6.
