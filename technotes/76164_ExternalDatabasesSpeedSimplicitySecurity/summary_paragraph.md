Charles Vass's Tech Note explores 4D v12's two new SQL commands, CREATE DATABASE and USE DATABASE, which let developers programmatically create and switch to external 4D databases for data segregation. It covers the rules and restrictions around these commands with worked examples, then applies them to a concrete archiving use case: reading a table's structure, creating a matching external database, and moving qualifying records into it via SQL, plus reading them back from the archive later. The note extends the idea into a broader 'Database Sandbox' architectural pattern — segregating data per-user, per-test-runner, or via a partitioning scheme — discussing segregated vs. single data file tradeoffs, implementation notes, and several named variations (Dedicated Database Sandbox, DB Schema per TestRunner, Database Partitioning Scheme). A demo database and changes to a WebAccount component illustrate merging these ideas into a working system, showing default external database selection and access to a sandboxed database per user/context.
