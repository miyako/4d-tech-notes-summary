This Tech Note by David Hartje provides one worked example of configuring and establishing a remote (dial-up) connection between 4D Client and a 4D Server running on Windows NT, using entirely freeware components that either ship with the operating systems or can be freely downloaded. The connection technology demonstrated is Microsoft's Remote Access Service (RAS), configured on the server side, paired with the Windows 95 Dial-Up Adapter/Windows NT RAS on Windows clients and Config PPP/MacTCP/PPP extensions (specifically FreePPP for System 7.5.2) on Macintosh clients, over modem hardware (3Com Ethernet card on the server, US Robotics and Gateway 28.8 modems in the test setup). On the server, the note walks through installing the network card with both IPX/SPX (frame type 802.3, matching other 4D Server machines) and TCP/IP (with a fixed IP address on the same subnet) protocols bound to it, then installing and launching the Remote Access Service setup from the Network Control Panel, configuring the RAS Network Configuration to allow remote connections over TCP/IP and IPX/SPX, recommending a pooled IP address range for dial-in clients, and — due to Mac client authentication quirks — initially setting authentication to "allow any authentication, clear text included" before tightening security later; it also covers launching Remote Access Admin to grant per-user dial-in privileges (noting RAS itself need not be domain-joined). For Windows 95 clients, it details installing the Dial-Up Adapter, configuring matching TCP/IP/IPX protocols, selecting the correct Server Type ("PPP, Windows95, Windows NT 3.5, Internet"), and using the Dial-Up Networking Setup Wizard to create and launch a named connection before finally launching 4D Client — noting that any 4D Server instance not running directly on the Remote Access Server machine will not be visible through the connection Browser and must be hard-coded by address. For Macintosh clients (TCP/IP only — IPX/SPX dial-up was not supported on Mac), it covers installing FreePPP, configuring a direct PPP connection without connect scripts, dialing in, authenticating, and then launching 4D Client, with the same caveat about needing hard-coded server addresses for non-local server instances, plus a note that this connection type is limited to FTP and web access outside of 4D itself. The note explicitly frames its solution as illustrative rather than the only viable approach. As a guide built entirely around 1990s dial-up modem networking, Windows NT 3.51's Remote Access Service, and freeware utilities (FreePPP, Windows 95 Dial-Up Adapter) that have all been long discontinued, this Tech Note's specific instructions no longer apply to any modern remote-access scenario, though the underlying goal of securely reaching a 4D Server from off-site remains a standard IT requirement, now addressed via VPNs, direct internet TCP/IP connections, or REST/ORDA-based access rather than dial-up RAS.
