This Tech Note by Timothy Aaron Penner documents a new capability in 4D v14's Web Area form object: developer access to the WebKit Web Inspector, the same open-source debugging tool built into the WebKit rendering engine that 4D adopted cross-platform starting in v13. Prior to v14, developers had no native way to debug unexpected behavior (slow loads, missing resources, broken JavaScript) inside a 4D Web Area and had to rely on external tools outside 4D's context. The note explains the setup required — enabling the integrated WebKit engine and Contextual Menu on the Web Area in Design Mode, then calling `WA SET PREFERENCE` with the `WA enable Web inspector` flag at runtime before right-clicking to choose "Inspect Element" — and then tours the Inspector's practical uses: the Network tab for diagnosing load-time bottlenecks and missing resources, the Scripts tab for setting breakpoints and stepping through JavaScript, and the Console tab both for live JavaScript evaluation and for receiving `console.log()` output triggered from 4D code via `WA Evaluate JavaScript`. It also flags a deployment consideration: because the Web Inspector's console can enumerate and invoke any 4D method (even ones marked invisible) through the `$4d` object, deployed applications should carefully consider whether end users should retain access to it.
