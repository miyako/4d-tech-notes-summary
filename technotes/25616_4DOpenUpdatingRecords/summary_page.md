## Overview
A Tech Note on using the 4D Open plug-in to update records remotely on a 4D Server, simplified by using two identical database structures.

## Key Points
- Part of a 4D Open series covering adding, updating, and deleting records remotely (all three covered in this batch).
- Uses two identical database structures to simplify table/field number correspondence between local and remote sides.

## Featured Technology
- 4D Open plug-in
- Remote record update

## Historical Context
4D Open was the classic plug-in mechanism for cross-database connectivity before native remote datastore/ORDA capabilities existed; only the short teaser text for this note could be recovered here.

*Note: only the on-page teaser paragraph for this Tech Note could be recovered in this environment; the full PDF/example database is no longer accessible (old format/archive not reachable here), so this summary is necessarily based only on that short teaser text.*

## Historical Commentary
**Status:** Obsolete

4D Open as a distinct plug-in is obsolete; modern 4D applications would use ORDA remote datastores or REST APIs to update records on a remote 4D Server, both of which handle differing/unknown structures more gracefully than the identical-structure assumption made in this note.
