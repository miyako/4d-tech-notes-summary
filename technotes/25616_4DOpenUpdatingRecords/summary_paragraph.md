This Tech Note is part of a small series on using the 4D Open plug-in to perform CRUD-style operations against a remote 4D Server, this installment focused on updating records. It describes a setup using two identical databases running on two different machines, chosen deliberately so the table and field structure is known ahead of time, avoiding the need to first query the remote structure via 4D Open commands. Because the databases are identical, table and field numbers correspond directly between the local and remote sides (e.g., the [Employee] table has the same table number in both), simplifying the 4D Open calls needed to update remote records.
