This Tech Note by Fred Johnson explains how to configure Macintosh and Windows machines running multiple instances of 4D Server so that each instance and its specific corresponding database launch automatically at system startup, providing database administrators with a "turnkey" solution. On the Macintosh side, the note walks through using ResEdit to assign a unique Creator code (e.g., 4D>A, 4D>B, 4D>C) to each Server application along with its matching Structure and Datafile, so that double-clicking a structure alias placed in the Startup Items folder launches the correct paired server instance; it also covers troubleshooting file-not-found errors by verifying Creator codes and alias targets. On the Windows side, since 4D can technically run under Windows 3.1.x but Server is recommended only on Windows 95/NT, the note describes renaming each Server executable (e.g., 4dServ1.exe, 4dServ2.exe), writing a per-instance .bat file that supplies paths to the executable and its structure file, and placing shortcuts to those .bat files in the Startup folder (via Program Manager on NT, or the Start Menu Programs Taskbar Properties dialog on Windows 95). A substantial appendix addresses the deeper networking challenge behind running multiple 4D Server instances on one machine: AppleTalk's ADSP protocol could natively broadcast multiple simultaneous server instances, but TCP/IP and IPX/SPX addresses identify only a single machine, not multiple server processes on it, so 4D Server 1.5.x introduced a Port Number parameter (customized via 4D Customizer Plus editing an Options/.OPT file) to disambiguate instances, requiring 4D Client users to manually "hard code" a server address plus port number rather than discovering multiple instances via the connection Browser. The note closes with troubleshooting guidance for cases where only one server instance is visible, emphasizing that this is expected behavior for TCP/IP and IPX/SPX rather than a misconfiguration. As a system-administration and networking guide tied to classic Mac OS tooling (ResEdit, Creator codes, Startup Items) and now-obsolete network protocols (IPX/SPX, and to a lesser extent AppleTalk/ADSP), its specific mechanics are entirely superseded by modern OS service-management approaches, though the underlying goal of running multiple addressable server instances on one host remains a standard concept in IT administration today.
