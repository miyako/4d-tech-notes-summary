This Tech Note by Gordon Muirhead is part of a series previewing the then-unreleased 4D Version 6 (compatible with "4D V6 Developer Release 1 or later," explicitly subject to change before final release), focusing on three related new features: hexadecimal number display, bitwise operators, and the new BLOB (Binary Large Object) data type. It opens with a positional-numbering-system explainer, contrasting decimal, binary, and hexadecimal notation, and shows that V6 lets developers display a number using a "&x" or "&$" format code (e.g., decimal 26 as 0x1A or $1A), motivating hex as a human-readable, computer-friendly middle ground between verbose binary and abstract decimal. It then introduces V6's new bitwise operators — & (And), | (Or), ^| (Exclusive Or), ?? (Bit Test), >> (Shift Right), and << (Shift Left) — with worked bit-by-bit examples for And, Or, and XOR on 32-bit long integers, and explains that the V6 pointer symbol change to "->" freed up the traditional shift-operator symbols for use. The note explains BLOBs as arbitrarily large (up to 2GB, memory-limited) byte arrays addressable via MyBlob{byteNumber} syntax (zero-indexed), useful for storing anything byte-based — files, sounds, NC machine programs, or arbitrary binary structures — inside a 4D record, and demonstrates reading a disk file into a BLOB via DOCUMENT TO BLOB, then using bitwise operators to decode individual bits within specific bytes (e.g., testing bit 4 of byte 23 to check a furnace-fan status flag). The accompanying example database offers two interactive demo screens (a Hex/bitwise demo and a BLOB decoding demo reading a sample "blobstuff" file), and a code appendix supplies representative methods including Hex_str_to_dec (hex string to decimal conversion), pAndOrXor (demonstrates And/Or/Xor), RightArrow (demonstrates bit shifting tied to a UI control), bBLOBread (reads a file into a BLOB and populates display arrays), and Byte_to_binary_number (renders a byte as a binary string). The note closes by summarizing that V6's hexadecimal display, bitwise operators, and byte-level BLOB access together give developers the tools to store and dissect arbitrary binary object data whose internal structure they understand. As a hands-on language-feature preview for a major, still-in-development version of 4D, most of its core technical content — the bitwise operators, hex display formats, and BLOB byte-array model — proved durable and remains part of the 4D language essentially unchanged today, even though its framing as pre-release "Developer Release 1" documentation and its BLOB-centric approach to binary data are dated relative to modern object/JSON-oriented data handling in current 4D.
