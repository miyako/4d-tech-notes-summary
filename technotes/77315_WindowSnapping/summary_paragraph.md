This Tech Note by Tai Bui recreates the Windows OS "window snapping" feature — automatically docking and resizing a window to half, full, or minimized states via keyboard shortcuts or by dragging it to a screen edge — natively inside a 4D application, since 4D windows did not support this behavior out of the box. It first explains Microsoft's native implementation for context: Windows-key plus arrow-key shortcuts for half-screen/maximize/minimize snapping, and mouse-drag snapping to left/right/top edges, including multi-monitor edge behavior and vertical-resize-to-full-height snapping. The note then presents three distinct 4D implementations, each with different trade-offs demonstrated in separate sample database demos: a simple menu-bar-shortcut-driven snapping method (easiest to implement but ignores form size restrictions and requires assigning a menu to each form), an "adaptive" snapping method using invisible buttons on the form that account for a form's minimum/maximum size restrictions, and a globally active snapping method driven by dragging windows near a special palette window that listens for window movement events, working across all forms without per-form setup but without adaptive size-limit awareness. Each demo is described with its specific capabilities and constraints. The conclusion recaps the trade-offs plainly: the shortcut method is simplest but least flexible, the invisible-button method is most capable but requires the most per-form setup, and the window-manipulation/palette method is the most universally applicable but the least precise, letting developers choose based on their application's needs.
