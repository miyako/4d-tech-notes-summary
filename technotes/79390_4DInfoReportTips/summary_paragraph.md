This technical note is a practical operations guide for the 4D_Info_Report ("Information") component, which generates human-readable snapshot reports of a 4D Server's computer context, application version, settings, and current load, and can run as a stored procedure (via `aa4D_NP_Schedule_Reports_Server`) to produce reports every N minutes (5 by default) for historical monitoring. It walks through progressively more involved integration patterns — from zero-code invocation of shared methods prefixed `aa4D_M_`/`aa4D_NP_` from a remote client, to low-code snippets placed in the "On Server startup" method that check for the component via `COMPONENT LIST`/`Find in array` before launching the scheduler, setting a maximum retained report count, or wiring up host callback methods like `aa4D_M_Host_Attention_Reported`. It then covers efficient analysis workflows: connecting from a remote client via the `aa4D_NP_Report_Export_Display` dialog to browse, compare, or export reports (capped at 6000 latest reports, deliberately throttled to protect Server performance), versus the faster stand-alone mode that parses a local unzipped folder of reports directly — explaining the roles of `Array_profiler.json` (per-session computer/app summary) and `Attention_report.txt` (permanent and contextual warnings such as outdated macOS versions, cache-saturated temp files, or unexpected Server windows). The note details the Graph dialog's polygon types (counted values, memory in MB/GB, and a pink "Attention" severity polygon) and tips like drag-and-drop folder analysis and exporting a parsed folder as a "CompareBlob" for faster reloading. Finally, it presents anonymized real-world support cases — a Windows-only memory leak traced and fixed by 4D, cache saturation causing `.trans`/`.sort` temp files (mitigated via `ADJUST TABLE/INDEX/BLOBS CACHE PRIORITY` and ORDA), stray administration windows slowing the Server, and using report comparison to verify database integrity after a power outage or version conversion — demonstrating how the component supports 4D's technical support and Professional Services teams in diagnosing crashes, freezes, and leaks.
