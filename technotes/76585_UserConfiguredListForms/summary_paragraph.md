This Technical Note by Charles "Charlie" Vass presents a proof-of-concept prototype that lets end users construct and save their own customized output list forms at runtime, taking advantage of the major upgrade the List Box object received in 4D v13. Since 4D v11 SQL introduced the "enhanced" List Box, using it as a replacement for native output list forms had become common practice, but earlier versions limited it to fairly basic selection lists; v13's List Box now supports enough features to fully replace a native list form. The prototype stores each user's list form configuration — including which fields/columns are chosen and their arrangement — in a dedicated LSTFRM_Config table (defined via inline SQL DDL) keyed by user name, browser name, and configuration name, with the actual layout persisted as a BLOB; it also guards against duplicate configuration names per user. The note walks through configuring the underlying List Box object itself (typed variables, "Current Selection" vs. "Arrays" data source, zeroed initial columns to allow programmatic column construction, and manual OBJECT SET RGB COLORS calls for alternating row colors) before covering the surrounding "List Form User Tools" — a List Form Configuration Tool and a Records Selection Tool — plus a List Form Column Formula Editor for building column formulas interactively. The result is a reusable pattern (also packaged for component usage) that developers can adapt to give end users self-service control over how tabular data is displayed within a 4D application, while cautioning that the POC is a starting point rather than a finished, production-ready feature.
