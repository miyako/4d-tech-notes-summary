This Tech Note addresses cross-platform compilation pitfalls that could arise when a 4D database using third-party plug-ins was compiled on a different platform than the one the plug-ins were originally built for — for example, compiling with Windows plug-ins while working on a Macintosh, or vice versa, or even handling plug-ins available for both platforms simultaneously. The note states that this scenario can be handled without problems as long as certain constraints are observed, and it positions itself as a guide to achieving successful, predictable cross-platform compiled results under these mixed-plug-in conditions. This reflects the practical reality of cross-platform 4D development in the mid-1990s: 4D databases could run compiled on both Macintosh and Windows, but third-party plug-ins were platform-specific binaries built against 4D's classic (pre-modern) plugin API, so developers frequently needed guidance on how the 4D Compiler handled such platform mismatches during the build process. Filed under the 4D Transporter product line — itself one of 4D's companion tools from this era — the note targets developers and integrators dealing with multi-platform deployments who relied on plug-ins to extend 4D's native capabilities.
