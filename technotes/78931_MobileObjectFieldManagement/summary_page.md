## Proposition
This note demonstrates using 4D's object-attribute fields inside a 4D Mobile (native iOS/Android app-generation) application, via a sample 'Nutrition coaching' diet-tracking app storing user attributes as object fields. ## Key Points
- **Demonstrates object attribute fields inside 4D Mobile-generated apps**, letting varied per-record attribute sets be modeled without rigid per-attribute table columns.
- **Bundled with a 'Nutrition coaching' sample app**, modeling a diet-program use case (age, gender, goals, weight, height) built to fit each user's needs.

## Historical Commentary
**Status:** obsolete

4D's native mobile app-generation product line (4D for iOS / 4D Mobile) that this note depends on was discontinued; 4D subsequently redirected its mobile/low-code strategy toward Qodly Studio and responsive, ORDA/REST-based web applications rather than generating native iOS/Android binaries directly from a 4D structure. As a result, this note's specific mobile-app-generation workflow is no longer applicable to current 4D development, even though the general underlying concept — using flexible object-attribute fields to model per-record varying data — remains a sound and current data-modeling technique in 4D/ORDA generally, just not via the discontinued mobile pipeline described here.
