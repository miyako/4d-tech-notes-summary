Written by David Adams, this Tech Note explains how 4th Dimension 2004's new GET HTTP BODY command lets developers capture the entire raw HTTP body of an incoming SOAP request -- superseding the older, undocumented technique from Technical Note 04-19 that reassembled requests from GET WEB FORM VARIABLES name/value pairs, which was limited by the 32,000-character text-variable ceiling. It walks through 4D's automatic SOAP-handling model (SOAP DECLARATION binding method inputs/outputs to XML elements) and contrasts it with manual inspection, showing a soap_GetFullRequestAsText/soap_GetFullRequestAsBlob pair of methods built on GET HTTP BODY (with BLOB variants recommended to avoid the text-length limit) plus a GET HTTP HEADER example for the surrounding HTTP headers. A substantial application section demonstrates building a custom SOAP request logger inside the On Web Authentication database method, using DOM Parse XML variable / DOM Get First XML element / DOM GET XML ELEMENT NAME to extract the invoked method name (stripping any namespace prefix) and saving IP addresses, timestamps, user agent, and method name to a Logged_SOAP_Request table. The note closes with a second application: reading SOAP inputs that were never bound via SOAP DECLARATION (illustrating an optional "inRoundTo" rounding parameter for a ConvertFeetToMeters Web service method), useful for distinguishing an omitted input from one explicitly sent with a default value, and for handling evolving parameter lists without needing every input pre-declared in Compiler_Web.
