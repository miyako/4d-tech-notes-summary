This Technical Note introduces the Structure Export/Import feature new to 4D v11 SQL Release 1, enabling database structures to be exported to XML files and reimported to create new databases—a capability useful for template-based database provisioning, structure cloning across environments, and integration with other XML-aware systems. The note provides an extensive XML primer covering syntax rules (root elements, tag nesting, case sensitivity, entity references), Document Type Definitions (DTD) and the concept of well-formed vs. valid XML documents. It explains 4D's XML foundation: Apache Xerces libraries for parsing/manipulation (supporting DOM, SAX, and SAX2 standards) and Xalan libraries for XSLT transformations. The core distinction between DOM (Document Object Model, which loads the entire XML tree into memory for random access, suitable for small-to-medium files) and SAX (Simple API for XML, which streams elements one-at-a-time, memory-efficient for large documents) is clarified with practical guidance: DOM is recommended for typical cases; SAX for large XML files where memory is constrained. XPath notation is explained as the primary method to navigate and access XML elements (e.g., /root/element1/element2/element3). The Structure Definition XML format is then documented, including its top-level elements (base, table, field, index, relation) and their attributes, metadata (field_extra, table_extra, editor_*_info), and structure-level annotations (journal_file, base_extra). Crucially, the note emphasizes that a Structure Definition file contains schema only—no data—making it unsuitable as a backup mechanism but valuable for structure cloning and interoperability. The note also describes how XSLT can transform Structure Definition XML for advanced use cases (e.g., converting to documentation, migrating to other database systems, or generating code templates)."
