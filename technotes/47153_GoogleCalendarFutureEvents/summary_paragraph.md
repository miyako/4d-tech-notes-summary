This Technical Note shows how to interface 4th Dimension with the Google Calendar API to download and display a user's future calendar events inside a 4D database, using 4D Internet Commands (4DIC) to make raw HTTP requests since no official 4D client library for Google's API existed. It explains the underlying technologies: XML as the data exchange format, HTTP for transport (built and parsed manually with 4DIC), REST as the architectural style for URL-based data exchange, and GData (Google Data API) — Google's Atom/RSS-based protocol for reading and writing service data — noting that GData does not support feed deletion (only querying for deleted feeds to sync). The core workflow has three steps: Authentication via Google's ClientLogin endpoint (a raw HTTP POST to /accounts/ClientLogin with Email, Passwd, service="cl", and source parameters, built with explicit "\r\n" CRLF control characters per the HTTP 1.0 spec), then requesting the user's Calendar List, then requesting Future Events for the selected calendar(s), each returned as an Atom XML feed parsed with 4D's built-in DOM XML commands. The note walks through the structure of the returned Atom entries (id, links, author, gd:eventStatus, gd:visibility, gd:when start/end times, gd:where location, gd:reminder) to show how event data can be extracted field by field. A bundled sample database provides a login screen and "Sync Calendar List" / "Sync Calendar Event" buttons that drive the authentication and download process end-to-end. As a REST/GData integration example, it complements two companion notes referenced directly: 06-30 "Building a REST Client" and 07-32 "4D Deployment Options for Wide Area Networks." The specific Google authentication scheme (ClientLogin) and the GData protocol itself were both later deprecated by Google in favor of OAuth 2.0 and the modern Calendar API v3.
