Sean Le, a 4D Technical Support Engineer, introduces the 4D for ADO plug-in, which brings Microsoft's ActiveX Data Objects (ADO) interface to 4D 2004 on both Windows and Macintosh, enabling queries against most Windows RDBMSs — MS SQL Server, Oracle 8i/9i, Sybase ASE, MS Access, and others — plus ADO.Net-reachable sources like LDAP directories. He explains the two underlying access layers ADO can ride on: ODBC (Microsoft's original standard, requiring a Driver Manager plus a per-database ODBC Driver, configured via the ODBC Data Source Administrator on Windows or ODBC Administrator on Mac OS X) and OLE DB (a newer, more general COM-based interface that also covers non-SQL data sources), and walks through ADO's three core objects — Connection, Command, and Record Set — along with sample connection strings for SQL Server and Oracle under both access methods. The bulk of the note is a practical, code-heavy tour of the plug-in's DBGateway_-prefixed command set: DBGateway_Connect/DBGateway_Close for opening and closing a connection, DBGateway_Execute for running INSERT/DELETE statements (either with values embedded directly in the SQL string or bound via index-tag placeholders and DBGateway_AddTextParameter), and error handling via DBGateway_ErrorCode/DBGateway_ErrorString. For SELECT queries, Le shows DBGateway_Select returning a reference ID, then looping with DBGateway_NextRow and DBGateway_GetTextField (noting sibling commands like DBGateway_GetPictureField and DBGateway_GetBlobField exist for other field types) to populate 4D arrays, closing with DBGateway_CloseSelect once done. The technical note positions 4D for ADO as giving 4D developers a straightforward bridge into the broader Windows RDBMS ecosystem without needing to build custom ODBC/OLE DB integration code themselves.
