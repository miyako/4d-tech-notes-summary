This Technical Note by Larry Sharpe presents a redesigned technique, building on a similar note published by Steve Hussey in November 2000 for 4D v6.0, for building customizable pick lists in 4D applications, addressing the core problem that 4D's built-in structure-stored lists are lost whenever the database structure is updated. The solution stores list data in a new [xLists] table (deliberately prefixed with "x" to sort to the bottom of the table list) containing ListName, SortOrder, and Element fields, with the master list of list names itself maintained as a 4D hierarchical list, and centralizes all maintenance logic in a single Project Method, "xLists", implemented as a Case of dispatcher that handles opening the list editor dialog, saving modified lists (deleting and recreating all [xLists] records for a changed list rather than tracking individual diffs), and building the inter-process arrays used throughout the database at startup. The accompanying "ListEditor" form lets end users add/edit/reorder/delete elements within developer-defined lists (but not create new lists themselves), and the note extends the pattern to a keywords feature via a parallel "People_Keywords" Project Method and form that let a [People] record have zero, one, or multiple keywords attached through a two-list drag-and-drop or double-click interface, with cleanup logic ensuring related [PeopleKeywords] records are deleted when a parent [People] record is deleted. The note explains this "single-method Case of" style as easy to maintain and duplicate: adding an analogous keyword feature for another table (e.g. [CompaniesKeywords]) is framed as a straightforward copy-paste-and-rename exercise. It also demonstrates two simple use cases for single-selection custom lists in the demo — a City popup and a State validation field — both driven by the same [xLists]-backed inter-process arrays. Limitations noted include the lack of icon/image support per list element, which the author suggests could be added with an extra field. The note closes with the author's direct contact information, typical of this era's community-contributed Technical Notes.
