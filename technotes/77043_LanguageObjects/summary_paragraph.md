This Tech Note documents one of the most consequential additions in 4D's history: the introduction of the native `C_OBJECT` language data type in 4D v14, bringing JSON-inspired "objects" (self-documenting property/value structures) into the 4D language itself for the first time. It contrasts objects with the older, opaque BLOB type — where the developer alone must remember how bytes are laid out — noting that an object's contents are transparent and self-describing to anyone with access to it. The note works through the properties that define this new type: values are stored as named items, accessed randomly (not sequentially), fully modifiable, storable inside arrays, capable of holding arrays themselves, and capable of nesting objects within objects. It documents the full initial `OB_` command surface (OB SET, OB Get, OB SET ARRAY, OB GET ARRAY, OB Copy, OB Remove, OB GET PROPERTY NAMES, OB Is defined, OB Get type) alongside command changes needed elsewhere in the language to support objects — including BLOB TO VARIABLE/VARIABLE TO BLOB, VARIABLE TO VARIABLE, SET/GET PROCESS VARIABLE, and new MIME-type support in WEB SEND BLOB/WEB SEND TEXT, HTTP Get/HTTP request, and the WA EXECUTE JAVASCRIPT FUNCTION/WA Evaluate JavaScript web-area commands. It closes with a nine-page example database walking through each command family in turn, and a discussion of how JSON's null/empty value semantics map onto 4D objects — laying the technical groundwork for JSON import/export and, ultimately, for 4D's later object-based data architecture.
