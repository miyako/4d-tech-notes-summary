This Technical Note explains how 4D 2004's new LAUNCH EXTERNAL PROCESS command could be used to access Microsoft Windows COM (Component Object Model) objects directly from a 4D application. It covers the CreateObject macro, part of the 4D Macro Pack, which automates generating the 4D script needed to access a given COM object, and notes that this macro includes an object browser for visually exploring a COM object's available properties before wiring up code against it. By walking through this macro's implementation, the note aims to demonstrate concretely how a COM object can be leveraged inside a 4D-developed application, presumably enabling integration with Windows-native automation targets such as Office applications or other COM-exposed services. The precise code samples, browser workflow, and target COM objects demonstrated are not recoverable here since only the brief on-page teaser (not the full PDF/example archive) was available for this entry. As a Windows-specific integration technique published alongside several other 4D 2004 interoperability notes, it reflects the era's emphasis on making 4D a capable automation hub on the Windows platform specifically.
