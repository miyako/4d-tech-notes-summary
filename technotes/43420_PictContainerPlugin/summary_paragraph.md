This Tech Note by Thomas Maul introduces the PictContainer plug-in, which provides 4D 2004 developers with enhanced picture-handling capability beyond 4D's built-in picture fields — supporting reading, writing, and displaying images with scroll bars and zoom, and shipped with its full C source code and a demonstration database. On Mac OS the plug-in uses Apple's QuickTime API (preinstalled and the platform's preferred image library at the time), while on Windows it uses Microsoft's GDI+ API (preinstalled on Windows XP and 2003, with a DLL that can be shipped alongside the 4D application for older systems), a choice made partly because GDI+ offered better handling of damaged pictures than QuickTime would have on Windows. The plug-in automatically shows or hides scroll bars depending on the picture size, available display area, and current zoom setting, and supports drag-and-drop of pictures to and from 4D picture variables, fields, and scrollable areas (including 4D list boxes), with additional drag targets supportable via custom programming. It documents platform-specific format support: on Mac OS all QuickTime-readable formats (PICT, BMP, GIF, JPG, PNG, TIFF, Photoshop, etc.) are supported for reading, though writing is limited to converting documents into Macintosh pictures (matching 4D's own picture commands) or explicitly to BMP, JPG, PNG, and uncompressed TIFF; on Windows, BMP, GIF, JPG, PNG, TIFF, EMF, WMF, and ICO are supported for reading, with BMP, GIF, JPG, PNG, and TIFF for writing. The bundled example database ("PictContainer.4DB") demonstrates loading images from disk, zooming to 100%/400%, and dragging images between the PictContainer area, a 4D picture variable, and a 4D list box, and notes that the 4D Pack plug-in must also be installed to use PictContainer on Windows. This note is aimed at 4D 2004 developers who need a more capable, interactive picture-display control than 4D's native offerings provided at the time.
