This Tech Note by Jean-Yves Fock-Hoon (QA Manager, 4D, Inc.) traces how sending a Set (a bit-per-record record selection) from one 4D Client to others got progressively easier across 4D versions, culminating in 6.7.x. In 4D 6.0.x, a client had to save the set as a document, load that document into a Blob variable, and transmit the Blob via `GET PROCESS VARIABLE`/`SET PROCESS VARIABLE` or `Execute on Server`, with each receiving client re-saving the Blob back into a document before reloading it as a set; 6.5.x's `REGISTER CLIENT`/`EXECUTE ON CLIENT` commands identified which clients to update but didn't remove the temporary-document step. 4D 6.7.x introduced `CREATE SET FROM ARRAY` and `BOOLEAN ARRAY FROM SET`, letting a set be converted directly to/from a Boolean array (one bit per record) that is then stored in a Blob via `VARIABLE TO BLOB` and broadcast with `EXECUTE ON CLIENT("@";"SERVER_Update_Client_Requested";BlobF;BlobG;BlobH)` — using "@" to target all clients, or looping over `GET REGISTERED CLIENTS` for a specific subset. The receiving method reconstructs the Boolean arrays with `BLOB TO VARIABLE` and recreates interprocess sets via `CREATE SET FROM ARRAY([People];A_SetF;"<>SetF")`, then calls `CALL PROCESS(<>CurProcNum)` to notify the main process to refresh its display, entirely avoiding temporary filenames and document I/O.
