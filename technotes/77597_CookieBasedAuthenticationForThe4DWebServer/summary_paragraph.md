This Tech Note tackles a recurring limitation of 4D's built-in Web Server authentication: while 4D supports Web Passwords using BASIC or DIGEST HTTP authentication, neither option allows customizing the login dialog's appearance nor lets a user log out of a session without closing the browser window. The note proposes and demonstrates a cookie-based authentication system built on 4D's Automatic Session Management feature, giving developers full control over login/logout UX. The accompanying sample application uses a Bootstrap-enabled website with a styled login form, a user-creation page featuring Ajax-based username-availability validation, an account-modification page, salted password storage/validation, and explicit mechanisms for invalidating sessions to support remote logout. Sections cover HTTP session handling (validating sessions, handling login/logout, invalidating sessions), a full web user-management workflow (creation, updates, password validation), and protecting pages behind authentication. Because the note builds directly on 4D's HTTP session/cookie primitives rather than any UI-framework-specific approach, its core session-handling and salted-password patterns remain broadly applicable today, though the specific coding idioms (classic 4D Web Server code, Bootstrap-based front end) reflect the pre-REST/pre-Qodly era. Any modern 4D web app using ORDA + REST or newer front-end approaches (e.g., Qodly, SPA frameworks) would implement authentication quite differently, e.g., via token-based auth, so this note today serves best as a reference on the underlying session/cookie mechanics rather than a drop-in modern implementation.
