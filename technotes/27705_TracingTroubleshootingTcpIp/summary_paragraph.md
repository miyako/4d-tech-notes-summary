Written by David Adams, this Tech Note addresses a gap the 4D Debugger cannot fill: diagnosing problems in the TCP/IP network layer itself, relevant to 4D Web systems, 4D Web Services, integrations with other web servers like IIS or WebSTAR, custom TCP/IP code (email, FTP), and 4D Server client-connection issues. It leans on OS X's BSD Unix heritage to introduce the Terminal as the gateway to a wealth of free, powerful network tools, walking through installation paths (pre-built package installers, the OSXGNU project, Fink for tools like Ethereal, or compiling from source via the Apple Developer CD) and covering built-in commands like ping, traceroute, whois, and nslookup. A substantial "fundamentals" section defines addresses, ports (including OS X's restriction of ports below 1024 to root, and the recommended fix of using the ipfw firewall to forward port 80 to a high port like 8080 without running as root), interfaces (including the lo0 loopback for same-machine program-to-program tracing), DNS, DHCP, and the distinction between session-oriented and request/response protocols. It then works through specific tools in depth: ping and nslookup for connectivity/name-resolution checks, netstat for connection lists and interface configuration, traceroute for route discovery, and whois for domain registration lookups, followed by a packet-capture section contrasting the low-level tcpdump with the higher-level, stream-reassembling tcpflow, and the graphical analyzers EtherPeek (commercial) and Ethereal (free but X11-dependent on OS X). The note closes with practical tips for tracing same-machine 4D-to-web-server integrations (FastCGI, 4DLINK, 4DCONNECT, ISAPI) via the loopback interface and for using multiple bound IP addresses to separate traffic between concurrently running services.
