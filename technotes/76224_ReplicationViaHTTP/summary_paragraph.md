Written by Rudi Psenicnik, this Tech Note explains how 4D v12's new REPLICATION and SYNCHRONIZATION SQL commands can mirror data between a local 4D database and virtually any remote platform — from mobile devices to desktop servers — using HTTP requests and JSON notation as the transport. It clarifies that unlike automatic 4D-to-4D replication, HTTP-based replication requires the developer to write their own complete remote database client or server, making it a powerful but decidedly not out-of-the-box solution. The note walks through the replication process conceptually (sending record updates/deletions per table since the last sync), defines key terminology, and documents the specific HTTP calls needed to implement a working remote endpoint. It closes with a conclusion recapping the design tradeoffs of rolling a custom replication bridge versus relying on 4D's built-in synchronization. The note is squarely aimed at integrators needing to sync 4D data with non-4D systems such as early Android/iPhone apps.
