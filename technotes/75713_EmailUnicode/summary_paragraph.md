This Tech Note explains how, starting with 4D v11 SQL, developers can send and receive e-mails in a wide range of languages and character sets with relative ease, since 4D v11 SQL's Internet Commands now operate natively in Unicode and can convert to/from many character sets regardless of the system's language — a marked improvement over prior versions, which were largely limited to US-ASCII/ISO-8859-1 (plus automatic Japanese support) and otherwise required workaround tricks like changing the system language. The note builds up the necessary background carefully: why e-mail messages need encoding at all (the 7-bit US-ASCII legacy of the original protocol), and the main encoding techniques used to work around that limitation — Quoted-Printable (for mostly-Latin text with occasional special characters), base64 (for scripts that rarely use Latin characters, such as Chinese, Korean, or Japanese), and direct 7-bit/8-bit transmission. It then covers the structure of an e-mail message (IMF and MIME), how headers and bodies are each encoded, the specific encoding and decoding capabilities (and limitations) of 4D Internet Commands' Setprefs/Charset settings and UTF-8 support, worked encoding/decoding examples for both base64 and Quoted-Printable, a rundown of which text conversions 4D v11 SQL supports versus which encodings remain unsupported, and guidance on dissecting multipart-content e-mails. The note concludes with a walkthrough of the bundled 4D Email Tools component, demonstrating sending, receiving, editing, and viewing messages with full Unicode support.
