This Tech Note, written by Jean-Yves Fock-Hoon (QA Manager, 4D, Inc.) for Technical Note 04-02, demonstrates how to use 4th Dimension 2003's newly introduced native SOAP support to let one 4D database interact with another as an alternative to the 4D Open for 4D plug-in and its always-on TCP connection. The technique creates a persistent server-side process per client session, identified by a connection ID returned from an `s44D_NewConnection` SOAP call, which sits in a paused loop and wakes up whenever a Web service pokes a `CodeAction` variable via `SET VARIABLE PROCESS`/`VARIABLE TO VARIABLE`, then executes the corresponding 4D command before pausing again. Around thirty `s44D_*` Web services are implemented and documented, covering record navigation (`FirstRecord`, `LastRecord`, `GotoSelectedRecord`), CRUD operations (`CreateRecord`, `UpdateRecord`, `DeleteRecord`, `DeleteSelection`), set operations (`CreateSet`, `CopySet`, `Difference`, `Intersection`, `Union`, `IsInSet`), named selections (`UseNamedSelection`, `CutNamedselection`, `CopyNamedselection`, `ClearNamedSelection`), and structural introspection (`GetAllTableNames`, `GetTableProperties`, `CountTables`), each paired with a client-side proxy method generated from the server's WSDL. It also covers `ArrayToSelection`, which reconstructs 4D arrays from a blob payload for bulk data transfer. The author is explicit that the goal is not to replace 4D Open for 4D but to offer a viable alternative, and cautions that these SOAP-driven processes never time out on their own, so implementers must build their own idle-session cleanup using a background process and a timestamp check. The example database ships both the server-side and client-side (proxy) source components along with a demo interface for testing table listings, record creation, and set/named-selection operations.
