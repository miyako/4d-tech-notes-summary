This Technical Note (25-11, published November 29, 2025, requires 4D v20 R10+ in project mode) demonstrates inter-user TCP communication using 4D's modern `TCPListener` and `TCPConnection` classes, which replace the deprecated legacy TCP commands and the 4D Internet Commands plugin. The vehicle is a simplified peer-to-peer messenger application supporting text, images, videos, and arbitrary files (up to a 64MB limit configurable in `input.js`), where every user simultaneously acts as sender and receiver with no central server. A "zMessInput" Web Area handles both message composition and rendering (via `WA EXECUTE JAVASCRIPT FUNCTION` calls into `input.js`/`output.js`/`output.css`), since a web area is the only 4D object capable of displaying mixed rich content types; per-machine preferences (username, encryption key, listen address/port, avatar, referenced "nodes," and named "channels" of recipients) persist to a JSON file under `Data/Messenger/<machineName>.json`, managed by a `Lib_Messenger_Preferences` class. Wire data uses a custom compact binary framing: a 4-byte size, a 32-byte structure hash, then encrypted content (routing code, sender, recipient(s), timestamp, message ID, and a JSON "cargo"), packed/unpacked by a `Lib_Messenger_Net_Request` class's `requestPack`/`requestUnPack` functions; encryption uses 4D's `Encrypt data BLOB`/`Decrypt data BLOB` commands, with an MD5 digest embedded before encryption specifically to detect wrong-passphrase decryption failures (which would otherwise silently produce garbage) and to correctly strip trailing padding after decrypt. On the receive side, `Lib_Messenger_Net_Input.onConnection` validates the connecting address against the configured "nodes" list before delegating to a `Lib_Messenger_Stream` class that accumulates bytes until the declared size is reached, then routes the unpacked request and sends single-byte acknowledgment codes (0x1 for message receipt, 0x2 for an icon-request reply) back to the sender to trigger UI updates. The note positions this dedicated-class architecture (`Lib_Messenger_Net_Input`, `Lib_Messenger_Net_Output`, `Lib_Messenger_Net_Request`) as a template for building resilient, serverless real-time messaging systems on 4D's modern TCP framework.
