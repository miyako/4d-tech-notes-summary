This Technical Note is Part 1 of a two-part series on 4D plug-in development for 4D 2004/v11 SQL, focused on writing plug-ins that are cross-platform, Unicode-aware, and built as Universal Binaries. Author Keisuke Miyako explains why developers write plug-ins (to reach beyond the standard 4D language via open-source libraries or system calls) while cautioning against over-dependence on them. The note highlights substantial API changes introduced in 4D v11 SQL — including Unicode and endianness handling, native picture handling, the retirement of the Altura Mac-to-Windows porting library, and the "sunset of QuickDraw" — that plug-in developers of the era needed to understand. It introduces the Plug-in Wizard for generating Xcode (Mac) and Visual Studio (Windows) project scaffolding, and sets up the theoretical groundwork (with Part 2 promising hands-on examples) for handling text, picture, and numeric data consistently across platforms. Solid C programming knowledge is assumed given the plug-in API's direct memory management.
