Written by Eric Saltzen of 4D Inc. Technical Support, this Tech Note explains how to collect "Referer" information (the URL of the page a visitor came from, per the HTTP header field — misspelled by standard convention) using 4th Dimension's web server, so a site owner can determine which external sites are driving traffic and how visitors navigate internally. It ships two sample databases: 67RefererGrab, published on port 8080 with an index.shtml home page that embeds a `<!--4DSCRIPT/RefererGrabber-->` tag, and 67LinkerSample, serving on port 80 with hard-coded links (via linker.html and sublinker.html) back to 67RefererGrab's home page at the local loopback address, so the Referer mechanism can be tested entirely on one machine. The On Startup database method sets two flags, `<>refererDiagnosticMode` (store the full HTTP header text alongside each hit) and `<>refererLogFile` (also append entries to a "RefererLog" file), while the RefererGrabber project method — invoked automatically whenever index.shtml is served — calls the new 4D v6.7 `GET HTTP HEADER` command to retrieve header name/value arrays, uses `Find in array` to locate the "Referer" and "X-URL" entries (since $1/$2 aren't available inside a 4DSCRIPT context), stores them into an [HTTP_Requests] table, and optionally appends a "referer -> url" line to the RefererLog file with `Append document` and `SEND PACKET` in the same format standard web server logs use, so it can be processed by any log analyzer such as Analog. The note closes by noting that any page wanting referer tracking must include the 4DSCRIPT tag and use the ".shtml" extension so 4D processes its server-side includes.
