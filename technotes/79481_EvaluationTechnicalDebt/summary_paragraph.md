This Tech Note addresses the challenge of assessing technical debt when migrating legacy 4D codebases to 4D 20 LTS/Rx, particularly when the database was developed by a different team, by introducing the "Methods_Statistics" component — compatible with 4D 20.4 LTS on both Intel and Apple Silicon. Installed simply by dropping the component into a host database's Components folder (no code changes required), it exposes two "no code" shared methods runnable via the Run/Method menu: ______Struct_Stats_Dialog, which parses all project methods and collects statistics on legacy patterns — counts of C_xxx-style variable declarations, interprocess variables/arrays (a concurrency risk since they aren't thread-safe), #DECLARE usage, var declarations, class functions (including singleton classes as of 20 R5), and deprecated commands (e.g., _O_ARRAY STRING, _O_C_STRING) — displaying results in an alert with an option to generate a timestamped JSON report and optionally auto-correct/replace deprecated code; and ______Struct_Dialog_List, which produces a sortable list box of all methods (by name, last modification date/time, and code size) with export capability to timestamped .txt files and a summary .csv, useful for tracking recently changed or particularly complex code sections. Both shared methods run only in interpreted mode (with a warning if attempted in compiled mode) and are compatible with remote mode execution, and can be invoked headlessly on 4D Server without an interface. The note positions this component as a practical tool for developers to quantify code quality/complexity, identify refactoring targets, and track migration progress over time via comparable timestamped reports.
