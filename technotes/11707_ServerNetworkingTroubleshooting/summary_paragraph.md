This Tech Note provides an overview of networking fundamentals and troubleshooting practices for 4D Client and 4D Server connections in 1996. It opens by defining the three popular desktop networking protocols of the era — ADSP (AppleTalk Data Stream Protocol, Apple's native Mac networking), TCP/IP (the Internet's protocol, using unique per-node IP addresses), and IPX/SPX (Novell's protocol) — and presents a table of which protocols are natively included with which operating systems (Mac OS, Windows for Workgroups 3.11, Windows NT, Windows 95), noting where third-party add-ons like MacLAN Connect or Novell's NetWare Client are required. It then explains the layered architecture of a 4D Client/Server connection: requests pass from the application through an "ACI Network Component" (a protocol-specific translator), through the OS networking layer, across the wire, and back up an equivalent stack on the server side — with ACI Network Components pre-installed on Mac (installable/removable per-protocol) and delivered as DLLs on Windows (4DNCADSP.DLL, 4DNCTCP.DLL, 4DNCSPX.DLL, plus WATKSOCK.DLL/WIPXSOCK.DLL for Windows 3.1x/WFW). A dedicated subsection covers 4D Remote, described as ACI's own proprietary dial-up networking protocol/component enabling remote 4D Server access without needing AppleTalk Remote Access, available at the time only on the Mac side. The general troubleshooting methodology given is: (1) identify what recently changed in the computing environment, (2) confirm network protocol configurations are intact, and (3) as a last resort, re-install 4D Client/Server software (remembering to re-apply any Customizer Plus memory/settings customizations afterward, since a fresh install reverts to defaults). Platform/protocol-specific tips follow for ADSP (Open Transport on PCI Macs, MacLAN Connect version requirements for Windows), IPX (Frame Type must match between client and server), and TCP/IP (subnet mismatches, router/gateway misconfiguration, using Ping to test connectivity, and the "-10002" timeout error explained as 4D Client giving up waiting for a server response, adjustable via the TCP.OPT file's time-out setting). The note also flags a known Windows 95 TCP memory leak (with a Microsoft "Kernal32 Update" patch) and notes that corrupted .opt preference files can cause 4D Client to freeze on launch. Featured technology centers on 4D's ACI Network Component translation layer atop ADSP, TCP/IP, and IPX/SPX, plus the proprietary 4D Remote dial-up protocol.
