Written by Cha Yang of 4D Technical Support, this Tech Note demonstrates the new cross-tab mode of 4D 2003's Quick Report editor -- now an internal plug-in with its own "QR" command set for procedurally reproducing anything the interactive editor can do -- using a sample database of 23 fictitious students taking exams in four subjects. It explains the relational structure needed for a good cross-tab report (Student, Subject, and Exam tables linked by one-to-many and many-to-one relations) and how 4D propagates a selection from a parent table down into and back up from related child tables when the report runs. Two complete sample methods are walked through in detail: `RunCrossTab_PerClass`, which builds a per-student, per-exam average-score report for a chosen subject, and `RunCrossTab_FinalGrade`, which computes a weighted final grade across all four subjects by multiplying each exam's grade by its assigned weight. Both use the same three-step recipe: define the parent-table selection (via query plus relate-many, or `ALL RECORDS`), bind three data sources to columns 1–3 with `QR SET INFO COLUMN` (column/row titles and the calculated cell value, often a formula like `[Exam]Grade*[Exam]weight`), and configure subtotal/aggregate calculations per cell with `QR SET TOTALS DATA`. The note also shows `QR SET HEADER AND FOOTER` and `QR SET TEXT PROPERTY` for report presentation, and stresses that because the join-style relation propagation excludes any parent record lacking matching child records, a student with no exams for a subject simply will not appear in that report.
