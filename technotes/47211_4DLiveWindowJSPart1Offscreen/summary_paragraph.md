This is Part 1 of a two-part series on 4D Live Window (4DLW) JavaScript integration, focused on treating JavaScript functions loaded in a 4DLW plug-in area as reusable "code libraries" callable from 4D code — a capability added in 4DLW 1.1 via the Web_JavaScriptReturn(Area; Function; Result; Parameter1...5) command, which executes a named existing JavaScript function (with up to 5 text parameters) and returns its text result. Because 4DLW could not create a genuinely offscreen/invisible plug-in area (a technical limitation of the underlying browser layer), the author's workaround is to place a 4DLW area inside a 4D "Palette window" and then programmatically move that window off the visible screen bounds using Open window with coordinates beyond Screen width; critically, the hosting process must not be hidden with HIDE PROCESS, since that would disable the plug-in area entirely. To make this hidden window responsive to calls from other processes, the note implements a custom event model: an interprocess variable stores the requested "event," and CALL PROCESS wakes the hidden window's process to handle it via an OnOutsideCall event handler, with the calling method waiting for a result. The demo database implements three example JavaScript-as-4D-method functions (get browser user agent, calculate day-of-week of a birth date using Zeller's algorithm, get OS from navigator.appVersion) alongside utility methods to show/hide/refresh/restart/stop the hidden "JavaScript Utility Window." As in other 4DLW notes of the era, JavaScript execution is Windows-only because Mac OS's WebKit browser layer was too unstable to programmatically execute JavaScript, and the sample uses a time-limited 4DLW 1.1.2 demo license. The technique demonstrates a resourceful, if very plug-in-specific, way to bridge 4D's procedural language with arbitrary JavaScript logic.
