This Technical Note introduces regular expressions (regex) as newly natively supported in 4D v11 SQL, presenting them as a meta-language for validating and searching text that is widely used across programming languages, word processors, and text editors, tracing their lineage from Stephen Cole Kleene and Ken Thompson's work through Perl and PCRE to 4D's chosen implementation, the ICU (International Components for Unicode) regular expression package. It explains the core syntax components — literals, metacharacters (such as "." and "$"), and operators (such as "*", "+", and the "|" OR operator) — with concrete examples like matching "*.txt" or case-insensitive alternatives via "[R|r]egex". The note's centerpiece is the new Match regex command, whose syntax and optional parameters (start position, pos_found/length_found as scalars or arrays, and the "*" anchor-to-position flag) are explained in detail, including how using arrays for pos_found/length_found enables "Capture Groups" to extract structured substrings (e.g., splitting a "MM/DD/YYYY" date into its components). It contrasts a four-line manual 4D search-and-compare routine using Position/Substring/Character code with the equivalent single-line Match regex call to argue for regex's efficiency and reduced code volume, especially given 4D's case-insensitive string comparisons. Practical guidance is given on escaping metacharacters (e.g., matching a literal "+" requires "\\+" due to 4D's own escape-character handling of backslashes) and on why 4D displays a generic error dialog for invalid patterns. The note closes by positioning regex as an industry-standard technique worth learning for future development work, and points to external resources including the ICU documentation and Jeffrey Friedl's "Mastering Regular Expressions." As one of the first 4D Technical Notes covering regex, it reflects 4D's broader 2007 push (alongside the new SQL engine) to align 4D v11 with established industry standards.
