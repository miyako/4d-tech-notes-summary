This Tech Note shows how to build an Output form that lets the end user choose, at runtime, which field appears in each of the form's available columns — not merely selecting the field, but also customizing that column's header text, the display format for Date, Time, Number, or Boolean fields, and the column's text alignment (left, centered, or right). All of these per-column settings are held in memory and survive for as long as the database session runs, even if the window displaying the form is closed and reopened, though the author flags that persisting the settings to disk (across sessions) is left for a future note — which indeed became the subsequent "User Preferences" Tech Note (05-28). The technique is implemented compactly: four layout variables are used per desired column (to track field, header, format, and alignment), paired with a single reusable method that requires updating only one section to adapt it to a different database and table structure. This design goal — a generic, drop-in mechanism rather than a one-off custom solution — reflects a common theme in the era's example-driven Tech Notes, prioritizing code developers could lift directly into their own applications.
