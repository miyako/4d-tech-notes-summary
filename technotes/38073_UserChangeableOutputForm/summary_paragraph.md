The first Tech Note in Larry Sharpe's example-database series shows how to build an output form that lets end users choose which field appears in each of six columns, along with the column's header text, its Date/Time/Number/Boolean display format, and its left/center/right alignment — all held in memory for the session via four layout variables per column (sColumnName, sColumnValue, asColumnPopup, oColumnSplitter) and a single reusable Output_Columns project method. Users pick a field from a popup at the top of each column, Control-click the header to set its format, Option-click to set alignment, Command-click to rename the header, and click or right-click to sort or reverse-sort by that column. The Output_Columns method dispatches on a $command parameter with sections for Startup (creates interprocess variables), DefaultColumns (the single place to change for a different table or column count), OnLoadForm (restores saved settings), OnUnloadForm (saves the user's current arrangement to an interprocess array, not yet persisted to disk), OnDisplayRow (sets each visible row's value/format per column, kept lean for performance), HeaderClicked (handles all four modifier-click behaviors), and PopupSelected (resets formatting when a new field is chosen). The note also highlights 4D 2004's new form-layer "Views" feature, used here to separate decorative elements, labels, live variables, and buttons onto different view levels for easier editing.
