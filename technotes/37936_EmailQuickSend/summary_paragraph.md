Written by Melinda Gallo with code by Dave Batton, this Tech Note addresses the fact that the 4D Internet Commands plug-in's convenient SMTP_QuickSend command does not support SMTP authentication, even though the lower-level SMTP_Auth command needed for it has quietly existed in the plug-in for several releases. The included Email_Demo database exposes a simple form (host, sender, recipient, subject, message) whose Send button prompts the user for a password via `Request` and then calls the custom Email_QuickSend project method — a drop-in analog to SMTP_QuickSend that takes one extra password parameter. Internally, Email_QuickSend sequences the low-level 4D Internet Commands (SMTP_New, SMTP_Host, SMTP_Auth, SMTP_From, SMTP_To, SMTP_Subject, SMTP_Body, SMTP_Send, SMTP_Clear), checking each call's success through a small wrapper method, Email_HandleSMTPError, which sets the system Error variable and displays an Alert identifying both the failing command and its error number if anything goes wrong. The note notes that SMTP_Send (the simpler, non-authenticating alternative) is easier to use but implies an open-relay mail server, which carries its own security risk.
