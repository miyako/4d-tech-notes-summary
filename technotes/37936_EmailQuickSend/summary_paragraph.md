This Tech Note addresses a specific and, per the author, under-recognized capability: sending email through SMTP servers that require authentication, using the SMTP_Auth command from the 4D Internet Commands plug-in. The note points out that although SMTP_Auth had shipped in several releases of 4D Internet Commands, it remained little known among developers, most of whom instead used the simpler SMTP_QuickSend command — which, crucially, does not support server authentication and therefore fails against SMTP servers requiring a login. The proposed solution is a custom method, Email_QuickSend, that mirrors the calling convention of SMTP_QuickSend but adds one additional parameter for the password, internally routing the call through SMTP_Auth instead. This gives developers who already relied on SMTP_QuickSend calls throughout their code a low-friction upgrade path to authenticated SMTP support, without needing to rewrite their existing email-sending calls from scratch — they simply add the password argument. The technique reflects the practical, incremental nature of many Tech Notes from this era: rather than a deep exploration of SMTP itself, it is a small, targeted wrapper method solving a specific, common pain point (authenticated outgoing mail) for the installed base of 4D Internet Commands users. As only the on-page teaser text for this note survived in this archive, the actual Email_QuickSend method code and its exact parameter signature are not available for further detail here.
