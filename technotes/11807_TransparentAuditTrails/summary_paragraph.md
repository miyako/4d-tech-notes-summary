This Tech Note describes a transparent audit trail system for 4D V6 databases that tracks all record changes with minimal impact on existing code. The system uses V6's triggers and BLOBs to automatically archive copies of records whenever they are saved. When a record is saved (new or existing), a copy is stored as a BLOB in an [Archive] table, with metadata including timestamps, date stamps, and field information that allows later retrieval. The system can decompress BLOBs transparently if they are compressed, and supports tracking who made changes. The key virtue is transparency: adding this capability to an existing database requires only trivial changes — incorporating the archive table and methods, then adding two lines to triggers for each table to be tracked. The methods can recover earlier versions of any changed field or record. The only unsupported field type is subtables, as supporting them would substantially increase complexity. The note also discusses variants such as BLOB compression and user tracking.
