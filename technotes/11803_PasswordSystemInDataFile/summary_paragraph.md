This Tech Note addresses the problem of 4D's password system (users and groups) being stored in the structure file rather than the data file. When developers shipped updated structure files to clients, all user and group modifications made by the client were lost. The note proposes a solution to preserve password system data across structure file updates, likely by programmatically exporting user/group definitions to the data file and reimporting them after the structure update. This was an important deployment concern for 4D developers distributing applications, as the structure-data separation meant routine application updates could disrupt client security configurations. The technique addressed a fundamental architectural limitation of 4D v6 that affected any multi-user deployment requiring periodic structure updates.
