This Tech Note explains how to implement drag-and-drop interactions on 4D list boxes bound to ORDA entity selections or collections, framing the choice between the two data source types as a tradeoff between memory/speed efficiency and manipulation flexibility. It first distinguishes unordered entity selections (created via query(), newSelection(), or(), and(), minus(); default primary-key ordering, no duplicates, fastest/smallest) from ordered entity selections (created via orderBy() or newSelection(dk keep ordered); freely reorderable, allows duplicate references, slower/larger) and collections (fully ordered, mixed-type, richest set of built-in manipulation methods like insert/slice/filter/combine). The implementation pattern hinges on two form events: On Begin Drag Over, used to record which list box a drag originated from into a shared variable (e.g., LB), and On Drop, where the actual data manipulation happens. For unordered entity selections, single-item moves use entitySelection.add() to insert into the destination and entitySelection.minus() to remove from the source, while multi-selection moves use entitySelection.or() (to union without duplicates) and .minus(). For ordered entity selections, custom Entity_Insert/Entity_Splice-style helper methods handle inserting at a specific Drop position. For collections, same-listbox swapping is done manually with the Drop position command and a temp variable to avoid data loss, while cross-listbox multi-selection moves use collection.combine() (optionally at a specific position) to insert and collection.filter() with a callback method (checking .indexOf() against the selected items) to remove. The note closes by reiterating that entity selections excel at fast bulk removal of unique/distinct elements while collections trade memory and speed for a much richer manipulation API, leaving the choice to the developer's specific use case.
