This Tech Note explains how to make 4D's Quick Report tool produce output that Microsoft Excel 2003 can open directly, by exploiting the HTML template tag system that Quick Report normally uses when its destination is set to an HTML file. It first walks through generating a standard Quick Report HTML output programmatically (QR New offscreen area, QR INSERT COLUMN, QR SET SORTS, QR SET DESTINATION with qr HTML file), then documents the template's tag vocabulary — <!--#4DQRheader-->, <!--#4DQRrow-->, <!--#4DQRcol--> (optionally with a column index), and <!--#4DQRdata--> — which control how column titles and per-row/per-column data are woven into the output. Because these tags can emit arbitrary markup rather than strict HTML, the note shows how to repurpose them via the QR SET HTML TEMPLATE command to construct two different Excel-compatible XML outputs instead: a basic custom XML file (one XML element per table/row, parseable by Excel's generic XML import) and a full XML Spreadsheet / SpreadsheetML document (Excel's own native XML format, which Excel opens automatically with no import dialog, akin to opening a .xls file). Full example methods are provided, including a ConstructBasic_XMLTemplate/ConstructXMLSpreadsheet-style method that dynamically builds the template text by iterating the Quick Report's columns, detecting each column's field type to emit correct SpreadsheetML "ss:Type" attributes (Number vs. String), and concatenating a static metadata header (read from a template file) with the dynamically generated body. A bundled sample database demonstrates both output paths via simple UI buttons ("Generate XML file" and "Generate XML SpreadSheet"). The technique is presented as a practical bridge between 4D reporting and Excel-based data consumption at a time when 4D had no native Excel export capability.
