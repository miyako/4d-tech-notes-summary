This Tech Note uses basic mathematical Set Theory to demystify how 4D's Search Editor evaluates multi-line queries combined with the And, Or, and Except conjunctions. It begins with a primer on set theory fundamentals — defining a "set" as any collection of objects, and explaining union (combining two sets, analogous to Or), intersection (elements common to both sets, analogous to And), and complement/difference (elements in one set but not another, analogous to Except) — illustrated with simple Venn-diagram-style examples using shapes and colors. It then maps these operations directly onto 4D's Search Editor conjunctions: each search criterion line defines a set of matching records, "Or" performs a union of the sets from each line, "And" performs an intersection, and "Except" removes a set from the result. The note introduces the "Funnel Concept" as a visualization aid: imagining each search line as progressively funneling the candidate record set down (for And) or adding to it (for Or), which helps explain why the *order* in which search lines are written changes the final result even though the individual criteria are unchanged — since each line operates against the running result of all lines above it rather than against the whole file independently. Using the 4D Airlines sample database (flights, employees, pilots), the note walks through several side-by-side query examples with different line orderings and conjunction placements, showing how reordering "And"/"Or"/"Except" lines produces different record sets even when the same criteria are present, and offers guidance on structuring queries (e.g., grouping Or'd alternatives together, placing Except lines appropriately) to get the intended result. Featured technology is 4D's Search Editor interface and its And/Or/Except query conjunction model, taught here through the lens of formal set theory using the 4D Airlines demo database.
