This Tech Note documents the deployment considerations for 4D Server 64-bit on Mac OS X, a product that had shipped in preview form from v14 R3 through v15.0 before reaching certified/production status starting with v15.1. It frames the core benefit of 64-bit as addressing more RAM, while noting that is "just the beginning" of the advantages. Topics covered include the minimum required OS X version, 64-bit-specific architecture considerations, 64-bit code compilation, compiled-code compatibility concerns when moving between 32-bit and 64-bit builds, differences in process stack size, and a list of features not yet supported in the 64-bit product at that time. A major focus is the new ServerNet network layer introduced alongside 64-bit Server, including how to activate or deactivate the legacy network layer for compatibility, guidance on migrating merged 4D clients to the new architecture, and how to set up encrypted client-server connections. The note closes with guidance on logging client requests for diagnostics. This Tech Note is inherently a snapshot of a specific, one-time platform transition (32-bit to 64-bit 4D Server on Mac) that has long since completed industry- and product-wide: modern 4D Server has been 64-bit-only for years, ServerNet has long been the standard (not "new") network layer, and the entire premise of choosing between a legacy 32-bit product and a 64-bit "preview-turned-certified" one no longer applies to current deployments. The note is thus almost entirely of historical interest today, useful mainly to understand the transition period or for anyone still running extremely old hybrid 32/64-bit environments.
