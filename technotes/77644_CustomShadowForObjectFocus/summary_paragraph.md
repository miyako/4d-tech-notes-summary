Authored by Add Komoncharoensiri, Director of Technical Services at 4D Inc., in September 2016 for 4D v15.x, this tech note tackles a purely visual design problem: 4D's built-in focus indication (a simple blue border on the active tabbable object) works but looks dated compared to modern, shadow-based "elevation" design languages that were becoming common in UI design at the time. The note demonstrates a technique to replace or supplement that default focus border with a soft drop shadow that makes a rectangle or picture object appear to "float" above the background, giving a more contemporary visual feel. It builds the shadow effect from a set of pre-rendered gradient picture assets (eight labeled pieces such as borderShadowTopLeft, borderShadowTop, etc., forming the corners and edges of a rectangular shadow) that are composited around the target object, and provides methods — showBorderShadow(ObjectName), showFloorShadow(ObjectName), setShadowShade(ShadeLevel), and getShadowShade — to apply, adjust, and query the shadow effect programmatically for any object or picture on a form. The technique is demonstrated with example screenshots of rectangles, pictures, and toolbar icons all gaining a "floating" appearance from the shadow treatment, and a "Try It Yourself" section invites hands-on experimentation. This is a lightweight, self-contained UI enhancement note representative of the classic 4D forms era, when achieving modern visual effects required manually compositing picture assets rather than relying on native styling properties. The technique still works today since it's built on ordinary picture objects and methods that remain supported, but it is fundamentally a workaround for a styling capability 4D forms lacked natively; the same effect is now trivial to achieve with a single CSS box-shadow declaration in any Qodly or browser-based front end, making this manual picture-compositing approach largely superseded for web-facing UI work, though still valid for classic desktop forms.
