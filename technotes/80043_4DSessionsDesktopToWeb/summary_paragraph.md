This Technical Note (26-06, published June 29, 2026) documents four session-management capabilities introduced across 4D 21 and extended in 4D 21 R3, using a cross-platform KYC (Know Your Customer) identity-verification demo, 4D Secure OTP, that coordinates a compliance officer's desktop client, a web console, and a subject's mobile device within one shared session. Prior to 4D 21 R3, the `Session` command returned `Null` on remote clients, forcing developers to write server-side relay methods just to expose session metadata; now `Session.info` (username, machine name, IP address, session ID, creation timestamp) and related properties are readable directly from client-side form/object methods. `Session.createOTP()`, originally web-only, now also works from desktop sessions, generating a short-lived single-use token appended to a URL as the `$4DSID` query parameter, which the 4D server matches to bind a new HTTP connection (and subsequently a cookie) to the originating session — used first to admit a browser into the desktop session, then a second OTP to admit a mobile device via a QR code at a `/pair` route. `Session.storage`, a shared object scoped to the session, propagates state (such as a challenge-response value) in real time to all connected clients regardless of protocol. `Session.setPrivileges()`/`clearPrivileges()` now return a Boolean success indicator, enabling tighter control flow around privilege-gated operations like `Session.hasPrivilege("verified_user")`-guarded file uploads. The note stresses security practices around OTP lifetime, mandatory HTTPS in production, and privilege cleanup at case closure, positioning these APIs as removing an entire class of custom server-relay infrastructure previously required for multi-channel 4D applications.
