This tech note is a foundational, largely platform-agnostic primer on why and how to move a website (and specifically a 4D-published web application) from HTTP to HTTPS. It opens by explaining HTTPS's three pillars — authentication (preventing man-in-the-middle attacks), encryption (protecting data from eavesdroppers), and data integrity — and contrasts HTTP's plaintext request/response cycle with HTTPS's use of TLS (successor to SSL) to secure the channel via a hybrid of asymmetric encryption (for the initial key exchange) and symmetric encryption (for the bulk of the session). It covers certificate fundamentals: what a digital/public-key certificate contains, the three validation levels (Domain, Organization, Extended Validation) and four functional scopes (single-domain, multi-domain, wildcard, multi-domain wildcard), plus the concept of a trusted Certificate Authority. On the practical 4D side, the note explains that `key.pem` (private key) and `cert.pem` (certificate) must be placed next to the database structure file (or project folder, for project-mode databases) — or manually copied to the remote machine's local resources folder in remote mode — and that HTTPS must then be explicitly enabled in the Web section of Database Settings, with the HTTPS port (default 443) configurable and checked for conflicts. A seven-step checklist walks through the full migration: confirming HTTP already works, obtaining a certificate from a CA, verifying the port and file placement, checking firewall rules, enabling HTTPS in settings, running the site over HTTPS, and validating the resulting secure connection. The note closes by tying HTTPS adoption to both security and SEO/browser-trust considerations, reflecting the period when browsers began actively flagging non-HTTPS sites as "not secure."
