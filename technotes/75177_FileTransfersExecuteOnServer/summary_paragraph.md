This Tech Note explains the Execute on Server method property, a simplification introduced in 4D v11 SQL Release 2 that lets a project method always run on the server in Client/Server mode without needing the older Execute on Server command, and demonstrates a practical use case: transferring files from the server to client machines. It contrasts the property with the command — the command always spawns a new process (in both single-user and Client/Server modes) while the property instead runs the method in a "twin" process of the requesting client process, automatically synchronizing parameters and dereferenced pointer values in both directions, subject to the same restrictions as stored procedures (no interface/dialog commands). The note's featured implementation, GFFS ("Get Files from Server"), lets a 4D Client browse a server-side folder hierarchy (rooted at a configurable `<>gffs_DocRoot` variable) and download files up to 2GB regardless of the client's geographic/network location, as long as it has a database connection. Under the hood, `gffs_s_getDocument` runs on the server via the Execute on Server property; if a requested file is smaller than a configurable `<>gffs_FileLimit`, it is returned whole as a blob, but larger files are split into chunks read with `READ PACKET`, each returned blob prefixed with custom header bytes (a "multipart" marker, current chunk number, and total chunk count) that the client parses to reassemble the file progressively using `SEND PACKET`, looping until all chunks are received. The included File Browser sample database provides a GUI to navigate the shared folder hierarchy, view folder sizes, and download individual files or entire folders, with a Transfer in Progress dialog supporting pause/cancel and automatic cleanup of partially downloaded files. This note is aimed at 4D developers building client/server applications that need to move data or files efficiently between tiers, or who simply want to understand the new Execute on Server property.
