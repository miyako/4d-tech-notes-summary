This Tech Note by Vance Villanueva explores the query file format that 4D's classic Query Editor (a v14-introduced UI, still current at the time of writing) can export as readable JSON, and builds custom components to work with that format programmatically. It explains the motivation: prior to v14, the Query Editor could save queries but not in any human-readable or editable form, forcing developers to reopen the Query Editor UI itself just to view or reuse a saved query; the v14 JSON export changed that by making the query file both readable and structured, opening the door to querying without ever launching the Query Editor. The note provides an extensive breakdown of the JSON query file schema, covering table number, field number, criterion, and line operator elements, along with type-specific box configurations for text, number, date, time, boolean, blob, and picture fields, including "one box," "one box with units," "first/second of two boxes," and preset date values. Having documented the format, the note describes developing a component that extracts each query line and field type from a JSON query file, builds the corresponding query commands using PROCESS 4D TAGS, and executes them — packaged into components named OF_Execute_Query, OF_Display_Readable_Query, and OF_Display_4D_Code_Query for running a query, showing a human-readable rendition, or showing generated 4D query code, respectively. A demo database rounds out the note, showing query files loaded into a list box tab (with mouse-move and selection-change event handling), the ability to add new queries to that list, and a workflow for modifying and re-executing an existing query file. As a deep-dive into a specific legacy file format and its programmatic manipulation, the note is thorough but tied to the classic Query Editor mechanism that ORDA's newer query methods have since largely supplanted for building dynamic queries in code.
