This Tech Note examines the classification system and resource structure of external routines (plug-ins) in 4th Dimension. It notes that 4D's programming language contains hundreds of commands and that one of its major strengths has always been the ability to extend functionality through compiled native code extensions. These extensions were called 'external routines' in versions prior to 4D 3.5 and were renamed 'plug-ins' thereafter. The note documents how plug-ins are classified, what resources they contain, and importantly, how to properly handle or remove them when converting a 4D database to version 6. This was critical information for developers managing the v3/v3.5-to-v6 migration, as plug-in compatibility was a significant concern during major version transitions. The note reflects the era when plug-ins were essential for extending 4D's capabilities beyond its built-in command set.
