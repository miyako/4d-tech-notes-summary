This Tech Note is the second half of a two-part series on using Clusters — a pattern built on 4D's classic Saved Sets feature — to substantially improve the query performance of a database. Where Part I (Tech Note 05-21) covered the setup work of creating and maintaining the clusters (essentially precomputed, saved groupings of records intended to speed up later access), this Part II focuses on the payoff: actually using those pre-built clusters to retrieve data efficiently. The series reflects a common performance-engineering pattern of the classic 4D era, where developers facing large datasets and comparatively limited built-in query optimization would manually precompute and cache useful record groupings (as named Sets) rather than repeatedly re-running expensive QUERY operations from scratch. This kind of manual optimization technique required real developer effort and domain knowledge of the specific dataset's access patterns, since 4D at the time lacked the sophistication of a modern relational query planner or (much later) ORDA's lazy-loaded entity selections. As only the on-page teaser text for this note survived in this archive, the specific set operations, code, and retrieval examples used in Part II are not available for further detail here — readers are encouraged to also consult Part I (asset 37462) for the cluster creation and maintenance half of this technique.
