The second half of Kent Wilbur's two-part Clusters series shows how to actually use the per-word Boolean "cluster" arrays built in Part I to answer keyword and exact-phrase searches almost instantly. Against a roughly 6,000-record [TextBlocks] table, the note benchmarks five approaches to finding a known unique phrase: an uncached Contains query (1219 ms), a cached Contains query (1097 ms), and cluster-based keyword OR (3 ms), keyword AND (3 ms), and Contains-narrowed-by-cluster (4 ms) queries — a better than 99% time savings for the exact-phrase case. The M_ClusterQuery method drives a demo dialog and dispatches to CLUSTER_DoQuery, which parses the search text into words (excluding common stop words), looks up each word's stored Boolean array in the [Words] table via CLUSTER_LoadFromBLOB, and combines per-word sets using UNION (for OR) or INTERSECTION (for AND); for exact-phrase "Contains" searches, the cluster AND result is first used to shrink the candidate set, and only those few records are then re-queried with a traditional Contains query for the exact phrase. CLUSTER_LoadFromBLOB reads the stored Boolean array with BLOB TO VARIABLE and either builds a named 4D Set via CREATE SET FROM ARRAY or, for a single-word search, directly changes the current selection via CREATE SELECTION FROM ARRAY for extra efficiency. The note closes by porting the same capability to the web, using a plain HTML search form, a WEB_ClusterQuery method invoked via 4DACTION, COMPILER_WEB variable declarations for automatic form-to-variable mapping, and .shtml pages with #4dloop/#4dif tags to render results and handle the search's three possible error conditions.
