This Tech Note addresses web application security in 4D v11 SQL, starting from the premise that running any web server opens a window into the local network that must be carefully controlled. It explains that 4D's web security model rests on three pillars: the On Web Authentication and On Web Connection database methods, the default web folder specified in preferences, and access to 4D methods via 4DACTION/4DSCRIPT — all layered on top of 4D's built-in Users & Groups password management system and the concept of a Generic Web User. It documents the On Web Authentication method's six parameters (requested URL, HTTP header/body, client and server IP addresses, username, password) and its Boolean return value that accepts or rejects a connection, contrasts Basic authentication (credentials sent as plain text, compatible with 4D's built-in password system) against the more secure Digest mode introduced in 4D v11 (encrypted credentials, but incompatible with 4D's own password system), and covers the On Web Connection method that follows once authentication succeeds. It then walks through building a fully custom security system layered on top of these hooks, and explains how to install and use the included component and sample database to set up custom security realms and authentication rules for a real deployment.
