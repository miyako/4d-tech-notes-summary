This Tech Note clears up a naming and functionality change introduced in 4D v11 SQL: the classic EXECUTE command from 4D 2004, which ran a single line of code (a method call, 4D command, or assignment) passed as a string, has been renamed EXECUTE FORMULA for clarity, with identical syntax, functionality, and limitations to its predecessor — notably that local variables cannot be passed as parameters when running in compiled mode, since the statement itself is always interpreted rather than compiled. Alongside this rename, 4D v11 SQL introduces an entirely new command, EXECUTE METHOD, which goes further: it lets a developer execute a named project or (shared) component method directly, passing parameters and retrieving a result, without needing to construct a one-line formula string. The note details EXECUTE METHOD's syntax (methodName, an optional result placeholder or *, and any number of parameters) and its ability to call methods across host and component ("matrix") database boundaries. It then draws a direct three-way comparison between EXECUTE, EXECUTE FORMULA, and EXECUTE METHOD across representative use cases — executing simple formulas/assignments, calling methods between host and component databases, and executing multi-line code statements — clarifying which command is appropriate in which scenario, and why EXECUTE METHOD is generally the more powerful and flexible choice for genuine method invocation.
