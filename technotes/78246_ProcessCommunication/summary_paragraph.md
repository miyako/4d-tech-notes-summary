This Tech Note is a broad, reference-style survey of every mechanism 4D provides for processes to share data and coordinate timing, spanning both classic and modern (R-release era) techniques. It starts with process fundamentals — how processes are created (menu bar methods, Execute Method dialog, New process, Execute on server, CALL WORKER) and what state is process-local (current selection/record, process variables, ON ERR CALL handler, Debugger window) versus shared — then contrasts cooperative and preemptive multitasking. For sharing data, it covers interprocess variables (prefixed <>, simple but not thread-safe, incompatible with preemptive execution), the SET/GET PROCESS VARIABLE and VARIABLE TO VARIABLE commands for direct cross-process variable access, shared objects and shared collections (introduced in v16R6, created via New shared object/New shared collection and requiring Use…/End use blocks for safe concurrent modification, and thread-safe enough to be used in preemptive processes), and Storage, a globally-accessible system object holding shared objects/collections without needing explicit parameter-passing, at the cost of persisting in memory for the app instance's lifetime. For process synchronization/timing, it explains flags-and-checks polling loops, Semaphore/CLEAR SEMAPHORE (named, machine- or database-scoped locks distinguishing local $-prefixed vs. global semaphores), CALL WORKER for message-passing between persistent worker processes (with KILL WORKER to clean up), and the newer Signal object (New signal, .wait(), .trigger(), .signaled) for finer-grained mid-method synchronization between workers, including an optional grace-period timeout on .wait(). The note closes with ten paired demos in the sample database illustrating each technique concretely, positioning this as a comprehensive "which tool for which job" reference for developers architecting multi-process 4D applications.
