This Tech Note demonstrates connecting 4D to an external PostgreSQL database using PostgREST, a standalone tool that turns a PostgreSQL schema into a REST API, and then driving standard CRUD operations from 4D using HTTP requests. The environment setup walks through installing PostgreSQL 14.7 for macOS, Docker (used to run a containerized "tutorial" PostgreSQL instance exposed on port 5433), and PostgREST v10.1.2, including troubleshooting shared-library load errors by copying `libpq` and related dylibs into `/usr/local/lib`. Inside the Dockerized Postgres instance, the author creates a schema and a "membre" table (id, name, age), inserts sample rows, and creates a dedicated, minimally-privileged database role (rather than reusing the superuser "postgres" role) granted select/insert/update/delete rights, then writes a PostgREST configuration file (renamed from .rtf to .cfg) to launch the REST façade with `./postgrest tutorial.cfg`. On the 4D side, a single project method demonstrates all four HTTP verbs against the exposed `http://localhost:3000/membre` endpoint: GET retrieves the full row set as JSON text; POST inserts a new record by JSON-parsing a literal object and passing it to `HTTP Request` with the POST method; DELETE removes a row by appending a PostgREST filter (`?id=eq.1`) to the URL; and PUT updates a specific row's fields the same way. Response bodies are cleaned up with simple `Replace string` calls to strip brackets/newlines before display. The note positions this REST-based approach as a lightweight, database-agnostic alternative for 4D applications that need to read and write data in other SQL systems without deep native connectors, useful for heterogeneous environments requiring rapid, flexible data interchange.
