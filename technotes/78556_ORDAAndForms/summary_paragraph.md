This Tech Note is a foundational, beginner-oriented tutorial on using ORDA (introduced in 4D v17) inside 4D Forms to perform basic record management. It first covers the core entity/entity-selection member functions in isolation: creating a record with `ds.Table_1.new()` followed by setting fields and calling `.save()`; retrieving all records with `.all()` or a filtered set with `.query("lName = :1";"Fool@")`; and modifying a specific entity by querying for it, taking `.first()`, changing a property, and calling `.save()` again. The bulk of the note then walks through a complete sample "People" application: a form's entity selection is assigned to `Form.selection` (via `ds.Table_1.all()`) and bound directly to a list box configured with Entity Selection as its data source, exposing fields with the `This.FieldName` convention. From there, the note demonstrates the full CRUD lifecycle wired into UI actions — creating a record via a "Add new person" button or double-clicking an empty list box row, which opens an `AddNewPerson` sheet-form dialog fed a fresh `.new()` entity through the `DIALOG` command, and calls `.save()` plus refreshes `Form.selection` on Accept; updating a record by opening the same dialog pre-loaded with an existing entity retrieved via `Form.selection[$row-1]`; and deleting a record via a "Delete Person" button that confirms with the user, calls `.drop()` on the selected entity, and — since the dropped entity remains in memory until refreshed — reassigns `Form.selection` to remove it from the displayed list. The note closes by noting that this single pattern (checking `$dropInfo.success`, refreshing the selection) generalizes cleanly across create, update, and delete flows, making it a compact reference for building simple, ORDA-driven data-entry forms.
