This Technical Note introduces native Scalable Vector Graphics (SVG) support, newly built into 4D v11 SQL's rendering engine, explaining SVG as an XML-based vector image format whose geometric (rather than pixel-based) construction gives it scaling advantages over raster formats like JPEG or GIF, and notes that although SVG content lives in an XML tree, 4D developers can manipulate its attributes directly through 4D method code. It documents how to invoke SVG rendering via the existing GRAPH command, whose graphics engine selection now depends on the type of the first parameter passed — a 4D Chart area/graph reference invokes the older 4D Chart plug-in, while a Picture-type variable invokes the new SVG engine — paired with the GRAPH SETTINGS command for configuring axis ranges, gridlines, and titles. Using a bundled sample database that tracks a user's daily exercise time across three activities (Wii, gym, basketball) over a 31-day month, the note walks through concrete 4D code that populates array-based datasets via Sum() aggregations and calls GRAPH(vGraphPict;1;times;wii_time;gym_time;bas_time) followed by GRAPH SETTINGS(...) to produce a bar/column chart, explaining each parameter (graph style number 1–8, axis min/max defaults via zero values, proportional/gridline booleans, and legend title strings). It highlights that the sample includes three different graphs (activity totals, activity averages, and per-day activity breakdowns) all driven by the same SVG rendering mechanism, and notes that the older 4D Chart plug-in remains available as a fallback for developers who prefer its look. The document goes on to cover contextual menu behavior and how to export the resulting chart as an SVG image file to disk. As a feature-focused note tied to 4D v11 SQL's modernized graphics capabilities, it reflects 4D's effort to adopt open, XML-based standards (mirroring the contemporaneous native SQL and regex additions) rather than relying solely on proprietary plug-in technology for data visualization.
