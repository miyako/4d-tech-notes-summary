This Tech Note accompanies a debug-logging edition of the OCI Mapper, a 4D component (with source) that emulates the older 4D Oracle plug-in's high-level commands on top of the lower-level 4D for OCI plug-in introduced with 4D 2004. Rather than modifying the original OCI Mapper methods directly (which would clutter the code), 4D released this as a separate two-part update: this note is the debug half, adding 26 new "OCIM_DBG_" methods that log the start/end of every OCI Mapper method call and every underlying 4D for OCI call (with parameters) to a plain-text log file. Log entries use a process ID, a "stack level" (an artificial indentation concept to visualize nested method calls, unrelated to 4D's real call stack), and readable representations of OCI constants (as strings rather than raw integers). Only integer and string parameters are logged natively, though the parameter-formatting method can be extended. To avoid uncontrolled disk growth, a background "log monitor" process caps log files at a configurable size (default 500KB) and keeps a configurable number of rotated archives (default 6), with semaphores protecting concurrent access. The component exposes toggles to independently enable/disable logging of OCI Mapper calls versus raw OCI calls, plus commands to set log file path, size limit, and archive count. Developers can also invoke the same logging primitives (OCIM_DBG_Log_MethStart/End, OCIM_DBG_Log_OCIMethBefore/After) inside their own custom 4D methods and 4D for OCI calls, making the component reusable as a general debugging harness beyond the OCI Mapper itself. Installation requires 4D 2004, the 4D for OCI plug-in, and uninstalling the "regular" (non-debug) OCI Mapper component first via 4D Insider before installing this debug variant. The note positions itself as a companion to TN 06-06 ("OCI Mapper 2004-3"), which documents the non-debug OCI Mapper in full.
