This Tech Note addresses a real regression introduced by project mode: binary-mode 4D used to automatically generate an input and output form for any table lacking a defined form, but project mode dropped this feature (attributed to ORDA's paradigm shift and a general preference for listbox-based UIs over classic list forms), leaving developers with only the more manual, from-scratch Form editor experience. The provided autoForms component (a project-mode database dropped into a host's Components folder, exposing a single `openTableSelection([tableName])` method) restores similar convenience: an auto-generated 'Output' form displays a dynamically built listbox with one column per applicable field (BLOBs excluded) for any selected table, with buttons to add/delete records, show all/subselected records, run a query editor, sort, and launch the Quick Report/Label editors, plus a table-selector dropdown in the corner; double-clicking a row (or an empty row) opens a companion 'Input' form with dynamically generated input objects for each applicable field, navigation buttons (first/previous/next/last record), and delete/cancel/validate controls. Notably, the component's implementation deliberately uses 4D v19's newer coding conventions — `var $x : Type` declarations instead of the classic `C_TEXT`/`C_LONGINT` compiler-directive style — and ORDA/object notation where applicable, both to showcase modern 4D style and because the component targets project-mode-only databases. It also explains project-mode-specific component packaging quirks: the Components folder sits next to the Project folder (not next to a .4DB/.4DC file), compiled project-mode components use the .4DZ extension (a zipped Project folder) rather than .4DC, and uncompiled components need an alias/shortcut trick to be usable directly from a Components folder.
