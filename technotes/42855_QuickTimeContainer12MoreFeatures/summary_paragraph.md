This Tech Note, co-authored by Thomas Maul and Louis Thoumin, documents new features added in version 1.2 of the QuickTime Container plug-in for 4D, an update to the plug-in originally released in TN 05-30 that fixes minor issues and expands its capabilities beyond simply displaying movies and pictures in a form area. The headline addition is offscreen area support via two new commands, `QTNewOffscreenArea` and `QTDeleteOffscreenArea`, which let a developer open a movie or audio file invisibly (i.e., without displaying it in a plug-in area) in order to read information from it programmatically — such as movie length via `QTGetControl`, ID3-style metadata tags, or a screenshot of a specific frame — with the note stressing that offscreen areas must always be explicitly closed to avoid leaking memory. A second major feature is `QTGetTags`, which returns two parallel text arrays describing whatever "user data" metadata QuickTime can extract from a document: for MP3 files this covers album, artist, song title, comment, and track number (4-character QuickTime tag codes prefixed with a copyright symbol), while for digital-camera pictures it covers maker, model, software, timestamp, host, and comment fields. A third addition, `QTScreenshot`, captures the current frame of an open movie as a native 4D picture at the movie's displayed size (or, combined with `QTSetControl(Area; QTSize; 100)`, at the movie's real/native size). The note also documents smaller but useful changes: `QTSetMovie` now accepts file paths longer than 255 characters on both platforms, a new `QTRemoveMovie` command cleanly closes/erases a movie or picture from a container area and hides its controller, and two new read-only `QTGetControl` selectors (`QTGetMoviePreferredRate` and `QTGetMoviePreferredVolume`) expose a movie's preferred playback speed and volume. Finally, the note describes redraw and portability optimizations: significantly reduced flicker on Windows during window resizing (especially for growing containers), and an updated C-language codebase recompiled against then-current Apple Xcode 2.2 and Microsoft Visual Studio 2005 to maintain compatibility with contemporary operating systems and 4D releases. As a whole, this note is squarely a plug-in reference document for a media-handling wrapper built entirely on Apple's now-defunct QuickTime framework.
