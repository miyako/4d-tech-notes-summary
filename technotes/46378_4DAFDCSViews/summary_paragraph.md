This Technical Note by Tom Fitch of 4D Inc. covers Developer Created Selections (DCS), a feature of the 4D Ajax Framework (4DAF) Client, compatible with 4D Web 2.0 Pack 1.1, that lets developers programmatically create Views appearing in the 4DAF Portal alongside normal Control-Panel-defined Views, but backed entirely by arrays that can be populated from any data source of the developer's choosing rather than directly from 4D table records — a design the note recommends pairing with compiled applications for best performance given its heavy array usage. Implementing a DCS View requires editing four developer hooks (after installing the 4DAF component, not included with the demo, per the standard installation guide): `DAX_DevHook_DCS_ViewAdd`, called once by `DAX_Dev_Initialize` to define the View's shape by calling `DAX_Dev_DCS_AddCustomView` with parameters for the view name, column titles, column data types, and per-column unique/mandatory/non-enterable/non-modifiable flag arrays; `DAX_DevHook_DCS_SetSelection`, called whenever a View is accessed (including refreshes) to populate it via `DAX_Dev_DCS_SetSelection`, which takes a pointer to a Longint array of unique record IDs (which need not be actual 4D record numbers) plus one data array per column, all type-compatible with the column definitions; `DAX_DevHook_DCS_RecordSave`, invoked on record creation/edit, receiving the view name, record ID (or a "new record" constant), and pointers to arrays of only the modified field names and values, and returning the (possibly newly assigned) record ID; and `DAX_DevHook_DCS_RecordDelete`, invoked on record deletion, receiving the view name and record ID and returning a Boolean success flag that determines whether the 4DAF Client refreshes the View or shows an error. The example database implements these four hooks via four corresponding Project methods (prefixed `A_DCS_`) working against [Actors] and [M_LineItem] tables, illustrating logic such as conditionally creating vs. loading records, parsing which fields changed, and using `GOTO RECORD()` for straightforward ID-to-record-number mapping in the deletion case. The note concludes that DCS Views' key benefit is flexibility to surface data from any source or combination of sources through the same 4DAF View mechanism used for ordinary table-backed Views.
