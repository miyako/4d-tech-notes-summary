Written by Jamras Komoncharoensiri, a 4D Evangelist, this Tech Note introduces two new 4D 2004 connectivity plug-ins -- 4D for MySQL and 4D for PostgreSQL -- that communicate with each open-source database's native wire protocol directly, bypassing the generic ODBC layer entirely so no ODBC driver or DSN setup is required and connections can be made or switched programmatically at runtime. For 4D for MySQL, the note demonstrates the `MySQL_Connect`/`MySQL_Execute` pattern for INSERT/DELETE/UPDATE statements, contrasting hard-coded SQL text against a parameter-binding approach using `MySQL_AddStringParameter`/`MySQL_AddLongIntParameter` and numbered tags (%1, %2, %3), and shows the `MySQL_Select`/`MySQL_NextRow`/`MySQL_Get<Type>Field` loop for retrieving query results row by row into 4D arrays. For 4D for PostgreSQL, it shows the single-command `PGSQL_Execute` model where the caller must check `PGSQL_GetResultStatus` for `PGRES_COMMAND_OK` versus `PGRES_TUPLES_OK` to distinguish non-SELECT from SELECT results, followed by `PGSQL_GetRowCount` and `PGSQL_Get<Type>Value` to extract the result set. The note frames both plug-ins as an alternative to the existing 4D ODBC plug-in/native ODBC commands, trading ODBC's broad portability for the direct plug-ins' improved performance and simpler setup when the target DBMS is known to be MySQL or PostgreSQL specifically.
