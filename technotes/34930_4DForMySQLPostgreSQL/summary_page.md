# Tech Note 04-47: Introduction to 4D for MySQL and 4D for PostgreSQL

## Overview
This note introduces two new plug-in products for 4D 2004 — 4D for MySQL and 4D for PostgreSQL — intended to give 4D a more direct communication channel to these two leading open-source RDBMSs than the ODBC-based approach many 4D solutions relied on previously.

## Key Points (from available teaser)
- MySQL and PostgreSQL are identified as two of the most popular open-source SQL databases.
- Some existing 4D solutions interfaced with them only via ODBC prior to these plug-ins.
- The two new 2004 plug-ins (4D for MySQL, 4D for PostgreSQL) provide more direct connectivity.
- The note covers steps needed to implement a 4D database that works with MySQL/PostgreSQL via these plug-ins.

## Featured Technology
- 4D for MySQL plug-in
- 4D for PostgreSQL plug-in
- MySQL and PostgreSQL open-source RDBMSs
- Direct (non-ODBC) 4D-to-external-database connectivity

## Historical Context
**Note:** Only the on-page teaser paragraph was recoverable for this Tech Note; the full PDF and example database could not be retrieved in this environment (old archive format not accessible), so implementation specifics cannot be detailed here. The 4D for MySQL and 4D for PostgreSQL plug-ins themselves have long been discontinued, and modern 4D-to-open-source-database integration is handled through 4D's native SQL engine, standard ODBC/JDBC connectivity, or ORDA-based data source integration rather than these dedicated 2004-era plug-ins.
