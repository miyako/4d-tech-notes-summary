The second Tech Note in Larry Sharpe's example-database series builds directly on "User Changeable Output Form" (July 2005) by persisting the previously in-memory-only output form column selections, along with several other user preferences (Startup View, Data Entry defaults, and Server Settings), into a new [xPreferences] table so the choices survive a database restart. Preferences are stored per user (Designer, Administrator, Test User) and per preference type as a single BLOB field per record, which lets the example freely mix variable types without needing separate columns for each preference — as long as the Save and Load code sections stay in sync in both order and type. The prior single xPreferences_Users project method is split into three: xPreferences_Users (opens the edit dialog), xPreferences (does the actual load/save/default work via a Case of on a $command parameter), and the new xPreferences_Processes (opens a separate, still-in-progress preferences form reserved for server process settings covered in a planned future note). The [xPreferences]EditPrefs form uses a Tab Control and a popup of usernames (plus "Server" when running Client/Server) so Designer/Administrator users can edit any user's preferences, automatically saving the current page's variables whenever the user switches pages or users.
