This Tech Note introduces 4D Server's request log recording feature, enabled in 4D 2004 via SET DATABASE PARAMETER with selector ID 28 ("4D Server Log Recording"): passing a value of 0 stops recording, while any positive value both starts recording and becomes a suffix appended to the generated log file's name, with a new 10MB-capped, auto-rotated file created as needed next to the structure file. It documents each column in the raw text log — time, PID (internal process ID, distinct from the developer-visible process ID), UID (internal per-connection user ID, retrievable via On Server Open Connection's first parameter), CID (connection ID, via that method's second parameter), the numeric request ID identifying what 4D Client asked the server to do, bytes in/out for the request/response packet sizes, duration in milliseconds, and an optional (usually empty) human-readable request name that would otherwise require installing a resource in 4D Server's resource file. It frames the practical motivation as helping developers reduce network chattiness and diagnose latency-sensitive Client/Server deployments, noting that low latency alone does not guarantee good performance if too many clients or too many requests overload the server. A bundled demonstration database shows how to operationalize this: a "Request Log File" dialog lets the user toggle recording, clear existing log files via a server-side stored procedure, and view results; because raw logs can span tens of megabytes across multiple files, the data is imported into a [Requests] table rather than loaded into arrays directly, then displayed via a "Raw Data" listbox (paginated into user-configurable sets using named selections to preserve sort order), a "Mnemonics" tab computing per-request-type call counts and average/sum duration and byte statistics via the Quick Report editor and an XML export, a "Processes" tab performing similar aggregation per connection/process ID, and a "Graphs" tab offering five 4D Chart visualizations (bytes per request, bytes over time, durations over time, percentage share per request type, and duration per request type). The note closes with an extensive Appendix 1 listing every internal 4D Server request ID and its mnemonic/description (e.g., Proc_GetProcessVar, Set_Create, Struct_SetDBParam, Bck_GetLastBackupInformation), explicitly deferring the actual interpretation/evaluation of these figures to a future Tech Note (which became TN 06-04).
