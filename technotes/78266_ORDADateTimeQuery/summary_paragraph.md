Only a short readme file for this Tech Note's accompanying sample database was retrievable, not the full PDF text, so this summary is necessarily limited to what the readme and title reveal. The note addresses how to store, query, and access date-and-time values in the context of ORDA (4D's Object Relational Data Access layer), a topic made non-trivial because ORDA introduces object/entity-based representations of records that must still support the classic need to filter by date and time components. Based on the listed project methods, the sample database demonstrates storing date-and-time values into an object (store_dateAndTimeInObject), into a collection (store_dateAndTimeInCollection), and into an entity (store_dateAndTimeInEntity), followed by querying date and time values across collections and entity selections (Query_Date, Query_Time), and more granular filtering by month/day (query_DateByMonthAndDay for both entity selections and collections, with an accompanying test method) and by hour/minute/second (query_TimeByHMS, query_ColTimeByHMS, with a test method). The environment requirements note that the sample must be run in 4D standalone with 4D v17.0 or later. Given only the readme is available, this summary cannot confirm the exact ORDA query syntax or date-formula patterns used, but the topic — reconciling classic date/time querying idioms with the object-oriented ORDA data model — was a natural and recurring concern as 4D pushed developers toward ORDA-based development in the v17 timeframe.
