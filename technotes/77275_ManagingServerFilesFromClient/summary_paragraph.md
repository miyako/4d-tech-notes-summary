This Tech Note by Timothy Tse builds a full client-side file management interface for 4D client/server deployments, letting users on client machines view, create, upload, download, rename, and delete files that live on the server, all confined to a designated root folder that the server administrator controls. It explains that any 4D method flagged with the "Execute on server" property can be invoked remotely by the client to perform operations directly on the server's file system, which underlies the entire feature. The centerpiece is a "browser" UI — actually a header/footer/gridline-less array-based listbox with four columns (icon, name, modified date, and an invisible full path column) — populated by a project method (BROWSER_GET_DIR_ITEMS) that runs server-side using FOLDER LIST and DOCUMENT LIST to enumerate directory contents, and GET DOCUMENT PROPERTIES/GET DOCUMENT ICON to fetch metadata and icons for each entry, passing results back to the client via array pointers. A breadcrumbs area tracks navigation depth, letting users descend into subfolders (via double-click) and click back up through prior folder levels. The note then documents each file operation in turn: creating new folders, downloading files or entire folders from server to client (including a drag-and-drop variant), uploading files or folders from client to server (also with drag-and-drop support), deleting files and folders, and renaming files and folders — each described with its underlying commands and UI trigger. An appendix supplies the full method code for BROWSER_GET_DIR_ITEMS. The conclusion frames this as a reusable, self-contained solution for exposing controlled server file management to end users directly from within a 4D client application, without requiring external FTP or file-sharing tools.
