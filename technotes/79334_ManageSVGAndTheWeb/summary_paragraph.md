This technical note explains why SVG (Scalable Vector Graphics) became 4D's standard vector-drawing format after the retirement of the proprietary 4D Draw plugin (SVG support arriving in 4D v11 SQL and v12), and how it addresses modern UI challenges like high-DPI/UHD displays and dark mode where raster images lose crispness at scale. It presents a balanced pros/cons comparison against raster formats: SVG offers scalability, plain-text/XML editability, native interactivity/animation via JavaScript and CSS, accessibility (indexable, screen-reader friendly, supports metadata/comments), and compactness for simple geometric content — but is unsuited to complex photographic imagery, exposes its content freely (no protection of design work), poses script/CSS-based security risks specifically within web areas, lacks an integrated graphical SVG editor in 4D, and has no default metadata support (mitigated via `GET PICTURE METADATA`/`SET PICTURE METADATA` for custom fields like copyright notices, which also helps strip sensitive metadata from raw photos served via the HTTP server). The bulk of the note walks through a sample v20.2 project-mode database that lets users browse SVG/HTML/GIF files from a "SVG_Files" folder and display them simultaneously in a 4D Web Area (via `WA OPEN URL`, with `WA ZOOM IN`/`WA ZOOM OUT` support) and a picture object (via `READ PICTURE FILE`), or launch them in the platform's default or Firefox browser via `OPEN URL`. A "Build 4D Logo SVG" button demonstrates generating SVG source text programmatically and writing/reading it as a file, while a `ClassSVG` class example illustrates manipulating SVG/HTML/CSS text by parsing out unique hexadecimal color codes (format "#123456") via a `colorChanges` function and replacing each one in the source through a `colorChangesEach` function, showcasing SVG's core textual advantage: it can be edited and transformed with ordinary string/code logic rather than specialized graphics tools. The note closes by pointing to external, more comprehensive open-source color/SVG manipulation class libraries by Vincent de Lachaux (on GitHub) for developers needing capabilities like named-color-to-hex conversion or raster image color editing beyond this note's illustrative scope.
