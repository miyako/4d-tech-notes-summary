This Tech Note builds on the earlier "Advanced Keyword Search" (TN 09-09), which explicitly split multi-keyword searches on whitespace, by proposing a more elegant alternative: let 4D's own keyword-indexing algorithm decide what counts as a "word." Using 4D v11 SQL's keyword index and the `%` "contains keyword" operator on Alpha/Text fields, the technique saves each user search string into a separate keyword-indexed field (`[Saved_Searches]Data`), then runs `DISTINCT VALUES` on that field to obtain an array of the exact keyword tokens 4D itself would extract — automatically handling apostrophes, hyphens, and multi-word phrases the same way as the indexed content field. A procedural loop then builds a compound `QUERY` statement (chaining terms with the `*` "and" continuation) using those extracted keywords against the Wiki-article demo content field. The note highlights that 4D v11.2 introduced a new ICU-based keyword algorithm that treats numbers, apostrophes, and hyphens as whole tokens, and stresses that this technique automatically benefits from any future changes to that algorithm since it never hard-codes delimiter rules itself. A sample Wikipedia-based database demonstrates searches like "Jim Henson's muppets," "Mac OS X v10.5," and "$616,667" all resolving correctly.
