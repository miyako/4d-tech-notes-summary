This Tech Note by Eric Saltzen (4D, Inc. Technical Support) addresses a behavior change introduced in 4D v6.5: in v6.0, a Pop-up menu/Drop-down list's object method only ran if the user actually selected an item, but starting in v6.5 4D followed Macintosh interface guidelines more closely and fired the object method (with an `On Clicked` event) even when the user merely browsed the menu and dismissed it without changing the value. The workaround places a placeholder value ("Please make a choice...") as the first item of the associated choice list, resets the control to that placeholder after every real selection, and layers a second, display-only text object ("displayValue") directly on top of the Pop-up menu/Drop-down list to show the actual current selection while masking the underlying placeholder. The `myPopDropList` object method's `On Load` handler uses `PLATFORM PROPERTIES` to detect Windows and nudge/color the overlay object to match platform conventions, loads the choice array via `LIST TO ARRAY`, and uses `Find in array` to locate and display the record's existing value; its `On Clicked` handler ignores activations that leave the placeholder selected (assuming mere browsing) and otherwise commits the real selection back to the underlying field, resetting the control to the placeholder. A companion `displayValue` object method uses `POST CLICK` to forward any click on the overlay back down to the underlying Pop-up menu/Drop-down list, preserving the illusion of a single interactive control, with `On Getting Focus`/`On Losing Focus` handlers providing Windows-style blue/white focus highlighting via `SET RGB COLORS`.
