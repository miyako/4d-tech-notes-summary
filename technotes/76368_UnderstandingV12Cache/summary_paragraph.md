This Tech Note provides a thorough explanation of the 4D database cache — a large block of memory fully managed by 4D itself, rather than by the OS, through which all data-file I/O is routed — and why understanding it is critical to the performance and health of any 4D database. It describes what the cache is and how it is used at a conceptual level (much of which the note notes applies to versions well before v12), then covers the major redesign introduced with 4D v11 SQL, which brought 64-bit support, improved memory management, larger and more efficient caches, and better diagnostic tooling, followed by v12's continued refinements to performance and management. The note explains how to observe the cache using the GET CACHE STATISTICS command, distinguishing normal cache usage patterns from a cache that is too small or genuinely malfunctioning. It closes with further tuning tips: the FLUSH BUFFERS(*) command, keeping the cache resident in physical memory, the _USER_IND_COLUMNS parameter, and a 4D v11 SQL-specific 20-second flush interval behavior. The note targets 4D administrators and developers responsible for diagnosing performance problems or sizing server hardware appropriately.
