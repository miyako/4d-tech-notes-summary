This technical note implements a classic computer-science "Set" abstract data type in 4D v20, choosing a hash-table backing (as opposed to a binary search tree) to achieve average O(1) add/has/delete performance versus O(log n) for ordered-tree implementations, at the cost of losing element ordering. The core trick is representing a hash table using 4D's native object literal: each set element becomes an object property name (converted via `String()`), with the property's value simply set to `True`, giving constant-time existence checks and insertion; because object property names must be text, the class maintains two parallel internal objects, `This._strSet` and `This._numSet`, so that the number `36` and the string `"36"` can coexist as distinct set members, with `Value type()` (not `Type()`) used to correctly dispatch by real internal type. The class exposes a public `size` property and five functions — `add`, `has`, `delete`, `clear`, and `collection` (which reconstructs a 4D collection of all set values, converting number-subset keys back with `Num()`) — with `add`, `delete`, and `clear` each returning `This` (typed as `cs.Set`) to support method chaining like `Set.delete(x).add(y).clear().add(z)`. Internal properties are prefixed with an underscore to hide them from code completion, a documented 4D convention for encapsulation. The constructor accepts either no argument (empty set) or a collection, converting its distinct values into set membership by delegating to `add`. On top of this class, the note implements canonical set operations as simple project methods: `getUnion` (merges both sets' collections), `getDifference` (starts from set A and deletes every element present in B), and `getIntersection` (keeps only B's elements that A also `has`), noting the accompanying sample component additionally ships `getSymmetricDifference` and `isSuperSet`. Finally, the note explains packaging the class as an installable, namespaced 4D component (naming the namespace "Hash" so consumers reference `cs.Hash.Set`) to avoid class-name collisions with other components, enabling "Generate syntax file for code completion" so IDE tooling works for the component's users, and pointing to the companion Tech Note on creating Markdown-based documentation for methods/classes as the recommended way to document the shipped component.
