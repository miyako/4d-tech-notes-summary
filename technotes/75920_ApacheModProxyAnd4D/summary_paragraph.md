This Tech Note explains how to place the Apache HTTP Server in front of 4D's built-in web server using Apache's mod_proxy module, addressing the common enterprise scenario where IT departments insist on deploying with Apache rather than an application's native web server. It introduces mod_proxy conceptually, then walks through the key directives — ProxyRequests, ProxyPass, and ProxyPassReverse — explaining their syntax, defaults, and typical placement in httpd.conf or .htaccess files. Four concrete configuration examples are given: proxying a specific directory to 4D, proxying only SOAP requests (matching the 4DSOAP path), proxying both SOAP and a directory together, and proxying all requests to 4D as a full reverse proxy. The note emphasizes that no configuration is required on the 4D side; all the work happens in Apache. It also flags a practical gotcha: the rewrite engine doesn't strip the internal port number from the 4DWSDL file correctly, so developers are advised to manually save and edit the WSDL's soap:address location before distributing it to SOAP web service consumers. The note closes by pointing readers to Apache's own documentation and community resources for further configuration options.
