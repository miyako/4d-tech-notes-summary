This tech note demonstrates how to send and archive email in a 4D application using the native Transporter commands rather than the legacy 4DIC (4D Internet Commands) plugin. It explains the SMTP/IMAP/POP3 protocol trio at a conceptual level, then focuses on SMTP as the outgoing protocol. The core API is SMTP New transporter(), which builds a transporter object from a parameter object (host, port, user, password, acceptUnsecureConnection), plus transporter.checkConnection() to validate credentials and transporter.send() to dispatch a constructed email object. One example composes an email body directly from a 4D Write Pro area using WP EXPORT VARIABLE with wk mime html and MAIL Convert from MIME to build a proper MIME email object with attachments (MAIL New attachment) and headers. Sent (and received) emails are stored as ORDA entities in an Archive dataclass, demonstrating ds.Archives.new(), entity.save(), and entity.drop() for record lifecycle management alongside the mail workflow. A second example shows the same SMTP sending logic triggered from a 4D web server contact form via WEB GET VARIABLES and the On Web Connection database method, illustrating that the mailing/archiving pattern works identically in desktop and web contexts. The note positions native Transporter commands as the modern, recommended replacement for the older 4DIC plugin.
