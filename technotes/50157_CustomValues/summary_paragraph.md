Custom Values are a flexible data-passing mechanism in the 4D Ajax Framework that allow developers to send arbitrary name/value pairs from JavaScript (frontend) to the 4D backend and receive computed results back, without being limited to framework-object-specific data like grid records. They work seamlessly with framework objects (Data Grids, Charts) and standalone queries, and require the newly beta-released Data Bridge 2.0 object (successor to Bridge 1.0). On the frontend, JavaScript code calls grid/chart/query methods like clearCustomValues() and addCustomValue(name, value), then runQuery() or refresh() to send the values to 4D. On the backend, the DAX_DevHook_OnQuery project method intercepts requests, retrieves custom values via DAX_Dev_GetWebVar(valueName), acts upon them (e.g., looking up option prices based on a selected car model), builds matching arrays of return variable names and values, and sends them back via DAX_Dev_SetCustomVariables(). On the frontend, the JavaScript code retrieves returned values via grid.getCustomValuesFrom4D(), receiving an array of name/value pair objects with .name and .value properties. The example database (provided in interpreted-source versions for 4D 2004 and v11 SQL, plus a merged version) simulates a car dealership internal quoting system with tables for [Brands], [Models], [Options], and [Colors]; when a user selects a car model via a grid, the custom value mechanism triggers backend queries to fetch and return the prices for colors and options available for that model, dynamically updating the web UI without a traditional form-level grid refresh. The pattern requires careful array synchronization—the order of names in customVarName_at must match the order of values in customVarValue_at—and developers must explicitly enable a custom 'myDevHook' method call in the DAX_DevHook_OnQuery method to activate the feature."
