This Tech Note by Thomas Maul, General Manager of 4D, documents a new capability introduced in 4D version 2004.5: support for printing plug-in content — specifically 4D Write — when using Print Form, 4D's engine for producing multi-page reports with headers, footers, and repeating detail/break areas. It builds directly on an earlier Tech Note (TN 06-27) that demonstrated printing complex, multi-page invoices with varying headers/footers using only plain 4D text fields; this note's enhanced version replaces those plain text item descriptions with a 4D Write area, allowing styled text and embedded pictures to appear as invoice line-item descriptions. The example database extends the standard "Invoice" sample database (from the 4D 2004 Evaluation installer) by adding a 4D Write field to the product table, and requires the 4D Write plug-in to be installed to run. The note highlights key behaviors carried over from the earlier note (different headers on the first vs. subsequent pages, different footers for subtotals vs. the final page) plus the new 4D Write-specific behavior: when an item's styled 4D Write content is too large to fit in the remaining space on the current page, the content is automatically measured, resized, and split so the remainder continues printing on the following page via a break area. The core logic lives in a method named PrSF_WriteBreakCalculation, called from the print form's form method, which adjusts the 4D Write object's width to match the invoice form, computes the available vertical space, compares it to the 4D Write document's actual height, and either prints the whole item in the Detail area or splits it between the Detail and a Break0 area. The note gives step-by-step integration instructions: use 4D Insider to copy the "PrintSmartForm" method group (the four PrSF_-prefixed methods) into a target application, design a print form with exactly two headers and three breaks, add a specific form-method snippet handling the On Printing Detail event that loads the 4D Write BLOB and calls PrSF_WriteBreakCalculation and PrSF_PrintFormMethod, and write a driving print method that initializes variables/totals and calls PrSF_Print with parameters controlling the main and item table pointers, footer text variable and its font/size/style/width, and whether to show the print dialogs. It also flags that using a different plug-in, such as 4D View, would require writing an analogous break-calculation method, and that a PrSF_ItemCalculation method (executed once per printed item) may need customization to accumulate running subtotals or support multiple document types (invoices, shipping papers, orders, etc.) via a single Case of-based template method.
