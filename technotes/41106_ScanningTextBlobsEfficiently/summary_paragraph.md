This Technical Note by David Adams uses the practical problem of scanning text and BLOBs character-by-character or byte-by-byte as a vehicle for teaching how to design and interpret meaningful performance tests in 4th Dimension. It opens with a striking benchmark: scanning 32,000 characters of text through a pointer took roughly 710 times longer (in normalized "speed factor" terms) than scanning the same data directly or via a duplicated copy, versus only about 4 times slower for the equivalent BLOB-through-pointer case — a dramatic, non-obvious finding used to motivate closer performance investigation. All tests were run compiled under 4th Dimension 2004.2 and normalized against the fastest result rather than reported in raw milliseconds, since the note's purpose is to illustrate relative trade-offs rather than provide universally applicable absolute numbers. It reviews the differing syntax for reading text (1-based, using [[n]] or ≤n≥ on Mac) versus BLOBs (0-based, using {n}), and for passing parameters by value versus by pointer, before presenting further test results comparing scanning speed across data types and passing conventions. A key lesson is that percentage or ratio differences can be misleading in isolation — a "four times slower" BLOB-through-pointer operation might amount to less than two seconds of real difference on a 1MB BLOB, meaningless for an unattended process but potentially significant for a user waiting on a redrawing screen — so test results must be calibrated against real-world needs and available memory (since passing large BLOBs by value forces costly contiguous memory allocation). The author's personal rule of thumb, offered as a starting point rather than an absolute rule, is to pass text by value to avoid the extreme pointer-scanning penalty and pass BLOBs by pointer to conserve memory, closing with a testing database included for readers to reproduce and extend the results on their own hardware.
