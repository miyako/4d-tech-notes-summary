This Tech Note serves as a practical reference for developers using 4D v11 SQL's new Data Definition Language to programmatically create database structures. Since SQL requires standard SQL type names while 4D internally uses its own field types, the note provides a mapping table (VARCHAR, REAL, NUMERIC, FLOAT, SMALLINT, INT, BIT, BOOLEAN, BLOB, CLOB, TEXT, TIMESTAMP, DURATION, INTERVAL, and PICTURE mapped to their 4D equivalents) and explains the handful of details a developer might otherwise overlook. It covers character types in depth — VARCHAR(n) for bounded alpha fields up to 255 characters (creating an error if declared larger), unqualified VARCHAR/TEXT/CLOB all becoming 4D Text fields up to 2GB, and the distinction that CLOB fields are not indexable, mirroring their traditional RDBMS role as external large-text storage. It also documents Time, Timestamp, and Duration/Interval type behavior, Numeric/Float precision considerations, Boolean handling, and how Picture and BLOB large-object types map through. The note reassures developers that once fields are created via SQL, they behave identically to fields created through the Structure editor and can be freely manipulated with either approach.
