Written by David Adams, this Tech Note explains that because the SOAP 1.1/1.2 standards define no single authentication mechanism, different Web services expect credentials in different parts of the message, and shows the three 4th Dimension 2004 commands that address each location. It breaks a SOAP request down into its constituent parts -- HTTP headers, HTTP body (the SOAP envelope), an optional SOAP header section, and the mandatory SOAP body -- using an illustrative example SOAP request containing dummy credentials in all three locations at once. AUTHENTICATE WEB SERVICE is shown adding a standard HTTP Basic Authorization header before a CALL WEB SERVICE call, with a caveat that custom (non-standard) HTTP headers can't currently be set this way. SET WEB SERVICE OPTION, new in 4D 2004, is demonstrated building a SOAP header block using DOM Create XML Ref/DOM Create XML element/DOM SET XML ELEMENT VALUE and passing it with the Web Service SOAP Header option constant, noting that only the last call's header value is used if invoked multiple times. Finally, SET WEB SERVICE PARAMETER is shown passing credentials as ordinary SOAP body parameters (e.g. name/domain/password), emphasizing there is nothing inherently special about "authentication" parameters from 4D's perspective -- it is entirely up to the receiving Web service to interpret them as security-related.
