This Technical Note explains how 4th Dimension 2004 supports authenticating outbound calls to third-party Web services built on SOAP (Simple Object Access Protocol), a topic made necessary by the fact that neither the SOAP 1.1 nor SOAP 1.2 standard defines how requests and requestors should handle authentication, leaving each service provider free to invent its own approach (with some supporting more than one simultaneously). The note identifies and explains the three common authentication techniques 4th Dimension 2004 supports for passing credentials alongside a SOAP request: providing an HTTP Basic username and password using the AUTHENTICATE WEB SERVICE command, passing credentials as SOAP header values via SET WEB SERVICE OPTION, and passing credentials as standard SOAP input parameters using SET WEB SERVICE PARAMETER. A compatibility note flags that setting SOAP headers specifically requires 4th Dimension 2004 or later, implying this was itself a newly available capability at the time of writing. The precise code examples demonstrating each of the three techniques against a real or sample Web service are not recoverable since only the brief on-page teaser (not the full PDF/example archive) was available for this entry. Paired with the same period's note on reading raw SOAP requests, this piece rounds out 4th Dimension's story for consuming secured third-party SOAP web services during the mid-2000s Web-services boom.
