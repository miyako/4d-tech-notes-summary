This November 1996 Tech Note by Thomas D'Urso is part of a series previewing the then-unreleased 4D Version 6 for developers, explicitly noting that V6 was subject to change and that the accompanying examples required V6 Developer Release 1 or later. It introduces the terminology shift at the heart of V6: procedures and scripts are now called Methods, of which there are five kinds — Database Methods (executed by the database environment, e.g. On Startup, On Exit, On Server Startup/Shutdown, On Server Open/Close Connection, On Web Connection), Project Methods (formerly global procedures), Table Methods (formerly file procedures, also called Triggers, invoked by Database Events like saving/deleting/loading a record), Form Methods (formerly layout procedures, driven by Form Events), and Object Methods (formerly scripts). Correspondingly, execution cycles are replaced by Events: Database Events (handled in table triggers), Form Events (handled in form/object methods, covering display, printing, and record import/export), and user-generated events (keyboard/mouse), which can be handled through the forms architecture or intercepted via ON EVENT CALL. The note walks through how to view, create, edit, and delete each method type via the Explorer and Browser design-environment dialogs, documents how existing Version 3 Startup procedures can still run via a compatibility setting, lists the full set of Form Events with their numeric values (On Before, On Click, On Data Change, On Keystroke, etc.), and introduces Constants as a new named, compiler-optimized alternative to hand-rolled variables for representing these event values (e.g. Carriage Return replacing a custom ×CR variable). The featured technology is entirely the new V6 object/event model that reshaped how 4D developers organize and trigger code.
