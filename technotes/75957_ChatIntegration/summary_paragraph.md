This Tech Note demonstrates how to build a lightweight chat feature between clients connected to a 4D Server v11 SQL database, since 4D's built-in "send message to clients" feature was designed for administrator broadcasts, not two-way conversation. The chat window is a 4D Web Area displaying an HTML page (Chat.html) styled with CSS and driven by a JavaScript `addChat` function that WA EXECUTE JAVASCRIPT FUNCTION calls into to append new message bubbles. When a user types a message, a client-side method sends it to the server via an Execute-on-Server method (`Ch_sendText`), which stores it in shared, two-dimensional server arrays (`<>message_at_at`, `<>message_read_ab_ab`, `<>chatClients_at`) keyed by a "Caller-Called" chat identifier, and immediately tries to wake the target client with EXECUTE ON CLIENT. Each open chat window also runs an On Timer process that periodically calls `Ch_getText` on the server to retrieve any unread messages for that conversation, serialized through a blob. A sample database (Chat.4dbase) is included to demonstrate the full flow between at least two connected clients. The note concludes that this pattern can be extended or restyled by developers wanting integrated messaging inside their own 4D applications.
