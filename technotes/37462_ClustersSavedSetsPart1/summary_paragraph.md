In the first half of a two-part series, Kent Wilbur (Manager of Information Systems, 4D, Inc.) revisits 4D's Sets feature — bitmap-style record membership markers that are extremely memory-efficient and dramatically faster than re-querying — and introduces "Clusters," a technique for keeping a set of saved sets automatically synchronized with changing data. He opens with a worked example: a multi-dimensional sales report that took over 20 minutes to compute using per-cell queries was reduced to under 2 minutes by precomputing one Set per Genre and one per State with CREATE SET, then combining them per report cell with INTERSECTION, since single-criteria queries are far cheaper than repeated multi-criteria ones. He credits clusters as the actual technology behind 4D's own online Knowledgebase's renowned search speed since 2000, noting the technique dates back over a decade in the 4D community — originally saved into size-limited text variables, then into documents via DOCUMENT TO BLOB once BLOBs arrived in version 6 — and that this note introduces a further refinement: moving sets between data and 4D Sets using SAVE SET/LOAD SET-style BLOB storage without ever writing to a document on disk, plus support for exact-phrase matching. The example database builds this for a [TextBlocks] table: every unique word (filtered against an excluded-word list) is parsed out and stored in a [Words] table, each holding a BLOB-encoded Boolean array flagging every [TextBlocks] record containing that word, maintained automatically whenever a record is saved.
