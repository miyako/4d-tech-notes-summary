This Tech Note opens a two-part series on using Clusters, a technique built around 4D's classic Saved Sets feature, to drastically improve the performance of a database. Part I focuses specifically on the foundational work: how to create and maintain the clusters themselves, establishing the precomputed, cached record groupings that Part II (Tech Note 05-22) will then show how to use for efficient data retrieval. The clustering approach reflects a hands-on, developer-managed performance-tuning pattern typical of the classic 4D era — rather than relying on an automatic query optimizer, developers would proactively organize likely-to-be-reused subsets of records into named Sets, maintaining them as the underlying data changed, so that later queries against those groupings could be dramatically faster than re-running a full QUERY each time. This kind of manual technique demanded a solid understanding both of the 4D Sets/selection model and of the specific application's data access patterns, making it valuable but non-trivial guidance for database performance-conscious developers of the period. As only the on-page teaser text for this note survived in this archive, the specific cluster creation and maintenance code and examples are not available for further detail here — readers should also consult Part II (asset 37526) to see the technique put to use.
