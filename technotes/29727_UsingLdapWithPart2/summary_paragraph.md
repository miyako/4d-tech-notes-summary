This Tech Note is Part II of a series on using LDAP (Lightweight Directory Access Protocol) with 4D, following on from Part I (technical note 02-54, by Christian Cypert) which gave an overview of LDAP as an x500-standard-based directory service organizing data as a hierarchical Directory Information Tree accessed via Distinguished Names, in contrast to a relational database's table/record model. Part II presumably goes deeper into practical implementation — likely the actual 4D code needed to bind, search, and authenticate against an LDAP server. Only the short on-page teaser text could be recovered here, so the concrete implementation details are not available, but LDAP-based authentication was an important enterprise integration requirement for 4D applications in corporate/directory-service environments of the time.
