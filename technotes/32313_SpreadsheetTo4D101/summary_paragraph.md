Written by Sati Hillyer, a 4D Technical Support Engineer, this beginner-oriented technical note is a comprehensive survey of the ways 4D 2003/2004 can import Microsoft Excel spreadsheet data, framed around the common scenario of a business outgrowing Excel and wanting to migrate into a proper 4D database without manually re-entering everything. After explaining how to re-save Excel files into 4D-importable formats (CSV, tab-delimited TXT, SYLK, or DIFF), the note walks through four scenarios using an accompanying sample database: converting a spreadsheet into a brand-new 4D table (manually via the built-in 4D Import Dialog, or programmatically via the IMPORT DATA command with automatic table and form creation); importing new records into an existing table (manually, or programmatically using IMPORT SYLK/IMPORT DIFF, noting that CSV/TXT files can only be imported programmatically when not creating a new table); loading spreadsheet data into a 4D View plug-in area, either by opening a Tab-Delimited/SYLK file directly in 4D View or by mapping specific table fields into 4D View columns; and importing from Excel via ODBC on Windows, covering driver installation, ODBC data source setup, naming a range in Excel as a named table, and running the import through 4D's ODBC plug-in. A feature-by-feature compatibility table clarifies exactly which import capabilities (create table, use headers as field names, import into an existing table, import into 4D View) are available for each file format, both manually and programmatically.
