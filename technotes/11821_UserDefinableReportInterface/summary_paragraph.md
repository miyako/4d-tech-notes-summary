This Tech Note describes a technique for building a user-definable report and function interface in 4D, designed to scale gracefully as the number of reports in a system grows. Rather than calling reports directly from 4D menus (which becomes unmanageable with many reports), the approach stores report names and their associated method (procedure) names in the application data file. This metadata is used to populate a drop-down list from which users can choose reports to print or functions to execute. The system incorporates access control through 4D's password groups, ensuring each user only sees reports and functions their group allows access to. The principle works whether accessing reports from a dialog or functions from a detail form. This data-driven, metadata-based approach to UI construction was a sophisticated pattern for the 4D v6 era and represents a design philosophy that remains valid in modern development.
