This Tech Note by Tai Bui surveys the feature set of 4D View Pro as of v17R4, framing it as the 64-bit, object-based successor to the legacy 32-bit 4D View plugin, which the note explicitly calls deprecated given the industry-wide shift away from 32-bit support. It first covers three list box enhancements gated behind a 4D View/View Pro license: Variable Row Height (a `Longint` array bound to the Row Height Array property for per-row pixel control), Automatic Row Height (auto-sizing rows between configurable min/max bounds), and Object Type Arrays (assigning an object array to a list box column so each cell can carry its own `valueType` — text, real, integer, Boolean, color, or event — plus properties like `requiredList`, `choiceList`, and `alternateButton` to build dropdowns, combo boxes, and custom widget cells). It then describes the dedicated 4D View Pro form object ("4D View Pro Area"), contrasting its ribbon-style toolbar, contextual menu, and multi-sheet tab navigation with the classic 4D View area, and notes that document manipulation is instead driven by a family of commands all prefixed `VP` (create/open/save documents). The note walks through 4D View Pro's document structure (built around the Object data type), converting legacy 4D View documents to 4D View Pro format, and 4D View Pro Ranges — range objects for reading/writing cell data, named ranges, and formulas — plus programmatic reaction to document content changes. It closes by noting 4D View Pro's foundation on the third-party SpreadJS spreadsheet component. The note is squarely positioned as an onboarding/orientation document for developers migrating spreadsheet-style UI from legacy 4D View to the new 64-bit-compatible component ahead of 4D v17R5/v18, where 32-bit support was being dropped entirely.
