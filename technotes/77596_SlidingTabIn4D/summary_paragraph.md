This lengthy Tech Note (the longest in this batch) documents a "Sliding Tab" component that recreates the kind of horizontally sliding, swipeable tab/carousel interface common in mobile apps, implemented entirely within a classic 4D subform. It opens by motivating why a developer might want a sliding tab (compact space usage, modern look-and-feel) before detailing the architecture: a subform hosts variable objects (for pictures or text) plus scroll buttons, and a SlidingTab form method handles On Load, On Bound Variable Change, and On Timer events to animate the transition between tab "pages." The bulk of the note is a methodical walkthrough of the component's internal methods — stc_initSlidingTab, stc_loadSlidingTab, stc_resizePictureWidthHeight, stc_shiftObjects, stc_tabSelection, stc_varTabEventHandler, stc_updateInfoTabText, stc_setHeightTab/setWidthTab/setWidthInfoTab, stc_refresh, stc_getJSONSubformProperties, and stc_setEventInfoTab/unsetEventInfoTab — each explained with its role in initializing, resizing, and animating the sliding behavior, plus JSON-based property storage for configuration. This is a classic example of the pre-modern-UI-toolkit era of 4D: achieving a polished, app-like sliding interaction required substantial custom form-object manipulation, manual pixel-based resizing/shifting, and On Timer-driven animation loops rather than any built-in gesture or animation framework. While the component would still technically run in current 4D (subforms and these events still exist), 4D has since introduced richer built-in form objects, and web-based UI (via 4D's web area, or fully web/Qodly front ends with CSS/JS transitions) is now a far more common and less labor-intensive way to achieve equivalent sliding/carousel effects, making this note's approach largely of historical/reference interest rather than a recommended modern pattern.
