Thomas Maul, General Manager of 4D Germany, presents a 4D component — built with 4D Insider 2004.1, source included — that generates barcode pictures for a wide set of common 1D symbologies through a single command, Barcode_Create(barcodetype; code; createchecksum; showchecksum; printcode; {chartarea}), which returns a picture and supports optional checksum calculation/display and clear-text printing beneath the code. Supported types include Industrial 2 of 5, Interleaved 2 of 5, Code 39, Code 128 (subtypes A/B/C), EAN-8/EAN-13, UPC-A/UPC-E, and 2- or 5-digit supplemental codes, with a companion Barcode_Calc_Checksum method for computing/validating a checksum independently (e.g. to catch a mistyped EAN-8 number before printing). A substantial portion of the note is a detailed symbology reference: supported character sets and lengths per code type, real-world usage (USPS, LOGMARS/DoD, retail EAN/UPC), how UPC-A converts to the compressed UPC-E format, and — timely for its 2005 publication — the incoming 'Sunrise 2005' rules requiring all US/Canada point-of-sale systems to read EAN-8/13 in addition to UPC, plus GTIN's 14-digit leading-zero convention that the component automatically strips when printing. Internally, the component renders barcodes using a 4D Chart offscreen area (reusable across calls via CT New offscreen area for a roughly 2.7x speed improvement in the note's own benchmark), then upsamples the vector picture 3-4x and converts it to a bitmap (picture | picture, then scaled back down) to substantially improve print quality on inkjet printers, with six adjustable variables (Barcode_Width, Barcode_Height, Barcode_Add, Barcode_Font, Barcode_FontSize, Barcode_FontOffset) for manual tuning. An addendum notes commercial and free (GNU-licensed PostScript Type 1) barcode fonts as an alternative approach, while flagging the added burden of ensuring the fonts are installed on every client machine.
