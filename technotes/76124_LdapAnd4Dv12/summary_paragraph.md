This Tech Note introduces LDAP (Lightweight Directory Access Protocol) and explains why it matters to 4D developers, since Microsoft Active Directory and similar directory servers commonly expose an LDAP interface for storing usernames, passwords, and group information. Because 4D v12 has no native LDAP commands, the note relies entirely on the version's new PHP integration — the PHP Execute command — to call functions from PHP's built-in LDAP module. It walks through a reusable wrapper syntax for calling PHP functions with parameters and handling errors via PHP GET FULL RESPONSE, then demonstrates a "shared password system" example where a 4D application authenticates a username/password pair against an LDAP directory (using Active Directory in the sample), configured through an [LDAP_Preferences] table. It further explains that true single sign-on isn't achievable from 4D code alone (since 4D/PHP has no way to read an already-authenticated OS credential), but password-sharing against a central directory is achievable. A second example demonstrates read and write access to LDAP entries and attributes. The note is aimed at developers wanting to centralize credential management rather than maintain per-application user tables.
