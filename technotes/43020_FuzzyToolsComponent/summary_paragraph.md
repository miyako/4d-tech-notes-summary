This Tech Note documents the public, user-facing API of the FuzzyTools component for 4th Dimension, a compiled-methods component that packages a suite of fuzzy string-comparison tools behind roughly 20 exposed methods (versus 70+ internal ones), reducing complexity and making the toolkit easier to learn, update, and use safely across multiple projects. It explains the rationale for shipping the code as a component — reduced surface area, simplified updating, and a "gateway" error-checking architecture where a small number of protected routines validate all inputs before dispatching to private low-level workers that can then assume correct parameters — and notes the code is designed to run compiled with full variable typing rather than interpreted. The accompanying sample database offers four demo screens: "Show Words" for experimenting with phonetic and distance measures against ~15,000 surnames and ~5,000 place names; "Show People" for a duplicate-hunting report over 500 records with 50 known duplicate pairs (elaborated further in the companion TN 06-20 Data Cleaning and Deduplication); "Compare Strings" for interactively comparing two arbitrary strings across all supported algorithms; and "WordList Utilities" for comparing blocks of text by shared-word percentage. The core of the note documents the `Fuzzy_GetPhoneticKey` function, which generates a phonetic code using one of seven supported algorithms — Metaphone4, Metaphone6, Skeleton_Key, and four Soundex variants (Knuth, Miracode, Simplified, SQLServer) — with guidance that Metaphone4/6 are generally the best choices for English-language matching since Soundex produces many false positives and Skeleton_Key produces many false negatives; it also documents the companion `Fuzzy_GetPhoneticMethodTypes` function for discovering valid algorithm names at runtime. The note references its two companion technical notes — TN 06-18 Fuzzy Matching in 4th Dimension for the algorithmic internals and full component source code, and TN 06-20 Data Cleaning and Deduplication for applying the tools to real deduplication projects — positioning itself as the practical, task-oriented middle document of a three-part series. As a whole, this note is a solid worked example of API design and component packaging for 4D, wrapped around genuinely useful, still-valid string-matching algorithms, but the FuzzyTools component itself is a period third-party artifact rather than a built-in or currently maintained part of 4D.
