This Tech Note covers how to perform SQL dumps in 4D v12 — the export of a database's data in a standard SQL-statement format, analogous to mysqldump, Oracle's exp, or PostgreSQL's pg_dump. It notes that while 4D v11 SQL introduced a powerful new embedded SQL engine, it did not include dump/export capability; 4D v12 completes that picture by adding three new commands: SQL EXPORT DATABASE (exports the entire database's data as a SQL dump), SQL EXPORT SELECTION (exports just the current selection of a specified table), and SQL EXECUTE SCRIPT (imports a SQL dump back into 4D). The note details the usage of each command in turn, then walks through a complete included sample: a sample database, an example of exporting the entire database, an example of exporting a table selection, an example of importing the resulting data, a sample structure definition, and a sample SQL dump file for reference. It targets 4D developers who need standards-based data export/import for backup, migration, or interoperability with other SQL-based systems and tooling.
