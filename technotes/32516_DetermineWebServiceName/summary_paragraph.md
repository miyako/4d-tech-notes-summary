This Tech Note addresses a practical need that arose once 4th Dimension 2003 gained the ability to publish project methods as SOAP-based Web Services: reliably determining, from inside the called method, the name of the method or Web Service that was actually requested. Such information is valuable for developers implementing custom security checks, audit logging, or shared dispatcher-style methods that need to branch behavior depending on which Web Service endpoint was invoked. The note explains the built-in behavior and limitations of 4D's native `Get Soap info` command, which provides some but not all of the identifying information a developer might need. To fill that gap, the note describes custom code that inspects the incoming HTTP request and extracts the SOAP method/service name directly from the `SoapAction` HTTP header, when present, since that header is set by SOAP clients to indicate the target action. The featured technology is squarely 4D's early-2000s SOAP Web Services stack, built on the native 4D Web server rather than any external SOAP toolkit. As with other Tech Notes from this era, it ships with a downloadable example database (Windows/Mac) demonstrating the technique in a runnable form. The note is a small, focused utility-pattern guide rather than a broad architectural piece, aimed at developers already using 4D's Web Services publishing feature who need finer-grained request introspection than `Get Soap info` alone provides.
