Written by David Adams, this technical note addresses a specific gap in 4th Dimension 2003's SOAP Web Service publishing: while the native Get SOAP info function reliably returns the requested method name (via the SOAP Method Name constant), it cannot reliably return the Web Service name, because in 4th Dimension 2003.2 and later Get SOAP info always returns an empty string for the SOAP Service Name constant (and behaved unpredictably, sometimes generating errors, in earlier 2003 versions). The note explains why: unlike the method name, the Web Service name simply isn't present anywhere in the SOAP XML request body itself. As a workaround, it shows how to extract both the Web Service name and the method name from the optional SoapAction HTTP header (formatted as "ServiceName#methodName"), which sits outside the SOAP XML payload as a standard HTTP header. Full code is provided for a GetSoapAction helper method (with public wrappers GetSoapAction_MethodName and GetSoapAction_WebServiceName) that reads the incoming HTTP headers with GET HTTP HEADER, locates SoapAction, strips its surrounding quotation marks, and splits it at the "#" character. The note closes with caveats: the SoapAction header is optional and may be absent, there's no guarantee it matches the method actually specified in the SOAP body, and the header itself was dropped from the later SOAP 1.2 specification even though 4th Dimension 2003 (like most tools of the era) implements SOAP 1.1.
