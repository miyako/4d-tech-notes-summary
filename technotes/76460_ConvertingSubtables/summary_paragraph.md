This Technical Note by Darrell Draper provides a migration path for 4D developers still relying on subtables, a feature no longer supported starting with 4D v11 SQL, where databases created in 4D 2004 or earlier have their subtables automatically converted to standard tables linked by a special compatibility relation upon upgrade. While this compatibility relation lets legacy code keep functioning, the note stresses that the relation and its associated commands are deprecated, will eventually be phased out of 4D entirely, and will no longer receive bug fixes or improvements — unlike standard table commands, which continue to be actively developed — making migration away from subtables a strategic imperative rather than an optional cleanup. The note walks through one concrete process for the migration (acknowledging alternative approaches exist and that the guide can be adapted for databases already upgraded to v12): changes to the database structure, updates to affected forms, and fixes to queries and other commands that previously relied on subtable-specific relationships. It closes with final steps to complete the transition safely and with minimal end-user impact, framing the whole document as a flexible guide rather than a single rigid procedure, since different use cases and legacy structures may call for different specific steps.
