Written by Jean-Yves Fock-Hoon, 4D's Q.A. Manager, this is the second of two Tech Notes on building a custom Quick Report wizard, following on from a first note that covered list-format reports; this installment extends the same `Wizard_Start`/`Wizard_Changepage`/`Wizard_OnCommand` framework to generate cross-tab reports on the `[Invoice Lines]` table. It introduces a 3x3 cell-naming convention for cross-tab reports (cells A through I, arranged as three columns by three rows) used to explain which column-number/break-level parameters a given QR command needs -- for example, using `QR SET TOTALS DATA` on cell F requires column 3 and break level 2. The wizard walks the user step by step through selecting the report type and table (`QR SET REPORT KIND`, `QR SET TABLE`), then defining data sources for columns (cell B), rows (cell D), and the calculated cell value (cell E) via `QR SET INFO COLUMN`, with `QR GET INFO COLUMN` first called to preserve properties like column width that shouldn't be reset by a new data source assignment. It explains how a cross-tab report is actually computed internally -- 4D parses every record, builds internal arrays for each unique column/row value, and applies the chosen aggregate (Sum, Count, Min, Max, Average) to populate each cell -- and details the semantics of the optional Total column (cells C/F) and Grand Total line (cells G/H/I), noting that their values are computed independently from the raw data rather than as an average of the displayed row/column averages. The note closes with sorting via `QR SET SORT`, display-format characters (`#`, `0`, `*`, `^`) applied per-cell-type (B/D/E), and per-cell style attributes such as font selection via `FONT LIST`/`Font number`.
