This note revives and updates a component originally published on the 4D blog for building a web-based 4D Server administration dashboard, refreshed to take advantage of newer server APIs available by v19 R6. It targets headless server deployments where a native Administration window isn't practical, letting developers monitor connections, memory, processes, and settings through an ordinary web browser at a URL like http://127.0.0.1:8081/admin/ini. Installation requires enabling "Execute on host database event method of the components" in the host database's structure settings and copying the component into the Resources folder, after which the component's On Host Database Event method registers a set of shared-object route definitions (Storage.obWebAPI) exposing endpoints such as /admin/ini, /admin/users, /admin/processes, and /admin/settings. Because 4D since 18 R3 supports multiple independently configurable web servers, the component runs its own dedicated WEB Server instance rather than colliding with the host application's main web server, started conditionally via the WEB Server command and an On after host database startup event. Data collection methods use GET MEMORY STATISTICS for memory breakdowns, Get process activity for the users/processes lists, and CALL WORKER to run cooperative worker tasks that drop or message a connected user/session — a pattern that avoids blocking the calling web process. The note positions this as an evolving, customizable starting point rather than a finished product, explicitly inviting developers to extend it release over release.
