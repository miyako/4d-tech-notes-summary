Written by Frank Chang of 4D Technical Support, this technical note demonstrates how to let end users programmatically switch between multiple 4D data files sharing a single structure file, rather than requiring them to quit 4D and hold down Alt (Windows) or Option (Mac) at launch to pick a different data file. The accompanying sample database's On Startup method determines the current data file's name (via a platform-aware Get_Name method that parses the path using the correct delimiter for Windows vs. Mac) and opens a simple interface with List and Open buttons. Clicking List invokes the Select Folder command to choose a directory, then DOCUMENT LIST to enumerate its contents, filtering for files with the platform-appropriate 4D data file extension (.4dd on Windows, .data on Mac) via a Do_Loop helper. Selecting a file and clicking Open calls OPEN DATA FILE, which shuts down and relaunches 4D with the chosen data file bound to the current structure file (after warning the user if they picked the file already in use). The note also covers the WEDD resource, configured via 4D Customizer Plus with a matching signature value on both structure and data files, as a mechanism for ensuring only intentionally paired data files can be opened with a given structure file, preventing accidental mismatches.
