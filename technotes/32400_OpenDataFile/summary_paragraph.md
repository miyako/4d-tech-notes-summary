This Tech Note demonstrates how to programmatically open different 4D data files from within a running 4D application, addressing the increasingly common need for personalized or per-user data sets built on a single shared structure (application definition) file. Rather than requiring end users to manually quit 4D, browse the filesystem, and reopen the structure file while selecting a different data file — an error-prone and unintuitive process for non-technical users — the accompanying example database implements a simple mechanism that presents a list of available data files and automatically relaunches 4D with the user's selection. This pattern is particularly relevant to vertical-market or multi-client deployments where a single 4D structure file needs to serve multiple distinct data sets (for example, per-client or per-project databases) without duplicating the application logic itself. The featured technique centers on 4D's classic Design Mode-era architecture, in which a binary structure file (.4DB/.4DC) defines the application while a separate data file (.4DD) holds the actual records, and the note leverages 4D's command-line/relaunch capabilities to reopen the structure file bound to a newly chosen data file. As with other notes of this era, it ships as a downloadable example database for both Windows and Mac. The proposition is squarely about improving end-user experience around structure/data file separation, a foundational but often under-documented aspect of the 4D architecture at the time.
