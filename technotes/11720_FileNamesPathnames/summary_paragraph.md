This Tech Note by ACI US Technical Support explains that document (file) names and pathnames follow different rules on Windows versus Macintosh, then provides two reusable, platform-independent 4D utility routines to handle both conventions transparently. It describes the Windows rules of the era — DOS limiting names to 8 characters plus a typically 3-character extension, while Windows NT 3.5.x/upcoming 4.0 and Windows 95 allowed up to 255 characters, with paths formatted as `DriveLetter:\DirectoryName\...\DirectoryName\` — versus the Macintosh rule of a flat 31-character file name limit regardless of OS version, with paths formatted as `VolumeName:FolderName:...:FolderName:`. It stresses that 4D developers writing utility subroutines dealing with document names/pathnames should build in platform independence from the start, especially since code is often moved between projects using 4D Insider. The note supplies an example database ("Paths & Names") with two demonstrations: opening a document via a standard file dialog and displaying its extracted name and pathname (showing that on Windows the file extension is stripped from the returned "name"), and saving multiple documents (ten) to a chosen folder using a base name, with Windows correctly re-appending the file extension. On the source-code side, it explains that 4D returns a document's long name into the `Document` process variable after any standard open/create/save dialog, and that the `MAP FILE TYPES` command helps generically convert between Mac file types and Windows file extensions; it also supplies small support routines — a `STARTUP` procedure setting debug and platform flags, an `Is Compiled` function, and an `On Windows` function using `GET PLATFORM INFO` — before presenting the two headline routines: `Path to name`, which strips the pathname (splitting on the platform-appropriate separator) and, on Windows, also strips a 3-character file extension, to return just the document's short name (with an explicit caveat that it assumes 3-character extensions); and `Path only path`, which returns everything up to and including the last separator as the pathname. Worked examples show these routines used in a "Test one document" menu command (displaying a chosen document's name and location in an alert) and a "Save Multiple" menu command (creating ten numbered documents at a chosen location). As a foundational cross-platform utility note tied to classic Mac OS's 31-character names and DOS-era 8.3 extension assumptions, its specific file-naming constraints are entirely obsolete on modern operating systems with long file name support, though the broader engineering discipline of writing platform-abstraction code for a cross-platform 4D application remains a conceptually sound practice.
