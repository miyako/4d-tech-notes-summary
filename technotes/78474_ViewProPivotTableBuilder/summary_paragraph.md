This tech note tackles a common business-intelligence need — summarizing large flat data tables into pivot tables (rows, columns, aggregated values) — by walking through a from-scratch pivot table builder implemented with 4D View Pro and ORDA. The UI uses four cascading dropdowns (table, rows field, columns field, values field) populated dynamically: table names via `GET TABLE TITLES`, field names via `OB GET PROPERTY NAMES` on an ORDA dataclass, and value labels prefixed with "Sum of" or "Count of" depending on whether a field is numeric (aggregated by sum) or non-numeric (aggregated by count). Selecting a table loads its entity selection once via `ds[tableName].all()` for reuse across subsequent calculations, embodying idiomatic ORDA usage (`ds` datastore object, dataclass, entity selection). As selections cascade, the builder resets the View Pro document using `VP DELETE COLUMNS`/`VP INSERT COLUMNS` (rather than a full `VP NEW DOCUMENT`) so multiple pivot tables can coexist on separate sheets, and the logic branches to handle four scenarios: no rows/columns, rows only, columns only, and both rows and columns, building up the summarized grid procedurally. Collections are used throughout in preference to arrays for their built-in methods like `.push()`. The note frames this as an educational exercise in combining ORDA data access with the newer v18R2 View Pro manipulation commands to build a reusable spreadsheet-analysis feature entirely inside a 4D application, without needing an external BI tool.
