This Tech Note is an operational/deployment guide rather than a coding tutorial: it explains the three main ways a 4D database or 4D Server application can be run in production. The 'user executed application' model is the familiar double-click launch with full GUI. The 'as a Service' model (Windows-only) registers 4D Server to run in the isolated Session 0, configured through the Windows Services console with Startup Type options (Automatic, Automatic Delayed Start, Manual, Disabled) and a dedicated Log On account, giving high availability across reboots at the cost of no accessible GUI. 'Headless mode' is presented as the newer, cross-platform (macOS and Windows) alternative, launched via CLI arguments such as --args, --structure, --data, and --headless, with the LOG EVENT command's 'Into system standard outputs' selector used to route Information/Warning/Error messages to stdout and stderr, which can be redirected or merged to log files using standard shell redirection syntax (1>, 2>>, 1>&2). The note also covers administrator-facing features — the Administration window (accessible from a connected 4D Remote client's Help menu even when the server itself is headless/serviced), two-way interactions (toggling Web/SQL servers, managing users/processes, enabling logs) versus one-way/read-only monitoring (uptime, memory, request/web logs, email notifications, OS event viewers). It closes by comparing tradeoffs: user-executed apps are simplest/most familiar, Windows Services provide automatic restart-on-reboot at the cost of GUI access, and headless mode offers the most cross-platform control at the cost of more setup effort.
