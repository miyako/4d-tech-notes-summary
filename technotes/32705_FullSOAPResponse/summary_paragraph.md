Written by David Adams, this technical note explains how to bypass 4th Dimension's automatic SOAP response handling in order to inspect the raw XML of a Web Service response, which is useful for debugging, reading values not automatically bound to 4D parameters or arrays, or simply learning more about the SOAP protocol underlying 4D's Web Service client. It contrasts the default "Web Service Dynamic" mode of CALL WEB SERVICE, where results are read individually with GET WEB SERVICE RESULT calls tied to named output elements, with the "Web Service Manual Out" mode, where the same call instead returns the entire SOAP message body as a single BLOB that can be examined directly, saved as text, or parsed with Parse XML variable. A worked example shows a SOAP proxy method returning three named values (a longint, a real, and text) and demonstrates both retrieval styles side by side against the same underlying XML response. The note then shows how to extract specific values from the manually retrieved XML using the companion XML_Utilities component's xutil_GetValue function, and enumerates several practical advantages of the manual approach, including easier debugging when a SOAP server renames or adds elements, and avoiding errors thrown by GET WEB SERVICE RESULT when an expected element is missing. It closes with limitations: the manual BLOB only captures the SOAP message body (not headers or surrounding HTTP metadata), and a SOAP fault response yields no results at all under either technique.
