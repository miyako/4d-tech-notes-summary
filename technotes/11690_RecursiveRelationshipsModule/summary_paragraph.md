This February 1996 Tech Note by Forrest Swilling builds directly on an earlier 1990 Tech Note ("Two-File Hierarchical Filing System" by Ron Dell'Aquila, TN 90-205), which introduced the classic 4D two-file recursive relationship pattern using an [Objects] file for data and a [Links] file to maintain parent-child relationships — a structure well suited to modeling computer file systems, genealogies, help systems, bills of materials, or multi-level marketing hierarchies at unlimited depth. This note extends that foundation with a full module of five reusable procedures: FindBranch (finds all records subordinate to a given node by repeatedly using PROJECT SELECTION and JOIN to walk downward, accumulating results in a 4D Set via UNION), FindNonBranch (the complement — finds everything not subordinate to a node, using DIFFERENCE against the branch, orphans, and the start node itself), FindNextLevel (returns only the immediate next level of children, a simpler subset of FindBranch), FindOrphans (finds any record disconnected from the tree, useful for a maintenance UI), and FindTop (finds the single topmost/root record by comparing arrays of child and parent IDs via SELECTION TO ARRAY and Find in array, with notes on adapting it for multi-root trees like a help system with multiple entry points). The note explains a subtlety of the JOIN command: because JOIN doesn't take an explicit field parameter, when multiple relations exist between two files, 4D uses the first relation in field order, so the field order within the [Links] file directly affects behavior — an important gotcha the module's design accounts for. It closes with implementation notes suggesting adaptations for web-site file-structure emulation or help-system "more available" indicators. As a fully readable full-PDF Tech Note, this summary reflects the complete document, using an example genealogy of 1960s B-movie actors to illustrate each procedure.
