Since the introduction of 4D v11 SQL and prior to 4D v11 SQL 11.3, the only way to exchange data between two 4D databases was through the 4D v11 SQL ODBC driver or through dedicated Web Services. Using ODBC as the communications channel there were significant limitations and a speed tax imposed. Using Web Services as the communications channel there is significant time consuming development involved. Beginning with 4D v11.3 SQL there is now a native communications channel between 4D Servers and 4D Professional applications that provides great flexibility and a huge boost in communications speed. Published November 25, 2008 as Technical Note 08-41 for 4D v11.3 (Mac &amp; Win), this note was written by Charles Vass, Technical Services Team Member, 4D Inc. during the 4D v11 SQL era, when 4D's newly integrated SQL engine (introduced 2007) and the 4D Ajax Framework (4DAF) for AJAX-based web UIs were the platform's flagship modern capabilities. It reflects the pre-ORDA, pre-Project-Mode 4D development model, in which the binary Design Mode structure file was the only structure format and 4D's own SQL layer was still new relative to the classic procedural/set-based language that had defined 4D since the 1980s.
