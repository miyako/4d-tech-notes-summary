Written by Roland Lannuzel of 4D S.A., this technical note addresses a specific gap between 4th Dimension's two selection mechanisms: Sets, which are non-sorted bitmap selections supporting union, intersection, and difference operations natively, and named selections (introduced in version 6), which are more memory-efficient for small selections in large tables but lack any built-in set-style combination operations. The note explains that named selections are, under the hood, simply arrays of record numbers (the same numbers returned by Record Number and accepted by GOTO RECORD), and that the commands LONGINT ARRAY FROM SELECTION and CREATE SELECTION FROM ARRAY provide the bridge between named selections and ordinary longint arrays. Building on that insight, it presents a family of generic, pointer-based methods, 4DARR_Union, 4DARR_Intersection, 4DARR_Difference, and related helpers, that perform set-style operations on any pair of same-typed arrays (string, text, real, integer, longint, date, boolean, or picture arrays), using helper routines like 4DARR_CheckParam for type validation and 4DARR_BuildArraysCheck to efficiently identify common elements via a bounded Find in array loop. It then shows a thin wrapper layer (4DSEL_UNION and similar) that converts named selections to arrays, applies the chosen array operation, removes duplicates with 4DARR_DistinctValues, and rebuilds a named selection from the result, giving named selections the same union/intersection/difference/exclusion capabilities long available for Sets, while explicitly warning that CREATE SELECTION FROM ARRAY is a low-level command requiring valid, unique record numbers.
