This Tech Note demonstrates how to reduce the quality of an image (pixelate it) using a combination of native 4D commands, a hidden Web Area running JavaScript, and SVG drawing — useful for protecting full-resolution images from non-paying users or obscuring identities in shared views. The technique divides an input picture into a grid of cells whose dimensions are determined in 4D, converts each chunk to Base64, and builds an object passed into a hidden Web Area to execute a JavaScript function (color_avg.js) that uses HTML5 Canvas image data to compute the average color of each chunk — capability not available through native 4D commands at the time, so the Web Area is used purely as a JavaScript execution sandbox that can be inspected for errors/console logs during development. The averaged color values are stepped through back in 4D and used to draw solid-colored rectangles with SVG_New and SVG_New_rect, reconstructing a pixelated version of the original image entirely out of colored blocks. The resulting SVG is exported via DOM Export to VAR, the Web Area is closed (DOM CLOSE), and the SVG is decoded (XML Decode) and converted into a usable picture with BLOB TO PICTURE, which is then saved into the database as the new pixelated image. A bonus form, "Pixelizer_Area," lets a user select just a rectangular region of an image to pixelate while leaving the rest untouched, combining the pixelated region back into the original. The note positions this as a way to extend 4D's native image capabilities using JavaScript for calculations not otherwise implemented in 4D.
