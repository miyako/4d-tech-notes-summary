Written by David Adams, this Technical Note addresses a query optimization for fuzzy string searches implemented via the FuzzyTools component (previously introduced in Tech Notes 06-18 and 06-19), motivated by the observation that users increasingly expect Google-like tolerance for imprecise search input (e.g., finding "Jon Smithe" via a search for "John Smith") that 4D's built-in QUERY tool cannot provide out of the box. It explains the two core string-similarity algorithms used — Edit Distance (Levenshtein distance, counting the additions/deletions/substitutions needed to transform one string into another) and Longest Common Subsequence (LCS, finding the longest ordered, non-contiguous matching character sequence) — with worked examples ("kitten"→"sitting" has an edit distance of 3; "John Anderson" vs "Jon Anderssen" has an LCS of 11, yielding a more human-intuitive ~85% similarity than a substring-based comparison would). Since fuzzy comparisons cannot be indexed and must be performed sequentially across a selection, the note's central optimization insight is that a string's length constrains which other strings can possibly match under a given edit-distance or LCS threshold, so pre-querying an indexed numeric field storing each string's length can eliminate impossible candidates before the expensive sequential fuzzy comparison runs. This principle is implemented as new optional parameters on the updated FuzzyTools routines Fuzzy_FindByEditDistanceCount and Fuzzy_FindByLCSLength, which accept a pointer to a string-length field and automatically perform a QUERY SELECTION to narrow the candidate set first. The note also discusses complementary "blocking" strategies for reducing the initial selection (querying on a reliable field first, random sampling of large datasets, or phonetic-encoding pre-filters) and notes that four other US Census-derived similarity algorithms in FuzzyTools do not receive this optimization because no generalized length-bound formula exists for them. A demonstration database with over 15,000 sample surnames and the updated FuzzyTools component source/component file are included as accompanying materials, and the featured technology throughout is the FuzzyTools component, its edit-distance/LCS routines, and 4D's QUERY SELECTION and SELECTION TO ARRAY commands used to keep network traffic low under 4D Server.
