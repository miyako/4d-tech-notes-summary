This Technical Note (26-07, published July 29, 2026, compatible with 4D v21 R3+) addresses a gap left by ORDA: unlike classic selections, which have long relied on the simple `ORDER BY`/`TRI` command, ORDA entity selections have no native mechanism for building complex, multi-criteria sorts dynamically. The solution is a modular, no-code sort editor centered on a `Lib_Mod2` class that acts as the business-logic hub between a project form (`fm_mod2_orderBy`) hosting an embedded Web Area and the underlying 4D engine. Users visually assemble sort criteria from three categories of drag-and-drop "modules" — table, field, and direction — with real-time positional validation that prevents invalid combinations, then apply the resulting structure via `orderBy()`, which accepts either a pointer to a table (classic mode, driving the `TRI` command) or a reference plus path to an ORDA entity selection, with the graphical experience identical either way. Sort definitions can be saved/reloaded as portable `.4od` files, enabling reuse and sharing across users or applications. Communication between the JavaScript-based editor and the 4D business logic runs entirely over the `$4d` bridge, with JSON-serialized payloads, while an i18n JavaScript library (distinct from 4D's native XLIFF mechanism, which doesn't reach embedded Web Areas) handles interface localization. The note frames the architecture as generic and extensible, calling out current gaps (no formula-based/calculated sort criteria, no field selection via relations) as areas for future development, and positions the whole system as a drop-in library requiring no external runtime dependencies.
