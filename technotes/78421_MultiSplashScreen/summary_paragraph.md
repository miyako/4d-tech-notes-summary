4D has long supported a single static splash screen image at application startup, but this tech note extends that with a sample database that randomly picks from a developer-curated set of splash images each time the app launches, adding variety without extra effort per release. Developers upload candidate images into the database's Picture Library, then run a provided "Splash Image Chooser Form" method that lists every picture with checkboxes, letting the developer mark which ones should be eligible splash images; the selections are persisted as a `splash.json` file in a `Splash` folder inside the database folder using `JSON Stringify`/`Document to text` and reloaded via `JSON Parse` on subsequent form opens, so previously checked images stay checked. The sample handles edge cases robustly: pictures added to the library since the last save appear as new unchecked rows, pictures deleted from the library are removed from the saved JSON, and pictures renamed in the library have their saved entries updated to match, all reconciled against the live `PICTURE LIBRARY LIST` output. At startup, the `On Startup` database method reads `splash.json`, picks a random eligible image, resizes oversized images for a consistent splash window size, and routes the image to one of two splash forms depending on picture type — a standard `splash_screen` form using a variable object for static images, or a `Gif_splash` form using a Web Area to properly render animated GIFs. Additional per-form behaviors covered include auto-dismissing the splash window after a timer or on click, and adding a clickable URL link (e.g., to the company website). The note positions this as a reusable, customizable foundation — e.g., for per-user/group splash targeting, rotating image transitions, or contextual splashes during long-running tasks — built entirely from standard 4D form, Picture Library, and JSON APIs.
