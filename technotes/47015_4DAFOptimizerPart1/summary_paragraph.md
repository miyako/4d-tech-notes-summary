This Technical Note introduces the 4DAF Optimizer, a standalone tool built for 4D developers who embed 4D Ajax Framework (4DAF) objects into custom HTML pages, designed to strip out unnecessary JavaScript files from the framework's 'js' folder and thereby speed up page load times. The tool works in two steps: first, the developer selects which 4DAF objects and features their application actually uses from a checklist — "Core" files that are always required, the full "Client" bundle (the default 4DAF front end, selectable only as a whole), individual "Objects" (Calendar, Data Grid, Data Tree, DDW, Data/Image Matrix), and standalone "Features" (Hierarchical List, Sidebar, Taskbar) — after which clicking "Generate" builds a new, trimmed 'js' folder (including a rebuilt 'framework.js' that only loads the necessary files) in the application's Extras folder. Second, the developer copies that new 'js' folder into the correct location relative to the database's Default HTML Root (typically \dax\js), overwriting the existing contents. The note walks through three of the 4DAF demo applications bundled with the Web 2.0 Pack 1.1 installation as worked examples — the 4D Jukebox (uses only Data Grid), Vacation Tracker (uses Data Tree and Calendar), and Contacts (uses Data and Image Matrix) — and flags that each demo's homepage HTML must be edited afterward to reference 'dax/js/framework.js' instead of the original 'dax/js/compile.js'. It closes by noting that a future version of the 4DAF Optimizer (implied to be covered in a later "Part 2") would add support for Templates and Localization, which were not yet handled by this initial release.
