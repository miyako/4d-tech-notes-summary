Charles Vass's Tech Note tackles a practical Client/Server administration problem: users who leave 4D running in Remote mode for long stretches without activity, tying up server licenses and resources. The note presents a technique combining an 'internal' notification mechanism (a background process that tracks 4D-level user interaction) with an 'external' notification mechanism (OS-level idle-time detection on Windows and Mac OS X) to more reliably determine true user inactivity beyond just 4D's own event loop. It walks through the individual parts of both the internal and external detection approaches, explains how a countdown dialog warns the user before disconnection, and shows how the technique programmatically quits 4D in Remote mode once the configured idle timeout has fully elapsed. An implementation section ties the pieces together into a working solution developers can adapt. The result is a self-contained idle-session watchdog for Client/Server 4D deployments.
