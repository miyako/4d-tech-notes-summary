# Tech Note 06-41: Debugging XML with Export

**Author:** David Adams
**Published:** November 13, 2006 | **Product/Version:** 4D v2004 | **Platform:** Mac & Win
**Page:** https://kb.4d.com/assetid=44687
**Download:** https://kb.4d.com/DLTN/TN/2006/Windows/TN_2006_40-43_(NOV)/06-41_Debugging_XML_Export.zip

## Overview
4th Dimension's DOM XML commands build XML as an internal tree of linked nodes rather than text, so the document is essentially invisible until serialized. This note shows how to use the `DOM EXPORT TO VAR`/`DOM EXPORT TO FILE` commands to dump the current state of a DOM tree at any point, dramatically easing debugging of hand-written XML-building code and of the denser proxy code generated by the 4D 2004 Web Service Wizard for SOAP calls.

## Key Points
- DOM XML in 4D is a structured tree of nodes (name, value, attributes), only converted to a final text document on export/serialization.
- A worked example builds a `<contact>` document with business/home phone elements using `DOM Create XML Ref`, `DOM Create XML element`, and `DOM SET XML ELEMENT VALUE`.
- SOAP proxy code auto-generated by the Web Service Wizard is denser and harder to reason about, making tree visibility even more valuable there.
- The note's `DOM_DumpTreeToClipboard` utility calls `DOM EXPORT TO VAR` and appends a labeled snapshot of the tree to the clipboard at each step, producing an easy-to-read trace of how each command changes the XML.
- Full code for `DOM_DumpTreeToClipboard` is provided (simple, "quick-and-dirty," limited by 4D text variable size limits).
- A special caveat: `DOM EXPORT` always adds a full XML prolog since it must produce a legal standalone document, but `SET WEB SERVICE OPTION` (SOAP Header) does not insert a redundant prolog into the actual SOAP message — so an apparently duplicate prolog seen while debugging a SOAP header tree is not really a bug.
- Concrete SOAP request/response XML samples (with and without a custom `<credentials>` header) illustrate this prolog nuance.

## Featured Technology
- 4D DOM XML commands (Create XML Ref, Create XML element, SET XML ELEMENT VALUE)
- DOM EXPORT TO VAR / DOM EXPORT TO FILE
- SET WEB SERVICE OPTION and SOAP headers
- 4D 2004 Web Service Wizard (SOAP proxy code generation)

## Historical Context
Published for 4D 2004, in an era when SOAP (not REST/JSON) was 4D's primary web-services integration mechanism, and years before 4D's native SQL engine (v11, 2007), Project Mode (v17), or ORDA existed. The debugging philosophy — serialize/dump intermediate program state to inspect it — is timeless, but the specific SOAP/DOM tooling is a relic of a bygone integration approach.

## Historical Commentary
**Status:** Superseded

The DOM XML commands and Web Service Wizard-generated SOAP proxy code central to this note reflect 4D's mid-2000s web-services approach, which has been largely superseded by REST and JSON-based integration in current 4D development; SOAP support still exists in 4D but is rarely the default choice for new projects today. The general debugging technique of dumping intermediate state for inspection remains valid and applicable in any era, even if the specific commands and workflow shown are dated.
