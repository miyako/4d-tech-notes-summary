Written by Xiang Liu, this Tech Note is an in-depth guide to `dataClass.query()`, ORDA's method for retrieving an `entitySelection` based on a query string built from `attributePath comparator value {logicalOperator attributePath comparator value}` segments, contrasted directly with the classic 4D `QUERY`/`QUERY BY ATTRIBUTE` commands. Using a `People`/`HealthRecord` example schema, it shows how `query()` collapses what would require multiple `QUERY`/`QUERY BY ATTRIBUTE` calls into a single readable string — e.g., `ds.People.query("firstName in :1 AND healthRecord.additionalInfo.prescription[].drugName in :2 AND ...", new object("parameters"; new collection(...)))` — and highlights three key ergonomic advantages: single-string search criteria construction (useful for building queries programmatically), dot-notation `attributePath` for multi-level relation traversal (e.g., `department.city.name`) that is more readable than nested `QUERY` calls, and native support for passing multiple values via `IN`/collections rather than chained OR queries. The note then moves into best practices "gathered through my own experience and not currently documented," starting with the `NOT` comparator, showing algebraically how `NOT (lastName = Smith OR lastName = Blazer AND firstName = Aaron OR ID > 3)` is logically equivalent to rewriting each comparator/operator (e.g., `#` for not-equal) and reversing precedence — a subtlety the author warns is easy for developers to misjudge. Later sections (per the table of contents) cover the `EXCEPT` logical operator for joined queries, using `IN` with a collection to narrow query scope, correctly querying attributes holding a Null value, and ordering query results, alongside a review of `querySettings` options like `queryPath` and `queryPlan` for introspecting query execution. The note is positioned as an advanced companion to 4D's official ORDA documentation, aimed at developers who already know the basics of `query()` but want to avoid subtle logic errors and unlock lesser-known capabilities for building precise, performant ORDA queries.
