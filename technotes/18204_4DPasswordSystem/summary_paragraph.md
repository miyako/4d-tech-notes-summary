This Tech Note (TN 01-41, 4D v6.7, Mac & Win, published September 30, 2001) by Jean-Yves Fock-Hoon, Quality Assurance Manager at 4D, Inc., is a comprehensive tour of 4D's built-in, structure-file-embedded password and privilege system. It explains that every structure file actually maintains two parallel user/group stores -- the Designer's system (tied permanently to that structure file) and the Administrator's system (portable between structure files via Save Groups/Load Groups) -- and walks through how Access and Owner group assignments gate who can load or edit specific forms, methods, menu items, licensed plug-ins, and per-table record operations (load/add/modify/delete), each enforced with a Privilege error if the current user isn't a member of the required group. The note explains the special status of the Designer account (always a member of every group, and the default login when no password is set), the Database Properties options for 4D Open Access/Structure Access/User Mode access/Default User, and demonstrates the accompanying User_and_Groups example database's use of commands like GET USER LIST, GET USER PROPERTIES, Set user properties, GET GROUP PROPERTIES, and Set group properties to build a full user/group management UI. It closes with a worked example of layering custom logic on top of the built-in system: a Users table tracking forced password expiration and account lockout, using CHANGE PASSWORD/Set user properties and the Validate password command to implement password-history checks and complexity rules that 4D's native system doesn't provide out of the box.
