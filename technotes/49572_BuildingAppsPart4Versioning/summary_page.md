# Building Applications Examples – Part 4 Versioning

## Overview
Part 4 of a five-part XML-keys tutorial series, this note focuses on the versioning-related XML keys available in the 4D 2004-era Build Application dialog's underlying project file — covering how build numbers, version strings, and related metadata are expressed as XML keys and edited through the companion GUI project-file editor introduced earlier in the series, so a shipped application correctly reports its version to end users and update mechanisms.

## Key Points
- Published April 23, 2008 as Technical Note 08-15.
- Targets 4D v2004.7r3 on Mac & Win.
- Author: Josh Fletcher, Technical Services Team Member, 4D Inc..

## Featured Technology
- 4D 2004 Build Application XML keys
- Versioning metadata
- XML project file
- Custom GUI editor tool

## Historical Context
Part of a well-documented five-part series on 4D's XML-based build configuration system from the mid-2000s; while the specific 80+ key XML format described here (4D 2004 era) has been superseded, the general idea of declarative, versioned build configuration persists in modern 4D's build/compile settings.

**Status:** superseded

**Related updates:**
- 4D's application build and versioning configuration has been substantially modernized in later 4D versions, moving away from this specific XML-key project-file format
- Project Mode (2018+) introduced a fully text-based, git-friendly project structure that further changed how build settings are stored and versioned
