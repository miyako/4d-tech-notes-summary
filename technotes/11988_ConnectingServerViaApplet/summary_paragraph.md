Written by Jonathan Baltazar of 4D, Inc. Technical Support, this Tech Note explains how to connect a Java client interface to a 4D Server using an applet built with 4D Open for Java, the then-new Java API/library for connecting Java programs (standalone or applet) to a 4D Server. It first covers installing the 4D Open for Java classes correctly — keeping the database, the .java/.html/.class files, and the "Aci" folder of 4D Open classes together in the same folder, since compilation fails with unresolved-command errors otherwise. The core of the note addresses why an applet run via appletviewer (Windows) or dragged onto Appletrunner (Macintosh) can connect fine to a server on the same machine (127.0.0.1) but fails to reach a separate Mac or Windows server: Java's SecurityManager, by default, only permits an applet to reconnect to the host that served its .class file, and this restriction is normally satisfied transparently in a full web browser but not in a bare appletviewer. The note walks step-by-step through using Sun's policytool utility on Windows to create a .java.policy file, add a Policy Entry, grant it the AllPermission permission, and save it (with a note on how to instead point java.security at a differently named or located policy file), noting that Macintosh does not require this step. Once the policy is set, the applet's Connect button succeeds and the interface can display and query records, saving the user from re-typing the server's IP address on every connection attempt.
