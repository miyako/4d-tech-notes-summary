This Tech Note by Xiang Liu tackles a UI/UX challenge specific to the 4D Mobile platform: because 4D Mobile's REST API (built on the Wakanda framework) returns entity collections in fixed-size pages (default 40 records) using $top and $skip parameters, and exposes lazy-loading helper methods like nextPage(), prevPage(), and more(), developers need a pattern for smoothly displaying large record sets in web UIs without loading everything at once. The note explains the underlying REST mechanics — how a Wakanda REST URI query returns a JSON payload describing an entity set (with __ENTITYSET, __COUNT, __SENT, __FIRST metadata) alongside a portion of the actual entity data — and how the $top/$skip parameters and pagination helper methods work together to fetch additional pages on demand. It then demonstrates two concrete implementations of infinite scrolling: one using the Angular-Wakanda framework's built-in constructs to detect scroll position and trigger nextPage()/more() calls, building an infinite-scroll-ready UI in Angular; and a second, framework-agnostic version using plain HTML, jQuery, and Ajax to achieve the same lazy-loading behavior for developers not using Angular-Wakanda. Both approaches aim to eliminate unnecessary network traffic by only fetching records as the user scrolls, improving perceived performance for large data sets in 4D Mobile web/mobile client applications. The note closes with a summary contrasting the two approaches and reiterating the performance rationale for lazy-loaded, paginated data over eagerly loading full collections. As a piece of guidance, it captures a real and recurring UI pattern (infinite scroll) but is entirely anchored to the now-retired 4D Mobile/Wakanda technology stack.
