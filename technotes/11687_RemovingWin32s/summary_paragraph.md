This January 1996 Tech Note by Christopher Chapman addresses a common support issue of the era: 4D and 4D Server, being Win32 applications, could only run under Windows 3.1(1) and Windows for Workgroups via a 32-bit compatibility/thunking layer called Win32s. Users frequently installed other applications bundling older or proprietary versions of Win32s, which were often incompatible with 4D, causing problems that a simple reinstall of 4D wouldn't fix — particularly once the other application had overwritten shared Windows system files. The note provides a precise manual removal procedure: delete the `device=<Windows>\<System>\win32s\w32s.386` line from the `[386Enh]` section of SYSTEM.INI; modify the `drivers=` line in the `[BOOT]` section to remove `winm16.dll`; delete the files W32SYS.DLL, WIN32S15.DLL, and WIN32S.INI from the Windows System directory; and finally run `deltree <windows>\<system>\win32s` from the DOS command line to remove the remaining folder. Once cleared, the compatible version of Win32s could be freshly installed simply by running the installer for 4D, 4D Client, or 4D Server. The featured technology is entirely the Win32s compatibility layer and the low-level Windows 3.1 configuration files (SYSTEM.INI) and DOS commands used to manage it. As a fully readable full-PDF Tech Note, this summary reflects the complete (and quite short) document.
