This Tech Note explains the mechanics behind 4D 2004's custom client/server multiplatform application generator, which can be driven either through the Build Application dialog or, with much finer control, through an XML build project file passed to the BUILD APPLICATION command. It covers how to select the Mac and Windows 4D Client folders/packages used to build double-clickable client executables (noting you can only build for the platform you're currently on, and each target platform requires its own Developer license), and how the generated EnginedServer.xml file (placed in the "4D Extensions" folder) lets a client auto-connect to its server's IP/port without manual entry, either created automatically at build time or defined explicitly via XML keys like <IPAddress> and <PortNumber>. It documents a set of BuildApp.XML keys for customizing server/client IP and port, custom icons, version-range management (<RangeVersMin>, <RangeVersMax>, <CurrentVers>), and plug-in exclusion lists (<ArrayExcludedPluginName>/<ArrayExcludedPluginID>), including a note that several tag names changed between 4D 2004 and 2004.1 (e.g., FolderIsValid renamed to IncludeIt). A major section details the automatic client-upgrade feature (enabled via <BuildCSUpgradeable>), walking step-by-step through how an outdated 4D Client detects a version mismatch with the server, downloads a new client archive into a temporary $temp4dclient folder, runs a platform-specific script (upgclnt.bat or upgclnt.sh) to install the new client and delete the old one, and reconnects automatically — noting this only works with a compiled database, not an interpreted or development-mode client/server setup. The note also explains plug-in integration priority across three possible plug-in source locations (4D's own Plugins folder, the source database's plugins/Mac4dx/Win4dx folders, and 4D Server's plugins folder), with 4D Server's plugins folder always taking priority in case of version conflicts, illustrated through a worked example showing which plug-ins end up in the final built application. The featured technology throughout is 4D 2004's compiled client/server build pipeline: the Build Application dialog/command, XML build project files, the EnginedServer.xml auto-connect mechanism, and the client upgrade script pipeline. As a snapshot of mid-2000s 4D deployment tooling, its specific XML schema and file/folder names are tied to that era's compiled Design-Mode architecture and would need re-verification against any current 4D release.
