Written by Aziz Elghomari of 4D S.A. Technical Support, this is the second Tech Note in a series on 4D Open, following a prior note on structure-file access; this one covers 4D Open's data-access side. It walks through deleting all existing records with `_4D_SelectAllRecords`/`_4D_DeleteSelectedRecords`, then creating new records of every supported field type (Alpha, Text, Real, Integer, Long Integer, Date, Time, Boolean, Picture, Blob) using `_4D_CreateBuffer` and `_4D_AddToBuffer` against the `DataRec` union structure. It documents the `_4D_Search` routine and its `SearchRecord`/`SearchLine` structures for building a query (shown searching an integer field for the value 999), the equivalent `SortRecord`/`SortLine` structures for defining an ascending/descending sort, and the set-handling routines (`_4D_CreateEmptySet`, `_4D_CreateSet`, `_4D_AddToSet`, `_4D_RecordsInSet`, `_4D_ClearSet`) used to build and count named sets such as "the current record" and "the results of a search." A final section demonstrates retrieving a Blob's length via `_4D_GetFields`/`_4D_GetNthField` and the `data.u.blob.BlobLen` field. The note ships with Code Warrior 5 (Mac) and Visual C++ (Windows) sample projects that link against the 4D Open library/DLL and require a 4D Server v6.5.x database configured for TCP/IP, and closes by touting 4D Open's thin-client footprint (a 264 KB 4dopen.dll versus an 8.6 MB full 4D client) as the payoff for using this lower-level API.
