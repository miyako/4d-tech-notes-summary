This 2003 Tech Note by Steve Hartman of 4D, Inc. documents the 4D WebSTAR API 2003.1 component, a set of nearly 50 WSAPI (WebSTAR API) commands that let a 4th Dimension database log in to a WebSTAR Admin Server and drive it the same way the standalone WebSTAR Admin Client application would. The accompanying "Employee Demo" example database shows a typical workflow: call WSAPI_LoginDialog or WSAPI_Login to authenticate and obtain a session ID, optionally call WSAPI_GetSettingsGroup to pick a settings group, use routines such as WSAPI_Admin_GetComponents to read server information (e.g. verifying the connected WebSTAR Admin Server version), and finish with WSAPI_CloseSession and WSAPI_Quit to tear down the session and background processes. The note frames the value proposition as avoiding duplicate data entry across a 4D employee database and the WebSTAR mail/FTP/security configuration, since a single "Sync" button in the demo pushes and pulls settings like e-mail accounts and FTP access between the two systems. It also covers installation via 4D Insider (linking the component's [WSAPI] table into an existing structure) and notes the WSAPI component requires 4D 2003.1 or later, a compatible 4D Internet Commands plug-in, and WebSTAR 5.2 or later. The note closes by emphasizing that the API only exposes actions the logged-in user is already authorized to perform on the WebSTAR Admin Server, so it cannot be used to bypass WebSTAR's own permission model.
