This note is an onboarding guide to 4D's user-defined class feature, aimed at developers who may only know classes as an internal mechanism (e.g. inside ORDA) rather than something they can define themselves. It establishes the basics: classes are only available in project-mode databases (not binary/.4DB structure files), a class instance is declared with the cs (class store) command, e.g. var $myRectangle : cs.Rectangle, and object notation used to access a class's attributes and functions is case-sensitive, with the code editor's autocompletion helping enforce correct casing. It works through a worked Rectangle class example (Length/Width attributes, Perimeter()/Area() functions), all four ways to create a new class (menu, toolbar, keyboard shortcut, Explorer window) and the resulting Project file layout, and how to define a class constructor plus computed-property getters/setters (Function get Length_cm() / Function set Length_cm($input : Real)). It also documents 4D's own built-in class-store classes, contrasting their benefits over generic objects, and specifically covers the 4D Datastore's relationship to ORDA — noting that early ORDA code samples over-explicitly assigned datastore/dataclass instances where more idiomatic patterns now exist. Finally, it highlights code-editor improvements tied to classes: object-notation suggestions, project-method detail tooltips, a code-navigation dropdown, and the ability to debug class functions directly.
