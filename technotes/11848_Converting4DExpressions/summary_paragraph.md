This Tech Note (TN 99-34) resolves a specific problem that occurs when converting a 4D database from version 3 to version 6: 4D expressions (commands) inserted into plug-in areas — 4D Write, 4D Calc, 4D Draw, and 4D Chart — may return syntax errors because 4D cannot determine which version the expression was originally inserted under. The solution involves creating a '4DT5' resource with ID 128, which triggers automatic re-conversion of plug-in expressions when the database is opened in v6. The note provides a complete example database (v3 and v6 structures) and detailed methods: an On Startup method that creates the 4DT5 resource if a sentinel 'ToConvert' file is present, an UpDate method that opens each plug-in area and re-saves records to force re-evaluation, and a MyMethod that uses WR PICTURE TO AREA / WR Save to picture to reload and save 4D Write areas. The solution handles cross-platform differences between Mac OS (68K and PowerPC) and Windows, including path name and resource file conventions. The note requires a minimum of 4D v6.0.6 and emphasizes that this fix applies only to databases being converted — not those already running in v6.
