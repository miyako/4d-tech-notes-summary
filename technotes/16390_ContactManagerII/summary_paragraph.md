This Tech Note (TN 01-35, 4D v6.7, Mac & Win, published July 31, 2001) presents part two of a look at how the Contact Manager example database's calendar interface is managed. Only a short on-page teaser paragraph survives in this archive rather than the full downloadable PDF and example database, because the original download was an old Windows self-extracting .exe installer (https://kb.4d.com/ftp://ftp.4D.com/ACI_TECHNICAL_NOTES/2001/Windows/TN_2001_31-35_(JUL)/01-35_Contact_Manager_II.exe) that could not be extracted in this environment; the original 4D Tech Notes site offered separate Windows and Mac downloads of the complete note and its companion example database, but neither is retrievable here. Based on the surviving teaser text, the note's proposition is: This is the second technical note on the Contact Manager example database. The purpose of Part II of this technical note is to take a closer look at how the interface is managed in the calendar of the sample database. Part I explained how objects were placed and displayed in the calendar. Its featured technology centers on Calendar UI construction, Form object placement/display, Example database (Contact Manager series), reflecting typical concerns of the 4D 6.7 (4D 2000/2001 era) developer community working in binary Design Mode on classic Mac OS/early Mac OS X and Windows 98/2000/NT. This is the second in a series on the Contact Manager example database, focusing specifically on how the calendar interface's display is managed, following an earlier note (Part I) that covered placing and displaying the calendar's objects. The general technique of building a custom calendar view from form objects is a pattern developers still sometimes need today, even though modern 4D development would more likely reach for a List Box, a plug-in calendar component, or a web-based calendar widget rather than hand-managing individual form objects as shown here.
