This Tech Note addresses the problem of running command-line tasks (OS utilities, Git, etc.) from 4D without freezing the user interface. It contrasts the long-standing LAUNCH EXTERNAL PROCESS (LEP) command, which can only return a response when executed synchronously (thereby blocking the process and freezing any form UI), with the new System Worker class introduced in 4D v19R4. Unlike LEP, System Worker is not a legacy command but a class available through 4D's class store, and it natively supports asynchronous callbacks so a developer-defined callback method handles the command-line response while the calling process continues running in parallel. The note requires project mode (since classes are a project-mode-only feature) and walks through three demos: comparing LEP against System Worker for OS information queries, driving a responsive inventory-list form with async System Worker calls to find/print/open files, and — most substantively — building a full Git front end (init, add, commit, push, remote/SSH setup) entirely through System Worker calls to the git command. The Git demo illustrates a realistic, still-common use case: giving a 4D application scriptable access to an external CLI tool while keeping the interface responsive. The tech note positions System Worker as a clear improvement over LEP for any scenario needing background command execution with a returned result.
