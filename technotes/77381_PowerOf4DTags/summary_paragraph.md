This Tech Note by Charlie Vass explores PROCESS 4D TAGS, the renamed and enhanced successor to the older PROCESS HTML TAGS command, arguing that 4D Tags are a general-purpose templating mechanism whose usefulness extends well beyond dynamic HTML web serving. It first covers the classic web-serving use case — semi-dynamic HTML (SHTML) templates, embedded tags in HTML documents served via 4DACTION, 4DCGI, or custom URLs, and processing HTML embedded directly in text/blob variables — then pivots to demonstrate 4D Tags applied outside the web context entirely, including building report templates, inserting raw HTML into documents with the 4DHTML tag, forcing literal (untranslated) characters, and embedding one HTML document's body inside another. It documents the individual tag vocabulary in depth: 4DBASE for setting a base reference, 4DELSEIF for conditional branching, 4DEVAL for inline expression evaluation, 4DSCRIPT for referencing 4D commands/methods from within a template, and 4DLOOP (enhanced in v14 R4) for iteration, including recursive processing patterns. A "Getting Creative" section pushes further into unconventional applications — generating end-user automation scripts, building hierarchical lists, and even producing SVG output — all driven by the same tag-processing engine. The note includes a cautions section covering common pitfalls: mismatched input/output contexts, quirks with 4DEVAL and variable scope, debugging difficulties, sensitivity to stray whitespace, interactions with styled text, and — notably — security guidance on preventing malicious code injection when processing user-supplied content through 4D Tags, along with recommended precautions and code/text editor suggestions. The conclusion positions 4D Tags as an underappreciated, versatile automation and templating tool that many developers only ever associate with web pages.
