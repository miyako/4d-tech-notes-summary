This Tech Note by David Adams is a general-purpose methodology overview of data cleaning and record deduplication, framed as applicable to any database system (4D, FileMaker, SQL Server, MySQL, DB2, Oracle) but demonstrated with 4D's companion FuzzyTools component (documented separately in TN 06-19 and TN 06-18). It opens by cataloguing why duplicate/inconsistent data accumulates (typos, address/name changes, merged data sources, format inconsistencies) and why fixing it matters (report accuracy, mailing cost reduction, service quality, lookup efficiency, external-system reconciliation), then breaks the deduplication process into four stages: cleaning/standardization, query-based reduction of the comparison set ("blocking"), fuzzy matching of candidate duplicates, and human-reviewed merging. On standardization, it discusses USPS/UPS free address-verification web services callable from 4D (via cURL or 4D Internet Commands HTTP GET) and surveys commercial address-cleaning vendors (PostCode Anywhere, AddressDoctor, DesertSoft) while warning that address rules (citing USPS Publication 28) are genuinely complex and best left to dedicated validation systems rather than hand-rolled logic. On blocking, it explains the near-exponential growth of pairwise comparisons ((n²−n)/2) and gives concrete blocking strategies (matching on reliable fields like gender or ZIP code, adjacent-ZIP lookups, birthdate proximity, or random sampling) to keep duplicate-hunting tractable. The matching section demonstrates FuzzyTools' phonetic (Soundex/Metaphone) and distance (edit distance, LCS) algorithms via the bundled "Show People" demo (500 records, 50 duplicate pairs) and a hard-coded rule-weighting table combining multiple field comparisons with positive and negative scores, while candidly noting that a production system should ideally store such rules as configurable data rather than hard-coded logic. It closes with practical guidance on combining/merging confirmed duplicates within transactions (watching for orphaned child records), running nightly duplicate-checking sweeps to train data-entry staff, considerations for probabilistic/frequency-based matching (e.g., a rare surname is more diagnostic of a true match than a common one), a caution against naive concatenated-field comparison, and a tip to use APPLY XSLT TRANSFORMATION to generate multiple report output formats from one XML report. Overall the note reads as a solid, largely tool-agnostic primer on the deduplication problem space, anchored to the FuzzyTools component and 2006-era vendor/service references.
