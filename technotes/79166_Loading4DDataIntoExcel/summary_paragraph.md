This Tech Note presents the 4D REST API as a modern alternative to ODBC for pulling live 4D Server data into Microsoft Excel. It first recaps how to configure the REST server: enabling "Expose as REST server" under Database Settings > Web, exposing/hiding individual tables and fields via their "Expose as REST resource" property (or the catalog.4DCatalog `hide_in_REST` attribute), and controlling access either through 4D's Users and Groups Read/Write settings or a custom `On REST Authentication` database method that takes precedence and returns True/False to accept or reject a session — noting that REST sessions consume 4D Client connections and require a REST-capable license (three free connections in single-user Developer mode for testing). It covers the REST URL conventions — appending `/rest/` to check connectivity, `/rest/<TableName>` to fetch all entities, and the `$filter` query parameter using ORDA `dataClass.query()` syntax to scope results. On the Excel side, the note walks through the "Get & Transform Data"/"From Web" feature (Data tab > Get Data > From Other Sources > From Web), which opens a Power Query Editor where the query — generated automatically as `Json.Document(Web.Contents("http://host/rest/Table"))` — can be manipulated with the graphical UI or, for advanced cases, hand-edited Power Query formulas, without requiring deep Power Query expertise for the basic case. The bundled example database and companion instructions show applied steps for formatting the loaded JSON into a proper Excel table, adjusting/refreshing it, and then interacting with the resulting data using ordinary Excel features (sorting, filtering, simple summaries), including handling of date fields converted through Power Query. The note frames REST as preferable to ODBC because it avoids installing an ODBC driver, works over standard HTTP, and integrates smoothly with Excel's built-in web-data tooling.
