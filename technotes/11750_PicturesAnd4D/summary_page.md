## Overview

This Tech Note reviews the history of how 4th Dimension has handled picture data in fields and variables, with particular focus on the complications introduced by 4D for Windows needing to reconcile Mac and Windows picture format conventions, and summarizes 4D's current (v6) picture handling capabilities.

## Key Points

- Frames 4D's picture handling evolution around the introduction of 4D for Windows as a key turning point.
- Explores the technical details of which picture formats 4D can handle.
- Provides historical context on how support for pictures changed over time.
- Summarizes 4D's then-current (v6) picture handling capabilities.

## Featured Technology

- 4D picture fields/variables
- Cross-platform picture format handling (Mac/Windows)
- 4D for Windows picture compatibility

## Historical Context

Written in 1997, this note reflects a transitional period in 4D's history as it matured from a Mac-only product into a genuinely cross-platform one, requiring picture/image handling to be reconciled between classic Mac graphics conventions and the different formats and APIs found on Windows; the specific formats and mechanisms it describes have been superseded by 4D's modern, much broader image format support.

## Historical Commentary
**Status:** Superseded

This note traces the history and then-current state of how 4th Dimension handles picture data, particularly the added complexity introduced once 4D for Windows required cross-platform picture format compatibility alongside classic Mac picture formats (e.g. PICT); the specific formats and internal handling mechanisms described are tied to 4D v6-era classic Mac/Windows graphics conventions and have been superseded by modern image format support and rendering in current 4D.
