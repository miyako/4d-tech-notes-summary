This Tech Note addresses a mandatory, non-negotiable requirement for distributing any 4D OEM application on macOS: satisfying Apple's Gatekeeper security barrier, which otherwise warns users that an unsigned app downloaded from outside the Mac App Store is a potential risk. It walks through the full certificate lifecycle — subscribing to the Apple Developer Program, enabling two-factor authentication, generating a Certificate Signing Request (CSR) via Keychain Access's Certificate Assistant, and creating/downloading a Developer ID Application certificate from the Apple Developer portal — using macOS Big Sur and Xcode 12.5 as the reference environment. It also explains 4D's OEM licensing model: how to auto-migrate v18 OEM license numbers to v19 through the License Manager, and distinguishes the two compilation/deployment license tiers — 4D Developer OEM v19 (full dev environment, compiled mode, unlimited single-user executable deployment) versus 4D OEM Desktop v19 (adds the SQL engine, component usage, Web Services client, and the 4D Write/4D View expansions for running compiled multi-user-capable applications) — noting licenses are cross-platform until first registration but can be changed at renewal. The note then covers generating a single-user OEM application, signing it (with troubleshooting tips for common signature failures), and notarizing the signed application so it can be freely distributed over the internet without triggering Gatekeeper warnings.
