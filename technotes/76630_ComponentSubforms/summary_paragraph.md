This Technical Note by consultant Bertrand Soubeyrand revisits 4D v12's improved subform (included form) capabilities, explaining how a single subform can be represented multiple times across different host forms as either a list or page/detail presentation, and how components make these subforms both programmable and portable. It defines the core vocabulary — host form, subform, subform container, and subform instance — and introduces four key commands for coordinating behavior: CALL SUBFORM CONTAINER (to pass events between subform and host), OBJECT Get pointer and OBJECT Get name (to retrieve pointers/names of subform objects), and EXECUTE METHOD IN SUBFORM (to run code inside a specific subform instance without host interference). A major theme is 4D v12's new "dynamic variables" concept, which lets 4D create and destroy subform-instance-specific variables automatically rather than requiring developers to manage static process variables per instance, saving memory and avoiding cross-instance interference. Worked examples in the accompanying demonstration database show two-way communication patterns: updating a subform's internal display from the host via a container variable and pointer, and sending custom event codes from the subform back up to the host's container object method. The note concludes that these mechanisms give host forms and subforms genuine two-way communication, opening up more sophisticated, reusable interface designs — with an included variant that works without a component for simpler cases.
