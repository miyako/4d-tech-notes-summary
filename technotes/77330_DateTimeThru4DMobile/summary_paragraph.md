This Tech Note by Xiang Liu tackles a common source of confusion for 4D Mobile developers: 4D stores Date and Time as two separate field types, while JavaScript (used throughout Wakanda's client and server layers) represents both in a single Date object built on a millisecond-based moment-in-time model. The note opens with a primer on JavaScript's Date object — its four constructor forms (no argument, milliseconds since epoch, date string, or full numeric arguments) and its get/set accessor methods for year, month, day, hour, minute, second, and millisecond — before mapping these onto their 4D language equivalents. It then contrasts Wakanda's native date and duration attribute types against 4D's Date and Time fields, noting structural differences developers must account for when moving data between the two systems. The bulk of the note is a practical walkthrough of reading, querying, and modifying 4D Date/Time fields from 4D Mobile: formatting date/time values on the client side versus the Wakanda server side, querying against formatted versus calculated date/time attributes, and saving updates back to formatted versus calculated attributes. All demonstrated code requires Wakanda Enterprise 10 paired with 4D v14 R5 or later, situating the note firmly within the original 4D Mobile architecture where a JavaScript-based Wakanda layer mediated between 4D and mobile/web clients. The conclusion reinforces that understanding this date/time model mismatch up front prevents subtle bugs when building 4D Mobile applications that manipulate date and time data.
