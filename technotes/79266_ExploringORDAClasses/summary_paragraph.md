This technical note is an introductory, example-driven tour of 4D's ORDA class model — Datastore, Dataclass, Entity, and Entity Selection classes — and how they can be extended with custom functions to make form-driven business applications more efficient and maintainable. Working from a sample "TestClasses" project with a "Contact" table, the note shows that since v18R5 (and automatically since v20) every table gets a corresponding Dataclass class (e.g., "Contact") and Entity class ("ContactEntity") that developers can extend directly. On the Dataclass side (`Class extends DataClass`), it demonstrates a set of named query functions — `getAllMales`, `getAllFemales`, `getContactsFromUSA`, `getContactsFromFrance`, `searchByName($searchText)`, and `getActiveContact` — each simply wrapping a parameterized `ds.Contact.query("attribute = :1"; value)` call and returning a typed `4D.EntitySelection`, illustrating how repeated query logic (gender, country code, active status, name search) can be centralized into readable, reusable, self-documenting class methods instead of being duplicated inline throughout the application. On the Entity side (`Class extends Entity`), it shows per-record convenience functions operating on `This` (the current entity): `getFullName` concatenates first name with an uppercased last name; `getLastConnectionDate` converts a stored `lastConnection` value to a `Date`; and `getFormattedAddress` demonstrates a `Case of` branching on `This.countryCode` to assemble a country-appropriate multi-line address string (US-style street/city/state/postcode ordering, French-style street/postcode/city/state/country ordering, and a generic fallback pattern for other countries) from nested `This.address.street.*` attributes. The note's overarching message, reinforced in its conclusion, is that wrapping both dataclass-level queries and entity-level computed/derived values inside ORDA class functions yields more modular, testable, and scalable 4D code compared to scattering equivalent logic across forms and project methods.
