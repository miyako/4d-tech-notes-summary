This tech note documents 4D v18's newly introduced remote datastore feature, which lets one 4D application expose its ORDA datastore as a REST server that another 4D application can connect to and manipulate as if it were a native local datastore — an alternative to connecting via 4D's SQL server. Setup is two-sided: on the host, the database owner enables "Expose as REST server" in Database Settings' Web/REST resource tab (requiring a 4D Developer Professional or 4D Server license), then restricts access either through 4D's built-in users/groups Read/Write privilege setting or, for finer control, an `On REST Authentication method` taking username, password (plus a hashed flag), and requesting IP address, returning a boolean to accept or reject the connection — with the caveat that defining this method takes priority over the simpler group-based setting and must be deleted via the Explorer window (not just emptied) to fully disable it. Individual tables and fields can also be excluded from exposure via the "Expose as REST resource" toggle in the Structure editor's Inspector. On the client side, the `Open datastore` command connects using a configuration object (`hostname`, `user`, `password`, `idleTimeout`, `tls`, `type:"4D Server"`) and returns a datastore object that behaves like a local ORDA datastore, letting the calling application interact with data using all standard ORDA operations. The note walks through several sample configurations (running the remote host and client databases together) to illustrate real usage patterns. This feature represents 4D extending ORDA beyond single-app data access into a full inter-application data-sharing/integration mechanism.
