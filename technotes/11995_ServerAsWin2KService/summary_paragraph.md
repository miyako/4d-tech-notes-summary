Written by Steve Hartman of 4D Technical Support, this Tech Note explains how to register 4D Server as a native Windows 2000 service so that it launches automatically when the server boots, rather than requiring someone to log in and start it manually. After confirming the application resides in a path with no spaces or special characters, the developer launches 4D Server normally under the Local System profile and chooses Register as Service from the File menu; from then on the service can be managed through the Windows 2000 Services MMC console snap-in (reachable via Start > Programs > Administrative Tools > Services). The note walks through the resulting Service Properties dialog's four tabs: General (display name, description, startup type, and start/stop/pause/resume/restart controls), Log On (which account the service runs under — typically Local System, with the 'Allow service to interact with desktop' option required for the 4D Server administration window to remain visible), Recovery (configuring Take No Action, Run a File, Restart the Service, or Reboot the Computer responses to service failures, with separate settings for first, second, and subsequent failures), and Dependencies (revealing that 4D Server depends on the Windows Print Spooler service, so a default printer must be installed for the service to launch). It closes by noting Windows 2000's one-click Restart option as a convenience improvement over Windows NT 4, where administrators had to stop and separately restart services.
