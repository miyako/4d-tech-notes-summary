This September 1996 Tech Note by David Adams was published ahead of 4th Dimension version 6's release to help developers prepare their existing v3.x databases and code for a set of breaking or notable changes coming in the new version. Its most prominent point is a terminology overhaul: what were called Files and Layouts throughout 4D's documentation and language become Tables and Forms in v6, a naming change developers needed to be aware of both for reading v6 documentation and for understanding renamed commands. It addresses backward compatibility for the EXECUTE statement, which executes 4D code stored as text at runtime: because v6's compiler and language differ from v3.x, the note explains that source text for EXECUTE targets should be stored in STR# resource #8 so that 4D can apply appropriate compatibility handling when compiling or interpreting that code under v6. It flags a significant identifier-length increase: table, field, and other object names can now be up to 31 characters long, up from the previous 15 (or in some contexts 11) character limits, which affects databases and generators that assumed the older, shorter limits. It documents a new syntax for the pointer sign character used to declare and dereference pointers in 4D code, which existing v3.x code may need review to accommodate. Finally, it notes a change to stored procedure behavior: process IDs returned for stored procedures are now negative numbers, distinguishing them from ordinary process IDs, which existing code checking or comparing process ID values needed to account for. As a fully readable full-PDF Tech Note, this summary reflects the complete document.
