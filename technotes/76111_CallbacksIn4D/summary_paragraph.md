This Tech Note explains the concept of a callback — a method reference passed as a parameter so that a lower-level or external code module (such as a component or plug-in) can invoke logic defined in a higher-level, host-database layer — and shows how to implement callbacks in 4D v11 SQL using EXECUTE METHOD, since 4D has no native function-pointer syntax. It motivates callbacks primarily through the lens of writing reusable, encapsulated components: a component providing generic functionality (printing shipping documents with varying formats, listening for TCP traffic and dynamically routing it, communicating with hardware like a serial-port weight scale) can remain agnostic of host-specific logic by having the host supply a callback method that the component invokes at the appropriate moment. The note details the "Shared by components and host database" method property required for cross-boundary calls, and carefully explains callback execution context — whether a callback runs in the callee's process or the caller's own process, depending on whether the caller was launched as a separate process — which has significant implications for process variable scope. A demonstration database illustrates these concepts concretely. The note is aimed at component and plug-in-adjacent developers seeking clean architectural separation between reusable modules and host application logic.
