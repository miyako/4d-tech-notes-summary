This Tech Note explains the process of converting a 4th Dimension 3.x.x database with a customized color palette to version 6.0, and is aimed particularly at developers who write 4D extensions dealing with customized colors and palettes. It describes a significant internal change starting with 4th Dimension 6.0: on Macintosh, colors were no longer restricted to the 256 simultaneous colors predefined by a color palette ('pltt' resource) stored in the application's resources (whether in 4D itself, Runtime, Client, or Compiled/Merged applications). The note lists the resulting benefits: pictures copied and pasted from any graphical application with a custom color table are now displayed with their actual colors rather than the closest approximation from the 'pltt' resource; 4th Dimension no longer installs the 'pltt' resource or calls the Mac OS SetPalette routine; all objects now store their colors as 24-bit $RRGGBB values instead of color indexes referencing the 'pltt' resource; and the 'pltt' resource that supports color menus can now be freely customized since its role is limited to the user interface only. The note does include one caveat: colors are still subject to approximation if the monitor is set to 256 colors or fewer, if the video card doesn't support more than 256 colors, or if a 4D extension itself sets a color palette on a window. This is a focused, technical migration note aimed at ensuring extension/plugin developers understand how color handling fundamentally changed between the 3.x.x and 6.0 (V6) architectures.
