Written by Roland Lannuzel of 4D S.A., this Tech Note tackles a problem beyond 4D's basic per-object Grow/Move resize behaviors: coordinating multiple form objects so that, when a window is resized, they grow and reposition proportionally rather than overlapping or leaving uneven gaps. The note explains the underlying math — each object is assigned a percentage of the window's width/height increase to apply to its own growth and to its own repositioning, so that objects and the spaces between them scale together while preserving the form's overall visual proportions — and walks through worked examples of equal-size and unequal-size objects, plus margins and inter-object spacing, before applying the technique to a fully resizable on-screen calculator with 17 buttons of varying sizes. For each form object the method tracks eight values (initial X/Y coordinates, width, height, move percentage, and grow percentage for both axes, stored as long integer/real arrays loaded from an `Elements` table via `SELECTION TO ARRAY`), plus an object-name array. The `On Load` form event initializes these arrays and places objects with `MOVE OBJECT`, while the `On Resize` event computes the window's size delta via `GET WINDOW RECT` against reference dimensions and re-applies `MOVE OBJECT` to every object using its stored move/grow percentages; a helper also recalculates font sizes for the calculator's display and buttons proportionally to the new height. Window resizing itself is driven by an invisible thermometer object at the window's bottom-right corner, repurposed to continuously execute a `ResizeWindow` method while the mouse button is held, enforcing the window's aspect ratio. The note closes by suggesting the same array-driven approach could be reused for skinning, or for showing/hiding objects based on user login.
