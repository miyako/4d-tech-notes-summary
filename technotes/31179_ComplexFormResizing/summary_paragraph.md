This Tech Note tackles a common but often tricky UI challenge in 4D application development: computing the correct placement and size of form objects when an entry form is resized by the user. It notes that most entry forms benefit from being resizable, whether to display more information at once or to let objects adapt to a user's preferred window size, and that while 4D provides some basic default behaviors for automatically resizing a form or repositioning its objects, developers sometimes have no choice but to drop into the 4D language to achieve the exact behavior they want. The tech note's core contribution is a described method that lets a developer both move and resize form objects together in response to a resize event, combining what might otherwise be two separate operations into what the note characterizes as "a simple and logical manner." This suggests the technique provides a single, coherent computation (likely based on anchor points, ratios, or relative offsets) that determines both the new position and new dimensions of each object as the form's overall size changes, rather than requiring developers to write ad hoc, object-by-object resize logic. The featured technology is 4D's classic Design Mode form object model and its resize-related language commands, addressing a foundational UI concern — building forms that gracefully adapt to different window sizes — that remains relevant to form design in 4D even as the underlying object model has evolved over the decades since this note's publication.
