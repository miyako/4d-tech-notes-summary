This Tech Note by Vance Villanueva addresses the practical problem of serving different language versions of a website from a single 4D Web Server, using the same URL for all visitors regardless of their browser's language preference. It begins by explaining how browsers signal a preferred language and how, without special handling, a 4D web server serving static pages will show the same (e.g. English) content to every visitor regardless of that preference. The note explains cookies as the storage mechanism used to persist a visitor's chosen or detected language across requests, and walks through organizing web pages by language into separate folders, then implementing the routing logic. Implementation steps include setting the language via an HTML-based web request, checking incoming web requests for an existing language cookie, setting a new cookie when a language choice is made, checking for that cookie on subsequent requests, and reading the browser's Accept-Language HTTP header as a fallback when no cookie is present yet. All of this logic is unified inside 4D's On Web Connection method, which serves as the central request-routing entry point for the 4D Web Server, ultimately serving the appropriate localized web page based on cookie state or browser header. A demo database illustrates the full flow: clicking menu items to change language, setting the cookie, and having the correct language persist even after reopening the browser. The technique is a solid, low-level approach to server-side web localization that remains conceptually sound even as many modern web apps now push this responsibility to client-side JavaScript frameworks instead.
