This Technical Note provides a systematic eight-step process for duplicating a database in 4D v11 SQL, leveraging the new drag-and-drop mechanism and XML structure import/export features to reduce development overhead and enable efficient object reuse across database instances. The process begins by running two instances of 4D v11 SQL on the same machine and carefully handling tables in the trash (which must be empty or removed to avoid corrupting internal table numbering), then exporting the database structure from the original database to an XML file via File > Export > Structure definition to XML file. A new database is created in the second instance from this XML structure definition (File > New > Database From Structure Definition), which automatically recreates all tables with preserved relationships and field numbering. For databases converted from 4D 2004, the original .RSR resource file must be manually copied to the new database folder and opened in the On Startup Database method using the Open Resource File command to maintain resource references. The Toolbox objects (pictures, help tips, lists, filters, resources, style sheets) are then migrated—users and groups and menu bars cannot be dragged and must be recreated manually in identical order, while pictures, help tips, lists, filters, resources, and style sheets can be dragged and dropped one-at-a-time between open Toolbox windows. Finally, forms (list, detail, input/output forms) and methods (project methods and database/trigger methods) are dragged from the original to the new database, with plug-ins either copied to the new database folder or re-registered as needed. The note emphasizes that preserving references between objects and maintaining internal numbering requires strict adherence to this sequence, and provides examples of how table numbering changes when structure is exported/imported after deletions.
