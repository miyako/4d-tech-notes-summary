This Tech Note introduces 4D's built-in documentation feature, available since v19 for project databases, which lets developers create and preview Markdown-formatted documentation directly from the Explorer window for project methods, database methods, trigger methods, project/table form methods, forms, and — new in v19R7 — classes. Each documentable element gets its own `.md` file, automatically named after and synced with the element (renaming or deleting the element renames or deletes its documentation file), stored centrally in a "Documentation" folder at the root of the project package; a project form and its form method (likewise a table form and its method) share a single documentation file. Creating documentation is a one-click action in the Explorer's Documentation tab that opens the auto-generated file (pre-populated with an HTML-comment summary placeholder and a fenced ```4d code block template) in the developer's default Markdown editor, and the same file can subsequently be edited via "Edit Documentation." The note surveys which Markdown syntax 4D's preview actually renders — headings, bold/italic/strikethrough, fenced ```4d code blocks, tables, and links are officially supported, while underline, indentation, centering, colored text (via inline HTML/CSS spans), and special symbols work unofficially — and shows that the first line's HTML comment also surfaces as an inline hover tooltip in the method code editor. Documentation benefits highlighted include easier onboarding/maintenance, smoother team collaboration, and — most distinctively — a critical role in components: since a compiled component's method internals are inaccessible to the host database's developer, its Markdown documentation (automatically copied into the build output by "Build Application") becomes the only reference for how to use it. The note positions this feature as a low-friction, version-control-friendly (plain text, diffable) way to keep 4D applications and components properly documented without external tooling.
