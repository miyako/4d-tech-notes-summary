# Tech Note 02-61: Limiting Access When Using 4D Client Across the Internet

**Author:** Not specified in source document
**Published:** December 31, 2002 | **Product/Version:** 4D v6.8 | **Platform:** Mac & Win
**Page:** https://kb.4d.com/assetid=25617

## Overview
A Tech Note addressing how to limit 4D Client access to a 4D Server when that server is reachable over the open Internet, motivated by a real customer security concern.

## Key Points
- Motivated by a real-world scenario: uncontrolled 4D Client access to a 4D Server over the open Internet.
- Addresses the need to limit and monitor which clients can connect to a 4D Server remotely.

## Featured Technology
- 4D Client / 4D Server
- TCP/IP access control

## Historical Context
Written before 4D introduced more built-in network security features (e.g., stronger server-side access controls, TLS support) in later versions; only the short teaser text for this note could be recovered here.

## Historical Commentary
**Status:** Superseded

The core concern — controlling and auditing remote access to a database server — remains a fundamental, still highly relevant security practice, but current 4D Server deployments have far more robust built-in access control, encryption (TLS), and network security options than were available in 2002, making the specific mitigation techniques in this note largely superseded by modern equivalents.
