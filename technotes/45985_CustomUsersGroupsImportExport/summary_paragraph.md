Written by Josh Fletcher of 4D Inc., this Technical Note presents an example implementation of a fully custom Users and Groups import/export module for 4D 2004, motivated by a specific gap in the built-in Tool Box import/export feature: it does not preserve per-plug-in access group assignments, forcing developers to manually reconfigure those settings after every import into a new database. The note explains that 4D's built-in feature (accessible via the Tool Box "Groups" page or the EDIT ACCESS command) already saves user names, passwords, startup methods, groups, group owners, and memberships, but omits plug-in access, which the note addresses by layering custom code on top using four core commands: USERS TO BLOB and BLOB TO USERS (which programmatically export/import the entire encrypted user/group access system as a BLOB) plus SET PLUGIN ACCESS and Get plugin access (which set/read which group is authorized to use each licensed, serialized plug-in, useful for security and for managing scarce plug-in licenses in client/server deployments). The accompanying source database ("UG_Source.4DB", ~40 project methods) demonstrates exporting this information as XML using 4D's DOM commands, with the Base64-ENCODE'd Users/Groups BLOB stored as one XML element and plug-in access settings stored as a loop-generated set of XML elements keyed by pre-defined XPATH constants, centered on four key methods (UG_EXPORT_UGToXMLTree, UG_EXPORT_PluginAccessToXMLTree, UG_IMPORT_XMLTreeToUG, UG_IMPORT_XMLTreeToPluginAccess). Design notes cover using a string-based "messaging" system instead of numeric error codes (to catch typos via the compiler and enable 4D's code-completion), a documented method-prefix naming convention, and acknowledged limitations such as the exported Users/Groups BLOB being unreadable as plain XML and the plug-in XPATH/ID lists being hard-coded rather than dynamically discovered. A demo database ("UG_Demo.4DB") walks through setting a Designer password, restarting, logging in as Administrator, and importing a sample demo.XML file that sets access for a list of specific serialized plug-ins (4D Draw, 4D View, 4D Write, 4D for OCI/ADO/MySQL/PostgreSQL/Sybase, etc.), with color-coded (green/orange/red) status messages indicating success, warnings, or errors. Featured technology centers on USERS TO BLOB/BLOB TO USERS, SET PLUGIN ACCESS/Get plugin access, 4D's DOM XML commands, and BLOB ENCODE/DECODE, applied to the classic 4D access/security and serialized plug-in licensing systems.
