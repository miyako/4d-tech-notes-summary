As 4D pushed its platform toward 64-bit architecture, the legacy 4D Write plugin (32-bit only) needed to be replaced by 4D Write Pro, which is fully integrated into 4D itself rather than an external plugin. This tech note is a practical migration guide covering three conversion scenarios. First, converting stored documents: existing 4D Write content held in Blob fields can be converted directly with `WP New([field])`, while content stored in Picture fields must first be loaded into a 4D Write off-screen area (`WR New offscreen area`, `WR PICTURE TO AREA`) and exported to a Blob (`WR Area to blob`) before `WP New` can consume it — all wrapped in a loop over `ALL RECORDS`/`NEXT RECORD` that writes results into a new Object field, since 4D Write Pro documents are stored as objects (a change dating from 4D v16). Second, converting off-screen areas: although 4D Write Pro has no literal off-screen area concept, a 4D Write Pro object itself serves the same purpose and can be manipulated directly (e.g., replacing `WR PRINT MERGE` over an off-screen buffer with a loop calling `WP PRINT` per record). Third, converting form-based Write areas: the note maps each classic 4D Write menu/toolbar action — search, lock/unlock document, show/hide references, toggle toolbar, insert date, save, find/replace — to its 4D Write Pro equivalent using commands from four different families (dedicated 4D Write Pro theme commands, Objects/Forms commands for formatting, Styled Text `ST` commands for content, and Objects/Language commands for area attributes), such as `OBJECT SET ENTERABLE` replacing `WR LOCK DOCUMENT`, and `ST COMPUTE EXPRESSIONS`/`ST GET OPTIONS` replacing `WR EXECUTE COMMAND`/`WR Get doc property` for reference display. The note is framed as giving developers a complete toolkit to retire 32-bit 4D Write dependencies while preserving all existing document-editing functionality.
