This Tech Note explains that when a record is deleted or created in a classic 4D database, 4D systematically enforces the referential integrity constraints defined in the structure file — including cascading deletion of related records triggered by deletion of the corresponding "one" side record in a one-to-many relationship. This is foundational relational-database behavior that every 4D developer needs to understand to avoid unexpected data loss or orphaned records.
