This Tech Note presents a reusable approach for handling application and user preferences — runtime parameters like colors, fonts, sort orders, or folder locations — stored externally in an XML file rather than inside 4D's built-in data engine. The author explains the advantages of an external file: preferences can be copied between installations, hand-edited with a text editor, and even used to make a single database behave differently depending on which preferences file is loaded. The included component loads the XML into memory using 4D's built-in DOM commands and organizes preferences under named "themes" (e.g., Web, Print, GUI), with each preference identified by a composite ID combining its theme and preference name so the same preference name can be reused safely across themes. The note documents the full preferences lifecycle — loading from and saving to disk, creating and deleting themes, listing theme names, getting/setting/deleting individual preference values — and describes a bundled Preferences Viewer GUI that lets developers or advanced users inspect and edit themes and preferences interactively, including guidance on using the approach safely in a client/server environment. A complete demo database and component source code are provided.
