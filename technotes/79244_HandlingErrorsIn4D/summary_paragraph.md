This Tech Note explains 4D's default error-handling system and how developers can replace it with a custom error handler to improve the experience for both developers and end users of deployed applications. By default, 4D traps syntax and runtime errors and shows a blocking dialog with a summary, an expandable stack of errors (most recent at the top), and Edit/Trace/Continue/Abort options plus Save/Copy actions to export the details as text — information that is useful to a developer but often confusing to an end user. A custom handler is installed per-process with ON ERR CALL("methodName"), and since 4D v19R8/v20 an optional second parameter lets the handler target a wider scope using the ek local, ek global, and ek errors from components constants, so a single method can catch errors database-wide or from a component; Method called on error checks what is installed and ON ERR CALL("") uninstalls it. Once installed, the handler runs instead of the dialog and can read dedicated process system variables (Error, Error method, Error line, Error formula), plus the newer Last errors command (an object collection with errCode/message/componentSignature, replacing the older GET LAST ERROR STACK array-based command) and Get call chain (an ordered collection of the calling methods) and Get system info for environmental context. The note distinguishes expected errors (anticipated failure codes handled inline, e.g., DELETE FOLDER's -47/-120) from unexpected errors, which need generic information-gathering and delivery strategies such as writing a text file for the user to send, auto-emailing details, or logging to a dedicated error table. A bundled example database demonstrates the default handler, a simple custom handler, handler scopes and precedence, handler install/uninstall/check management, and both automated and user-involved information-delivery workflows. Overall it positions custom error handling as a straightforward but consequential investment: trap errors quietly, collect rich diagnostic context with a few commands, and route that information to whoever needs to act on it.
