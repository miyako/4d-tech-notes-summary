# Tech Note 21-10: Deep linking with 4D for iOS: implementation and deployment

**Author:** Chaima ELBHIOUI, Technical Support Engineer, 4D Morocco
**Published:** June 21, 2021 | **Product/Version:** 4D v18 R6 | **Platform:** Mac & Win
**Page:** https://kb.4d.com/assetid=78729
**Download:** https://kb.4d.com/DLTN/TN/2021/21-10_4DforiOSDeeplinking.zip

## Proposition
Deep linking lets a shared URL open specific content directly inside a native mobile app. This note shows how to add both URI-scheme and universal-link deep linking to apps generated by 4D for iOS, plus how to configure the resulting build for deployment on macOS and Windows 4D servers.

## Key Points
- **Two deep-linking mechanisms:** URI schemes (simple, but open an empty page if the app isn't installed) and Universal Links (require an HTTPS domain, provide a graceful web fallback).
- **App configuration walkthrough:** organization/developer info, table/field selection, data source, a predefined "sharing" Action bound to a table/entity scope, icon assignment, and list/detail form generation.
- **`On mobile app action`** database method must call `MobileAppServer.Action.new($1)` and dispatch to `.shareContext()` for the sharing action to work.
- **`On Web Connection`** must call `MobileAppServer.WebHandler.new().handle(...)` to route universal-link requests, falling back to a plain HTML page when unhandled.
- **App generation step:** the deep-linking feature is enabled in the Publishing section, auto-filling a URL scheme (e.g. `e-learn://`) or accepting a universal-links domain.
- **Version compatibility matrix:** specific Xcode/Swift/iOS/4D version combinations are required (e.g. Xcode 12.4 + Swift 5.3.2 + iOS 14.4 + 4D 18 R6 beta).
- **Deployment step:** the generated `manifest.json` must be placed under `4DBASE/MobileApps/TEAMID.BundleID/` on the 4D Server, identical on both macOS and Windows hosts.

## Featured Technology
- 4D for iOS (native mobile app generation)
- URI Scheme deep linking
- Universal Links (Apple's `apple-app-site-association` mechanism)
- `MobileAppServer.Action`, `MobileAppServer.WebHandler` classes
- Xcode / Swift toolchain integration

## Best Practices Highlighted
1. Prefer Universal Links over URI schemes when a fallback web experience is required for users without the app installed.
2. Keep the compatible Xcode/Swift/iOS/4D version matrix in sync, since 4D for iOS build tooling was version-sensitive.
3. Test URI schemes via the simulator/browser before configuring the more complex universal-links webhook flow.

## Context / Positioning
This note reflects 4D's mid-2021 push into native mobile app generation as a differentiator ("developing iOS apps in a few clicks"), positioning 4D for iOS as a no-Swift-required bridge from a 4D database to a real App Store-deployable app, complete with advanced platform features like deep linking and push notifications.

## Historical Commentary
**Status:** Obsolete

4D for iOS — and the parallel 4D for Android product — has since been discontinued. 4D shifted its mobile/low-code strategy toward Qodly, a separate visual low-code platform, and toward responsive ORDA/REST-based web applications that work across devices without a native app generator. As a result, every technique in this note (the `MobileAppServer.Action`/`MobileAppServer.WebHandler` classes, the app-generation workflow, the manifest.json deployment path) is tied to a product line no longer offered. A developer today wanting deep-linking-style behavior for a mobile-facing 4D app would build a responsive ORDA/REST web front end (or use Qodly) and implement routing-based "deep linking" at the web-app level instead.
