This tech note documents implementing deep linking in native iOS apps generated by 4D for iOS, a code-free mobile-app-generation feature introduced in 4D v18 that lets developers publish 4D tables/entities as an iOS app via Xcode without writing Swift. It covers both deep-linking mechanisms available on iOS: URI schemes (simple to set up but fail silently to an empty browser page if the app isn't installed) and universal links (require a real HTTPS domain but provide a graceful web-page fallback). The walkthrough goes through the 4D for iOS project configuration steps — organization/developer info, choosing tables/fields, data source, defining a predefined "sharing" Action scoped to an entity, editing the On mobile app action database method to invoke MobileAppServer.Action.new($1).shareContext(), assigning icons, building list/detail forms, and finally generating the app with either a custom URL scheme (e.g. e-learn://) or a universal-links domain entered in the Publishing section. For universal links, an additional On Web Connection method must call MobileAppServer.WebHandler.new().handle(...) to route shared URLs, falling back to a static HTML page when the mechanism doesn't apply. The note ends with deployment notes for placing the generated manifest.json under 4DBASE/MobileApps/TEAMID.BundleID/ on both macOS and Windows-hosted 4D Server deployments, and requires specific compatible versions of Xcode, Swift, and iOS at time of writing (Xcode 12.4, Swift 5.3.2, iOS 14.4).
