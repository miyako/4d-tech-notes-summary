This Technical Note by Josh Fletcher opens with a thorough introduction to REST (Representational State Transfer), explaining its defining architectural constraints — client-server separation, statelessness, cacheability, layered systems, optional code-on-demand, and a uniform interface — and contrasting REST's lighter-weight approach with SOAP-based web services. It grounds these concepts with three worked examples: a Google REST search, a Flickr "echo test," and Wakanda's Entity Catalog (highlighting Wakanda's built-in REST support), before introducing the note's main deliverable: a 4D v13 REST Tester tool. Built using 4D v13's brand-new HTTP Client feature (a small set of new commands enabling HTTP requests/responses directly from 4D), the tester also leverages the DIALOG(...;*) technique and a Web area to display responses, with the whole tool structured around method abstraction for maintainability. The note documents the tester's features in detail — defining tests with custom headers, viewing test responses, browsing test history, fill/auto-fill conveniences, search/filtering, deletion, and list box copy support — followed by a usage walkthrough covering running a test, checking results, reviewing history, and a set of example tests built into the tool. The result is both an educational REST primer and a reusable diagnostic utility that 4D developers could drop into their own databases to experiment with and debug REST API calls.
