This Tech Note describes the author's realization, while maintaining 4D View code used to replace output forms, that a lot of near-duplicate code was being written for each form/table combination that needed a 4D View-based display — even when two forms for the same table only differed slightly in which fields were shown. In response, the author built a generic solution: a simple, easy-to-use editor that lets end users build their own "Views" (custom record display definitions), save those View definitions, and then use the saved Views as a substitute for traditional, hard-coded output forms. This represents a notably more sophisticated, reusable architecture than a one-off 4D View implementation, effectively giving users a lightweight, self-service reporting/viewing tool.
