This Tech Note by Jean-Yves Fock-Hoon is Part II of a two-part series introducing the List Box object in 4D 2004, with Part I (a separate note) covering Design mode configuration and Part II focused entirely on manipulating list boxes through the 4D language. Using a "Building a List box" demo dialog based on the [Contacts] table, it walks through a sequence of buttons that each exercise a different set of list box commands: Clear All (using Get number of listbox columns and DELETE LISTBOX COLUMN to empty the box), Insert Default and More Columns (using a generic M_InsertColumn method built on INSERT LISTBOX COLUMN and BUTTON TEXT to add columns and their header titles), and Attributes (using a generic M_SetupColumn method built on SET RGB COLORS, FONT, FONT SIZE, and FONT STYLE to style individual columns, including a special-cased background color reversion for one particular column). It notes an important constraint: all columns in a list box must be inserted before any of their attributes can be defined within the same method — you cannot interleave insert-then-configure calls column by column. The note also covers the Grid button, which cycles through five display settings using SET LISTBOX GRID COLOR and SHOW LISTBOX GRID, and — most substantially — the Re-Order button, which reorders list box columns despite there being no direct "move column" command in 4D's language; the technique retrieves each column's width and metadata via Get listbox column width and GET LISTBOX ARRAYS, computes a new desired order in a local array via a M_Setorder method, deletes all existing columns, and re-inserts them in the newly computed order. This column-reordering workaround is presented as a reusable pattern for any situation requiring dynamic list box column manipulation beyond what the List Box object natively supports. The note targets 4D 2004 developers building applications that need runtime-configurable list box layouts rather than fixed Design-mode-only configurations.
