# Tech Note 13-05: 4D and Web Pagination

**Author:** Charles “Charlie” Vass, Technical Services Team Member, 4D Inc.
**Published:** May 22, 2013 | **Product/Version:** 4D v13.2 | **Platform:** Mac & Win
**Page:** https://kb.4d.com/assetid=76824
**Download:** https://kb.4d.com/DLTN/TN/2013/13-05_4DAndWebPagination.zip

## Proposition
This Tech Note surveys web pagination — the technique of splitting large result sets across multiple pages — and demonstrates four different implementation strategies for a 4D web application, ranging from client-side JavaScript-only pagination to server-managed pagination using record selections, SQL, and 4D Tags, each with documented pros and cons.

## Key Points
- Reviews general pagination UX rules, citing Faruk Ates' "Pagination 101" 7 aspects of good pagination.
- Demo 1: all pages pre-rendered and managed entirely in the web client.
- Demo 2: pages generated by the 4D Web Server using a record selection combined with 4D Tags.
- Demo 3: pages generated by the 4D Web Server using SQL queries combined with 4D Tags.
- Demo 4: pages generated by the 4D Web Server using SQL and a JavaScript multidimensional array for client-side rendering.
- Weighs strategy pros/cons for each demo (server load, responsiveness, statefulness, scalability).

## Featured Technology
- 4D Web Server (classic)
- 4D Tags
- SQL (embedded)
- JavaScript multidimensional arrays
- Record selections / SET

## Best Practices Highlighted
1. Choose a pagination strategy based on data volume and desired client/server load balance.
2. Apply established UX rules (visible page ranges, first/last/next/prev controls) rather than ad hoc pagination.
3. Use SQL-based queries for large data sets instead of loading entire record selections into memory.

## Context/Positioning
Published for 4D v13.2 during the era of the classic 4D Web Server and 4D Tags-based dynamic HTML generation, when 4D was positioning itself as a capable web application backend independent of external frameworks.

## Historical Commentary
**Status:** Partially Superseded

The core pagination UX principles remain timeless and still apply to any web application built with 4D today. However, the concrete implementation techniques — 4D Tags-based HTML generation and the classic 4D Web Server request model — have been superseded for new development by REST/ORDA-based APIs consumed by modern JavaScript front-ends (e.g., React, Vue) that handle pagination client-side against paged entity selections, making server-side 4D Tag templating far less common for new projects.
