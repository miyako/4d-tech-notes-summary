This Tech Note addresses the challenge of shutting down 4D Server v6 when stored procedures — methods executed on the server machine within dedicated 4D processes — are still running. Stored procedures were a major new feature in 4D Server v6, enabling server-side computation outside the context of any connected client. Because these methods run independently on the server, a simple shutdown could leave processes in an inconsistent state. The note describes the recommended approach for ensuring that stored procedures complete their execution before the server shuts down. It also covers the proper sequence for disconnecting 4D Client connections prior to initiating the server shutdown.
