# Tech Note 05-26: Using ListBoxes as Subforms

**Author:** Not specified in available source

## Overview
This Tech Note discusses 4D 2004's new List Box object as an alternative to the classic Subform, following 4D 2004's rewrite of list-style forms (Output forms, Subforms, and User mode).

## Key Points
- 4D 2004 introduced the List Box: a grouped, scrollable array object with greatly enhanced capabilities versus older list mechanisms.
- The note does not claim List Box always beats Subform, but gives scenarios where List Box may be the better fit.
- It shows how to substitute a List Box in place of a Subform when desired.

## Featured Technology
- 4D List Box form object (array-backed, at the time)
- Subforms / included forms
- 4D 2004's rewritten Output/list form architecture

## Historical Context
**Status:** Still relevant

The List Box vs. Subform decision this note addresses remains meaningful today, since both objects still exist in current 4D — though the List Box has grown dramatically more capable, now supporting object, entity selection, and collection-backed data sources in addition to arrays, well beyond what was available in 2005. Modern 4D UI guidance generally leans further toward List Box for tabular data, making this note's early advocacy for List Box's use directionally still valid, even as its concrete 2005-era examples are dated.
