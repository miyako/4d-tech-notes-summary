This Tech Note addresses a design question introduced by 4D 2004's complete rewrite of list-style forms (covering Output forms, Subforms, and User mode): when should a developer use the new List Box object instead of a traditional Subform? It describes the List Box as a grouped, scrollable array with greatly enhanced display and interaction capabilities compared to older list mechanisms — colloquially described in the note as "grouped scrollable arrays on steroids." Rather than definitively answering whether List Box or Subform is the better general choice (a common point of developer confusion at the time), the note takes a practical approach: it offers concrete scenarios where a List Box may be preferable to a Subform, and walks through how to substitute a List Box in place of a Subform when that is the developer's preference. This positions the note as a practical migration/decision aid for developers navigating 4D 2004's major list-form overhaul (the same release covered more broadly in the companion FAQ Tech Note 05-19). The List Box object introduced here would go on to become one of 4D's most heavily used and continuously enhanced UI objects over the following two decades, eventually supporting object, entity selection, and collection data sources far beyond the array-based model available in 2005. Because only the teaser paragraph for this note survived in this archive, the specific example scenarios and step-by-step substitution instructions are not available in further detail here.
