Kent Wilbur, Manager of Information Systems at 4D, Inc., compares the classic Subform object against the List Box object introduced with 4D 2004's list-form rewrite, framing the List Box as a "grouped scrollable array on steroids." The note argues that Subforms require heavy Client/Server traffic because 4D Client sends each related record to the server as the user navigates rows, forcing the use of transactions to safely roll back a Cancel; List Boxes, being arrays, transfer all their data to the client once, need no network traffic while in use, and can eliminate transactions entirely since nothing is saved to the database until the user commits via ARRAY TO SELECTION. The example database reimplements a classic [Invoices]/[LineItems] input form using a List Box (fLineItems) instead of a subform: the On Load event loads related records into six parallel arrays sorted by a saved Position field, On Validate strips empty rows and writes the arrays back with ARRAY TO SELECTION, and On Unload frees the arrays and rolls back an unused sequence number if the user cancels. The List Box also gets built-in sortable columns, alternating row colors, resizable rows without splitters, and drag-and-drop row/column reordering — including persisting the user's custom row order via a `Position` field — none of which are available out of the box on a traditional subform.
