This Tech Note introduces WebSocket technology and 4D v20's new native support for it via the 4D.WebSocketServer and 4D.WebSocketConnection classes, contrasting it with the stateless request/response model of HTTP and the inefficiencies of short and long polling. Because WebSocket keeps a persistent, full-duplex TCP connection open (upgraded from HTTP via the handshake), either the server or any connected client can push updates at any time, which is ideal for chat, collaboration, or live-dashboard style applications. On the server side, a WebSocketServer is instantiated with 4D.WebSocketServer.new() inside a worker process (via CALL WORKER) and paired with a user-defined "ServerHandler" class implementing onOpen, onConnection (mandatory), onTerminate, and onError callbacks; onConnection must return an instance of a "ClientHandler" class or Null to reject the connection. Each accepted connection becomes a WebSocketConnection object exposing send(), terminate(), and a handler/wss reference, while the ClientHandler class implements onOpen, onMessage (mandatory), onTerminate, and onError to react to per-client events. The note walks through a complete example — a sales team "prospect list" app where team members can mark contacts as busy/available — implemented with a WSServerHandler class holding shared data, a WSClientHandler class that pushes JSON state on connect and merges updates from onMessage, and a browser-side client using the native JavaScript WebSocket object plus the Tabulator.js library to render and edit a live table, showing bidirectional real-time sync across multiple open clients. The note positions WebSocket as filling a gap in 4D's web-server toolkit for scenarios where classic HTTP polling is too slow or wasteful, without requiring any third-party real-time messaging service.
