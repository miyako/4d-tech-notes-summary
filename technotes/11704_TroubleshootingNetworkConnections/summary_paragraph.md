This Tech Note is a practical, symptom-oriented troubleshooting companion covering the three network protocols 4D Client/Server supported in 1996: ADSP (AppleTalk), IPX/SPX (Novell), and TCP/IP. For ADSP, it addresses issues such as clients on PCI-based Power Macintosh models requiring Open Transport (rather than Classic AppleTalk) to see a 4D Server, Windows clients needing MacLAN Connect (with specific version compatibility notes) to speak AppleTalk, and general AppleTalk zone-visibility problems caused by router/zone misconfiguration. For IPX, the main culprit discussed is a "Frame Type" mismatch — since IPX can run over multiple physical frame formats, client and server must be configured to use the same one, or the server will be invisible to the client. The TCP/IP section is the most detailed: it walks through diagnosing subnet mask mismatches and misconfigured or missing default routers/gateways as common reasons a 4D Client on a different subnet cannot reach 4D Server, recommends using the OS-level Ping utility as the first diagnostic step to confirm basic IP connectivity before blaming 4D itself, and explains the "-10002" error as 4D Client's own connection timeout being exceeded while waiting for a server response — adjustable via the TCP.OPT configuration file. It also flags a specific known defect: a Windows 95 TCP/IP stack memory leak that could degrade or break long-running network connections, along with the Microsoft-provided fix. The note closes with general good-practice troubleshooting advice: isolate whether the problem is 4D-specific or a general network/OS issue (e.g., by testing whether other networked applications work), and check for recent changes to the network environment before assuming a software bug. Featured technology is squarely the three legacy connection protocols (ADSP, IPX/SPX, TCP/IP) as implemented in 4D Server's client/server architecture circa 1996.
