This Tech Note documents 4D v11 SQL Assimilator, a component successor to the original 1999 4D Assimilator and the 2004 version (TN 04-38), designed to let developers migrate an existing database into 4D v11 SQL without manually recreating structures and data. Unlike its predecessors, which relied on the 4D ODBC or ODBC Pro plugins for all communication, this version does its work purely through 4D's then-new native SQL language, reading system-table metadata directly for supported vendors (MySQL 5, SQL Server 2000, MS Access, and other 4D v11 SQL databases) — connecting directly (without ODBC) to a 4D v11 SQL Server, but still requiring an appropriate ODBC DSN, username, and password for third-party databases or 4D databases prior to v11 SQL. The note details the component's private `ASS_`-prefixed methods (login/logout, table-list retrieval per vendor, record-count and cycle-size calculation for chunked imports, table creation, and paginated batch record retrieval), documents special-character and type-mapping caveats (e.g., MySQL ENUM becomes a 4D Alpha field sized to the character_maximum_length), and walks through the resulting three-page Wizard UI: selecting tables and fields (with unsupported SUBTABLE/UNDEFINED fields automatically excluded), previewing up to 25 sample records per table, and setting "Action Preferences" governing whether to create new tables, replace existing ones (which deletes existing data), and how many records to import per processing cycle (tunable via a size-based "ruler" or manually locked to a byte count). Because Assimilator adds no permanent methods to the host database, it can be installed only for the duration of a migration and then discarded. The intended audience is developers performing one-time or repeated database migrations into a fresh or existing 4D v11 SQL structure.
