This Tech Note (TN 01-55, 4D v6.7, Mac & Win, published December 30, 2001) presents a technique for programmatically enabling and disabling field indexes on a compiled database. Only a short on-page teaser paragraph survives in this archive rather than the full downloadable PDF and example database, because the original download was an old Windows self-extracting .exe installer (https://kb.4d.com/ftp://ftp.4D.com/ACI_TECHNICAL_NOTES/2001/Windows/TN_2001_54-57_(DEC)/01-55_Index_Control_Panel.exe) that could not be extracted in this environment; the original 4D Tech Notes site offered separate Windows and Mac downloads of the complete note and its companion example database, but neither is retrievable here. Based on the surviving teaser text, the note's proposition is: There are times indexed fields may need to have their indexes turned off and on for rebuilding a particular field's index or for other reasons. If the database is compiled, the access to the design environment is not available and it is time consuming to re-index the uncompiled version and recompile it. This technical note explores a means of turning indexes off and on programmatically. Its featured technology centers on SET INDEX / index management commands, Compiled database maintenance, reflecting typical concerns of the 4D 6.7 (4D 2000/2001 era) developer community working in binary Design Mode on classic Mac OS/early Mac OS X and Windows 98/2000/NT. This note addresses a practical pain point of the compiled-database era: needing to toggle field indexes on and off without access to the Design environment, since a compiled database could not be re-indexed or recompiled quickly. The technique of programmatically enabling/disabling indexes via the classic language remains valid in current 4D versions, though modern deployments increasingly manage index/data maintenance through 4D Server's administrative tools rather than hand-rolled control panels.
