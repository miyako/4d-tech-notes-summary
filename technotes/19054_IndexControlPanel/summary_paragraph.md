This 2001 Tech Note by Steve Hartman, MCP, of 4D, Inc. Information Systems (with the sample database co-authored by Kent Wilbur) addresses a practical problem: compiled 4D databases have no access to the design environment, making it time-consuming to turn a field's index off and back on to force a rebuild, since doing so normally requires re-indexing the uncompiled version and recompiling. The accompanying "Index Control Panel" sample database provides a runtime UI, opened from the File menu, that lists tables and fields with toggleable "X" marks; turning a field's mark off and quitting/relaunching the database, then turning it back on and quitting/relaunching again, forces 4D to fully re-index that field (with 4D 6.7 automatically re-indexing related fields when their index is toggled). The note walks through the core method M_INDEX_SetIndexes, which checks that the current user is a Designer or Administrator, verifies (via Count users) that no other client is connected before allowing structural changes, reads the current index state from a zStructure table using QUERY and SELECTION TO ARRAY, displays the toggle dialog wrapped in a START TRANSACTION/VALIDATE TRANSACTION block, and guards against concurrent modification with a "ModifyingStructureTable" semaphore. The companion method INDEX_ModifyIndexes then walks the table and field arrays and calls SET INDEX(pField->;True/False) for each field based on the toggle states. The note credits Kent Wilbur for co-authoring the sample database and positions the technique as a lighter-weight alternative to opening a database with 4D Tools purely to repair or rebuild indexes.
