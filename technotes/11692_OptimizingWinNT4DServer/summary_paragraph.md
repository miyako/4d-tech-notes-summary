This February 1996 Tech Note by Christopher Chapman provides a set of Windows NT optimization techniques for running 4D Server under Windows NT Workstation or Windows NT Server, explicitly framed as based on Microsoft's recommendations and ACI's own testing, with the caveat that results may vary and changes should be tested carefully before production use. It recommends using the NT File System (NTFS) over FAT or HPFS for speed, reliability, and NT's built-in security model; sizing the pagefile as physical memory plus 12 MB, splitting it evenly across all physical hard drives except the one containing the /WINNT directory (with a worked example for a 24 MB RAM, three-drive system); compressing the directory containing the 4D data file on an NTFS volume to roughly halve physical disk reads (with a caveat to add processor speed/RAM headroom to offset decompression overhead); launching 4D Server from a batch file using `start /REALTIME 4DSERVER.EXE` to give it priority over other running applications for CPU time slices, with the caveat that no other application should run concurrently on the server machine; configuring the display to a minimal 640x480x256-color setting to reduce rendering overhead (with the underlying pixel/color-depth memory math shown); and configuring the desktop to use a blank/None screen saver (or simply turning off the monitor) to minimize unnecessary overhead. The featured technology is entirely 1996-era Windows NT system administration and configuration as it pertains to 4D Server performance.
