This Tech Note by Bertrand Soubeyrand, a 4D Developer, describes a compact 15-line-of-code system for dynamically renaming tables and fields throughout a 4D application, useful for multilingual databases or for presenting friendlier labels than a structure's original creation-time names. It centers on four commands: SET TABLE TITLES and SET FIELD TITLES (which existed previously but were limited in scope) and the two commands new in 4D 2003, GET FIELD TITLES and GET TABLE TITLES, which for the first time let a database retrieve its own current custom names and numbers — extending where custom titles could be surfaced to include the Search editor, Sort editor, dynamic field/table labels in forms, the Quick Report editor, and Import/Export dialogs. The technique stores one 4D choice list per table (named e.g. 'SV_Table1'), where entry 0 holds the table name and subsequent entries hold each visible field's custom name, keyed to the field's physical creation-order number via ARRAY TO LIST's optional reference-number parameter; because 4D ships an editor for choice lists, renaming and reordering entries is just double-click-to-rename and drag-and-drop, with no custom UI needed. A '4DSV_Rename' method run from On Startup reads back every choice list with LIST TO ARRAY, pulls out the table name (element 0), and calls SET FIELD TITLES and SET TABLE TITLES so every process sees the custom names from the start. A companion '4DFIELD_ReadSV' method uses RESOLVE POINTER to accept a generic pointer to any table or field and return its current custom label, useful for building generic alert/status messages. The note also includes a 6.x-compatible version of the storage method (using Table name/Field name/Count tables/Count fields instead of the new GET TITLES commands) for developers supporting older structures.
