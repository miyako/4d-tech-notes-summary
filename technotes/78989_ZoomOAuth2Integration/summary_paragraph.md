This note walks through end-to-end integration between a 4D application and the Zoom meeting platform using OAuth 2.0, which 4D has supported natively via its OAuth2 provider class since v18 R6. On the Zoom side, it covers registering an account-level OAuth app in the Zoom Marketplace, configuring an allowed redirect URL (e.g. http://127.0.0.1:80/authorize/), and granting meeting-related scopes such as meeting:read:admin. On the 4D side, New OAuth2 provider($param) is instantiated with clientId, clientSecret, authenticateURI, tokenURI, redirectURI, and scope, and $oAuth2.getToken() exchanges credentials for a bearer access token, which is cached in a shared object (Storage.token, wrapped in Use/End use) so it can be reused across CRUD operations for up to its one-hour expiry rather than re-authenticating on every call. Once authenticated, standard 4D networking commands — HTTP Get for listing meetings via Zoom's REST API (api.zoom.us/v2/users/me/meetings), and HTTP Request with the POST/DELETE method constants for creating/updating and deleting meetings — drive the actual meeting CRUD operations, with 401 responses triggering a re-authentication flow. The retrieved meeting data is also serialized to a Meetings.json file and rendered in a 4D web area using the third-party 'fullcalendar' JS library, with WA SET EXTERNAL LINKS FILTERS used to allow the embedded Zoom join links to open externally.
