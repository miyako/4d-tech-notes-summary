This Tech Note documents a custom server-monitoring component built around Get process activity, a command first introduced in 4D version 16 R4 that returns information about connected user sessions and their related running processes on a 4D Server — including internal processes not previously reachable via PROCESS PROPERTIES. The note opens with an abstract acknowledging that 4D already provides native server-monitoring UIs, but explains that a custom interface is sometimes needed for tailored dashboards, filtering, or automated logging. It compares the existing Process Manager tool against the new component, then documents the Get process activity command's parameters and its Sessions/Processes return objects in detail. The bulk of the note walks through a sample "Processes_Display" form with Init_Form and Update_Form methods, supporting Manage_Lists, Filter_Listbox, and Manage_Arrows methods for interactive filtering and sorting of a listbox display. It also covers graphing captured data (Sort_Two_Arrays_And_Graph and Graph_CPU_Top_5 methods) to visualize top CPU-consuming processes, and a logging subsystem (Set_Log_Location, Log_Manager, Data_Logger) that can output both JSON and plain-text log formats with example output shown for each. The resulting component/sample is designed to be dropped into any 4D database running v16 R6 or later and launched automatically at server startup for continuous background monitoring, filtering, and historical logging of server activity.
