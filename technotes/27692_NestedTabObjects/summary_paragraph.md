Written by Steve Hartman of 4D's Information Systems group, this Tech Note builds on the Tab Control object introduced in 4D v6 to show how one Tab Control can be nested inside a page of another, creating a hierarchical multi-page navigation structure, illustrated with an "Employee Demo" database that restricts information access by department (Human Resources, Accounting, Manager, Information Systems). The first example shows a top-level tab control whose object method, fired `On Load`, uses `SET LIST ITEM PROPERTIES` to disable specific tabs (e.g., hiding Accounting/Information Systems tabs from a Human Resources user) based on `Current user`, so different roles see a different subset of available tabs on the same form. The second example nests a further tab control on the Information Systems page itself, used to switch between Email, FTP, and database account information for an employee; its object method tracks the currently active tab in a variable (`LLastTab`), re-enabling the previously active tab and disabling the newly clicked one via paired `GET LIST ITEM PROPERTIES`/`SET LIST ITEM PROPERTIES` calls on both `On Load` and `On Clicked` events. Because 4D's `SET VISIBLE` command does not work on grouped objects directly, the note describes a naming convention where every object belonging to a given nested-tab "page" is prefixed with a group name (Group1, Group2, Group3) and then grouped for layout purposes; the tab control's object method then uses `SET VISIBLE(*;"Group@";False)` to hide everything and `SET VISIBLE(*;"Group"+String(LLastTab)+"@";True)` to reveal only the objects belonging to the newly selected page. The note concludes by reiterating that tab controls are lightweight, fast, and intuitive, and that nested tab controls extend that same navigation model to multiple levels within a single form.
