This Tech Note, written by Julien Feasson of 4D's Information Systems group, introduces the 4D remote FastCGI component, which lets a 4D database act as a FastCGI responder for any FastCGI-capable web server such as 4D WebSTAR V. It opens with a survey of the evolution from CGI (simple but slow, spawning a process per request) to proprietary server APIs (fast but insecure and non-portable) to FastCGI, a language- and platform-independent protocol that forwards requests to a long-running process instead of spawning a new one each time. The note documents the low-level FastCGI wire protocol, including the FCGI_Record C struct and its record types (FCGI_BEGIN_REQUEST, FCGI_PARAMS, FCGI_STDIN, FCGI_STDOUT, etc.), before showing how the 4D component hides this complexity behind just four functions: FCGI_Accept and FCGI_Send to communicate with the web server, and FCGI_ValueVar/FCGI_ValueParam to read environment variables and posted form parameters. A basic 4D FastCGI script is structured as a `While(FCGI_Accept(RemoteHost;LocalPort))...FCGI_Send(response)...End while` loop, with FCGI_Accept populating arrays like FCGI_Name/FCGI_Value and FCGI_ParamName/FCGI_ParamValue for each request. The note walks through a complete echo-script sample that reflects all environment variables and POST parameters back as an HTML page, and closes with configuration steps for pairing the component with 4D WebSTAR V on port 80, plus the license and version requirements (4D v6.8.1+, a 4D Web License, and 4D Internet Commands v6.8).
