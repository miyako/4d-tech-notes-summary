This Tech Note builds a "Reporting Frontmost Status Tool" (RFST) to answer a practical productivity question: how much of the time a user has 4D open is 4D actually the frontmost (actively used) application, versus running unattended in the background? The implementation is built entirely on features new around 4D v16R6 — Storage, Workers, and preemptive processing — to let 4D Server track and display frontmost status across all connected clients without heavy custom infrastructure. On the client side, each connection registers with the server, periodically checks whether the 4D client process is frontmost using platform-specific checks for both Mac and Windows, and sends its status to the server using CALL Worker; clients also unregister on disconnect. The server side maintains a Storage object holding the registered client list, and a "Check registered users" mechanism plus CALL FORM keep the RFST monitoring form in sync. The RFST form itself, opened in 4D Server by holding the Shift key, presents an "In Front" column, a "Users" column, and a "Time elapsed" column, continuously updated as clients report status. The note also documents startup/shutdown wiring (At Startup, At Exit, On Server startup, On Server shutdown) so the tool integrates automatically with normal server and client lifecycle events, and packages the whole thing as a component that can be dropped into any database to gain visibility into actual client-side usage/productivity patterns.
