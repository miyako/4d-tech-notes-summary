This Technical Note explains how to use the 4D Ajax Framework (4DAF), part of the 4D Web 2.0 Pack, to "inject" JavaScript into a web page by having a Developer Defined Window (DDW) method return script content instead of HTML. The back end configuration requires creating a DDW pointed at a 4D method that returns a string of JavaScript prefixed with "JS:", installed via the DAX_DevHook_DDW_Install hook and DAX_Dev_DDW_Create function (or via the 4DAF Control Panel). For custom HTML pages, the front end must build a DDW URL (using the DDW id found in the "DDW.xml" file plus the logged-in session id), call it with the 4DAF "makeCall" function, and manually parse the XML HTTP response to extract and eval() the JavaScript. As of 4DAF 1.2, the 4DAF Client itself gained the ability to automatically detect and execute "JS:"-prefixed responses from a DDW Portlet without any custom parsing code. The bundled "Contacts" sample database demonstrates both approaches: a DDW Portlet that injects a simple JavaScript alert, and a custom "example.html" page that uses injected JavaScript to dynamically create 4DAF Data Grid objects (via the "DataWindow" JavaScript constructor) tied to different 4D Views/tables, abstracting view names out of the static HTML. The note stresses that DDW content is not validated by 4D in any way, so developers are responsible for ensuring returned JavaScript is well-formed. It closes with a caveat, common to all 4D Web 2.0 Pack notes of this era, that the subscription-based, rapidly-iterating 4DAF product may render specifics of the note obsolete quickly. Featured technology centers on 4DAF, DDWs, the Daxipedia "Bridge#makeCall" API, and 4DAF Data Grids, all built atop 4D's classic Design Mode / procedural method architecture that predates 4D v11's SQL engine, Project Mode, and ORDA.
