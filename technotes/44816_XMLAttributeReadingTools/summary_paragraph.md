This Technical Note by David Adams builds an enhanced utility layer on top of 4th Dimension's three native DOM commands for counting and reading XML element attributes (DOM Count XML attributes, DOM GET XML ATTRIBUTE BY INDEX, DOM GET XML ATTRIBUTE BY NAME), adding a set of refinements the base commands lack. The accompanying sample database implements automatic error handling to avoid crashes from invalid node references, automatic detection and safe handling of the synthetic "#document" node (which can cause some versions of 4th Dimension to quit unexpectedly if its attributes are counted naively), utilities to match attributes by name, by value, or by both name and value together, and a tool to copy all of a node's attribute names and values into a pair of parallel arrays. The documented routines include DOM_AttributesToArrays (copies attribute names/values into text arrays), DOM_CountAttributes (a safer wrapper around the native count command), DOM_GetAttributeNameWithValue and DOM_GetAttributeValueWithName (case-insensitive-by-default lookups in either direction), DOM_HasAttributeNamed, DOM_HasAttributeNameAndValue, and DOM_HasAttributeWithValue (boolean existence tests with configurable case sensitivity for values, always case-sensitive for names), plus the shared DOM_ReferenceIsValid, DOM_ReferenceIsValidOnError, DOM_StartCustomErrorHandling, and DOM_StopCustomErrorHandling internal helpers that install and restore a custom ON ERR CALL handler around risky DOM calls. It also includes a String_EqualCaseSensitively utility specifically for the case-sensitive element/attribute name comparisons XML requires. As a direct companion to the same era's "Avoiding Problems Reading DOM XML Nodes" note, this Tech Note packages the underlying defensive error-handling approach into a convenient, reusable attribute-access API layer, illustrating a common 4D pattern of the period: wrapping a raw, error-prone native command set with a richer and safer custom utility library for reuse across projects.
