This Tech Note introduces "Form Data," a feature new in 4D v17 that lets a developer bind a C_Object variable directly to a form via the new FORM command, giving all code executing in that form's context direct access to any property of the object. Previously, running multiple simultaneous instances of the same form (e.g., several dialogs) required careful juggling of process variables to avoid collisions; formData solves this by giving each form instance its own object reference, so opening the same dialog form multiple times in a single process no longer risks shared-state bugs. The note documents the new FORM command as well as an updated DIALOG command that now accepts a formData parameter, and shows how parameters can be passed both to top-level forms and into subforms through formData. It walks through accessing formData from code versus accessing it via form objects, then works through three concrete examples: using formData to manage multiple simultaneous windows in a single process, using it for general data-entry forms, and using it with a subform to extend a table's input form by binding a new Object field on the table to a subform's formData, enabling an effectively unlimited amount of ad hoc structured data to be attached to a record through a single field. This capability is positioned as a straightforward way to reduce reliance on process variables and interprocess variable pitfalls in 4D form code.
