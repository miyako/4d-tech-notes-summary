Charles Vass's Tech Note introduces assertions as a formal debugging discipline newly supported in 4D v12 via four commands (ASSERT, Asserted, Get assert enabled, SET ASSERT ENABLED) and two new system variables (Error method, Error line). It explains what an assertion is and why developers should use them to validate assumptions about program state (e.g., that a calculated value falls within an expected range), then details when and where assertions are most useful in a codebase. The note walks through implementing assertions in a demo, contrasting 'the old way' (manual conditional checks) with 'the ASSERT way' and 'the Asserted way,' and shows the default v12 Assert-failed alert as well as how to build a custom alert using the Error method/Error line system variables inside an ON ERR CALL error-catching method. The Tech Note positions assertions as a lightweight, low-overhead technique for catching logic errors early during development.
