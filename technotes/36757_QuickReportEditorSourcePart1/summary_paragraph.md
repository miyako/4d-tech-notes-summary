Kent Wilbur, Manager of Information Systems at 4D, Inc., opens a three-part series dissecting the source code behind 4D 2003/2004's completely rebuilt, wizard-driven Quick Report editor, whose 16 form pages and 39-plus project methods can look intimidating at first glance. Part 1 focuses on the code that prepares the editor for use before the user starts working with it: the entry-point method __Open_dialog and its three controlling option variables (nqr_wizard, nqr_allowsearches, nqr_allowautomatic), which mirror the last three Boolean parameters of the QR Report command. The bulk of the note walks through NQR_Init_Struct_Description, the routine that reads the entire database structure into a set of parallel one- and two-dimensional arrays (tables, fields, and relationship parent/child/automatic flags) using GET TABLE TITLES and GET FIELD TITLES, creating a fast in-memory "virtual structure" the editor can query without hitting the real structure repeatedly. It then explains how that virtual structure feeds NQR_MP_Get_Fields, which builds the hierarchical list of available report fields shown to the end user. Along the way Wilbur highlights a reusable 4D trick: using SET FORMAT with a picture-resource string like "1;4;:14934;64" to swap displayed images on the fly without touching the form in the editor, useful for building dynamic, code-driven UI. The note explicitly limits itself to the editor's own code, not the separately licensed Quick Report plug-in area, and closes by pointing forward to Parts 2 (manual mode) and 3 (the wizard itself).
