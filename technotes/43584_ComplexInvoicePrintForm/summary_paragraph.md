This Tech Note by Thomas Maul demonstrates the power of 4D 2004's greatly enhanced Print Form command by walking through a complex invoice-printing example, showing techniques that had previously been difficult to implement generically in earlier 4D versions. Built on the standard "Invoice" example database (with an added product-description text field and a "PrintSmartForm" component group), the example demonstrates printing an invoice with a different header on the first page versus subsequent pages, different footers for subtotal pages versus the final page, and automatic wrapping of a long invoice line-item's text description across a page break. The underlying 4D form is structured into named zones — an initial header, a repeating "following pages" header, detail and break areas for invoice line items, a filler area to pad unused page space, and separate subtotal/final footers — each triggered by the Print Form engine as needed. To handle text descriptions that may span multiple lines or pages, the note explains that a single print object cannot be used; instead, it relies on a plug-in to calculate word-break positions based on font, size, and style, using a recompiled version of "LineStarts," a plug-in first published in 1992 as the very first 4D US Tech Note, now rebuilt as a cross-platform Mac/Windows bundle. The note documents the simple LineStarts syntax (passing a text field, font, size, style, and target width to get back an array of break positions), and describes how to integrate the reusable "PrintSmartForm" method group (four "PrSF_" methods) into a target application either via 4D Insider or by manually copying the methods, then wiring a form's On Printing Detail event to call PrSF_PrintFormMethod and invoking PrSF_Print with pointers to the invoice and line-item tables plus text-formatting parameters. It further explains customizing PrSF_ItemCalculation, a per-item hook method used to accumulate running subtotals or perform other per-line calculations, noting it can be adapted with a Case statement to serve multiple document types (invoices, shipping papers, orders). The note is aimed at 4D 2004 developers needing sophisticated, reusable multi-page document printing without a full word-processing engine.
