This Tech Note demonstrates end-to-end integration between 4D's v18 REST server and a modern JavaScript single-page application built with ReactJS, using a demo app that lets users browse and read Edgar Allan Poe short stories. It walks through the required 4D database configuration — enabling "Expose as REST server" and CORS (with a wildcard domain for development) in Structure Settings — and scaffolding a React app with `create-react-app`/npm. Authentication is handled through 4D's `On REST Authentication` database method, invoked by a `fetch()` GET request to `/rest/$directory/login` carrying `username-4D`/`password-4D` headers and validated server-side with `Validate password`; the resulting session cookie must be included on subsequent requests (`credentials: 'include'`) to avoid consuming extra client license connections. For the story detail page, the note shows the basic Dataclass REST pattern `/rest/{dataClass}({key})/{attribute1,attribute2,...}` to fetch specific entities and attributes, plus a special image-fetching URL form (`?$imageformat=best&$version=...&$expand=...`) to retrieve picture attributes, whose returned URI is nested under `__deferred.uri`. For the list page, rather than consuming the verbose default Dataclass JSON (full of `__GlobalStamp`/`__STAMP` metadata), the note introduces an Entity Selection Class function: a "StoriesSelection" ORDA class extending the Stories entity selection class defines a `getInfo` function that iterates `This` and returns a clean collection of plain objects, callable via a POST request to `/rest/Stories/getInfo/` and filterable by adding `?$filter='category=Horror'` to have 4D pre-filter the entity selection before the function runs. The note positions 4D's v18 REST server as a fully capable backend for any modern JS frontend framework, independent of the classic 4D client, and it is one of several period Tech Notes pairing 4D REST/ORDA with popular frontend frameworks (React here, Angular in a related note).
