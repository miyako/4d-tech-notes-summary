# Tech Note 04-38: Using 4D 2004 Assimilator

**Author:** Not specified in source

## Overview
This note introduces the 4D 2004 Assimilator, a utility that can clone the data structure and data files from any ODBC-compliant database and import them into a new 4D database, aimed at developers migrating an existing database into 4D.

## Key Points (from available teaser)
- The Assimilator can clone data structures and data files from any ODBC-supporting database.
- It targets developers who want to migrate a current database into 4D without manually recreating structures/data.
- Works generically through ODBC, so it can in principle target any ODBC-compliant source database.

## Featured Technology
- 4D 2004 Assimilator tool
- ODBC-based database cloning/migration
- Database structure and data file import into 4D

## Historical Context
**Note:** Only the on-page teaser paragraph was recoverable for this Tech Note; the full PDF and example database were not accessible (old archive format not retrievable in this environment), so the specific migration workflow cannot be detailed here. The Assimilator as a distinct named tool is no longer part of current 4D offerings, and modern database migration into 4D relies on different approaches (ODBC/SQL import, scripted data import, or ORDA-based connections), making this note primarily of historical interest today.
