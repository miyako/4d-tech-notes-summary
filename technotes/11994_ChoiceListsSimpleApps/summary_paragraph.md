Written by Steve Hussey, CEO of Alto Stratus LLC, this Tech Note surveys practical, everyday uses of 4D's non-hierarchical choice lists: speeding and standardizing field data entry via Choice Lists, Required Lists (limiting entries to only the listed values), and Excluded Lists (blocking specific entries); populating drop-down menus by copying a list into an array with LIST TO ARRAY and reading the user's selection back from the resulting array/variable pair; and naming and configuring the tabs of a tab object, including procedurally enabling or disabling individual tabs at runtime with SET LIST ITEM PROPERTIES. It then confronts a genuine limitation of choice lists: because they are stored in the database structure file, any values a client adds or edits are silently overwritten the next time the developer ships an updated structure. The proposed solution stores each list's contents redundantly in two data-file tables, Util_List (list names) and Util_List_Item (a related-many table of list items), and provides a LIST_Updt custom function that queries these tables and rebuilds the in-memory list with SELECTION TO ARRAY/ARRAY TO LIST whenever needed (either at startup or before each use), plus a Modify Lists dialog letting end users create, delete, and edit list items entirely within the data file so their changes always survive a structure update.
