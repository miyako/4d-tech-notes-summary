This Tech Note tackles the problem of building record-entry forms "on the fly" for user-created tables — a common need once 4D v11 SQL let developers add tables/fields via SQL DDL at runtime. The included Dynamic Detail Forms (DDF) component uses 4D's table/field metadata commands to generate an HTML form (styled via a `ddf.css` stylesheet) that is rendered inside a 4D Web Area, with 4DVAR/4DSCRIPT tags binding field values and JavaScript handling in-browser interaction. Field values are read back from the HTML/JavaScript layer into 4D using the `WA EXECUTE JAVASCRIPT FUNCTION` command, which lets 4D call named JavaScript functions inside the Web Area and receive their return values as text. The component ships two usage modes: a turnkey `DDF_runForm` call that opens a ready-made window for any table, and eight lower-level shared methods (`DDF_onload`, `DDF_saveRecord`, `DDF_nextRecord`, etc.) for developers building fully custom detail forms with standard navigation/save/delete/cancel actions. Field-type-specific logic (e.g., special handling for Picture fields via `READ PICTURE FILE`) validates and commits each field before `SAVE RECORD` is called, and record locking is checked on load to disable Save/Delete when another process holds the record.
