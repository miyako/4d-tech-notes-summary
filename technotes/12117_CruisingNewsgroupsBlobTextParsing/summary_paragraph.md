Written by Tim Tonooka, a 4D Solution Partner, this Tech Note introduces the '4D News Jockey' example database, a full-featured Usenet newsreader built around the NNTP support in the 4D Internet Commands plug-in (v6.7), and uses it to teach a specific text-parsing performance lesson. The note walks through NNTP mechanics directly — sending HELP, LIST ACTIVE, GROUP, ARTICLE/HEAD/BODY, and the batch-oriented XOVER commands to a news server and parsing the replies — and highlights UI techniques such as HIGHLIGHT RECORDS, BOOLEAN ARRAY FROM SET, and LONGINT ARRAY FROM SELECTION (all new in 4D v6.5) for managing persistent multi-record selections in a scrolling list. Its central technical contribution addresses decoding uuencoded binary attachments embedded in article bodies, which can exceed 4D's 32,000-character text-field limit and therefore must be handled in BLOBs: the note demonstrates experimentally that BLOB variables are not inherently faster than text for equivalent string operations (a benchmark shows BLOBs were 105% slower on Windows and 180% slower on Mac OS for a simple fill loop), but that repeatedly converting between BLOB and text with the BLOB to text and TEXT TO BLOB commands inside a parsing loop is what actually kills performance. The fix shown is a family of custom methods (such as BLB_PositionF) that search and manipulate bytes directly inside the BLOB without ever converting substrings back to text mid-loop, converting to/from text only once at the very start and end of the overall operation.
