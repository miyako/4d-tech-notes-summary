Written by Timothy Aaron Penner of 4D Inc. in October 2016, this is Part I of a two-part tech note introducing the 4D-ACME-Client, an open-source 4D component that implements the Automated Certificate Management Environment (ACME) protocol to obtain free Domain Validated (DV) SSL/TLS certificates from Let's Encrypt for a 4D Web Server. It opens with a case for HTTPS generally (security against traffic interception, user privacy expectations), then introduces Let's Encrypt as a free, automated, browser-trusted certificate authority backed by the Linux Foundation and sponsored by major tech companies, noting the ACME protocol's IETF draft-spec origins. It explains certificate duration (90 days, intended to be handled via automated renewal rather than manual reissue) and distinguishes the three certificate validation tiers — Domain Validated (DV, only the domain name is verified), Organization Validated (OV, business identity verified), and Extended Validation (EV, the "green bar" browsers used to display) — clarifying that Let's Encrypt issues only DV certificates. The bulk of the note documents the 4D-ACME-Client component itself: it communicates using JSON Web Signature (JWS) objects entirely over HTTPS with a special Base64 URL-safe encoding, and exposes public methods (ACME_Auto_Cert, ACME_well_known_challenge, ACME_Show_GUI) alongside a graphical interface for creating and renewing certificates, plus a scriptable path suitable for unattended automation, with the ACME folder structure and example usage documented and a GitHub repository provided as an ongoing resource. As with its Part II successor, this note's foundational value has been diminished by 4D's later addition of native Let's Encrypt/ACME support directly in 4D Server's administration settings, but it remains a clear, well-explained worked example of implementing the ACME protocol and TLS certificate concepts from first principles in 4D, and the DV/OV/EV distinctions and 90-day renewal cadence it explains are still accurate today.
