This Technical Note (25-08, published August 29, 2025, requires 4D 20 R9) shows how to integrate a 4D application with Notion via its REST API using 4D's `HTTPRequest` class, demonstrated through a real-time inventory-syncing use case: a 4D backend manages warehouse stock while customer-facing staff track the same data in a Notion "Inventory Manager" database. The note walks through creating a Notion "Internal Integration" (versus a "Public" one, intended for private/internal workspaces), granting it explicit access to a specific Notion page, and obtaining an Internal Integration Secret used as a Bearer token on every request, alongside the required `Content-Type: application/json` and `Notion-Version` headers. It clarifies Notion's page-vs-database model (a database is a collection of pages; a page is analogous to a 4D record, with properties as fields) and how to extract 32-character page/database IDs (reformatted to 8-4-4-4-12 UUID form) from a Notion share link. Session credentials (bearer token, database ID) are captured once via `Request()` prompts at startup and cached in the shared `Storage` object for reuse across the application. Four CRUD operations are demonstrated with `4D.HTTPRequest.new()`: creating a page (`POST /v1/pages` with `parent.database_id` and a `properties` object), updating a page (`PATCH /v1/pages/{page_id}` with only the changed properties, since Notion's API supports partial updates), querying a database (`POST /v1/databases/{database_id}/query`, parsing each returned page's `properties` object — e.g. `$page.properties.Category.select.name`, `$page.properties["Date Added"].date.start` — into a 4D collection for a listbox), and "deleting" a page, which Notion implements as archiving (`PATCH` with `archived: true`, since there is no true delete endpoint). Error handling relies on standard HTTP status codes (401 for auth failures, 400 for schema mismatches, 403 for permission issues), checked via `$dbRequest.response.status`/`statusText`. The note also highlights a companion Qodly Studio web app that reuses the same 4D classes/business logic to extend the same inventory workflow to the browser, positioning the Notion integration pattern as generally applicable to any third-party REST API from 4D.
