# Tech Note: Google Chart API and 4D Live Window Integration

## Overview
The Google Chart API is a simple tool that is used to create various charts. The process is very easy for the developer: Choose the data to be graphed, decide what type of chart is needed, apply stylistic changes and pass this information to the API. This can be accomplished in the address bar of any web browser. The data is processed remotely on Google’s end. A .png image that contains the requested chart is returned to the browser as quickly as it takes to load the page. Becoming accustomed to using the Google Chart API all boils down to understanding how to parameterize the URL that is passed to Google. The sample database included with this Technical Note takes this simplification a step further as it gives 4D users a graphical interface with which to apply sample data to the Google Chart API and view it with 4D Live Window. The Google Chart API ------------------------------------------------------------------------------------------------------------------------------------------------------------------ The magic of the creation of a Google Chart is that all of the processing happens on the backend with Google. That being said, the only handle that developers have over controlling and styling their graphs is in the custom language. For example, to get a graph to look like this: Copy and paste this URL to the address line in a browser: http://chart.apis.google.com/chart?cht=lc&chs=600x400&chd=t:10,20,30|20,40,8 0&chtt=THIS+IS+A+TEST&chts=FF0000,22&chco=0000FF,FF00FF&chf=c,ls,0,efefe f,0.2,ffffff,0.2|bg,lg,66,00FF00,1,ffffff,0&chxt=x,y&chxl=0:|Jan|Feb|Mar|1:||10|20| 30&chdl=PS3|Wii Give it a try. The parameters are explained in greater detail later in this document. But to mentally assist in understanding the logic behind the jumbled mess above, here is an overview of each of the parameters used to create the chart: http://chart.apis.google.com/chart? All Google Charts requests begin with this URL. & Ampersands separate parameters. In the example, there are many parameters. Each one is listed below. cht=lc The chart type “cht” is set to Line Chart “lc”. chs=600x400 This is the chart’s area in pixels. The maximum size is 300,000 pixels (for example 1,000x300). chd=t:10,20,30|20,40,80 These are the data points used to plot the two series. The pipe character ( | ) is used to separate the series. It is possible to have more than two series in a graph. chtt=THIS+IS+A+TEST This is the chart’s title. A plus (+) denotes a space. chts=FF0000,22 The chart’s color and font size are determined here. chco=0000FF,FF00FF These determine the color of the two series’s lines. chf=c,ls,0,dfdfdf,0.2,ffffff,0.2|bg,lg,66,00FF00,1,ffffff The fill colors and styles of both the chart area and background area are determined here. chxt=x,y Determines how the axis will be labeled. chxl=0:|Jan|Feb|Mar|1:||10|20|30 These are the axis labels. chdl=PS3|Wii The graph’s legend is defined. Limitations Keep in mind that Google provides processing power and bandwidth for the Google Chart API to users for free as of this writing. Google could pull the plug, begin charging a fee, or revamp the language to this relatively new tool. Charts generated by the API are allowed to be deployed commercially, but their use is subject to Google’s terms and conditions as described in Google’s Terms of Service page: http://code.google.com/apis/chart/terms.html Additionally, only 50,000 chart queries per-user, per-day are allowed. Exceeding this limit may cause access to the Chart API to be blocked at Google’s discretion.

## Historical Context
This 2008 Tech Note documents a feature of the then-new 4D v11 SQL engine or the 4D Ajax Framework (4DAF), both of which were central to 4D's product strategy at the time. The 4D v11 SQL engine itself was foundational and its core concepts (schemas, SQL access, list boxes, components) persist conceptually in modern 4D, though the specific syntax and interfaces have evolved substantially through later versions and ORDA (introduced 2018). 4DAF-based web UI techniques (Data Grids, YUI integration, custom AJAX components), by contrast, reflect a web-development approach that has been superseded by 4D's modern web server, web components, and Qodly Studio (2021+).

**Status:** superseded

**Related updates:**
- 4D v11 SQL's data access model has since been extended by ORDA (Object Relational Data Access, introduced in 4D v17, 2018), which is now the recommended API for data access
- Project Mode (introduced 4D v17, 2018) added a text-based alternative to the binary Design Mode structure file referenced implicitly in this era
