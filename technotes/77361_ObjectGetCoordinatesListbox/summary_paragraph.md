This Tech Note by Timothy Tse documents a targeted v15 improvement to the `OBJECT GET COORDINATES` command: previously, calling it on a listbox sub object (a column, header, or footer) simply returned the coordinates of the parent listbox as a whole, but in v15 it correctly returns the sub object's own left/top/right/bottom pixel position. The note opens with form-object fundamentals — the coordinate plane convention (origin at top-left, X increasing rightward, Y increasing downward) and the four-sided coordinate model shared by all form objects — before detailing the command's parameters, including how to reference an object by variable name or by object name, and the specific syntax variations for each. It then walks through the listbox sub-object hierarchy (columns, headers, footers) with visual diagrams showing how each sub object's coordinates are computed relative to the listbox and to each other. Two practical worked examples close out the note: moving objects programmatically in sync with listbox columns (useful for overlaying custom controls aligned to specific columns), and determining which column the mouse is currently hovering over by comparing cursor position against each column's returned coordinates — a pattern useful for building custom tooltips, drag targets, or click-region logic tied to specific listbox columns. The conclusion frames this as a small but practically valuable fix that opens up more precise UI customization possibilities for listbox-heavy forms.
