Written by Frank Chang of 4D Inc. Technical Support, this is part 1 of a planned three-part series on data encryption in 4D (parts 2 and 3, on 4D Client/4D Open and Web Services/SSL encryption, are referenced but not included in this document). The note opens with a broad history of encryption -- from Caesar ciphers and WWII's Enigma machine to modern public-key cryptography -- before explaining, in concrete mathematical terms, how RSA-style asymmetric encryption works: choosing two large primes p and q, computing n=pq and f=(p-1)(q-1), picking a public exponent e coprime to f via the greatest common divisor, and deriving the private exponent d from d=(1+nm)/e. The bundled 'Encryption Demo 1' sample database walks a user through three stages -- key generation, encryption, and decryption -- and the note reproduces the actual 4D project methods used: Generate_Public_Key repeatedly calls a GCD method to find a candidate exponent whose greatest common divisor with (p-1)(q-1) is 1, Generate_Private_Key iterates to find the modular-inverse-like private exponent, and the Encrypt method applies the formula C = X^E mod N to each character's ASCII value. All arithmetic is done using 4D's Real number type (C_REAL) rather than any bundled cryptography library, making this a from-scratch, educational implementation of RSA rather than a production-grade encryption solution.
