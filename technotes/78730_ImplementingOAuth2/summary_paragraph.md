This tech note walks through implementing the OAuth 2.0 authorization-code grant flow entirely by hand in 4D, using Gmail/Google as the example identity provider, so that an application can send mail via SMTP without ever storing a user's password. It covers generating a Google Cloud OAuth client (client_secrets.json with client_id, client_secret, redirect_uri), building the authorization request URL and opening it via OPEN URL for the user to grant consent in a browser, and capturing the returned authorization code in the 4D web server's On Web Connection method using WEB GET VARIABLES, persisting it via an ORDA OAuth2 entity (ds.OAuth2.new()/.save()). The authorization code is then exchanged for an access/refresh token pair using a raw HTTP POST built with HTTP Request against Google's token endpoint, parsed and stored again via ORDA. The resulting access token is finally passed into SMTP New transporter with authenticationMode set to SMTP authentication OAUTH2 and accessTokenOAuth2 populated, letting Form.smtp.send() dispatch mail without a stored password. A token-refresh section shows repeating the POST-based exchange with grant_type=refresh_token to obtain a fresh access token once the original expires (typically after one hour), avoiding repeated user re-authentication. The note closes by pointing to a community-contributed sample using 4D Classes and the var keyword as a more modern reference implementation.
