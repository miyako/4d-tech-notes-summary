This Technical Note addresses a common deployment problem of the era: 4D's Client/Server model was designed, tested, and supported only for fast LAN environments, so it presents alternative architectures for serving 4D data to users connecting over a slower, higher-latency Wide Area Network. It groups the options into three categories. Web-based deployment leverages 4D's integrated web server and includes classic static "Web 1.0" pages, the newer "Web 2.0" 4D Ajax Framework (part of the 4D Web 2.0 Pack) for rich, partial-page-update interactivity, and XML-based Web Services using either SOAP or REST (the latter implementable via 4D Internet Commands, with pointers to companion Tech Notes 06-30 "Building a REST Client" and 07-30 "Google Calendar: Downloading Future Events"). Server-centric deployment keeps the actual 4D Client-to-Server connection on a fast LAN at a data center while remoting only the visual desktop over the WAN, via Microsoft Terminal Services or Citrix Presentation/Desktop Server — explicitly noted as not officially tested or supported by 4D, Inc., though widely used successfully by customers. Remote-desktop deployment (VNC, Apple Remote Desktop) works similarly but takes over an existing single active desktop session rather than spinning up new sessions, limiting it to one user at a time, useful mainly for individuals accessing their own second machine remotely. A closing section on optimizing native 4D Client/Server for WAN use (when attempted anyway) advises avoiding server-heavy commands like SELECTION TO ARRAY, tightly scoping queries, and raising client/server timeouts, while stressing this configuration remains unsupported by 4D. The note concludes that of the options discussed, only the web-based approaches are officially supported by 4D for WAN use; the others are troubleshootable-by-elimination (test on LAN to isolate WAN-specific issues) but carry no official support commitment.
