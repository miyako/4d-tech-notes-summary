## Overview
A Tech Note describing a method-naming convention strategy to simplify 4D component development, organized around 4D Insider's public/protected/private method categorization.

## Key Points
- Proposes method naming conventions to simplify writing, maintaining, and using 4D components.
- Sorts methods into public, protected, and private categories, consistent with 4D Insider's component model.

## Historical Commentary
**Status:** Superseded

4D Insider itself has been superseded by 4D's modern, native component architecture, so the specific public/protected/private mechanics tied to 4D Insider are obsolete, but the broader principle — using clear naming conventions to signal a component's intended public API surface — remains sound software engineering advice applicable to today's 4D components and classes.
