This Tech Note is an update to the earlier "Pointers from Scratch" (TN 01-39) and provides a thorough, example-driven introduction to the pointer concept in the classic 4D language for developers who find it hard to grasp. It starts from first principles — what a variable is, then what a pointer is (a reference containing a memory address plus a path to the referenced value) — using analogies like a shared CD player and a "your car" reference before moving into concrete syntax: referencing with `->`, dereferencing with the trailing `->`, and assigning through a pointer. It then catalogs everything a 4D pointer can reference — objects/form controls, process/interprocess/local variables, tables, fields, arrays and array elements, and even pointers to other pointers — with a table of which form object types can and cannot be pointed to, and shows the `Self` command for getting a pointer to the current object. Practical sections cover passing pointers as method parameters (and the special-case behavior when accidentally dereferencing before passing), and passing pointers between a component and its host database, including the asymmetric rule that compiled code can "unpoint" pointers from interpreted code but not vice versa, and why `RESOLVE POINTER`-based name comparison across components is unreliable. It closes with notes on `Get pointer`, multiple dereferencing syntax with parentheses, and links to further CMU documentation. The intended audience is developers, especially those newer to 4D, who need pointers explained clearly with both conceptual grounding and working code samples.
