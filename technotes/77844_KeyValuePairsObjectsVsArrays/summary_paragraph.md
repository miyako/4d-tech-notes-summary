This Tech Note by Timothy Aaron Penner examines a very common 4D programming pattern — storing key/value pairs — and argues for replacing the traditional two-parallel-array approach (one text array for keys, one for values, kept in sync by matching element indexes) with a single 4D object, where each key becomes a property name and each value becomes that property's value. The note walks through the classic array-based implementation using ARRAY TEXT and APPEND TO ARRAY commands, illustrating both its simplicity and its fragility (the burden of manually keeping two arrays synchronized, and needing extra code to check for existing keys before insertion). It then demonstrates the object-based equivalent using C_OBJECT and OB SET, which collapses the two-array bookkeeping into simple property assignment. Several concrete benefits are enumerated and demonstrated: values are easier to update or replace since a property set overwrites in place; property-based lookup offers faster access compared to scanning parallel arrays for a matching key; a 4D object can be trivially serialized to and from text (JSON) for saving to or loading from disk, unlike a pair of arrays; and objects natively support multiple data types per value (text, numeric, boolean, sub-objects, arrays) without needing separate array structures for each data type. The note includes a references section pointing to further reading. Overall this is a practical best-practices note nudging developers away from an older idiom toward 4D's more modern object type, and its guidance remains directly applicable to current 4D development, where objects/collections are even more central to the language than they were in 2017.
