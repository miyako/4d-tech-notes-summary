This Tech Note is a tour of seven creative and powerful applications of 4th Dimension's built-in Choice List feature, going well beyond its typical use as a simple data-entry aid. Example 1 shows Conditional Lists, where a one-line SET CHOICE LIST call in a field's script dynamically swaps the choice list shown in a dependent field (e.g., picking an Auto Brand changes the Auto Model list shown next), combined with GOTO AREA to auto-advance the cursor. Example 2 covers Linked Hierarchical Lists, which let users drill down through multiple levels (e.g., Platform → Mac → Mac PCI → specific model) with zero code, provided each level's choices repeat the prior level's label for clarity. Example 3 demonstrates using Choice Lists as fixed-width Rate Chart lookup tables — essentially simple flat files without index overhead — where careful padding of elements to fixed lengths lets a procedure (LiabRateCalc) parse out a rate via string offsets. Example 4 covers Required Values, using the "List Required" attribute to enforce that entered data matches an approved list, important for consistent statistical reporting. Example 5 shows Range validation for numbers or dates via choice lists, with a note that custom alert messages require a hand-written validation procedure instead of relying on 4D's default "not allowed" alert. Example 6 explains storing Demo Data in Choice Lists rather than shipping bulky data files, since lists are text-only, travel with the structure, and can be converted to/from arrays with SELECTION TO ARRAY, ARRAY TO LIST, and string functions. Example 7 outlines building a "List Updater" interface so a Database Administrator can edit any list (including non-"User Modifiable" ones) via a List-of-Lists selector and a scratch Updater list. The note closes by cataloging the attributes that make Choice Lists powerful (structure-level portability, type-ahead support in sorted lists, hierarchical linking, on-the-fly association/manipulation via SET CHOICE LIST/LIST TO ARRAY/ARRAY TO LIST, structure-level field association surfacing in the Search Editor, multi-user update propagation under 4D Server) and their limitations (30-character element limit, and unsuitability for lists beyond a few dozen elements, where a real 4D file should be used instead).
