This January 1996 Tech Note by Kent Wilbur tackles a common 4D Server administration need: automatically logging off users who have been inactive for a period of time, both to free up concurrently-licensed seats for other users and for security (preventing an unattended, logged-in session from being misused). The note first critiques two naive approaches — a purely time-delayed check (which unfairly logs off users mid-session without crediting recent activity) and a continuously-running event handler (which is accurate but imposes a significant performance penalty by intercepting every keystroke/click). It then presents a blended solution: a background LogoffChecker process sleeps for a fraction of the timeout period, then briefly enables ON EVENT CALL to detect any recent user activity (setting a presence flag via an OnCallQuit procedure), and either goes back to sleep (if the user was active) or displays a one-minute warning dialog before logging the user off with QUIT 4D if there's still no response — trading a small amount of imprecision in the exact logoff time for much lower overhead than continuous event polling. It also documents a companion controlled-shutdown technique using a global àfQuit flag, custom per-window processes responding to the OUTSIDE CALL layout execution phase, and a Shutdown procedure that iterates through all running processes (skipping local/system ones) to ensure any modified records are saved before the database quits — noting this only works if the database is architected around custom processes rather than relying solely on the User/Runtime process. An example "Auto Shop" database with three users (Moe, Larry, Curly) demonstrates the system, and the note closes by suggesting the logoff timeout and enable/disable behavior could be made a per-user preference via a [User] file.
