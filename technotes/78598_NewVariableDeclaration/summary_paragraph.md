Released alongside 4D v18 R4's continued push toward object-oriented programming, this Tech Note introduces the new `var <name>{;<name2>...}{ : <varType>}` declaration syntax as a replacement for the older `C_TEXT`/`C_OBJECT`/`C_LONGINT`-style "Compiler theme" directives. Beyond basic types (Text, Date, Boolean, Integer, Real, Pointer, Picture, Blob, Collection, Variant, Object), `var` critically supports declaring a variable as a reference to a specific 4D class (`4D.<className>`, e.g. `4D.File`) or user-defined class (`cs.<className>`), something the old Compiler theme could only express as a generic Object. This class-typed declaration unlocks IDE autocomplete/type-ahead: the method editor can now suggest a class's actual member functions when working with a variable, rather than only previously-referenced property names as it did for generic objects, and it correctly hides functions marked private with a leading underscore from those suggestions. The note flags two limitations as of this release: `var` does not yet support inter-process variables or arrays, which must still be declared with the Array/Compiler theme commands. To ease adoption, the note includes a database component with an "Open Update Variables Form" utility that scans all methods in a host database, lets a developer selectively apply the `var` declaration to variables still declared with Compiler theme directives, and offers a re-typing interface to upgrade previously generic Object-typed variables (e.g., a file object, entity selection, or class instance) to their specific class type for improved autocomplete and code readability — though this operation cannot run while the target method is open in the editor.
