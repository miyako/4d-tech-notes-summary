This Technical Note (26-05, published May 28, 2026, requires 4D v21.0 LTS) presents Sentinel, a demo application showing how two declarative 4D v21.0 LTS primitives — HTTP Request Handlers (`HTTPHandlers.json`, binding regex URL patterns to class functions) and HTTP Rules (`HTTPRules.json`, injecting security response headers by URL pattern with no code changes) — can anchor a production-grade web security architecture. On top of these primitives, Sentinel implements an eleven-gate defense pipeline evaluated in `DoSGuard.authenticateRequest`, ordered from cheapest/most decisive checks (master on/off switch, CPU/traffic panic flags, header-size limits, allowlist, blocklist) to progressively more expensive ones (honeypot URL matching, regex-based WAF scanning for path traversal/SQLi/XSS, per-IP sliding-window rate limiting, then global rate limiting), with the first gate to produce a verdict ending evaluation. A companion Sonar intrusion detection/prevention engine scores each request 0–100 on additive behavioral signals (missing User-Agent, tool-based clients, known attack signatures), routing high scores (≥80) to an immediate-block "sniper" queue and lower scores to a "drone" archive queue for pattern correlation, both drained by dedicated background workers. Authentication runs through a `SentinelAuth` class validating a bcrypt-hashed static passphrase or a one-shot dynamic passphrase, with per-IP brute-force lockout after five failed attempts. Fifteen shared singleton classes (`DoSGuard`, `Sentinel`, `IPManager`, `ConfigManager`, `RequestLogger`, `AlertManager`, `ProcessOrchestrator`, etc.) own discrete responsibilities, all runtime state persists to JSON under the project Data folder via an atomic write pattern with hot-reload (no server restart), and a vanilla-JavaScript dashboard exposes live telemetry, defense toggles, and internal attack simulators (CPU flood, bandwidth flood, header overflow, distributed IP flood) for demonstrating each defense layer. The note positions this as an extensible threat model developers can grow (e.g. Slowloris detection, JA4 TLS fingerprinting) while keeping routing and security-header policy decoupled from business logic.
