# Tech Note: Using a generic method to create cross tab reports

- **Product / Version:** 4D 2003
- **Platform:** Mac & Win
- **Author:** Gary Brocks, Software Evangelist, 4D, Inc.
- **Page URL:** https://kb.4d.com/assetid=27690

## Overview

Gary Brocks builds a single generic, parameterized method that generates seven different cross-tab reports for a fictitious video-rental invoicing database ("4D Video"), demonstrating 4D 2003's new "QR" command theme and, crucially, that cross-tab data sources can be formulas or custom methods, not just fields.

## Key Points

- Introduces cross-tab data source basics: Data Source 1 → Column 1 (column titles/subtotal groups), Data Source 2 → Column 2 (row titles/subtotal groups), Data Source 3 → Column 3 (cell calculation values), all bound with `QR SET INFO COLUMN`.
- Shows a straightforward field-driven example: revenue per state per product category using `[Customers]State`, `[Products]Category`, and `[LineItems]ExtendedPrice` directly as the three data sources.
- Demonstrates using a formula as a data source, e.g. `Month of([Invoices]InvoiceDate)` to break out a report by month within a queried year range.
- Presents the custom method `Dates_QtrLabelFromDate(pointer)`, which takes a pointer to a date field/variable and returns "1st Qtr" through "4th Qtr" based on `Month of`, used directly as a QR data source to build quarterly reports without a stored quarter field.
- Builds a single generic method, `Rpt_QRCrsTabReports`, accepting 12 parameters: report-type string (Revenue/Units/QuarterlyRevenue/QuarterlyUnits/Orders), a table pointer, three data-source pointers, a date-field pointer for quarterly filtering, a display format string, grand-total row/column titles, a report title, an output-destination code, and destination specifics.
- The generic method selects the aggregate operator based on report type (`qr sum` for Revenue/Units, `qr count` for Orders), prompts the user for a year via a helper dialog for quarterly reports, and queries/selects `ALL RECORDS` or a year-bounded query accordingly.
- Configures the report via `QR New offscreen area`, `QR SET REPORT KIND(qr cross report)`, and `QR SET REPORT TABLE`, then conditionally uses the `Dates_QtrLabelFromDate` method vs. a direct field/formula as Column 1's data source depending on whether the report is a quarterly one.
- All seven of the example database's reports (revenue/units/orders by state, category, and quarter) are generated by thin "M_"-prefixed wrapper methods that simply pass different parameters into the one shared `Rpt_QRCrsTabReports` method, invoked from a Sales Reports menu.

## Featured Technology

- Quick Report 'QR' command theme (4D 2003)
- Cross-tab report generation via QR SET REPORT KIND(qr cross report)
- Formulas and methods as report data sources (pointers to fields/methods)
- Generic parameterized reporting method (Rpt_QRCrsTabReports)
- QR SET INFO COLUMN / QR SET TOTALS DATA with pointer parameters

## Historical Commentary

**Status:** Partially superseded

Gary Brocks builds a single generic, heavily parameterized method, Rpt_QRCrsTabReports, that can generate seven different cross-tab reports for a fictitious video-rental invoicing database by passing in pointers to data-source fields, a custom quarter-labeling method as a data source, format strings, titles, and an output-destination code. The underlying QR command theme and the ability to use formulas or methods (not just fields) as cross-tab data sources are still present in current 4D and the generic-method pattern shown remains a sound, reusable design technique for report-heavy applications. As with the other 2003-era Quick Report notes, though, 4D Write Pro has since emerged as the more commonly used tool for building modern, flexible reports, so this specific QR-based generic method is a still-functional but now less frequently chosen approach for new report engineering.

References to newer/updated information:
- The QR command theme (QR SET REPORT KIND, QR SET INFO COLUMN, QR SET TOTALS DATA) and the ability to use formulas/methods as data sources remain part of current 4D and continue to work as shown
- 4D Write Pro has since become the more commonly used tool for building flexible, modern reports, though the classic Quick Report cross-tab engine and the generic-parameterized-method design pattern demonstrated here remain valid options
