Written by Gary Brocks, 4D's Software Evangelist, this Tech Note demonstrates 4D 2003's new "QR"-prefixed Quick Report command theme by building a single generic, reusable method that generates seven different cross-tab reports for a fictitious video-rental invoicing database, "4D Video." It first explains the fundamentals of cross-tab data sources -- column, row, and cell/value sources bound to Column 1, 2, and 3 respectively via `QR SET INFO COLUMN` -- illustrated with a revenue-per-state-per-category report driven directly by fields (`[Customers]State`, `[Products]Category`, `[LineItems]ExtendedPrice`), then shows that a data source can equally be a formula (e.g., `Month of([Invoices]InvoiceDate)`) or a custom method. It presents a full custom method, `Dates_QtrLabelFromDate`, that takes a pointer to a date field and returns a "1st Qtr"–"4th Qtr" string, used as a data source to build a revenue-per-state-per-quarter report without needing a quarter field in the database at all. The centerpiece is the generic method `Rpt_QRCrsTabReports`, which accepts twelve parameters -- a report-type string (Revenue/Units/QuarterlyRevenue/QuarterlyUnits/Orders), pointers to the report table and up to three data sources, a date field pointer for year-filtered quarterly reports, format/title strings, and an output-destination code -- and internally selects the right aggregate operator (`qr sum` or `qr count`), prompts for a year via a helper dialog when needed, configures the cross-tab report with `QR SET REPORT KIND`/`QR SET REPORT TABLE`, and binds the appropriate data sources depending on whether the report is quarterly (using the custom quarter-label method) or not. The note shows that all seven of the example database's reports, invoked from a Sales Reports menu through a series of thin "M_" wrapper methods, funnel through this one generic method, illustrating a reusable design pattern for report-heavy 4D applications.
