Written by Gou Yang of 4D Technical Support, this Tech Note introduces the new printing commands added in 4D 2003 that let developers procedurally control most of the options available in the default OS print dialog, illustrated with a sample "Print Options" database. It centers on a custom `PrintDialog` form that first checks the platform is not Mac OS 9 (since `PRINTERS LIST`, `SET CURRENT PRINTER`, and `Get current printer` are unavailable there), then loads current settings with `GET PRINT OPTION` (paper, scale, copies, source, color, destination, resolution, double-sided) and populates pop-up lists using `PRINTERS LIST` and `PRINT OPTION VALUES`, with generic helper methods (`CheckArray`, `CheckSetOption`) guarding against empty arrays. Per-user preferences are persisted in a `[PrintPref]` table, loaded via `PLoadPrintPref` when found or created via `PCreatePrintPref` on first use, and the interface conditionally shows/hides Mac- versus Windows-specific controls (e.g., color and double-sided options only apply on Windows) via `<>MyOS`. When the user clicks OK, the `SetOption` method applies the chosen values with `SET PRINT OPTION`, covering printer selection, copies, orientation, and destination (Printer, PDF, EPS, or PS, with document paths built via `Create document`). Finally, the note demonstrates `Print Form`, `Print Record`, and `Print Selection`, explicitly calling out the optional `>` parameter on the latter two, which prevents 4D from silently reinitializing (and thereby discarding) the developer's procedurally-set print options.
