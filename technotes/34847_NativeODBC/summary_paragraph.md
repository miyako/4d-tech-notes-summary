Written by Sati Hillyer, a 4D Evangelist, this Tech Note explains 4D 2004's newly integrated native ODBC support, which lets developers connect to any configured ODBC data source manually through an updated Import/Export dialog or programmatically through a new set of native commands, all without installing the separate 4D ODBC plug-in. Using Microsoft Excel as the worked example (with a caveat that Excel can only act as an ODBC data source on Windows, not Mac OS X), the note walks through defining a named range in a spreadsheet, registering it as a Windows ODBC Data Source via the Excel ODBC driver, and then importing it into 4D two ways: through the revamped User-environment Import dialog's new "From ODBC Source" option, and programmatically via a custom demo method that calls `ODBC LOGIN`, dynamically builds an `ODBC EXECUTE` statement from the target table's field list, and loads records with `ODBC LOAD RECORD`/`ODBC CANCEL LOAD` inside a `START TRANSACTION`/`VALIDATE TRANSACTION` block. Sample methods `GetTableNames`, `GetFieldNames`, and `ImportUsingODBC` illustrate discovering existing 4D table/field metadata to drive the ODBC statement construction. The note closes by clarifying that on Mac OS X the same native ODBC commands work identically against other ODBC-compliant data sources (just not Excel), and points readers to a companion "Assimilator" Tech Note for the more advanced 4D ODBC plug-in capable of dynamically creating tables from the source schema.
