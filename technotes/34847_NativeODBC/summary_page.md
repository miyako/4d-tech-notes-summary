# Tech Note 04-46: Native ODBC in 4D

**Author:** Not specified in source
**Published:** November 18, 2004 | **Product/Version:** 4D v2004 | **Platform:** Mac & Win
**Page:** https://kb.4d.com/assetid=34847
**Download:** https://kb.4d.com/DLTN/TN/2004/Windows/TN_2004_46-48_(OCT)/04-46_Native_ODBC.exe

## Overview
This note describes 4D 2004's newly introduced native ODBC support, which allowed developers to pull data from any ODBC data source directly into 4D without needing a separate ODBC plug-in, using Microsoft Excel as the flagship example.

## Key Points (from available teaser)
- 4D 2004 introduces native ODBC support, removing the prior need for an additional plug-in.
- Microsoft Excel is highlighted as a common, useful, but limited data source that 4D can complement.
- The note illustrates and describes the new native ODBC functionality with a practical example.
- Positioned as a starting point for developers wanting to bring external data into an existing 4D application.

## Featured Technology
- Native ODBC support (4D 2004)
- ODBC-based external data import
- Microsoft Excel data integration

## Historical Context
**Note:** Only the on-page teaser paragraph was recoverable for this Tech Note; the full PDF and example database were not accessible (old archive format not retrievable in this environment), so the specific commands and worked example cannot be detailed here. The general concept of built-in ODBC data import remains supported in current 4D, though the 2004-era implementation and example described have been superseded by many rounds of subsequent refinement, and modern integrations increasingly lean on ORDA or REST/API-based approaches instead of ODBC for pulling in external data.
