This Tech Note by Thomas Maul (4D Germany) provides a complete, ready-to-use CRC32 checksum implementation for 4D, aiming to simplify a concept previously explained more theoretically by Ruffin Scott in TN 99-11 so developers can protect Blobs and exported/imported documents without needing to understand the underlying CRC math. It explains that 4D already checksums every database record internally, but that Blobs (introduced in 4D v6) and documents sent to customers or synchronized across Distributed Systems via non-4D-Open channels (FTP, e-mail, etc.) are not automatically verified and need explicit checksumming. The core code consists of two methods: `CRC_CreateTable`, which builds a 256-element `CRC_Table` longint array of precomputed constants using bit-shift and XOR operations (needs to run only once), and `CRC_Calculate`, which walks a BLOB byte by byte applying `($value >> 8) ^| CRC_Table{...}` to produce the final checksum. The note includes rough benchmark numbers (a 3 MB file taking about 70 seconds interpreted versus roughly 2.4 seconds compiled) and describes an elegant verification trick: appending the checksum itself as 4 bytes to the end of a document via `LONGINT TO BLOB`, so that recomputing the checksum over the whole file (including the appended bytes) yields exactly zero if the file is intact.
