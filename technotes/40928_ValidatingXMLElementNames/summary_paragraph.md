This Technical Note by David Adams documents the XML specification's rules for naming elements and attributes and provides a 4D method for validating custom-generated XML names against those rules, aimed at 4D developers producing their own XML output. It lays out the key requirements: XML names are case-sensitive (unlike 4D's own case-insensitive variable/method naming), may begin only with ideograms, letters, hyphens, or periods, may otherwise contain ideograms, letters, digits, hyphens, periods, colons, and underscores, must never contain whitespace of any kind, may not begin with any case variant of "xml" (reserved for current and future XML standards), and have no defined length limit; the colon character, while legal, is reserved specifically for XML namespaces. The note works through concrete good/bad name examples (e.g., a name starting with a digit, a name containing a space, an initial colon, or a name beginning with "xml_") to illustrate the rules in practice, then distills them into a simplified checklist most 4D programmers can follow: names are case-sensitive, should start with a letter A–Z/a–z, should contain only letters, digits, periods, and underscores, and should avoid other punctuation absent a specific reason. It cross-references the companion TN 05-41 (Case-Sensitive Operations in 4th Dimension) since correctly comparing and validating case-sensitive XML names requires the case-sensitive comparison techniques documented there, situating both notes within the era's growing emphasis on 4D producing well-formed custom XML for data exchange and web services.
