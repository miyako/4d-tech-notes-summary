This Technical Note by Jason T. Slack of 4D Inc. shows how to combine two separate rich-web-application technologies for 4D: Active4D, a third-party ASP-style scripting language (developed by Aparajita's World, not by 4D Inc., and explicitly noted as unsupported by 4D) that provides a ready-to-go HTTP server with session and cookie support, and the 4D Ajax Framework (4DAF), 4D's own Web 2.0 Pack component for building rich internet applications. Because following the standard 4DAF installation guide verbatim conflicts with Active4D's needs, the note prescribes a nine-step custom installation: install the 4DAF component via 4D Insider, add the "4D Pack" plug-in (already placed by the Active4D installer), copy the 4DAF's "dax" web content folder into Active4D's required "web_decoy" web root folder, install the 4DAF Support folder as usual, configure 4D for the 4DAF while skipping the guide's step 5 (which needs customization to coexist with Active4D's code), ensure the 4D Web Server's root stays set to "web_decoy" as Active4D requires, and — the key integration point — modify the `On Web Connection` database method so that both systems' requests are handled: incoming requests tagged with the literal marker "@DAX@" are routed to `DAX_DEV_OnWebConn`, while everything else falls through to Active4D's own generated code, wrapped in an if/else (or optionally a more granular Case of) block. Remaining steps cover editing the `Active4D.ini` configuration file (which requires a 4D restart to take effect) and finishing setup. For its own example database, the note documents three specific tweaks: setting `default page` and `executable extensions` in Active4D.ini, modifying the `DAX_DevHook_Login` method to auto-authenticate a "Guest" user, and renaming the 4DAF Client's index pages to "admin" for clarity. It closes by pointing to an included FlowersDemo video and the `web\display.a4d` source file as concrete illustrations of mixing Active4D and 4DAF code, suggesting potential use cases like shopping carts and member "My Sites" portals built by combining the two systems.
