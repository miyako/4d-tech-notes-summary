This Technical Note, authored by Thomas Maul of 4D Germany, demonstrates how to build an automatic "health" reporting system for 4D Server that helps administrators detect problems in advance and monitor server state, using only built-in 4D functionality plus the 4D Internet Commands plug-in for emailing. The accompanying sample database (based on the "4D Invoice" example) generates a daily report covering a Server Overview (4D version, last start/reboot time, OS and service pack, physical/virtual memory), a "Critical errors in last 48 hours" section that flags clients or the server that quit without using the Quit command (helping distinguish client-side vs. server-side problems), hard disk usage with year/month/day historical deltas, per-table record counts and used-space ratios (useful for spotting large deletions or the need to compact data), a process list showing CPU time and memory for everything running on the server machine, and database segment sizes. Installation involves copying six project methods (ServerHealth, ServerHealth_Create, ServerHealth_Report, HTMLMail_Send, Compiler_HTMLMail, Compiler_ServerHealth) via 4D Insider drag-and-drop, one choice list, one [ServerHealth] history table, and Extras/Plugins folders (requiring 4D Internet Commands 2004.5+), then wiring ServerHealth_Create calls into On Startup/On Exit and On Server Startup/On Server Shutdown database methods to log client and server session boundaries, plus a background process that runs nightly to generate statistics and trigger the emailed report. The note explains that the report can also be accessed live as a web page via a 4Daction URL (e.g., http://localhost/4daction/serverhealth) rather than only by email. As a self-built monitoring solution assembled from 2004-era 4D commands and the 4D Internet Commands plug-in, its specific implementation details are dated, though the underlying goal of proactive automated server health reporting remains a sound administrative practice.
