This community-contributed Tech Note documents why and how to migrate away from 4D's Picture Library, a feature dating back to 4D 6.5 that provided an integrated, cross-platform picture manager and bitmap editor built on old-style resource files. By 2016, the note explains, the Mac OS had moved away from the resource-fork/resource-file model the Picture Library depended on, cross-platform image formats had matured, and far better external image editing tools existed — so 4D had stopped adding features to the Picture Library and was actively encouraging developers to switch to external picture files. The note surveys legacy uses of Picture Library images (centralized image repository, picture buttons and other graphic form objects, hierarchical list icons), reviews external picture file features as the replacement (storage/organization conventions, picture references in the Form Editor, how 4D handles missing pictures, and the 4D Resource Viewer tool), and then supplies concrete migration tooling: PictureLibrary_DumpToDisk and PictureLibrary_DumpToTable methods to extract images out of the Picture Library, guidance on updating the system to reference external files afterward, code-generation help for OBJECT SET FORMAT calls (used to bind external image paths to form objects), and — importantly — code to detect and gracefully manage missing external image files, since unlike the old embedded Picture Library, external files can go missing from disk. Because this note documents 4D's own deliberate, long-standing platform direction (moving away from the Picture Library entirely), it remains fully aligned with current best practice: any database still using the Picture Library today is working against nearly a decade of subsequent 4D guidance, making this migration note as relevant now as when it was published, if not more so.
