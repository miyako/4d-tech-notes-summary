Written by Steve Hartman (MCP, 4D, Inc. Information Systems, with co-authoring credit to Kent Wilbur), this Tech Note tackles a specific 4D printing annoyance: splitters (implemented as invisible buttons) that a user drags to widen a field on-screen for readability snap back to their originally designed position when the form is printed, undoing the user's adjustment. The solution duplicates the output form into a dedicated print form, visually identical except the Print button is removed and each invisible-button splitter is replaced with a line object; label and field objects on the print form are also systematically renamed to a generic label1/label2/field1/field2 scheme so they can be repositioned in a simple loop rather than with per-object code. An object method on the original output form's Print button, fired on the On Clicked event, loops through pointers to each Splitter object and calls the project method Save_Splitter_Position, which uses RESOLVE POINTER and GET OBJECT RECT to record each splitter's current left/top/right/bottom coordinates into parallel arrays; the same Save_Splitter_Position method is also wired to each splitter's own On Clicked event, so the arrays stay current whenever the user manually moves a splitter. When the print form is actually printed, its form method's On Header and On Printing Detail events call the project method Object_Move, which loops through the saved splitter positions and uses MOVE OBJECT to reposition the corresponding vLine, label, and field objects around each remembered splitter coordinate -- relying on the label/field naming convention so all affected objects can be moved generically in one loop rather than with individually hardcoded object references.
