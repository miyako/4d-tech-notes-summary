Written by Olivier Deschanels of 4D S.A., this technical note tackles a gap in 4D 2003: there was no built-in command to serialize an entire record into a BLOB, a technique useful for archiving obsolete records, shipping records between databases for synchronization, or storing a record as a reusable 'template' of default values. Rather than the document-based approach (SEND RECORD plus DOCUMENT TO BLOB), which the author dismisses for its performance cost and dependency on external files, the note designs a compact, versioned, self-describing binary layout: a 16-byte header (a 4-byte 'ENRG' magic string, a version byte, a record/field count area, a compression flag, and reserved padding) followed by per-field type/length descriptors and then the raw field data itself, written and read with Mac-OS-format byte ordering for cross-platform consistency. Two companion project methods, EVB_Store_Record and EVB_Restore_Record, implement the format using low-level commands such as SET BLOB SIZE, INTEGER TO BLOB, LONGINT TO BLOB, TEXT TO BLOB, and PICTURE TO BLOB, looping over Count fields/Field/Type to walk every column of the current record generically regardless of table structure. The restore method also handles some schema drift by comparing the stored field type against the current field type and applying reasonable coercions (e.g. numeric-to-boolean, alpha/text conversions) when they no longer match exactly.
