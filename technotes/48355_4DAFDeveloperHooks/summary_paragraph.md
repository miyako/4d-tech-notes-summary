This Technical Note documents the Developer Hooks system of the 4D Ajax Framework (4DAF), a component that let 4D developers add a rich, browser-based Web 2.0 interface — supporting live browsing, adding, modifying, and deleting records — on top of an existing 4D database, combining a database-side component (public "DAX_DevHook_" methods editable by developers, protected "DAX_Dev_" utility methods, and hidden private internals) with a front-end JavaScript/CSS/HTML framework. It surveys the full catalog of DevHook methods spanning Callback installation and event response, Developer Created Selections (DCS) creation and record handling, Developer Defined Window (DDW) installation, Choice List overrides, Users/Groups manipulation, Login/Session control, Query control, Record control, and global preferences, before focusing in depth on four areas: Developer Created Selections, Developer Defined Windows, Callbacks, and Choice Lists. The DCS mechanism is explained in detail as a way to expose a custom, non-table-backed "View" to the 4DAF web front-end by programmatically composing six parallel arrays (field names, types, and unique/mandatory/non-enterable/non-modifiable flags) via DAX_DevHook_DCS_ViewAdd, populating a matching dataset via DAX_DevHook_DCS_SetSelection and the protected DAX_Dev_DCS_SetSelection method, and handling saves/deletes via DAX_DevHook_DCS_RecordSave and DAX_DevHook_DCS_RecordDelete keyed by the DCS view's name. Sample 4D code snippets illustrate each hook, including constructing a "myContacts" DCS view backed by FirstName/LastName/DOB arrays and querying it against the underlying [Contacts] table using SELECTION TO ARRAY. The note is squarely aimed at developers wanting to go beyond the framework's default behavior to integrate custom data sources, windows, and business logic into the 4DAF web interface. As a deep customization reference for a now-retired framework, it captures a snapshot of how pre-ORDA, pre-REST 4D handled dynamic, non-table data exposure to a web client.
