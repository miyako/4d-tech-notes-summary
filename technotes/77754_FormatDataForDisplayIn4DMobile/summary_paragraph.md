Written by Xiang Liu of 4D Inc. in March 2017 against 4D v16.0 and Wakanda Enterprise 1.1.3, this tech note documents 4D Mobile's built-in attribute-level display formatting system, which let developers specify number, string, and date formats directly on data model attributes so that web/mobile client widgets would render them automatically without manual client-side formatting code. It details the placeholder syntax for numeric formats (# and 0 for digit placeholders, comma/period separators, percentage formatting), the four single-character options for string formats (uppercase, lowercase, capitalize-first-word, capitalize-each-word) plus a "#" wildcard wrapper syntax, and the twelve date-format tokens (d/dd/o/oo/D/DD/m/mm/M and more) modeled after common date-formatting libraries. It also shows how to apply the same formats server-side programmatically through 4D methods, and client-side by reading the defaultFormat property via REST and the Dataprovider API. The note is a solid piece of documentation for the 4D Mobile formatting system as it existed in that specific window of the platform's life, giving concrete JSON model-editor syntax and REST access patterns. However, it describes machinery that is entirely specific to the Wakanda-based 4D Mobile stack that 4D built out around 2015-2017 and later discontinued in favor of ORDA and REST-first web development, meaning that today the described data model editor, its defaultFormat properties, and the entire 4D Mobile client runtime no longer exist in current 4D products. A developer researching this topic today would need to reimplement equivalent formatting entirely in whatever web framework or ORDA-based REST layer they're using, since none of the described APIs survive.
