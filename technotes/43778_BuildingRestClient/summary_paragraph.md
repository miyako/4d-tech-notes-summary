This Tech Note by Yvan Ayaay introduces Representational State Transfer (REST) as a lightweight, URL-and-XML-based alternative to SOAP web services popularized by sites like Yahoo, eBay, and Amazon, and shows 4D 2004 developers how to build a REST client since 4D's Web Services Wizard of the time could only discover and invoke SOAP-based services, not REST ones. It explains REST's architectural principles, tracing the term to Roy Fielding's exposition of the web's architecture: client requests target resources identified by URLs, and each server response represents a state that the client transitions through as it follows links or issues further requests, giving the "state transfer" its name. The note contrasts REST with SOAP by noting REST's emphasis on resources (nouns, e.g. "city") versus SOAP's emphasis on operations (verbs, e.g. "getCity"), and lists REST's defining characteristics: client-server separation, statelessness (each request is self-contained), universally identified resources accessed via HTTP methods (GET, POST, etc.), and traversable resource representations. To make this concrete, the note walks through constructing a working REST client inside 4D that queries the Yahoo Web Search web service, issuing HTTP GET requests to a URL and parsing the returned XML response manually within 4D's language, since no built-in REST or JSON support existed at the time. This required developers to handle HTTP communication and XML parsing themselves rather than relying on wizard-generated glue code, in contrast to 4D's more automated SOAP web-service support. The note is a practical, hands-on illustration of how pre-JSON, pre-native-REST-support 4D developers integrated with the RESTful APIs that were becoming common on the web by the mid-2000s. While the specific Yahoo Web Search REST endpoint used as the example has long since been retired, the conceptual grounding in REST principles remains directly applicable today, even as 4D has since gained its own native REST/JSON capabilities that make this manual approach largely unnecessary.
