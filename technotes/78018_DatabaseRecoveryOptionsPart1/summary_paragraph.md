This Tech Note is the first of a two-part series providing a general, informative overview of the tools 4D offers to reduce downtime when a database becomes damaged or unusable. It begins by explaining the two files comprising a classic 4D database — the structure file (.4DB format) and the data file — and the types of corruption or damage that can occur. The core of the note covers the Maintenance and Security Center (MSC), detailing its Verify function (checking data integrity) and Repair function (attempting to fix a damaged data file), positioning MSC as the first line of defense for moderate corruption. It then describes 4D's backup system: how to prepare and schedule backups, and how to use them for both full restores and rollbacks to undo unwanted data changes. The final major section introduces mirroring as a higher-availability option, covering how to set up a mirror server, identify the mirror to the main server, generate and share log files with the mirror, integrate those logs, and run the mirror as a live failover or as a form of continuous backup — including the possibility of chaining multiple mirrors for extra redundancy (e.g., a "mirror of a mirror"). The note closes by promising a follow-up Part II with deeper, example-driven guidance specifically on mirroring setups for different real-world scenarios such as a hospital database requiring near-zero downtime.
