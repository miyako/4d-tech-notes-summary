This Tech Note explains how to implement dynamic global variables in 4D using shared singleton classes, a pattern combining two language features introduced in 4D 20 R5: shared classes, which instantiate objects whose contents are safely accessible and modifiable across processes via the Use...End use structure (or the "shared" keyword on functions to implicitly wrap it), and singleton classes, which restrict a class to a single instance per process via .new() or the .me property. Marrying both — "shared singleton Class constructor" — yields a class whose single shared-object instance is guaranteed unique across every process in the application, making it an ideal replacement for the deprecated interprocess variables (which are unusable from preemptive processes and thus incompatible with thread-safe, multi-core code). The note walks through a minimal GlobalVars class implementation, showing how to read/write properties via cs.GlobalVars.me, add a custom shared "assign" function using variadic parameter indirection (${$i}) to set multiple values in one call, and add type-validation logic to guard against accidental type changes on existing globals. The accompanying demo application illustrates initializing globals from a JSON environment file at startup, and managing scalar, shared-object, and shared-collection values as global properties — noting that shared objects/collections must themselves be created via New shared object/New shared collection since a shared singleton cannot hold non-shared object properties. The note positions this pattern as the modern, thread-safe approach for storing application-wide configuration, session/user state, and caching/memoization data that must be visible and updatable from any process, including preemptive ones.
