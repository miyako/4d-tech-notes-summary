This Tech Note explains how to allocate and tune the memory used by 4th Dimension, 4D Server, and 4D Client, covering both Windows and Macintosh configuration paths and offering PowerMac-specific performance advice. On Windows, since there's no Finder-level memory partition concept, all memory configuration (Stack size, Permanent off-screen buffer, Cache memory, kernel Number of blocks and Size of one block) is done through 4D Customizer Plus's Preferences resource dialog; the note explains each setting's role — e.g., cache memory holds records/index data progressively loaded during work, while kernel memory covers process stacks, structure elements, variables, selections, sets, externals, and transactions — and walks through a worked example totaling roughly 12.4MB of allocated memory from specific stack/cache/block settings. On the Macintosh, memory is allocated at the Finder level via Get Info, with the cache-versus-kernel percentage split configured separately via Customizer Plus's Memory resource; the note notes 4D Server can typically afford a higher cache percentage than 4th Dimension itself since it lacks interface-management overhead, while cautioning to reserve enough for client connections. A dedicated section gives era-specific PowerPC/PCI Macintosh tuning recommendations: add a Level II cache card if missing, enable the Modern (native PowerPC) Memory Manager, prefer real RAM over virtual memory, set the Mac disk cache to 1/16th of physical RAM to offset emulated I/O, and consider Speed Doubler for additional I/O and system-wide performance gains. The note's most technical section describes using MacsBug (a low-level Mac debugger) to precisely measure how much kernel memory 4D Server actually consumes under a simulated maximum production load — connecting the expected number of clients, opening the expected number of processes, creating maximum named selections, and selecting ~90% of records per file — then comparing "Heap Totaling" (HT) reports taken before and after the load test to see how much kernel memory was consumed, enabling data-driven adjustment of the cache/kernel percentage split for optimal throughput. Featured technology centers on 4D Customizer Plus's memory-configuration resources and, for the advanced technique, the classic Macintosh MacsBug debugger.
