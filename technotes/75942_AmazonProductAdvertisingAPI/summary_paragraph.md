This Tech Note uses Amazon's Product Advertising API as a demanding real-world example to illustrate advanced web-services client techniques in 4D v11 SQL, since the API cannot be called using 4D's built-in Web Services Wizard and `CALL WEB SERVICE`. Three obstacles are identified: 4D's SOAP client can't fully parse Amazon's complex responses, it can't build the multi-element SOAP headers Amazon requires for authentication, and 4D has no native command for the HMAC-SHA256 signatures Amazon mandated starting August 2009. The note shows calling Amazon's REST endpoint instead via `DOM Parse XML source` against a hand-built query URL, and separately demonstrates a hand-rolled SOAP call using 4D Internet Commands (bypassing `CALL WEB SERVICE` entirely) for cases where SOAP is still required. To solve the missing HMAC-SHA256 support, the author built a custom "4D OpenSSL Plugin" in C that dynamically loads and calls into the OpenSSL module already embedded inside the 4D application itself, exposing MD5/SHA1/SHA256/SHA384/SHA512 and their HMAC variants; an alternative Ruby/VBScript-based "Hash and Digest Component" using `LAUNCH EXTERNAL PROCESS` is also provided for developers who avoid plugins. All of this is packaged into a reusable "4D AWS Library" component (using XSLT transformations to generate REST URLs or SOAP envelopes from a generic intermediate XML) plus a GUI test suite and a sample "iTunes Artwork Manager" application that fetches album art from Amazon and applies it via AppleScript/VBA. The note closes by summarizing the multiple techniques covered as reusable patterns for any 4D developer needing to call complex, cryptographically-signed web services.
