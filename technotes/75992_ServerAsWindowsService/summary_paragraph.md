This Tech Note covers running 4D Server as a Windows service — a long-running background executable that starts and stops automatically with the operating system without requiring a logged-in user, similar in concept to a Unix daemon. It explains the benefits (automatic startup/shutdown tied to the OS, configurable recovery actions on failure) and walks through registering 4D Server as a service, including caveats specific to Windows XP, Windows Server 2003, Windows Vista and Windows 7, and Windows Server 2008. Maintenance guidance covers starting and stopping the service both via the Windows Services Control Panel and from the command line, as well as unregistering the database as a service entirely. A section on intermediate updates addresses the trickier scenarios of upgrading the 4D Server software itself or updating the database structure while running as a service. The note closes with general troubleshooting tips, including why 4D menu items related to Services may be unavailable and why a developer might be unable to interact with a running service. It targets 4D developers and administrators deploying 4D Server in unattended, always-on Windows environments.
