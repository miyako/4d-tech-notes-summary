This Tech Note explains a breaking behavioral change 4D 2004 introduced to window and form resizing, illustrated first through a demonstration database originally built for 4D 6.8: in that older version, a simple pattern of GET WINDOW RECT/SET WINDOW RECT was enough to synchronize two windows' sizes and positions, because SET WINDOW RECT automatically resized the window's contents along with the window itself. Ported unmodified to 4D 2004, the same code makes the interface unusable, because 4D 2004 introduced a new "pusher" system for form objects and split resizing into two distinct commands: SET WINDOW RECT now only changes a window's outer boundary without touching its contents, while a new RESIZE FORM WINDOW command performs the old-style "resize as if the user dragged the corner" behavior that moves and grows objects according to their form properties. The note works through the exact replacement code pattern needed (computing a size delta with GET WINDOW RECT, applying it via RESIZE FORM WINDOW, then repositioning with SET WINDOW RECT) and explains why the order and math of the operations matter. It then walks through seven progressively more complex example dialogs demonstrating the new capabilities: manually invoking SET WINDOW RECT to reveal previously off-screen objects; using SET FORM HORIZONTAL RESIZING and SET FORM VERTICAL RESIZING to programmatically enable/disable and bound resizing (even overriding a form's own min/max size definitions); combining fixed-size regions with RESIZE FORM WINDOW-driven expansion; defining sensible minimum/maximum width and height (warning strongly against leaving the 0–32000 defaults, which can make an interface unusable); and demonstrating what happens to Move/Grow-tagged objects at various window sizes, including objects sliding off-screen if resized too small. It recommends developers enable the "Display Limits" option in the form editor's contextual menu to visualize a form's real displayable bounds relative to the current window size, and stresses that all object and form resizing-related properties (Move, Grow, Automatic Size vs. fixed size, min/max width/height) must be defined consistently to avoid a form becoming unusable after a resize. The featured technology throughout is 4D 2004's window/form resizing command set (SET WINDOW RECT, RESIZE FORM WINDOW, SET FORM HORIZONTAL/VERTICAL RESIZING) together with the object pusher system and form-editor Display Limits feature — squarely a classic Design-Mode form migration and API-change guide from the mid-2000s.
