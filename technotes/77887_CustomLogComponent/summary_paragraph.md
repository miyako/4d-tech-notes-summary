This Tech Note, authored by 4D's Director of Technical Services, addresses the common need for application-specific logging beyond 4D's built-in log options by providing a reusable "customLogs" component. The component supports two output formats: a simple sequentially-numbered text log and a more structured JSON log, both automatically rotated into new files once they reach a 10 MB default size threshold, and both stored in a Logs folder next to the host structure file. The key technical innovation highlighted is the use of 4D v16's CALL WORKER command and preemptive process programming to serialize writes to the log file, replacing older approaches that required flag variables or semaphores to avoid write collisions between concurrent processes. The note walks through implementation details for both the simple text and JSON log formats, showing how developer code calls into the component to append messages safely regardless of which process or thread originates them. A use-case section demonstrates integrating the component into a real database scenario for capturing application events, trends, and troubleshooting data. The Tech Note positions this as a lightweight, general-purpose logging utility that any v16 database can drop in when built-in 4D logging options (such as the debug log or request log) do not fit specific application needs. Overall it is a practical utility-component note focused on concurrency-safe file I/O rather than any deep new 4D data-access technology.
