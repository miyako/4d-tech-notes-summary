Only the readme/setup instructions for this Tech Note's demo database were available (rather than an extended narrative PDF body), so this summary is based on that readme and the method/file names it references. The demo requires 4D v17 and Wakanda Enterprise 2.6.0+ (with a 4D Mobile Server Expansion, or standalone/uncompelled operation without one) to illustrate exchanging records between 4D and a Wakanda Enterprise-based mobile backend using ORDA collections rather than raw arrays. Sample 4D project methods `createEntitySelection` and `entitySelectionToCollection` demonstrate retrieving a collection representation from an ORDA entity selection, while `collectionWithOption` and `collectionWithFilter` show additional conversion options/filtering. Corresponding Wakanda-side JavaScript files (`getMobileSelection.js`, `getCollection.js`) contrast the legacy "Mobile Return Selection" approach with the newer collection-based approach for retrieving data server-side. Further demos cover building a selection-compatible array to send from 4D to Wakanda (`sendCompanyCollection.js` / `receiveCompanyCollection` 4D method), adding a timestamp to a collection sent from 4D Mobile (`sendCompanyCollectionWithStamp.js`), and handling entity locking during exchange — locking a record via the standard 4D input form and observing the effect when a Wakanda script (`sendCompanyCollectionLocked.js`) attempts to send/modify the locked record. Collectively, the demo illustrates practical patterns for building a 4D Mobile-backed mobile/web client (via Wakanda Enterprise) that reads and writes 4D data as collections while respecting entity locking, a workflow specific to the now-retired 4D Mobile/Wakanda Enterprise product pairing.
