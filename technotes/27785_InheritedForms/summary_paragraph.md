Written by Steve Hartman of 4D's Information Systems group, this Tech Note explains 4D 6.8's "inherited forms" feature, which lets a developer designate one form's objects to be automatically combined into other forms, similar in spirit to page 0 but applicable across the entire form set of a database. The motivating scenario is standardizing elements such as OK/Cancel/Next/Previous buttons and a logo across every entry form in a database: rather than copying those objects into each form's page 0, a developer creates a single form containing just those shared elements and designates it as the "inherited form" for the other forms, so a later style change only needs to be made once. The note details the precise object load-and-combine order when a form opens -- page 0 of the inherited form, then page 1 of the inherited form, then page 0 of the open form, then the open form's current page -- and notes that only pages 0 and 1 of an inherited form can be surfaced this way, and that the inherited form's own properties and form method are not invoked. It walks through the Form editor steps for setting the "Inherited form table" and "Inherited form name" properties, notes that inherited objects can be toggled via the Display submenu, and explains that 4D detects and blocks recursive inheritance loops. The note closes by re-emphasizing the load order and the pages-0/1-only limitation as the two things developers most need to remember.
