4D v11 SQL Release 3 introduced SQL schema support as a security mechanism for protecting database tables accessed via external connections (ODBC, SQL pass-through). Unlike earlier versions where access rights were configured globally through SQL Preferences, schemas allow database designers to create named containers for tables and assign per-schema access rights (Read Only, Read/Write, or Full) to specific 4D groups. Each table belongs to one schema; new databases automatically get a DEFAULT_SCHEMA that groups all tables. The note explains the CREATE SCHEMA, ALTER SCHEMA, GRANT, REVOKE, and DROP SCHEMA commands with SQL syntax examples, as well as how to assign schemas to tables via the Structure Editor Inspector or SQL. Notably, schemas only control external connections—internal 4D method execution (Begin SQL, SQL EXECUTE, QUERY BY SQL) retains full access regardless of schema permissions. The note includes a sample componentized database with a GUI schema editor that developers can drop into existing v11.3+ databases to visually manage schemas without writing SQL directly, addressing the limitation that GRANT cannot be applied to the EVERYBODY pseudogroup in that release.
