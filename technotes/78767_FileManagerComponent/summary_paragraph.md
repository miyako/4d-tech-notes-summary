This tech note updates and modernizes an older technique from 2015's TN 15-07 for managing files on the 4D Server machine from a 4D Remote client, repackaging it as a reusable, drop-in component. The central mechanism is the "Execute on Server" method property, which lets a client-side call transparently run a project method on the server and return results, letting methods prefixed "svr" (e.g. svrFolderSeparator, svrGet4DFolder, svrGetSystemFolder) act as thin wrappers around server-only commands like Get 4D folder and System folder. The component exposes five shared methods, most importantly openFileManager({pathOnServer}), which opens a File Manager window rooted at a given server path (or a default "Root" folder next to the structure file), and fileManagerStartup, which should be called from On Startup/On Server Startup to initialize state. The File Manager UI supports creating folders, deleting and renaming files/folders, uploading and downloading via both buttons and native drag-and-drop (Finder/Explorer to Listbox and vice versa), refreshing, navigating up a level, and a clickable breadcrumb trail. Compared to the 2015 original, the 2021 rewrite replaces the array-based Listbox with a collection-based Listbox, adds sortable/clickable headers, a file-size column, a footer item counter, and reduces the implementation down to two process variables via Form data objects, eliminating inter-process variables entirely. This modernization illustrates the shift in 4D UI coding style from array/interprocess-variable idioms toward object/collection-based form data, while keeping the fundamentally sound "Execute on Server" architecture unchanged.
