This Tech Note by Thomas Maul explains how to achieve Active Directory-based single sign-on (SSO) in a 4D 2004 application on Windows without requiring a plug-in, letting a domain-authenticated Windows user access a 4D database transparently using their existing network credentials rather than a separate 4D login. The core technique is a single 4D method, AD_UserGroups, which dynamically writes a small VBScript file to the temporary folder, executes it via LAUNCH EXTERNAL PROCESS and cscript, and parses the returned output to obtain the current authenticated user name, domain name, domain DNS suffix, and the list of Active Directory security groups the user belongs to; the method can return this data as either a plain text value or a text array, and explicitly does not work on Mac OS clients. The note then shows two integration strategies: layering AD group membership checks on top of an existing custom password dialog (using CHANGE CURRENT USER to grant temporary admin rights for validation), or fully adopting 4D's built-in password system so that 4D users and groups are automatically created, updated, and synchronized from Active Directory group membership on each startup, with a random encrypted password so end users never see 4D's own login dialog. It highlights practical benefits of using 4D's native password system — such as the "Current User" command being usable everywhere including triggers, integration with 4D Server's log/backup auditing, and support for "Locked Attributes" — and walks through a detailed startup algorithm involving a dedicated low-privilege "Default User," an admin account known only to developers, encrypted BLOB password storage, and array-based reconciliation of group memberships between AD and 4D. Featured technology centers on 4D's LAUNCH EXTERNAL PROCESS command, VBScript/WSH network and LDAP objects (WScript.Network, WinNT:// and LDAP://RootDSE ADSI providers), and 4D 2004's user/group management commands (GET GROUP LIST, GET USER LIST, SET USER PROPERTIES, CHANGE CURRENT USER). As a Windows-domain-specific, plug-in-free workaround built around shelling out to VBScript, the note is a snapshot of pre-SQL-engine, pre-Project-Mode 4D development practices from the mid-2000s.
