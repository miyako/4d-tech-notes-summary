This Tech Note provides an overview of SSL (Secure Socket Layer) theory and its implementation in 4D v11 SQL Release 6, covering how public/private key cryptography enables authentication and encryption using the RSA algorithm accepted by the US Federal Advanced Encryption Standard. It walks through generating a key pair with the GENERATE ENCRYPTION KEYPAIR command and requesting a signed certificate with GENERATE CERTIFICATE REQUEST, explaining how browsers access a secure server and what happens during the handshake. A major focus is 4D's SSL cipher list: the note documents cipher list format and strings, the available ciphers, how to get, set, and reset the cipher list, and highlights notable cipher suites including SSLv2, SSLv3, a "stronger" SSLv3 list, and the default v12 cipher list. An example database walks through adjusting the cipher list, creating an SSL key pair, submitting a certificate request (both self-signed and via a fully qualified certificate authority), and activating SSL for the Web Server, SQL Server, and Client-Server connections, including secured-mode client connection settings. The note targets 4D developers who need to deploy SSL-secured 4D Server, Web Server, or SQL Server connections.
