Written by Xiang Liu of 4D Inc. in September 2016 for 4D Mobile v15 R5, this tech note explains a structural difference between 4D Mobile sessions and ordinary 4D web sessions — a 4D Mobile session can be associated with multiple concurrent web processes (each method call spawning its own process, with context reset afterward), unlike a standard web session tied to a single process — and shows how 4D v15 R4/R5 added new and updated commands to properly manage this. It documents three existing web-session commands extended with 4D Mobile support (WEB Get Current Session ID, WEB CLOSE SESSION, WEB GET SESSION EXPIRATION), one new command (WEB Get session process count), and a renamed database method (On Web Close Process, formerly On Web Session Suspend), explaining that prior to v15 R4 these commands simply didn't work against 4D Mobile sessions at all, since 4D handled them automatically and opaquely. The practical demonstration builds a Wakanda-side session-administration console: storing all active 4D Mobile session IDs in an interprocess array (appending on login via a shared method, removing on logout), then rendering a live view of all active sessions in a Wakanda web page, with the ability for an administrator to forcibly end a given session and disconnect that 4D Mobile user, releasing the associated client license. This use case — session monitoring/administration — is a legitimate need for any multi-user server application, but the entire technical foundation here (4D Mobile sessions, Wakanda-based admin console, the specific WEB command extensions built for 4D Mobile) is tied to a product line 4D subsequently discontinued. The general WEB session commands referenced still exist for 4D's own web server today, but the 4D-Mobile-specific session semantics and the Wakanda administration console pattern described are no longer applicable to current 4D development, which handles session/connection management differently under ORDA and REST-based architectures.
