This Tech Note explains the new multithreading model introduced with 4D v11 SQL's rewritten data engine, aimed at helping developers understand how their business logic decisions interact with multi-core hardware. It first covers general multithreading concepts — what a thread is, the difference between cooperative threads (which yield control voluntarily) and preemptive threads (which the operating system can interrupt) — and how each behaves on single-core versus multi-core systems. It then explains how 4D specifically applies this model: 4D Server v11 SQL combines an application server, a web server, and a SQL server that all run simultaneously in separate threads, transparently to the user, with incoming requests routed through different ports (port 19813 or the Web server uses a cooperative thread, while ports 19812 and 19814 use preemptive threads). The note details how stored procedures and the "Execute on Server" method property behave under this model, how triggers execute, and how indexing, data cache, and backup procedures are threaded, plus how the SQL Server itself fits into the scheme. A closing section discusses the resulting scalability benefits on multi-core/multi-processor machines. The note targets 4D developers seeking to design applications that make good use of the new threading architecture.
