This Technical Note by Yvan Ayaay describes the integrated backup/restore module newly built directly into 4D 2004 (4th Dimension and 4D Server), replacing the separate 4D Backup plug-in used in prior versions. It walks through the two configuration areas that govern every backup: the Backup Settings (General Settings such as keeping only the last N backups and how to handle active transactions or failures, plus Archive options for segmenting, compressing, and optimizing the backup archive) and the Configuration Settings (specifying backup contents such as the structure and data files plus extra files/folders, the destination folder, last-backup information, and log file management). It explains the three ways a backup can be triggered — manually via the File menu, automatically via the Scheduler page (with configurable frequency down to specific days and times), or programmatically using the Backup command alongside the On Backup Startup Database Method and On Backup Shutdown Database Method hooks. A central feature discussed is the log file, which records every subsequent data modification and transaction after a full backup so that changes can be reintegrated into a restored database, keeping it up to date after an incident. The note also covers automatic restore configuration, including options to restore the last backup automatically when database damage is detected, integrate the last log file if the database is incomplete, and automatically restart the database after restoration. Overall, the note frames this backup/restore integration as a major simplification over the prior plug-in-based approach, giving developers manual, scheduled, and code-driven paths to protect and recover their databases.
