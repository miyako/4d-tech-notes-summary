This Tech Note by Jean-Yves Fock-Hoon (QA Manager, 4D, Inc.) explains how 4D 6.7 supported foreign-language ("foreign system") environments on both Mac OS and Windows NT, where 4D emulated the Mac Toolbox via Altura's ASINTPPC.DLL. It distinguishes Roman systems (French, US, German, etc.) from non-Roman "Script Manager" systems (Japanese, Arabic, Cyrillic, East European), each governed by a script that defines sorting, searching, calendars, and handwriting direction. Using Customizer Plus, developers could select a Comparison mode (4th Dimension, System, Turkish, or legacy Mixed/German options) and a TRIC resource that supplied the actual sort/search tables, with 4D storing an index signature in the data file to detect mismatched rebuild requirements. Cross-platform character translation between Mac and Windows extended ASCII tables was handled by a 'MapC' resource, accessible programmatically via the Mac to ISO and ISO to Mac commands, which was also relevant for Web Server character-set configuration. The note also covers font handling strategy (plain font substitution for West-European locales, FONT/FONT SIZE/FONT STYLE changes for Central European and Asian scripts, and MOVE OBJECT-based right-to-left layout for Arabic), recommending 4D's built-in style sheets as the cleanest solution throughout. It closes by distinguishing "Language" localization (needed to tokenize methods correctly under a foreign system) from "Usage" localization (needed for correct sorting/searching), and warns that editing 4D methods on an uncustomized foreign system risks corrupting tokenized code.
