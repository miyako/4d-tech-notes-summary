This Tech Note by Robert Molina is a refresher-style tutorial on 4th Dimension's six comparison (relational) operators — equality (=), inequality (#), less than (<), greater than (>), greater-than-or-equal (>=), and less-than-or-equal (<=) — and how each behaves across the five 4D data types that support them: String, Numeric, Date, Time, and Pointer. It opens by clarifying a common point of confusion for developers coming from other languages: in 4D, "=" is purely a comparison operator, never an assignment operator (assignment always uses ":="), unlike languages such as C++ where "=" inside a conditional can silently perform assignment. It walks through how comparison operators combine with operands to form conditional (Boolean) statements that drive 4D's branching (If/Case) and looping (While/For/Repeat) control-flow structures, briefly touching on Boolean algebra to explain how a TRUE/FALSE result is represented as a single bit. For String comparisons, it details that numeric characters sort before letters, that longer strings compare character-by-character left to right, and — notably — that 4D's default string comparison is case- and diacritic-insensitive (e.g., "A"="a" and "n"="Ñ" both evaluate TRUE), requiring the Ascii() command to distinguish characters by exact code point when case/accent sensitivity is needed; it also documents the "@" wildcard character, which must appear in the right-hand operand to match any number of trailing characters. For Numeric comparisons, it warns that floating-point equality checks can silently fail due to precision (showing 32.000001 = 32.000002 evaluating unexpectedly TRUE) and recommends using the Round() command to normalize precision before comparing. For Date comparisons, it explains 4D's date ordering rules, valid date range (1/1/100 to 12/31/32767), the two-digit year interpretation cutoff (>=30 assumed 1900s, <30 assumed 2000s), and a caution about date format mismatches (mm/dd/yyyy vs. dd/mm/yyyy) producing logically incorrect comparison results when importing external data. For Time comparisons, it notes 4D's 24-hour time range (00:00:00 to 596,000:00:00) and the fact that a Time value can be directly compared against its equivalent integer number of seconds. Finally, for Pointer comparisons, it explains that only equality/inequality are supported (no ordering), since pointer address values carry no meaningful ordering semantics, and that attempting < or > on pointers raises a runtime error — with equality checks instead used to enable generic, pointer-driven code patterns. As a foundational language reference rather than product-specific tooling, this note's content remains almost entirely accurate for current 4D development.
