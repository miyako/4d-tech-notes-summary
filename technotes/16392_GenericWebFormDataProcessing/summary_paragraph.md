This Tech Note (TN 01-36, 4D v6.7, Mac & Win, published August 31, 2001) by Kent D. Wilbur, Manager of Information Systems at 4D, Inc., is the first of a two-part series building a completely field-agnostic web-form intake system (the second half, covered separately in TN 01-49's GenericEval database, parses the resulting emails). Wilbur's design uses 4D 6.7's GET WEB FORM VARIABLES command to read any submitted form's field names and values into arrays without declaring each one individually, driven by a set of hidden HTML control fields on every form -- tFormName, tReplyFormName, tErrorForm, tMandatoryFields, tMailTo, tMailSubject, tMailFields, and tMailBody -- that tell the generic WEB_HandleForm backend method which fields are required, where to email the results, which fields to include, and which page to send next on success or failure. The WEB_fCompleteForm method validates that all fields listed in tMandatoryFields were actually filled in, producing a human-readable missing-fields message via a name-prettifying helper (GEN_sFriendlyName), while MAIL_tFields2Text encodes the submitted values into machine-readable [***FieldName***] Value blocks for the companion parsing database, and MAIL_tFields2Block can instead fill a stored email template with <!--#N--> positional placeholders to send the submitter a personalized confirmation. A final "almost generic" variant shows how declaring the form's fields in COMPILER_WEB (at the cost of full genericity) enables default values, error-preserving form redisplay, and daisy-chaining several forms together into a multi-page survey.
