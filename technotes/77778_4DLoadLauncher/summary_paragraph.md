This Tech Note by Timothy Aaron Penner addresses a practical benchmarking problem: setting up load tests for a 4D client-server application using cloud computing infrastructure isn't always feasible, so the note provides a local alternative for generating 4D Client load by running multiple 4D Client instances on a single Windows machine. The tool, called the Load Launcher, is itself written in 4D and uses the LAUNCH EXTERNAL PROCESS command to spawn multiple concurrent 4D Client processes, each configured with an isolated client resource folder so that many clients can connect concurrently to the same 4D Server without resource conflicts. Feature highlights include automatic server connection for each launched instance, the client resource isolation mechanism that makes multi-instance operation possible, and a hidden-UI option that suppresses each 4D Client's window, dramatically reducing desktop clutter when running dozens of simultaneous client instances for a load test. The note walks through preparing for a load test, then using the Load Launcher itself: adding different 4D versions to test against, launching instances, and managing already-running instances via a PID-based quick menu for tracking and controlling individual client processes. It concludes with a summary and a special note (likely caveats about the tool's Windows-only scope or limitations). As a niche but practical DevOps/QA utility for 4D client-server developers, this note packages a lightweight, self-contained load-generation technique that remains functionally usable today, even though more sophisticated cloud-based or multi-machine load testing setups have since become more common for rigorous performance validation.
