This Tech Note (TN 01-56, 4D v6.7, Mac & Win, published December 30, 2001) presents a guide to invoking 4D's Query Editor and QUERY-style commands from within a compiled C plug-in. Only a short on-page teaser paragraph survives in this archive rather than the full downloadable PDF and example database, because the original download was an old Windows self-extracting .exe installer (https://kb.4d.com/ftp://ftp.4D.com/ACI_TECHNICAL_NOTES/2001/Windows/TN_2001_54-57_(DEC)/01-56_4D_API_Query_Commands.exe) that could not be extracted in this environment; the original 4D Tech Notes site offered separate Windows and Mac downloads of the complete note and its companion example database, but neither is retrievable here. Based on the surviving teaser text, the note's proposition is: This technical note describes how to go about using API commands to create 4D Queries inside a plug-in. This technical note will also look at the two different ways to create a query. One is to use the built in 4D Query Dialog, while the other is to use the build in 4D Query commands. These would be similar to the "QUERY" command in 4D. Its featured technology centers on 4D Plug-in API (C-based), QUERY command, 4D Query Editor dialog, reflecting typical concerns of the 4D 6.7 (4D 2000/2001 era) developer community working in binary Design Mode on classic Mac OS/early Mac OS X and Windows 98/2000/NT. This note explains how a compiled C plug-in could programmatically invoke 4D's query mechanism, either via the built-in Query Editor dialog or the classic QUERY-style API commands, in the pre-Unicode, 32-bit plug-in API era. The classic QUERY command family it discusses is still present in 4D's language today, but the plug-in API itself has been substantially revised since (Unicode, 64-bit, Universal Binary), and ORDA's dot-notation entity queries now offer a more modern alternative to constructing query criteria programmatically.
