This Tech Note introduces 4D NetKit (added in 4D 19R3), which manages OAuth 2.0 authorization flows between 4D applications and third-party web APIs, replacing the older approach of manually handling OAuth for IMAP/SMTP/POP3 transporters. It explains OAuth 2.0's access-token/refresh-token model — access tokens authorize API calls and expire, while refresh tokens (if enabled) silently renew access without re-prompting the user through the browser — and walks through registering applications with both Google Cloud Console (creating OAuth consent screens, test users, and client secrets for the Gmail API) and Microsoft Entra admin center (registering an app for Microsoft Graph). The core technical pattern is constructing a cs.NetKit.OAuth2Provider object with name, permission ("signedIn"), clientId/clientSecret, redirectURI, and scope, then calling .getToken() to launch the browser-based consent flow (with 4D NetKit's built-in local web server intercepting the redirect). Once authenticated, cs.NetKit.Google and cs.NetKit.Office365 objects expose a mail namespace supporting send(), getMailIds()/getMails(), delete() (permanent or trash), and Gmail-specific label management (createLabel, updateLabel, update with addLabelIds/removeLabelIds) or Microsoft-specific folder management (getFolderList, createFolder, renameFolder, deleteFolder, move). The note requires 4D 20 R6+ and a Web Application Expansion license, and positions 4D NetKit as the modern, streamlined way for 4D developers to integrate secure, standards-based email and folder automation with major cloud providers without hand-rolling OAuth token handling.
