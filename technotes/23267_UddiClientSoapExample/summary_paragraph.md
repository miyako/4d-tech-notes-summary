This Tech Note, written by Julien Feasson of 4D Inc., is the first of a two-part series demonstrating how to build a UDDI (Universal Description, Discovery and Integration) client using 4D 2003's newly built-in Web Services and XML parsing features. It explains the UDDI protocol stack (UDDI over SOAP over XML over HTTP), its four core information types (business, service, binding, and specification/tModel information), and focuses specifically on the Inquiry API used to search and browse a UDDI registry, leaving the Publisher's API for a follow-up note. The included demo database implements a preferences panel for managing a list of UDDI servers to query, and a Search Assistant that lets the user look up web services by keyword. Under the hood, the UDDI_search method manually builds a Doc-style SOAP request as raw XML text (a hard-coded `find_tModel` template with the keyword inserted), converts it to a blob with `TEXT TO BLOB`, and sends it via `SET WEB SERVICE PARAMETER` and `CALL WEB SERVICE`. The returned XML blob is parsed with 4D's DOM-style XML commands (`Parse XML variable`, `Get First XML element`, `Get Next XML element`, `GET XML ATTRIBUTE BY NAME`) to extract tModel UUIDs and names into arrays, which are then used in a second `get_tModelDetail` SOAP call to retrieve full details (name, description, overview URL, categories) for display in the assistant. The author notes that many public UDDI servers were already becoming unreliable by 2003 and recommends xMethods.net as the most usable registry to query.
