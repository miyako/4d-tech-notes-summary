This Tech Note introduces ORDA (Object Relational Data Access), the new dot-notation data access layer added in 4D v17, by directly comparing it side-by-side with 4D's existing embedded SQL syntax across the four basic CRUD operations (Create, Read, Update, Delete). It walks through the core ORDA vocabulary: the Datastore (accessed via the `ds` command), the Dataclass (representing a table and its relations), Entity Selections (collections of rows analogous to classic 4D selections/sets), and individual Entities (single records), along with their respective member functions. Practical examples show creating a record with `ds.People.new()` followed by field assignment and `.save()`, reading and filtering data, updating fields and checking the returned status object, and deleting entities — each paired with the equivalent `INSERT`, `SELECT`, `UPDATE`, and `DELETE` SQL statements. The note also covers ORDA's locking model, explaining the default optimistic locking behavior (based on internal timestamps) versus explicit pessimistic locking via `lock()`/`unlock()`. A sample database with test forms for each CRUD operation is provided so developers can compare execution timing and code readability between the two approaches. The central selling point stressed throughout is that ORDA is thread-safe, unlike SQL, and that its object-oriented syntax is more readable and maintainable than raw SQL strings embedded in 4D code. As one of 4D's earliest ORDA-focused technical notes, it functions as an onboarding document aimed at developers accustomed to SQL or classic 4D commands who are evaluating whether to adopt the new API.
