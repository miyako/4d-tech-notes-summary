Written by Pascal Pradier, Program Manager at 4D S.A., this Tech Note demonstrates a less common use of 4D: establishing a serial dialog with a microcontroller to acquire sensor data. The chosen hardware is deliberately simple -- a Parallax BasicStamp II microcontroller (programmable in BASIC, 16 I/O pins, 2KB EEPROM, RS-232 interface, under $50) paired with a Dallas Semiconductor DS1620 temperature sensor that needs no extra components and can be queried directly or set up as a thermostat. On the 4D side, a dedicated background process ("recept") is created with New process, configures the serial port via SET CHANNEL(1;Speed 9600+Data bits 8+Stop bits One+Parity None), and loops on RECEIVE BUFFER inside a While loop, creating and saving a new [Table 1] record with the numeric temperature value each time non-empty data arrives. On the BasicStamp side, the PBASIC program uses "outs"/"dirs" to initialize the 16 output pins, "High 1" to trigger the DS1620's reset pin, and Shiftout/Shiftin (with lsbfirst byte ordering) to send the DS1620 a conversion command (value 238) and read back data, using Debug to stream results over the default RS-232 port to 4D once per second. The note also outlines an alternative asynchronous acquisition mode, where readings are instead accumulated in the BasicStamp's EEPROM and retrieved by 4D on a periodic schedule (e.g. weekly or monthly) rather than continuously, trading real-time visibility for reduced 4D-side load, and flags that continuous per-second record creation has practical weaknesses (better to accumulate into a size-limited BLOB and periodically prune obsolete records).
