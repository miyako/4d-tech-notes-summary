This Tech Note showcases the LAUNCH EXTERNAL PROCESS command, added to the 4D language in 4D 2004, through a demo application called "4D System Tool" that lets a 4D database drive native OS utilities on both Mac OS X and Windows. Because system calls are inherently platform-specific, the example app is split into two very different interfaces: on Mac OS X 10.4 it offers Appearance (tweaking Finder/Dock/Safari settings), Maintenance (running periodic maintenance, repairing disk permissions, rebinding), Man (browsing and exporting Unix man pages as PDF/HTML), and Info panels, plus a free-form "Execute Command" dialog; on Windows XP it offers Maintenance (defragmenting, scheduling chkdsk), Tasks (a Task Manager-like process list/kill tool), Quick Launcher (a curated list of Control Panel and Run-dialog utilities, editable and stored in an XML file), and Info. All calls funnel through a single project method, ST_comm_executeCommand, which builds the appropriate authorization flow (prompting for a username/password on Mac when required) and, on Windows, sets an environment variable to suppress the console window before invoking LAUNCH EXTERNAL PROCESS. The note walks through concrete code examples, such as calling the Unix "whoami" utility at startup and chaining "/bin/sh -c" invocations of man, groff, and open to convert and display man pages as HTML, explaining the use of shell quoting to avoid command-parsing issues. It closes by pointing to further Mac OS X man pages and the full list of Windows DOS commands as resources for extending the tool. The note is essentially a hands-on illustration of what became possible once 4D could shell out to the native OS, rather than a discussion of any specific business feature.
