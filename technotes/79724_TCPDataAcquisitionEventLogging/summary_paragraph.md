This Tech Note demonstrates 4D's modern approach to TCP/IP networking, introduced in version 20 R8 through the 4D.TCPConnection and 4D.TCPEvent classes, which let developers acquire data from and log events for external TCP servers or devices directly within 4D applications. The core technical approach wraps a TCP client connection in a custom 4D class whose constructor stores a URL and port, exposes connect()/disconnect()/sendPacket()/getInfo() methods, and implements five asynchronous event handlers — onConnection, onShutdown, onData, onError, and onTerminate — that 4D invokes automatically as connection lifecycle events occur, so the application never blocks waiting on network I/O. Key APIs include 4D.TCPConnection.new() to open a socket and 4D.TCPEvent objects carrying the event type, remote IP/port, and any received data as a blob, which callbacks convert to text with BLOB to text. A key operational caveat is that TCP is a stream protocol with no guaranteed packet boundaries, so onData handlers must account for fragmented data arriving across multiple events. The accompanying demo application, built on 4D Internet Commands (TCP_Listen) for the socket layer, walks through connecting, transmitting a file as packets, and receiving/reassembling them, requiring 4D 20 R8 build 100353 or later. The note also flags the forthcoming 4D.TCPListener class (introduced in 20 R9) for building a TCP server counterpart, positioning this as the first step in 4D's expanding native TCP/IP toolkit for real-time, event-driven networked application development.
