This Tech Note explains how to change the colors displayed within 4th Dimension by editing the "pltt" (palette) resource stored inside the 4D or 4D Client application file, covering both why a developer might want to and the mechanics of doing so on Mac and Windows. It identifies pltt resource #2000 as the one controlling picture field/variable display, procedure editor token colors, and layout editor object colors, and walks through opening the 4D application in ResEdit, navigating to the pltt resource, and editing individual color entries with the color wheel — while warning that since objects only store a color's palette index (not the color itself), changing an entry can unexpectedly recolor every object that used that index, so the technique should be used cautiously. A worked example shows changing color #9 (green) to dark purple in a sample "pltt_test" database and observing the resulting shift in a layout that used that color. For Windows, because pltt resources live in the platform's 4D.RSR file (the equivalent of the Mac resource fork), the note explains the workaround of using 4D Transporter to move the .RSR file to a Macintosh, edit it there in ResEdit, and transport it back to the PC. A Warning and Disclaimer section explains platform differences in palette handling: on the Mac, 4D's "logical" palette actually overrides the "absolute" system palette while frontmost (explaining the visible color-flash when switching applications), whereas Windows always maps to the OS's own best-matching colors and does not exhibit the same override behavior or flash. The note closes cautioning that this is a global change affecting the entire database's color display, so it should be approached carefully. Featured technology is squarely Apple's ResEdit resource editor and 4D's proprietary pltt palette resource format, alongside 4D Transporter for cross-platform resource file transfer.
