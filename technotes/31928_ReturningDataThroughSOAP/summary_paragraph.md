Written by David Adams, this Tech Note is a detailed technical guide to returning data from 4th Dimension methods published as SOAP Web Services, going well beyond the single `$0` result parameter available to locally-called methods. It reviews how SOAP requests and responses are internally represented as XML-encoded SOAP messages processed transparently by the native 4D Web server — handling reception, XML-to-4D data type conversion, security checks, dispatching, and response formatting automatically — while noting the prerequisites for enabling Web Services (server running, the "Allow Web Services Requests" preference, and the "Offered as a Web Service" method property). The core technical content centers on the `SOAP DECLARATION` command, which lets a method bind any number of process variables and arrays — not just `$0` — to named XML output elements in the SOAP response, effectively allowing a single Web Service call to return the equivalent of a full record rather than one field; the note walks through concrete XML response listings showing both default (`FourD_arg0`) and custom-named output elements. It provides a comprehensive table of supported data sources (only `$0`, process variables, and process arrays are eligible — fields, local variables, and interprocess variables/arrays are not) alongside a full 4D-to-XML/SOAP type mapping table covering BLOB, Boolean, Date, Integer, Longint, Picture, Pointer, Real, StringVar, Text, and Time, including a documented workaround for pictures (convert to BLOB) and a quirk around time arrays (stored as longint arrays). The accompanying example database demonstrates every supported variable and array type via matching Web Service/proxy method pairs, and the note offers deployment guidance covering configurable server port numbers, running client and server as separate 4D instances, the role of the `Compiler_Web` method for binding inputs, and best-practice reminders about `SOAP DECLARATION` (must be called directly in the Web Service method, requires legal XML element names, and is safely ignored when the method is called locally rather than as a Web Service). Overall this is one of the more substantive and reference-quality Tech Notes from 4D's early SOAP Web Services rollout.
