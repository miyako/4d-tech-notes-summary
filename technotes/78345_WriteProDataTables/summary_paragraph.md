This Tech Note addresses the common need to embed structured, tabular data (e.g., invoice line items, order lists, scientific data sets) inside a 4D Write Pro document, a native word-processing feature that replaced the legacy, plugin-based 4D Write after the deprecation of 32-bit architecture. The core technical approach centers on 4D Write Pro "object ranges" — objects that reference a section of a Write Pro document — obtained via commands such as WP Selection range (to target the cursor position or highlighted text). A table is created with WP Insert Table, which accepts an insertion mode (wk append, wk prepend, wk replace) and optional column/row counts, returning a table range object; additional rows are appended with WP Table append row, and existing cells are addressed and modified via WP Table get cells combined with WP SET TEXT or ST INSERT. The note walks through building a nested-loop routine that maps an entity selection's records and fields onto table rows/columns, and covers formatting through WP SET ATTRIBUTES (border, font/text, image, and table attributes), explaining that because Write Pro documents are HTML-based, styling must generally be applied at the cell level rather than the column level due to HTML/CSS priority rules. Five demo variations in the accompanying sample database progressively add header-row toggling, insertion-mode selection, border styling, and full dialog-driven field/record filtering. The note is explicit about limitations current to 4Dv17R6, namely that removing table columns/rows or restructuring an existing table is not straightforward and requires table recreation. Overall, it positions 4D Write Pro as a flexible reporting/document-generation surface — usable for invoices, emails, and technical documents — that can be populated directly from ORDA entity selections without leaving the object-notation coding style.
