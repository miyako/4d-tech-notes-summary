This Technical Note introduces the Web 2.0-era concept of "mashups" and shows how 4D developers can create them using the 4D Live Window plug-in, part of the 4D Web 2.0 Pack, which embeds an internet browser directly into a 4D form. The note explains that 4D Live Window lets a developer drive the displayed URL using data from the current record, so a 4D form can show contextual live web content — such as a customer's location on Google Maps, a package's FedEx tracking status, or an inventory item's UPC lookup — without leaving the 4D application. It documents the plug-in's six commands (Web_SetURL, Web_GetURL, Web_Back, Web_Forward, Web_GetContent, Web_SetPreferences) with full parameter tables and error codes, focusing primarily on Web_SetURL, which loads a URL into the browser area. Three worked examples are provided: a GetGoogleMapsURL method that assembles a Google Maps search URL from customer address fields (handling language codes and character escaping), a GetFedexURL method that appends an inventory tracking number to a FedEx tracking URL, and a GetUpcURL method that queries UPCDatabase.com with a barcode. Each example follows the same two-step pattern: format a valid URL string from database fields, then call Web_SetURL to load it, typically triggered from the form's "On Load" event. The note also covers platform-specific quirks, including Mac OS resize/repaint issues with JavaScript-heavy sites like Google Maps, HFS vs. Unix path encoding for local files, and the need to pair SET VISIBLE with Web_SetPreferences to fully hide the browser area. It closes by encouraging developers to find their own creative mashup use cases, positioning the plug-in as broadly useful for any external content with a predictable URL scheme. The featured technology is entirely centered on the 4D Live Window plug-in and the specific external services (Google Maps, FedEx, UPCDatabase.com) used as URL-string source examples.
