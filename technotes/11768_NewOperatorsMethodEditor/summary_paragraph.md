This brief Tech Note addresses a subtle side effect of the new operators introduced in 4D version 6: because the Method editor now had to disambiguate expressions that could be parsed multiple ways, it could, in a specific situation, misinterpret the interprocess variable symbol (<>) as a bitwise operator during tokenization. This behavior differed from how the older Version 3 Procedure editor handled the same code, meaning method code written or pasted under V3 assumptions could tokenize unexpectedly once opened under V6. The note exists purely to document this discrepancy and to give developers a workaround so they could keep their interprocess variable references intact rather than silently corrupted into an unrelated operator. It is a narrow, practical bug-avoidance note rather than a broad feature tutorial, aimed at developers migrating method code from V3 to V6. No example database or download is referenced; the note is text-only guidance. Given its highly specific and edition-bound nature, it reflects the kind of tokenizer edge case common when a mature 4D language grows new syntax on top of an existing editor.
