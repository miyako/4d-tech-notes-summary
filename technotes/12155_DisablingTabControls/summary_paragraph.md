Written by Yves Casquel of 4D S.A. Technical Support, this Tech Note demonstrates how to restrict user access to specific pages of a form navigated by a tab control, either through an automatic 'go to page' action or a custom method. The sample database assigns a hierarchical list to a tab control object and shows two techniques for the second (Appointments) tab: disabling it with SET LIST ITEM PROPERTIES so it appears grayed out but remains present, or removing it entirely by clearing and reloading the list with CLEAR LIST/DELETE LIST ITEM so the tab and its page are no longer reachable at all. A password-style Request dialog gates re-enabling the disabled tab, while a pair of radio buttons controls whether the Contracts tab is appended to or removed from the list altogether. The note walks through the On Load form-event code that builds the hierarchical list with APPEND TO LIST, the object method that toggles the Appointments tab's active state, and the GOTO PAGE logic that forces the current page to a valid page if the active one becomes disabled. It closes by summarizing that dynamically creating/deleting or enabling/disabling tab items is broadly useful either to gate access to specific pages or simply to tighten interface control.
