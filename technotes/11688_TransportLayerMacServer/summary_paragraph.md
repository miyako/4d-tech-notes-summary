This January 1996 Tech Note by Christopher Chapman addresses networking configuration needed for 4D Client running under Windows 3.1(1), Windows 95, or Windows NT 3.5.x to successfully connect to a 4D Server running on a Macintosh. It explains that Macintosh machines typically offer two transport layer choices — EtherTalk or Ethernet — and that EtherTalk works by splitting native TCP/IP or IPX/SPX packets (which are larger than AppleTalk packets) into multiple smaller packets and encapsulating them in AppleTalk's own format; only computers with an AppleTalk stack installed can reassemble these packets, and most Windows PCs of the era did not have AppleTalk installed. The Ethernet transport layer, by contrast, simply posts packets in their native TCP/IP or IPX/SPX format, which is compatible with virtually all PC machines and is also faster since no AppleTalk encoding/decoding overhead is incurred. The note concludes that Ethernet (not EtherTalk) must be selected in both the MacTCP and MacIPX control panels on the Macintosh server machine for Windows 4D Clients to see and connect to it at all (absent an installed AppleTalk protocol using the ADSP network component on the PC side); switching to Ethernet has no effect on Macintosh clients, including those using ADSP. The one exception noted for preferring EtherTalk is when part of the network must be routed through an AppleTalk-only router.
