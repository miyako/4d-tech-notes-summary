This Tech Note by Gilles Mellot (4D S.A.) explains the SkinMaker example database's technique for creating reusable, dynamically-sized form background templates rather than static images. Using nine source pictures -- four corners, four borders (top/bottom/left/right), and a center fill area -- along with 4D's picture concatenation (`|`) and tiling/scaling operators, the code assembles a single composite picture matched exactly to a target window's width and height, computed via the `Skin_VerifSize` and `Calc_Tips` methods. Each defined template ("skin") is persisted by packing its nine source pictures into a BLOB with `VARIABLE TO BLOB` and storing it in a custom resource named "skin" via `SET RESOURCE`/`SET RESOURCE NAME`; the `Skin_Fill` method reverses this with `GET RESOURCE` and `BLOB TO VARIABLE`, then loads the resulting composited border and fill pictures into the Picture Library with `SET PICTURE TO LIBRARY` (or removes them if no picture is defined for a slot). The SkinMaker dialog interface lets a user create, rename, delete, and preview templates, with a Test button opening a window of the specified Form Width/Height that immediately reflects the assembled skin, and the note stresses that the code (centered on the `Skin_Fill`-for-loading and `Skin_Calc`-for-composing pair of methods) is designed to be copied into other custom databases without modification.
