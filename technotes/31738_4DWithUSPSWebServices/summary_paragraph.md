Written by Thang Nguyen of 4D Technical Support, this technical note demonstrates integrating 4th Dimension with the United States Postal Service (USPS) Web Tool Kit API, specifically its Domestic Rate Calculator, at a time before 4D had native HTTP client commands well suited to consuming this kind of XML-over-HTTP-GET service. The USPS API expects requests as a specially formatted HTTP GET whose query string embeds an XML payload (including a registered USERID and PASSWORD), so the sample database builds this request manually across three project methods: usps_addHead_XML (constructs the GET line and opening RateRequest tag with credentials), generateXMLRequest1 (appends package details, service type, origin/destination ZIP codes, weight, container, size, and machinability, as nine parameters), and usps_addTail_XML (closes the XML and appends the HTTP/1.1 terminator). The completed request is sent over a raw TCP socket opened with TCP_Open, transmitted with TCP_Send, and its response accumulated across repeated TCP_Receive calls until the connection closes, then closed with TCP_Close. On the response side, usps_ParseXML_Response strips the HTTP headers by locating the "<?xml version=" marker, and a recursive XML_Parser method walks the resulting XML element by element using Parse XML variable, Get First/Next XML element, and GET XML ELEMENT NAME/VALUE, extracting the Postage price and shipping Zone (or an error Description) into interprocess variables displayed by the accompanying Request Form and List Form dialog boxes.
