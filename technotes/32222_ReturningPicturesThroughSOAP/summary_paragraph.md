Written by David Adams, this technical note addresses a specific limitation of 4th Dimension 2003's SOAP Web Service system: while nearly every native 4D data type can be automatically included in a SOAP response, the Picture type cannot, so pictures must instead be converted to BLOBs with the PICTURE TO BLOB command before being returned, and converted back with BLOB TO PICTURE on the receiving end. The note builds a small, complete SOAP-based image server around this technique, using an [Images] table as a backing store and offering Web Service methods for listing available images (GetPictureList), listing available return formats (GetPictureFormatList, which converts 4D's QuickTime-derived four-character format codes into platform-neutral MIME types via a [Picture_Format_Codes] lookup table), and retrieving a specific image in a requested format (getPicture, which queries the record, calls PICTURE TO BLOB, and returns the BLOB as a declared SOAP output). A client-side proxy method shows how trivially a caller can request and reconstruct the image with SET WEB SERVICE PARAMETER, CALL WEB SERVICE, GET WEB SERVICE RESULT, and BLOB TO PICTURE, needing just a single line of application code. The note further sketches richer commands the sample includes (getPictureData, getPictureListExtended, getPictureWithType, getThumbnail) and discusses alternative picture sources beyond database records, including documents on disk or network, PICT resources, the Picture Library, and 4D Chart/4D Draw plug-in output.
