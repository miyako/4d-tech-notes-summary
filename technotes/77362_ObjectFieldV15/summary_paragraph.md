This Tech Note by Vance Villanueva introduces the Object field, a new v15 table field data type that stores property/value data (essentially JSON) with no predefined schema, extending the C_OBJECT in-memory object type first added to the 4D language in v14 into persistent, indexable database storage. The note explains that data can be entered schema-based or schema-less, that Object fields can be indexed, and that querying against them via the new QUERY BY ATTRIBUTE command remains fast even without a fixed structure. It walks through the language-level integration — populating Object fields with OB SET and JSON PARSE, retrieving values, and how array commands and formulas interact with the field type — as well as how Object field data can be entered directly through 4D Forms. The bulk of the note is a long, systematic set of worked query examples using QUERY BY ATTRIBUTE, covering the query string's components (the attribute path, comparison operator, and value), the "#" operator to test for property presence/absence, the "@" wildcard for matching within array values, combining multiple conditions with "*", and handling different value types including numbers, ranges, and dates, each demonstrated at first and second nesting levels and against both singular and array-valued properties. This exhaustive example set (roughly a dozen labeled cases) functions as a practical reference for constructing QUERY BY ATTRIBUTE query strings against real-world nested object data. The conclusion frames the Object field as a meaningful expansion of 4D's flexibility for developers who need to model variable or evolving data shapes without redesigning the database structure for every change.
