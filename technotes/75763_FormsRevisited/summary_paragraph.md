This Tech Note revisits the fundamentals and best practices of 4D form design, aimed at developers planning a new application or wanting to improve an existing one. It starts by defining what a form is in 4D's terms (the interface object used for data entry, listing records, printing reports/labels, and custom dialogs), then surveys the available form types: traditional Input and Output forms (and hybrid combined list/detail forms), the then-new Project Forms introduced in 4D v11 SQL (table-independent forms ideal for dialogs and components, with restrictions such as no list forms and no use in the label editor or import/export editors), forms generated by the Form Wizard (a fast starting point, not meant to be end-user-facing as-is), and User Forms (limited-customization forms end users can rearrange but not add code/variables/fields to). It goes on to cover form elements and properties in general, how to determine an "ideal" form size, building inherited forms to maintain visual and behavioral consistency across an application, multi-page forms for organizing complex interfaces, using style sheets for consistent formatting, techniques for resizing forms responsively, and hiding/showing form elements dynamically to streamline the user experience.
