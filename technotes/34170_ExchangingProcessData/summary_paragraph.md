Written by Jean-Yves Fock-Hoon, this Tech Note tackles the practical challenge of getting multiple 4D processes to communicate reliably, centered on three core commands -- SET PROCESS VARIABLE, GET PROCESS VARIABLE, and VARIABLE TO VARIABLE (the only one of the three that supports arrays) -- and, crucially, on the synchronization discipline needed around them. Example 1 demonstrates a simple, fully synchronous two-process handshake (M_ProcessOne/M_ProcessTwo) where each process waits on a shared "ready" flag before sending and waiting again for a reply. Example 2 escalates to three input processes feeding one slower output process through a semaphore-protected inter-process array acting as a buffer, driven from a dialog window using On Timer to add items without freezing the UI, and SET TIMER(30) on the output side to periodically drain the buffer without hogging the CPU. Example 3 applies the same buffered pattern, without dialogs, to build a simple multi-process log-file writer. Examples 4 and 5 flip the topology to multiple output processes pulling from a single input process, using a semaphore plus a GetNextItem-style boolean handshake so each output process retrieves exactly one unconsumed item at a time. Throughout, the note stresses that missed CALL PROCESS/On Outside Call events are silently lost (not queued), so buffering, semaphores, and periodic re-checking via timers are essential to avoid losing data or desynchronizing processes -- illustrated with the classic "clicking Next too fast on a floating navigation window" bug scenario.
