This Technical Note (26-08, published August 19, 2026 for 4D v21) demonstrates OpenAI-style "tool calling" (function calling) as a replacement for hand-written keyword/intent parsing in conversational 4D applications, using a demo clinic-booking app called demoAPT. Twelve business operations (check availability, book, reschedule, cancel, look up appointments, etc.) are declared as JSON-Schema tools via the 4D AIKit's `cs.AIKit.OpenAITool.new()` class, each with a name, a model-facing description, and a typed parameters schema; the model reads the conversation and returns a `finish_reason: "tool_calls"` response naming which tool(s) to invoke and with what arguments. A single synchronous loop, `APT_WebChat_RunTurn`, dispatches each requested call through `APT_Tool_Dispatch` to ordinary ORDA-backed 4D methods, feeds the JSON result back to the model as a `role: "tool"` message, and repeats (capped at 6 rounds) until the model returns a final natural-language reply, all behind a single unauthenticated `/rest/$catalog/chat` endpoint reached from a plain HTML/JS web chat via `chat.completions.create()`. Crucially, the same `APT_Tool_*` business methods are also called directly by a native Admin form with no AI in the loop, so staff and the AI assistant can never diverge on business logic. The note details tool-design best practices (one tool = one responsibility, model-facing descriptions, strict parameter schemas, small structured JSON returns, explicit loop caps), security practices (server-side API keys via a gitignored config file, no raw UUID exposure, re-validated bookings against race conditions), and troubleshooting pitfalls (`Day of` returning day-of-month not weekday, `String(Null)` producing the literal text "null"). It positions tool calling as a generally reusable architecture for any 4D application wanting to expose data/actions through natural language alongside its existing forms and menus.
