Written by Timothy Aaron Penner during the industry-wide 32-to-64-bit migration, this Tech Note addresses developers who relied on legacy 4D Write for mail merges (template documents with data placeholders producing printed output, PDFs, or emails, often via an offscreen area) and now need to move that workflow to 4D Write Pro. The bulk of the note is a practical conversion cookbook covering every legacy format path: v6 documents on disk must first be upgraded to v7 using the 32-bit-only legacy plugin (`WR New offscreen area`, `WR OPEN DOCUMENT`, `WR SAVE DOCUMENT`); v7 documents on disk can be converted directly, in either 32- or 64-bit mode, via `WP Import document()` and `WP EXPORT DOCUMENT(...;wk 4wp)`; documents stored as Pictures (v6 or v7) require the 32-bit legacy plugin to convert to a v7 blob (`WR PICTURE TO AREA`, `WR AREA TO BLOB`); and v7 documents already in blob format convert directly to a native 4D Write Pro object via `WP New($wrBlob)`. With conversion covered, the note explains how mail merges actually function in 4D Write Pro: documents (new or converted) contain expressions computed at processing time, inserted via `ST INSERT EXPRESSION` (e.g., referencing `[People]Name`), and the note walks through inserting, viewing, computing, and "freezing" these expression values before producing final output through `WP Print`-style commands to paper/PDF or exporting to HTML for emailing. It closes with worked mail-merge examples — loyalty discounts, outstanding balances, and order confirmations — demonstrating end-to-end templates. The note is essentially a migration bridge document: it exists specifically because customers had years of legacy 4D Write mail-merge templates and needed a clear, format-by-format path to keep that functionality working once 4D Write itself became unavailable in 64-bit mode.
