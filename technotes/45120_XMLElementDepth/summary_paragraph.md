This Technical Note by David Adams, the first in a 2007 run of small XML utility notes, addresses the fact that 4th Dimension's native DOM XML commands provide no built-in function to return an element's "level" or depth within its tree — information useful whenever processing code needs to behave differently based on how deeply nested a node is, such as formatting a hierarchical list display (bolding nodes at particular levels), deciding which levels of an XML tree should become new database records versus be ignored, or indenting a textual tree representation with tabs proportional to depth. The note documents a DOM_GetNodeLevel routine that starts at a given node and repeatedly calls DOM Get parent XML element, incrementing a counter each time a valid, non-#document parent is found, until it reaches the top of the tree or hits an invalid/#document reference, at which point it returns the accumulated count as the node's level (with the root element at level 1). Like its companion notes in this series, the routine wraps its traversal in a custom ON ERR CALL error handler (saving and restoring the prior handler and Error variable state) so that navigating past the top of the tree or encountering bad references doesn't interrupt program execution. The accompanying sample database includes a Test_GetNodeLevel harness exercising the routine against good nodes, bad nodes, and the synthetic #document node, displaying pass/fail alerts. As with the related XML notes from this period, the featured technology is 4D's classic DOM XML command set combined with a simple, generically applicable ancestor-counting algorithm for computing tree depth.
