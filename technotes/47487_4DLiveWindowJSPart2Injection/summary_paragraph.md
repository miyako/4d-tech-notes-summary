This Technical Note is the second part of a series on 4D Live Window (4DLW) JavaScript integration, focusing on "injection" — the ability, added in 4DLW 1.1, to add and execute arbitrary JavaScript in a page displayed inside a 4DLW plug-in area, even if the page originally contained no script at all. It documents the Web_JavaScriptExecute(Area; Script) command in detail, clarifying a subtlety in the official documentation: the Script parameter must be literal executable JavaScript (e.g. "someFunction();"), not merely a bare function name/reference, which behaves differently (as illustrated with a document.prompt override example). The feature is explicitly limited to Windows, since the WebKit-based browser layer on Mac OS was too unstable to programmatically execute JavaScript reliably at the time, and the sample database ships with a time-limited 4DLW 1.1.2 demo license. The demo database shows two use cases: injecting JavaScript into a local HTML file bundled with the database (changing headings, images, table borders, or hiding content) and injecting into a "live" remote page — specifically the 4D Knowledgebase search page — to restyle colors and hide sidebar/breadcrumb elements. The note recommends Firefox's Firebug extension for inspecting unfamiliar remote pages' DOM/CSS structure to determine what selectors to target, while cautioning that 4DLW's underlying browser engines (Internet Explorer on Windows, Safari on Mac) expose different DOM APIs than Firefox (e.g. CSSRules vs. rules/stylesheets collections). It also flags a legal caution: modifying third-party pages (e.g. those using the Google Maps API) may violate the page owner's terms of use. Featured technology centers on the 4DLW plug-in, its JavaScript execution API, and browser developer tooling of the era, all tied to the discontinued 4D Web 2.0 Pack.
