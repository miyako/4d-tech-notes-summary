This Tech Note addresses a common deployment request: using Microsoft IIS, rather than 4D's own built-in web server, as the public-facing web server for a 4D application. It explains that this is achieved through a 3rd-party ISAPI filter, Helicon Tech's ISAPI_Rewrite, which acts like Apache's mod_rewrite but is built specifically for IIS, using regular expressions to catch and proxy requests to 4D's web server running on a different (typically non-standard) port. The note covers why IT departments often insist on IIS for corporate deployments, how the filter works (installed on the IIS machine, using global httpd.conf and per-site .htaccess-style configuration), and documents key directives (LogLevel, RewriteLogLevel, RewriteLog, ErrorLog, AllowOverride, RewriteEngine, RewriteBase, RewriteProxy, and flags like H for preserving the Host header, A for adding authentication headers, and CR for passing credentials). It then walks through practical example configurations: proxying only a specific directory to 4D, proxying only SOAP requests, proxying SOAP plus a specific directory, and proxying all requests, along with considerations for making sure a 4D-hosted WSDL file's URLs remain correct behind the proxy. The note targets 4D developers who need to satisfy enterprise IT requirements while still serving 4D's dynamic and static web content.
